# 家庭运行时

一个本地部署同时只服务一个家庭。后台随应用启动，维护该家庭的设备清单、规格和媒体状态，不依赖页面访问。首次设置选择家庭；之后可在“设置 → 米家家庭”重新绑定同一账号下的其他家庭，设备和看家页不提供家庭切换器。

本文的“设备清单”包含家庭、房间、设备及其归属；“设备规格”描述设备支持的属性、动作和事件。“公共状态（projection）”是后台已确认、供页面读取的状态，只包含允许公开的数据和规格摘要。页面通过 SSE（服务器持续推送状态的 HTTP 连接）接收这份状态。

业务规则、运行资格和故障组合的详细约定见[家庭运行时：功能与业务行为](contracts/household-runtime.md)。

## 绑定与运行资格

`mijia_home_selections` 保存本实例唯一的账号键和家庭 ID。账号键由区域和用户 ID 编码；绑定读写共用部署级事务锁，拒绝另一账号覆盖绑定，重新绑定时检查数据库中的原家庭与本次操作预期一致。首次只有一个候选家庭时自动可靠保存后采用，多个候选时由设置页选择。退出或凭据失效保留家庭绑定；重新登录必须使用原账号。

设置页提交绑定时，保存失败通过 HTTP 报错，可重新提交选择；保存确认后才采用绑定。绑定已保存但设备清单初始化失败时，保留绑定，只重试设备清单同步，不要求重新选择或重复保存绑定。

绑定和凭据必须可靠保存。绑定已确认、当前账号有授权、本轮完整云端清单通过校验并提交后才进入 `running`，允许设备任务和新播放。单台设备的规格准备不阻挡整个家庭启动，读取前仍须有适用于当前设备定义的规格。启动缓存只用于展示，不能授权设备读取。设备清单缓存可重新获取：读取或保存失败标记 `storage_degraded`，但已确认的云端清单、新设备及新归属仍可使用。`cloud_synced_at` 与最近成功的 `saved_at` 分别记录；缓存故障后的下一次后台或手动刷新重试保存。保存时在绑定锁内核对数据库，内容相同时复用保存时间，不能复用清理之前的内存保存确认。

退出时如果数据库中的凭据删除失败，账号和家庭绑定仍保留；后台立即重新获取完整云端设备清单，通过正常校验后恢复运行资格。

初始化云端请求失败时保持 `initializing` 并允许刷新重试。已运行家庭普通刷新失败保留已确认资料和任务。完整清单确认设备移除或转出时，先撤销该设备的读取、观察和播放资格，再取消对应资源；型号或规格变化使该设备的旧任务失效，其他设备继续运行。缓存保存失败、资料超限和迟到结果不能恢复已撤销资格。整个家庭失去访问时保留绑定、进入 `initializing` 并报告 `home_unavailable`，等待原账号权限恢复，不转为选择另一家庭。

### 切换家庭与清理数据

在“设置 → 米家家庭”选择同账号下的另一家庭，确认“清空数据并重新绑定”。首次绑定不清理数据。切换保留米家登录凭据、表结构和迁移记录；backend 在同一数据库事务中清空家庭资料表（设备清单缓存、成员、身份参考、上下文及关联、空间、通道、观测绑定，以及自动化配置、执行、动作、决策、模型调用登记、AI 条件调度与判断记录、家庭事件），并保存新绑定。自动化相关表由 `0016_automations.sql` 创建，纳入同一生命周期登记；表结构存在不表示自动化执行器或 AI 条件服务已接入。设备清单和空间写入共用绑定锁并检查当前绑定，旧家庭迟到写入不能恢复已删除资料。

表归属统一登记在 `household/data-lifecycle.ts`：新增 schema 表必须声明随家庭清空或跨家庭保留，漏登无法通过类型检查；运行时核对 `public` 中的实际表，未登记或缺失的表会阻止切换。清理使用显式表清单的 `TRUNCATE ... RESTRICT`，即在同一事务内清空全部指定表，拒绝越界级联删除。身份参考文件沿用所属领域的提交后清理。登录凭据、绑定记录和 `drizzle` 中的迁移记录保留。

保存确认后结束旧家庭运行，清空当前属性和房间总结，取消相关感知任务并初始化新家庭。切换不要求 Agent 在线；单次问答不保存家庭资料，不参与数据库清理。已经删除的 backend 业务数据不能通过切回原家庭恢复。

数据库提交结果不确定时沿用绑定核对机制。此流程不删除模型文件、连接配置、诊断 JSONL 或外部追踪数据，也不清理不再使用的 `agent_state` 表。不要直接改绑定 SQL 绕过清理流程。

## 领域职责与状态

`household/machine.ts` 用 XState 状态机库管理生命周期，`runtime.ts` 协调首次绑定、清单与规格准备。`HouseholdSource` 是接入边界，`mijia/household.ts` 连接米家服务；`MijiaService` 管理账号和凭据，`DeviceDiscovery` 获取云端设备清单，媒体模块管理 go2rtc，`HouseholdSpecifications` 管理后端完整规格与设备引用。

| 状态               | 含义                                                   |
| ------------------ | ------------------------------------------------------ |
| `unbound`          | 无可用账号授权，数据库中的家庭绑定可能仍存在           |
| `waiting_for_home` | 等待首次家庭选择                                       |
| `initializing`     | 等待当前完整清单，或绑定家庭不可访问                   |
| `running`          | 账号与当前完整清单已确认，缓存／规格／媒体故障分别显示 |
| `stopping`         | 正在关闭任务与资源                                     |

启动时先订阅来源通知再读取初值，避免遗漏初始化期间的变化。状态节点决定公共 `status`；普通数据发布不能改变生命周期。状态机一次性提交已校验的数据，转换条件（guard）只作判断。提交后再通知订阅者、执行后续操作；内部 `input_sequence` 是进程内状态提交序号，用于防止同一次操作重复执行，没有公共变化的有效命令仍会执行。网络、数据库、连接和取消控制器由各自模块管理。

`scope_epoch` 标识一轮有效运行，隔离重启、授权失效和新登录会话的旧结果；同账号凭据续期保留家庭运行标识。`sequence` 只在公共状态变化时递增。播放同时检查家庭标识与媒体 `revision`，它们分别管理自己的生命周期。

## 设备清单与规格

家庭和房间的成员列表用于确定设备归属，不保证当前账号能取得每台设备的详情，共享家庭也可能包含没有可用详情的成员。所有请求和分页成功完成后，只把返回详情且归属绑定家庭的设备加入运行范围；未返回详情的设备不阻挡其他设备运行，也不能沿用缓存取得访问资格。家庭仍存在且完整查询确认没有可访问设备时，可以运行空清单。请求失败、响应结构非法或分页异常时整批拒收，保留上次已确认的设备清单，不能据此推断移除。提交前检查账号、运行标识、取消状态和大小边界，旧结果不能覆盖当前状态。

整份设备清单的最新确认时间由家庭级 `cloud_synced_at` 表示，实体不附加每轮变化的确认时间。后台复用未变化记录，SSE 只发布发生变化的整条记录或删除标识；无变化刷新只更新同步信息。首次数据库保存完整清单，后续以 JSONB 条目补丁更新，保存时核对当前绑定与数据库内容，内容未变时不重复写入。JSONB 是 PostgreSQL 的二进制 JSON 字段；其物理存储仍可能整行重写。详细边界见[运行行为](contracts/household-runtime.md#增量处理的边界)。

后台每五分钟同步设备清单，结构变化通知经防抖触发同步；重复请求合并为在途任务和至多一次后续刷新，仍遵守供应商退避期限。家庭成员与设备详情的全部分页完成后一次提交当前账号可访问的设备清单。账号恢复取得的完整清单直接复用，普通 GET 不触发云请求。缓存只保存当前条目，不累积已移除设备或历史归属。绑定与缓存写入使用事务级咨询锁（advisory lock，由应用约定共同使用的数据库锁）协调：设备清单操作持有家庭绑定共享锁及设备清单排他锁，重绑持有家庭绑定排他锁；历史查询不会因共享绑定资格而阻塞普通设备清单保存；事务最多五秒，包含锁等待。提交结果不确定时，先核对数据库中的保存结果再执行后续写入；核对不改变已确认云端清单的运行资格。

完整规格由后端持有，按含版本的 URN（设备规格的统一资源名称）共享，并通过 Agent 专用通路交付；Web 家庭公共状态仍只提供规格摘要。优先使用设备的 `spec_type`，缺少时按型号解析。最多三个准备任务，瞬时失败额外在两秒、十秒重试。重复清单不重置失败次数；显式刷新合并同一批次，同一 URN 在批次内获取一次。没有设备引用的资料和解析任务被释放。容量检查复用未变化规格对象的大小，设备摘要只更新受影响的设备；空集合或摘要内容未变时不再发布状态事件。新增设备可以直接使用已接纳的同一规格，不让原设备重新准备。

页面收到 `spec_id/spec_status/spec_error`、分类和能力标签；`readable/writeable/notify/action/event` 分别表示可读、可写、可通知属性及动作、事件能力，不代表已启用采集或控制。旧摘要可继续显示；读取前检查规格是否适用于当前型号及定义。型号或 URN 改变后，旧显示缓存不能授权新读取。同定义刷新失败可保留已确认能力；一个解析任务失败不影响其他已成功任务。

## 公共接口与 SSE

| 接口                                | 内容                                                                                                                         |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/mijia/state`              | `{ scope_epoch, sequence, projection }`，只读诊断快照                                                                        |
| `GET /api/mijia/diagnostics`        | 按需 JSON 字节大小和最近进程内存采样                                                                                         |
| `GET /api/mijia/events`             | 完整快照与增量 SSE                                                                                                           |
| `GET /api/mijia/setup/homes`        | 首次设置和重新绑定候选 `{ items }`；不触发云请求                                                                             |
| `PUT /api/mijia/scope/homes`        | 保存或重新绑定 `{ scope_epoch, home_id }`，非空家庭 ID；保存完成返回 202 `{ state_version }`；过期运行标识或绑定冲突返回 409 |
| `POST /api/mijia/devices/refresh`   | `{ scope_epoch, target: directory / specs / all }`，接纳后返回 202 `{ state_version }`                                       |
| `GET /api/mijia/login/:id/material` | 当前尝试的二维码和验证材料，`no-store`                                                                                       |

公共 `projection` 包含账号、登录、连接操作、媒体、家庭、健康，以及 `home/room/device`、`latest`、`device_coverage`、`source_health` 和 `collection`。实体键按稳定身份编码。候选家庭、完整规格、凭据、登录材料和内部操作不进入 SSE。属性与在线状态的有效性独立于设备清单缓存；接口、策略和限制见[设备事实与房间快照](contracts/device-facts.md)。

Mutative 不可变数据更新库的 `produce` 构造候选，不冻结调用方数据；变化条目经共享 Zod schema（输入校验规则）的白名单和身份校验后成为独立不可变对象。设备清单准备和最终提交共用 `prepareProjection`，已经校验的同一实体记录在最终提交时直接复用；实体类型或身份键改变仍重新校验。前后端直接在 Mutative 草稿中应用条目变化，由库管理必要的复制。`packages/api/src/immutable.ts` 是项目内的薄包装：`produce` 生成候选，`freeze` 冻结自有结果，`parseImmutable` 校验并隔离外部输入；冻结本身不授予可信身份。未变化条目保留引用，浅冻结对象不能绕过校验。设备清单不维护重复的序列化字节账本；属性集合维护有界容量计数。

每个浏览器标签页共用一条家庭公共状态 SSE。先订阅再取得完整快照，此后整批发送连续变化；同版本编码可被多连接复用。运行标识变化或停止时要求重新同步；断线恢复当前状态，不补发事件历史。缺失版本或消息非法时重连，普通断流保留旧显示并标记未同步。设备历史使用下文的独立事件流，家庭公共状态不承载逐条历史报告。

心跳十五秒；浏览器等待响应头十秒、首快照三十秒，之后四十五秒无有效消息重连。退避从一秒增长到三十秒并加随机延迟，稳定同步六十秒后重置，遵守服务器 Retry-After。自动重连、手动重试和标签页恢复共用等待期限。

HTTP 命令与 SSE 确认分开。刷新返回 202 表示任务已接纳，完成或失败由订阅显示；相同目标的在途刷新合并，刷新不改变家庭绑定。命令按自身所需标识发起，不以 SSE 连通为通用前提；命令响应不回填公共状态。退出期间暂停新播放，等订阅达到回执或取得 HTTP 结束后重新订阅的完整快照才重新判断资格。新播放同时检查家庭运行资格、设备身份和媒体 `revision`，不单凭设备清单的在线字段阻止播放。房间、分类、能力与在线状态筛选仅改变页面显示。

## 资源限制与关闭

大小按 UTF-8 JSON 编码后的字节数计算；1 MiB 为 1,048,576 字节，1 KiB 为 1,024 字节。参数集中在 `household/config.ts`，公共传输参数由共享 `householdStreamPolicy` 定义。

- 设备清单接纳和缓存最多 4 MiB、1024 台设备；完整规格独立最多 4 MiB，单次规格响应也最多 4 MiB。
- 设置候选和账号资料各最多 2 MiB。规格摘要标识最多 256 个 ASCII 字符、分类最多 64 字符；规格错误最多 1 KiB，其他公共控制错误最多 4 KiB。
- SSE 快照上限 8 MiB，每连接变化队列最多 256 条或 2 MiB，最多 16 条连接。写入十五秒未完成、队列满或消息过大时关闭该连接。

设备清单或规格资料超限时报告 `capacity_degraded` 并保留上次接纳资料，不截断实体；已确认的访问撤销仍生效。设置候选超限报错；超大账号资料不能阻挡认证状态更新或资源清理。退出、停止、访问撤销和规格任务开始／结束不经过统一容量准入。数据与传输分别在自己的边界限制大小，没有控制空间或每设备字节预留。

诊断 `bytes` 分别报告当前设备清单、元数据、公共状态及后端规格的实际 UTF-8 JSON 字节数。进程内存每六十秒采样，峰值只表示采样观察到的值，不代表家庭独占内存或瞬时峰值。

停止和失效取消请求、订阅、计时器及观看，关闭等待媒体队列收尾。迟到结果不能更新新运行。慢 SSE 不阻塞其他连接，不触发额外云请求；HEAD 仅返回响应头，不建立订阅。

持续属性采集与房间事实快照已接入，设备页 `/devices` 可按房间查看原生属性、值、时间、质量与覆盖，并执行一次性读取。采集不依赖页面；当前值投影保留在内存，接纳的属性与在线报告另由[设备状态历史](#设备状态历史)保存到数据库并提供查询。场景判断尚未实现。配置与验证边界见[设备事实与房间快照](contracts/device-facts.md)。

## 验证范围

实现审查与确定性回归覆盖唯一绑定、运行资格、缓存故障隔离、规格与公共摘要分离、原子发布、迟到结果拒收及停止清理。它们不能替代真实设备、供应商故障及完整操作流程的证据。

已有实机覆盖包括：

- 无浏览器连接、无刷新命令时的五分钟后台发现；SSE 快照与连续增量、刷新、只读 GET、连接上限及取消回收；真实换房通知的基础行为。
- 家庭运行标识更新与异账号绑定拒绝；切换时数据库清理及跨服务故障组合仍需实机验收。
- 首次缓存锁超时仍可读取和播放、Agent 未启动时独立运行、后续保存恢复；运行中注入云端网络失败后保留已确认设备资格并恢复同步。
- 真实 PostgreSQL 提交后注入响应丢失，通过数据库核对确认保存结果；正常关闭、开发进程停止与再次启动。

尚未覆盖真实设备新增、移除、跨家庭转出及访问撤销叠加保存失败，自然凭据到期续期、供应商真实认证拒绝与限流，以及另一账号扫码登录的完整流程。启动时真实续期、数据库拒绝或故障注入不能替代这些场景；正常关闭也不能证明所有操作系统信号或异常杀进程方式都可安全收尾。

本机脱敏记录保存在 Git 忽略的 `data/verification/household-step-2/<run_id>/report.json`。共享文档维护当前行为和适用范围，不保存单轮操作日志，也不把局部证据泛化到所有设备和固件。

## Agent 当前数据与材料历史

统一观察交付最新状态集合：每位成员保留最后出现，未知身份按摄像头／镜头保留最新出现，其余线索按摄像头／镜头和类型保留最新一条；同一时刻的成员出现保留并列来源。选中的音视频窗口最多生成一条观察，成员记录通过 ID 关联，统一上下文保留引用、观察索引、设备与镜头来源、成员出现轻量身份投影及归因修订号、轻量窗口材料摘要（内容修订号、原始输入保留状态、片段生成状态、语音启用状态与段数、猫狗声分析状态／结果有效性与检测结果数量），不携带成员正文或完整音视频窗口详情；材料摘要变化会更新对应观察，仅来源读取时间或整理时间变化不重复推送。关联要求相同家庭运行、摄像头及镜头、视频运行、媒体代次、观察时间内的帧与跟踪编号。没有可关联窗口的成员记录仍生成独立出现观察，不证明当时没有音视频。窗口按关联成员、检测或跟踪目标、既有 `gate.visual=changed`、语音转写或猫狗叫声选取；画面变化无需检测到人宠，因此无成员画面变化也会交付。画面变化、语音和叫声归属窗口，不因成员在窗口中出现就归因给该成员。多个成员共享一条窗口观察；跨窗口共享音轨或转写不能算作独立重复证据。出现记录引用不等于已知成员身份；当前归属为 unknown（包括身份撤回）的目标仍标记 `unidentified_target`，即使已有出现记录或没有关联窗口。未知身份、未检测到目标和检测缺失不同，都不证明无人。成员与窗口来源分别读取、缓存和重试，失败时清除该来源数据并交付明确状态，其他来源继续发布；统一部分 ready 表示组装成功，不表示两个来源均 ready。变化仅是待分析线索，发布通路不调用模型分析或自动生成媒体，实际分析仍需模型接入。字段定义见[共享契约](../packages/api/README.md#agent-数据交付契约)。

Backend 的 `GET /api/agent/context/stream` 持续交付当前家庭资料，不要求 Agent 聊天或模型配置。Agent 启动时订阅，`GET /api/received-context` 本机只读诊断返回当前家庭身份、连接状态、收到的部分与最近接收时间。停止 Agent 不停止 Backend 采集；Agent 重启重新读取，不保存 SSE 消费进度或重放断线变化。配置与客户端用法见[Agent README](../apps/agent/README.md)，共享字段见[Agent 数据交付契约](../packages/api/README.md#agent-数据交付契约)。

专用快照分为 `household/spatial/device_state/members/observations` 五部分，分别包含家庭、房间、设备及完整规格，空间、通道和观测绑定，最近属性与在线值及采集状态，登记成员，以及关联成员出现与音视频依据的统一观察。空间资料复用空间模块的公开记录，包含停用的观测绑定；按稳定 ID 关联通道端点、观测目标和设备清单。空间修改成功或提交结果不确定时重新读取；版本冲突、引用阻止删除及已确认回滚不触发刷新，读取失败独立报告并重试，家庭切换时清空旧资料。音轨沿用 `audioTrackRunId` 关联，共享音轨及跨窗口引用用原 ID 识别；出现记录是相同观察的数据库历史视图，不能计为另一次观察。身份判断保留采样时点，当前归因不回填历史帧。通路只传已有字段、依据与媒体引用，不传凭据、参考照片、特征向量和媒体字节。

`POST /api/agent/context/material` 按 `{ scope, kind, id }` 解析单个引用，kind 为 `member_sighting` 或 `perception_window`。读取当前家庭资格下仍保留的源记录；成员来自数据库当前归因，窗口来自当前感知服务。返回当前可用内容，不保证是接收时的历史版本，不生成媒体，也不写回 Agent 接收上下文；引用不存在或窗口过期返回 404，家庭资格不匹配拒绝读取。此接口允许既有可信本机 Web 入口和 Agent 服务访问。

### Web 接收端观察

Web “数据”页面 `/agent-context` 通过本机只读代理读取 Agent 进程的真实接收索引、单次消息及合并结果，不独立订阅 Backend 发布流。页面展示接收记录、原始上下文和由同一读取快照生成的压缩后上下文；Agent 不可用不回退为发送端数据。接收记录有条数和字节上限，仅保留当前连接与家庭资格下的数据，淘汰、断线与重启不补录。访问限制、阅读和导出说明见[Web 接收数据观察](../apps/web/README.md#agent-接收数据观察)，接收接口与保留策略见[Agent README](../apps/agent/README.md#当前数据接收与只读历史客户端)。原 Backend stream 与 history 通路不变。

### 分部状态与刷新

每部分有 `status/read_at/data/reason/truncated`。首次读取尚未完成为 loading；ready 携带读取结果及 UTC 完成时间，空集合是成功空结果；unavailable 表示未配置、未启用或没有访问资格，failed 表示本应可读的来源失败。非 ready 的 data 为 null，unavailable/failed 给出安全原因；read_at 表示最近一次读取尝试的完成时间，没有完成过则为 null。failed 清空旧 data，并有界退避重试，不阻止其他来源刷新。

设备状态只交付属性身份、值、证据、质量和时间；描述、类型、单位与可读性由设备清单的规格提供，家庭、房间和规格归属由设备记录提供。新增动态记录按共享 schema 校验，未变化来源记录复用已生成的动态对象。

整理服务先登记监听再读取初值，各来源分别读取；每个来源最多一个在途读取，期间通知合并为完成后的再刷新。家庭资料、规格与设备状态按实际来源变化分别刷新；单部分更新保留其他已校验部分的对象，并累计各部分字节预算。同一不可变部分的紧凑 JSON 与字节数只生成一次，供预算计算和各连接全量发送复用；选择增量时直接复用已序列化的增量正文。感知维护周期只在交付状态或成员关联实际变化时刷新，仍覆盖音轨有效期和关联到期。

成员与出现记录只在事务成功且实际变化后通知，成员通知在参考文件清理前发出。提交结果不确定时，先在相同数据库锁下核对保存结果；无法核实时阻止后续盲写，并以 1 至 30 秒退避在后台继续确认，不依赖下一次修改。确认提交后通知一次，确认回滚后恢复成员参考状态而不通知成功。旧家庭资格不能交付迟到的确认结果。窗口接纳、晚到声音与转写、移除或失效，以及媒体生成完成、失败、过期和撤销都会刷新；状态读取不触发媒体编码。多个 SSE 连接共享整理缓存和来源监听，单连接关闭只释放本连接资源，Backend 退出停止来源监听、确认与重试计时器，并隔离迟到读取。

snapshot 为 `{ scope, parts }`，scope 使用当前绑定和家庭运行标识；首次包含全部五部分，后续省略某部分表示保留它。设备状态已有同一连接、同一家庭的 ready 基线时，后续优先发送更新／删除条目的增量；在线列表仅在变化时发送。差异对照该连接最后成功发送的状态计算，覆盖发送期间合并的通知；大量变化导致增量比全量更大时发送完整部分。其他部分及设备非增量消息整体替换，状态恢复后先发送完整设备状态。接收端复用共享 Mutative 不可变更新封装合并增量，保留未变化条目的对象；旧接收记录不随后续增量修改。heartbeat 只保持连接，不表示业务更新或同步完成。家庭切换、退出、撤权或停止先撤销旧读取资格并清空缓存，再交付全部部分 data 为 null 的清空快照；有新资格的部分为 loading，否则为 unavailable。清空快照发送后，已准备好的新版本继续串行发送，不等待下一次通知或心跳。家庭未绑定时 scope 为 null。接收适配器在运行资格变化时先清空，在首次连接和重连时释放旧数据，收到当前连接的全部初始部分后才完成初始接收；断线标记未同步，旧回调与迟到历史响应不能恢复旧资格数据。

统一观察的 `as_of` 是整理时间，不是目标观察时间。成员最近出现从数据库按当前归属和 `lastObservedAt` 选取，不受 30 分钟限制；身份撤回或改归属后重新选择，可能回到更早的有效记录。未知身份按设备与镜头选取最后出现，不视为某位成员。窗口级线索在当前仍保留且最近 30 分钟内的材料中，按摄像头／镜头与线索类型选取最新一条；相同窗口的最新线索合并，`reasons` 只列该窗口仍代表最新状态的类型。同一成员材料只关联一条选中观察，其余历史不进入 Agent 当前快照。没有观察不表示无人，最后出现也不表示当前位置。

成员数据库在共享家庭绑定和成员锁下，数据库排名只携带记录 ID、观察时间和分组计算所需字段，筛选后再按 ID 读取正文投影；由此选出各成员及未知来源的最近出现，并读取最近 30 分钟的轻量关联投影，以准确判定窗口目标的当前归属。关联投影仅供 Backend 整理，不交付为 Agent 历史缓存；投影没有身份图片、特征证据或转写正文。窗口按来源运行、家庭运行、镜头、媒体代次、目标编号及观察时间匹配；未选为最新出现的已知目标不会因此误标为未知。过期窗口和不再用于关联的近期投影通过到期刷新清理，成员最后出现继续保留。窗口素材仍受感知存储的到期、容量淘汰和重启限制，不承诺历史媒体可用。

各部分与传输字节预算由 `agentContextPolicy` 定义，最新集合仍受观察部分 4 MiB 上限约束；超限报告 failed/capacity_exceeded，不以部分集合冒充成功。游标每批读取 16 条投影，仅累计必须交付的最新成员引用作为最低输出占用，最近关联记录不参与该最低占用判断；完成整理后检查实际输出大小。来源独立读取、失败与重试，失败清除对应来源数据；家庭资格变化清空缓存，迟到结果不能恢复旧家庭数据。慢连接按写入期限关闭，重连取得当前快照，不重放历史。设备状态同样按属性身份保存最新值，历史报告通过独立接口查询。数据库排名查询的长期历史规模性能尚未验证。

历史页按单条记录、响应信封和游标累计字节，在交付前校验完整响应。音视频先扫描仍有访问资格的窗口，结合来源、视觉、音频和转写区间以及游标选取最多 `limit + 1` 个窗口 ID，再按需逐条复制正文；达到响应预算后停止读取，除已选正文外只保留当前候选及一条用于判断续页的前瞻记录。成员查询使用观察时间及对象条件的部分索引；记录与关联对象在共享成员锁下读取，写入使用排他成员锁，读者之间可以并行。索引由数据库迁移创建，未执行对应迁移时不具备这些索引。

### 成员出现与整体音视频补查

`POST /api/agent/context/history` 独立读取保留材料，kind 为 `device_reports/member_sightings/perception_windows`；设备分支沿用[设备历史](#只读历史接口)。公共输入是预期绑定 `account_id/home_id`、必填 UTC `start/end` 和 `limit/cursor`。`start < end`，查询半开区间 `[start,end)`；成员可选 `member_ids` 与 `sources`，窗口可选 `sources`。sources 为 `{ device_id, channel? }` 数组，省略 channel 匹配设备全部镜头，省略数组不筛选，显式空数组拒绝；筛选条件去重并固定排序。来源摄像头只说明观察来源，不表示成员当前位置。

成员分支从 `context_records` 读取 `member_sighting` 及其 `context_entities` 关联，返回原记录内容、时间依据和当前修订的归因。匹配条件为 `firstObservedAt < end && lastObservedAt >= start`：单点在 start 匹配，在 end 不匹配。跨度不证明持续在场，endedAt 不证明离开房间。member_ids 按当前已知归因匹配，sources 按记录 deviceId/channel 匹配；两者同时提供时取交集。SQL 在区间与对象筛选后按 `firstObservedAt/id` 升序应用游标和 limit+1，旧记录 scopeEpoch 不用于筛掉同一绑定的已保存历史。记录没有另设时间保留清理，成员删除保留历史，家庭重绑按既有规则清空。

音视频先读取当前有资格访问的完整窗口详情，再对视觉区间、非空音频区间和每条转写的 `observedStartAt/observedEndAt` 分别使用同一重叠规则，任一匹配返回整个窗口及匹配引用。只命中视觉区间以外的转写也能返回窗口；sources 按窗口设备与镜头筛选，音频沿用原 run。按 `startedAt/id` 升序对匹配详情分页。读取期间已撤销或不存在的窗口不返回；详情仍在但媒体过期时保留正文及原媒体状态，不调用编码接口补生成。

窗口在内存中最长约保留 30 分钟，可因容量或访问资格提前移除，Backend 重启不恢复；媒体另有[保留期限](perception.md#容量停止与访问期限)。接口不为已移除窗口建立缺失索引，当前最早剩余记录不能证明此前未采集或查询区间完整。成员历史返回数据库当前归因修订，转写历史随窗口 `speech.segments` 返回；原时间基准统一格式不证明设备时钟同步。

新增分支响应包含 `kind/account_id/home_id/start/end/records/next_cursor` 及各自的 retention 限制。游标绑定 kind、家庭身份、绑定记录 updated_at、规范化对象条件与区间；音视频还绑定 perception.instanceId，Backend 重启后拒绝旧音视频游标。同一绑定的成员历史可以跨进程续页，每页查询及响应前仍核验当前资格，家庭切换后拒绝旧请求。游标格式错误或条件不符返回请求错误，不退回首屏。

默认每页 100 条、上限 1,000 条，按完整记录及共享字节预算分页，游标指向最后实际返回记录；首条单独超预算返回容量错误，无下一页时 next_cursor 为 null。成功无匹配项返回 records=[]，不可用或读取失败返回错误。两类分页均不保持跨请求快照，归因修订、晚到内容和淘汰可改变后续页，结果不作为完整消费记录。Agent 通过共享 Backend RPC 客户端和有界 JSON 请求读取，`context/reader.ts` 校验响应与请求匹配，并在返回前重核接收资格，结合调用方取消和请求截止时间，失败时不用当前值或旧缓存替代。

### Agent 通路验证边界

真实来源验收覆盖家庭、设备、登记成员、Agent 接收、三类历史续页和窗口媒体状态；统一观察的成员关联、共享窗口和筛选尚未完成完整实机验收。Backend 重启后的重新接收、数据库成员游标续页及音视频旧游标拒绝已核对。该范围不证明声音或转写内容已完整送达；已有音视频观察与感知健康测试验证各自来源行为，不替代专用通路的组合验收。

以下组合尚未完成专项验收，不作为已验证保证：

- 成员资料新增、修改、删除及出现归因修订提交后持续到达，无变化和回滚不发成功通知；已提交结果不因随后参考文件清理失败漏发。
- 实际声音或转写晚到时更新同一窗口，保留视觉正文及原音轨／结果引用，以及视觉区间之外的转写匹配。
- 实际媒体失败、独立过期及撤销刷新接收值且不额外编码；窗口详情仍保留但媒体过期时，历史返回完整内容及现有媒体状态。
- 来源读取失败与恢复、慢连接、取消、删除／淘汰及容量超限的组合，包括失败清空旧 data、近期范围到期移除，以及历史分页游标指向最后实际返回记录并能继续前进。
- 家庭 A→B→A、解绑及撤权时先清空旧资格，清空之后无旧结果，新连接不能取得旧家庭缓存；未收到部分不标记同步、省略部分保留、空集合清空，以及 Backend 关闭期间迟到读取隔离。
- 成员单点 start/end 边界、当前归因与来源条件交集、多镜头筛选及进程重启续页的组合；音视频跨窗口共享引用保持原结果身份，分页或最早剩余记录不代表完整区间。

现有 Web 设备历史连接跨 Backend 重启的运行中，PostgreSQL 客户端 Postgres.js 出现 `socket.write` 异常；这一部署组合尚未确认稳定。

验证通过 Agent 接收诊断与只读历史客户端，使用真实来源和确定参数核对当前数据持续送达，以及同一区间内材料的时间、对象、正文和媒体可用状态，不推断因果；没有实机来源的部分保持未验证。遵守[仓库规则](../AGENTS.md)和[Backend 测试说明](../apps/backend/tests/README.md)，仅运行受影响的最小现有测试，未经用户明确许可不新增测试或故障注入脚本。原始验收材料只保留在 Git 忽略的本机目录，不把家庭数据、凭据或一次性运行日志写入共享文档。

该通路用于来源材料交付与只读诊断，尚未注册到模型工具或默认模型输入，不提供自动调查、因果推断、生活事件判断或语义回写。

## 设备状态历史

配置数据库并执行历史迁移后，Backend 在家庭采集启动前登记历史订阅，对接纳的属性、在线通知、成功读取候选和设备清单在线值，只保存首次值及后续值或属性说明的变化。同一设备的同一状态项连续同值不新增记录，来源变化本身也不新增记录；属性按 siid/piid 区分，在线状态独立比较，数字、字符串、布尔与 JSON null 不混同。重复接收仍按当前值规则更新时间和质量，不产生历史保存通知。合法家庭设备清单的在线值整批提交比较，未变化设备不写入；恢复本地缓存不生成新的清单读取报告。保存独立于页面、Agent 和模型；当前值提交不等待数据库。未收到的报告没有记录，写入失败或额度不足时丢弃当次提交，不落盘暂存、不重交；恢复后只保存新报告。

历史按 Backend 接收时间查询。米家普通推送标为 `push`，MQTT retained 消息标为 `retained`，云缓存属性读取标为 `read`，设备清单读取到的在线值标为 `directory`；当前来源没有已验证的设备采样时间。报告只证明收到过该值，不证明操作发起者、设备即时采样或两次报告之间的持续状态。空结果表示没有匹配的已保存记录，不表示区间完整。

`device_property_definitions` 保存设备 ID、MIoT 属性地址及接纳时固定的 `metadata`：`property_name`、`unit`、`value_list`。MIoT 的 `siid` 是设备内服务编号，`piid` 是服务内属性编号，必须取自真实规格。说明缺失项显式为 null；枚举保留规格顺序。相同属性及 JSON 内容在数据库事务中复用同一说明，说明改变则新增，旧报告继续引用原说明。

`device_observations` 逐条保存记录类型、设备 ID、接收时间、观测 ID、运行标识、接纳序号、原值和来源。`kind=property` 必须引用属性说明；`kind=online` 直接保存布尔 `value`，说明引用为空，不制造 MIoT 属性地址。数据库约束保证类型、值、说明引用与来源组合合法。数字、字符串、布尔与 JSON null 分开；缺少 value 的消息不成为 null 报告。历史说明、记录与最近保存状态三表无账号／家庭列，也不与当前设备清单建立外键。绑定访问事务与运行资格保护写入；设备移除后停止保存新报告，但同一合法绑定仍可查询旧报告。重绑在现有排他事务中与其他家庭数据一起 TRUNCATE，三表同时列入且不使用 CASCADE；事务失败保留原数据。

`device_history_state` 是最近保存状态的唯一所有者，每个设备和状态项只有一行，保存原值与属性说明内容；在线状态项为 `online`，属性状态项为真实 `siid.piid`。比较通过主键查找，不扫描时序历史、不按接收时间推断先后。状态与变化记录在同一个数据库事务中更新，事务失败一起回滚；连续同值不更新该表，也不追加历史。该表保留到家庭数据清理，不随一年历史保留边界删除，因此服务重启、时钟回拨或历史过期不重置比较依据。它用于决定是否保存变化，不代替当前状态的接收时间、质量和有效性。

历史服务使用已有 PQueue 按设备保持接纳顺序，不同设备可以并行保存，连接并发由已有 Drizzle / Postgres.js 连接池承担。一次接纳的完整设备清单只占一个提交名额，再交给各设备队列保存。每个设备批次在绑定事务内取得该设备的写入锁，批量比较状态并保存变化；同批同状态项按接纳序号比较，保留“开、关、开”的两次变化。最多保留 256 个排队或执行中的接纳批次、合计 4 MiB 完整报告内容；超限立即丢弃新批次，失败不重放。队列不保留旧家庭快照，设备队列空闲后释放。写入前后核对当前设备资格，设备撤销或家庭运行失效时回滚该设备批次的状态与历史，其他设备不受影响。同一接纳批次的全部设备事务结束后释放额度，分别统计保存、同值跳过、失败与丢弃；只有实际保存的记录触发历史通知。关闭取消订阅、撤销未完成提交的资格，沿用 Backend 关闭期限与连接池关闭。

### 只读历史接口

`POST /api/agent/context/history` 的 `kind=device_reports` 分支以一次性 JSON 响应提供设备历史；成员和音视频分支见[Agent 材料历史](#agent-当前数据与材料历史)。Web 的 `POST /api/device-history/events` 通过下文的 SSE 交付相同设备读取服务的页。两个入口仅接受本机访问，不触发设备读取。设备读取输入为预期绑定 `account_id/home_id`、必填 UTC `start/end`，以及可选的 `device_ids`、`kinds`、`properties: [{device_id,siid,piid}]`、`order`、`limit` 和 `cursor`。固定区间为 `[start,end)`，必须 start 早于 end，支持到微秒的时间精度。kinds 默认同时查询 `property` 和 `online`，可只选其中一类；device_ids 省略时不限制设备，显式筛选最多接受 1,024 台，与共享设备清单容量一致。properties 仅匹配真实属性地址，提供它时不会返回在线记录；三种筛选条件取交集，显式空数组拒绝。设备、类型和地址去重并固定排序，允许查询已移除设备。siid/piid 复用共享属性地址边界，范围为 1–2147483647，与数据库整数列一致，超界在输入校验时拒绝。

查询统一返回已保存的变化记录，直接按接收时间与游标定位，不做同值分段或报告次数聚合。写入时跳过的重复报告无法从历史恢复；查询区间内没有变化时可能为空，当前状态应从当前值接口读取。

响应携带绑定身份、校验后的 `start/end`、固定 `retention_days=365`、`records` 和 `next_cursor`；Agent 入口另含 `kind=device_reports`。每条记录包含 observation_id、received_at、kind、device_id、value、source；属性记录另含 siid、piid、definition_id 和 metadata，在线记录不返回属性说明字段。运行标识和接纳序号只供仓库及不透明游标排序，不进入 records。

排序键为接收时间、运行标识、接纳序号和观测 ID；`order` 默认 `asc`，也支持 `desc` 按最新优先读取。同一接收时间、同一运行按本地接纳顺序排序，降序时反转排序方向。时钟回拨仍按接收时间排序；跨运行相同时间的运行标识排序不表达因果。游标保留数据库完整时间精度，并绑定家庭身份、绑定记录的 updated_at、规范化设备、类型与属性筛选、区间与排序方向。重新绑定后拒绝旧游标，相同绑定跨 Backend 重启可续页；格式错误或条件不符返回请求错误，不退回首屏；游标时间最多保留微秒精度，序号必须在 PostgreSQL bigint 的非负范围内。每页在绑定事务内及交付前重新核验当前访问资格，退出或撤权期间不交付历史。

共享配置默认每页 100 条、上限 1,000 条，响应最多 1 MiB，请求最多 128 KiB。SQL 最多生成 limit+1 个页候选，Postgres.js 原生游标每批交付 16 条；查询服务按完整记录与响应容量组装，达到条数或字节预算后关闭游标，停止读取剩余候选。读取只保留当前原生游标批次及正在组装的有界响应，不保留全部结果；分页游标指向最后实际返回的位置。首条记录单独超预算返回容量错误，成功无匹配项返回空 records 和 null 游标；数据库失败返回存储错误。家庭历史与 Agent 历史使用 household_scope_changed、household_unavailable、household_capacity_exceeded 和 household_storage_unavailable 等公共错误码；HTTP 适配由家庭模块负责，不依赖米家错误转换器。

历史读取直接使用已有 Postgres.js 共享连接池，由驱动分配连接并调度等待。连接池最多 10 条连接，历史与其他数据库业务共用；历史读取不另外设置应用级并发或排队名额。Agent 历史、Web 实时首屏、分页与单游标导出共用同一资格与读取服务；读取请求受当前取消及读取期限约束，取得连接和交付结果前仍核验取消与家庭资格。

取消请求或到达读取截止时间时，读取入口立即停止交付结果。仍在连接池中等待的事务取得连接后先核验取消与家庭资格，已取消时不执行历史 SQL。执行中的 SQL 在游标下一批次检查或数据库预算到达时退出：每个 SQL 前后及每条游标记录交付都检查取消与资格，游标检查失败或达到分页容量后通过原生异步迭代退出结束读取；普通页读取设置 5 秒的语句、锁等待与事务期限。导出在单个只读事务和 SQL 游标中读取，语句、锁等待与事务期限沿用 Backend 的 BACKEND_REQUEST_TIMEOUT_MS，交付总期限也受同一请求截止时间约束，仍受客户端取消与当前家庭资格约束。数据库仓库仍等待事务完成或回滚结果，超时不自动缩小区间。连接池等待、数据库故障和事务收尾仍可能延迟资源释放，不能把请求截止时间当作释放连接的硬期限。全年区间可以查询，实际扫描量与排序成本仍取决于筛选、索引和数据规模。

分页不保持跨请求快照：晚提交、保留边界推进或清理可以改变后续页。后来提交且排序早于已返回游标的报告不会补入续页；需要核对区间时应从首屏重新读取。实时推送和历史保存分别交付，不能把分页结果当作完整消费记录。

### Web 历史事件流

`POST /api/device-history/events` 接收共享读取条件与 `delivery=live|page|export`。live 要求 `order=desc` 且不带游标，开始时间须早于当前时间；保留 start，每次读取把 end 更新为 Backend 当前时间。先监听保存成功通知，再读取首屏并发送 `page`，避免漏掉初始读取期间的保存。后续匹配的保存通知按 250 毫秒合并后读取 SQL 首屏；同一家庭作用域与规范化查询条件的活动连接共享已提交版本的读取 Promise 和首屏结果，最后一个连接离开时取消共享读取并释放结果。保存版本由历史服务拥有，提交成功且资格仍有效后推进；结果不会跨家庭作用域复用。共享页还按最早记录的保留截止时间失效，活动连接在该边界到达后重新读取并发送移除，即使没有新报告。定时器仅用于保留边界，不周期轮询历史。发送 `change`：`records` 只含新增或内容变化的完整记录，`record_ids` 给出当前页的全部有序 ID，`removed_ids` 移除不再属于当前页的项。记录 ID 使用 observation_id；不能把页增量当作完整逐条消费记录。

page 固定区间与游标，发送一条 `page` 和 `complete` 后关闭；export 固定区间，在单个 SQL 查询快照中用原生游标连续读取，按响应条数与字节预算把页写入本机私有临时文件。结果准备完成、数据库事务结束并释放连接及家庭锁后，才向客户端交付 `page` 数据批次；各批 next_cursor 为 null，不再重开 SQL 续页。临时页文件最多 64 MiB，超过时返回 device_history_export_too_large；正常完成、取消或失败均关闭文件并清理临时目录。临时文件不是历史存储或失败重试队列。慢客户端只影响文件读取与网络交付，不延长数据库事务。最后发送 `complete` 后关闭。晚提交和保留清理不会改变同一次导出的查询快照；数据范围以查询开始时已提交且符合区间与保留条件的记录为准。超过 Backend 配置的读取期限或任一读取／交付失败则不发送 complete，客户端不生成部分文件。两者复用相同的查询、资格、取消及每页容量边界。流内失败使用 `error` 事件。实时连接断开后重新读取当前有界首屏，不完整重放断线期间的逐条报告；数据库仍按一年历史保留边界供固定区间读取。保存失败、无记录获准保存或写入超限时，不从接纳回调推送未保存报告。

历史事件流最多 16 条连接，心跳间隔与单次写入期限均为 15 秒；单事件最多 1 MiB 加 128 KiB，待写事件最多 256 条且总量不超过两个单事件预算。慢连接或超预算关闭本连接。历史流与家庭状态、感知及语音快照共用 SSE 传输能力，但分别维护协议、连接计数及资格；相同实时查询共享计算，不同查询和导出的数据库读取由共享驱动连接池调度。客户端读取、数据库提交和网络交付是不同结果，不以其中一个推定另一个成功。

Web 的 `/device-logs` 使用该事件流读取、比较与导出同一套已保存变化记录，用法见[设备日志页面](../apps/web/README.md#使用流程)。滚动阅读保留已显示记录，实时流继续接收最新页；查询固定区间或滚动自动读取更早记录时关闭实时流，后台继续保存，更早记录追加到当前虚拟列表，保持阅读位置；设备对比表同样按时间分组虚拟化，离屏详情的展开状态保留，键盘焦点所在分组保留挂载；不展示页码或翻页按钮。点击“回到最新”重新取得实时首屏并释放追加的历史。历史只包含属性与在线报告，连接与订阅状态由当前家庭采集诊断提供。

### 数据库维护与验证限制

`0014_device_history_state.sql` 创建最近保存状态表，在家庭绑定排他锁内，按已有历史的接收时间排序为每个状态项初始化比较值，不删除或改写已有历史记录。已有数据没有独立的跨运行接纳序号，初始化不能还原过去时钟回拨期间的真实接纳顺序。初始化完成后的写入统一按设备接纳顺序更新比较状态，重启后直接复用。

`0013_device_history.sql` 直接建立属性说明表 `device_property_definitions` 和报告表 `device_observations`，并配置报告保留、压缩和说明清理任务。报告表是 TimescaleDB hypertable（按时间自动分块的表），采用部署扩展的默认分块周期。列式无损压缩按 received_at 降序，segmentby（压缩分组列）采用原生默认设置；迁移从 `timescaledb_information.dimensions` 视图取得实际分块周期，以一个分块周期作为压缩阈值。保留策略按接收时间保留 365 天，调度沿用原生默认；SQL 写入及读取同时使用数据库当前时间减 365 天的边界，尚未整块清理的超期行也不交付。

原生 `cleanup_device_property_definitions` 任务沿用保留任务的实际调度周期，每次最多处理 1,000 个无报告引用的说明。它先取得共享绑定事务锁，筛选无引用候选，再用不扫描压缩报告的独立语句以 FOR UPDATE SKIP LOCKED 锁住说明，随后用新 SQL 重新检查引用后删除。写入复用说明时取得 FOR KEY SHARE 行锁，外键继续保护已引用说明。任务配置与执行状态读取 `timescaledb_information.jobs`、`job_stats` 和 `job_errors`，不另建应用维护队列。

数据库目标基线为 PostgreSQL 18 / TimescaleDB 2.30.1，该基线的默认分块与压缩阈值为 7 天，保留及说明清理每天调度。现有隔离数据库验证覆盖基础结构与原生维护配置、真实推送和云缓存报告的保存与分页读取、非空报告压缩后的读写与说明引用保护，以及统一 TRUNCATE 的事务回滚。类型检查、现有回归测试和空库查询计划检查不证明真实规模与故障隔离已经通过。

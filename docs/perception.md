# 本地目标检测、人宠跟踪、人物身份与音频分析

本地检测模块使用 Bun 管理的独立计算子进程、Piscina 线程池和 ONNX Runtime CPU 执行 `det_4C.onnx`，接受图片文件任务或 RGB24（每像素三个 8 位红、绿、蓝通道）帧，返回人体、猫、狗、头部和人脸检测框。检测所需的文件读取、哈希、解码、缩放和推理在计算子进程中执行。检测池返回结果，不写输出图片；可选标注由独立图片命令在自己的进程中生成和保存。检测结果是画面证据，不表示房间在场或人员身份。

## 安装与使用

在仓库根目录运行 `bun install`。目标检测固定使用项目内随附的 `apps/backend/models/det_4C.onnx`，来源与原许可保存在同目录的 [README.md](../apps/backend/models/README.md) 和 [LICENSE.md](../apps/backend/models/LICENSE.md)。运行时不下载模型。

模型路径由感知模块内部常量统一定义，按模块位置解析，源码运行与构建产物使用同一份项目资产，不受启动工作目录影响。计算池、图片命令、基准命令和真实模型测试共用该常量，不接受模型路径参数或环境变量覆盖；调用方只提供待检测输入及处理选项。构建检查模型与许可证文件存在；部署时一起携带 backend 的 `models/` 和 `dist/`，保持同级布局。缺失模型时初始化明确失败。

`patches/piscina@5.3.2.patch` 修正 Piscina 的 `TransferList` 类型声明：从 Node 的 `StructuredSerializeOptions.transfer` 推导数组类型，避免从 `MessagePort.postMessage` 的重载错误推导成选项对象。Bun 安装时通过 `patchedDependencies` 自动应用；补丁不改运行时 JavaScript，使直接传入 `transferList` 能通过类型检查，无需类型断言。升级 Piscina 时需核对声明并移除已被正式版本覆盖的补丁。[Bun 补丁机制](https://bun.com/docs/pm/cli/patch)

```sh
bun run --cwd apps/backend detect:image --output-dir ../../data/perception /path/to/image.jpg
```

可传入多张图片；同一个模型 session 顺序处理，最后释放 session 并关闭计算池。`--output-dir` 可省略；指定时保存带框 PNG。标准输出为 JSON Lines（每行一个 JSON 对象）：首行为模型路径、SHA-256、输入输出元信息、运行环境、依赖版本及资源预算，其后每行是 `image_detected` 结果，包含 `imagePath`、`inputSha256`、尺寸、检测框、分段耗时及可选的 `annotatedImage` 路径。图片按存储像素方向解码，不应用 EXIF 旋转。模型指纹在子进程初始化时计算；检测输入在子进程有界读取一次，用同一份字节计算哈希并解码。指定标注导出时，命令重新有界读取图片并核对哈希，确认与检测时的内容一致后再画框；原图已变更则拒绝导出。运行期间不修改模型和输入图片。

```sh
bun run --cwd apps/backend build:perception
ORT_DISABLE_TELEMETRY=1 bun apps/backend/dist/detect-image.js /path/to/image.jpg
```

backend 的 `build` 同时构建计算子进程入口与图片命令，并生成 source map（将构建后的报错位置映射回源码）。图片命令不要求数据库、摄像头、go2rtc 或 LLM。网页也提供独立图片上传分析；后台摄像头持续检测使用下述独立配置与 HTTP 接口，页面不是采集的所有者。看家页的镜头详情提供单路连续视频帧关联与定格；页面范围与使用方式见下述说明。

## 独立图片上传分析

从看家页的“图片分析”或登录页的同名入口进入 `/cameras/images`。图片页只要求本机接口访问有效及检测模型可用，不要求米家登录、家庭选择、摄像头或媒体服务就绪。一个主按钮完成选择、分析与重新选择：选择文件后准备预览并自动上传，各状态保持稳定宽度，图标和文案直接切换。首次选图在准备完成前保持“选择图片”，准备成功后显示“重新选择图片”；重新选图、重试和继续分析在等待期间保留各自的操作来源，分别保持“重新选择图片”“重试分析”和“分析图片”。等待的前 150 毫秒禁用，持续等待后，同一按钮显示进度图标与可点击的“取消等待”；快速完成时不插入取消文案。准备与分析阶段还由下方状态提示展示。结果展示检测框、类别、置信度及默认展开的完整 JSON，空检测明确显示检出 0 个目标。完成后点击“重新选择图片”打开选择器，确认新文件才替换原内容；取消文件选择保留原图片、框和 JSON。准备失败回到“选择图片”，分析请求失败保留当前图片并显示“重试分析”；本机访问失效后释放图片并重新选择文件。取消等待保留已准备图片并显示“分析图片”；尚未准备完成时回到“选择图片”。图片名称旁的 × 直接清除图片与结果并取消在途等待，焦点回到显示“选择图片”的主按钮。准备、上传等待、忙碌、无效图片和检测失败都有反馈。

网页先检查文件字节数，再使用 `image-size` 读取尺寸，在创建完整位图前拒绝像素超限或无法确定尺寸的输入。文件必须同时满足该库的尺寸读取能力和浏览器的原生解码能力，不自行解析图片格式。浏览器应用 EXIF（图片方向元数据）方向，并通过 Canvas（画布）铺白透明区域、生成 PNG，不缩放；解码后再次校验实际尺寸。预览和上传使用同一份 PNG，显示实际提交尺寸。原文件和提交 PNG 均最多 32 MiB，每边不超过 8192 像素，总像素不超过 `3840 × 2160`。页面只保留一份当前提交图片、一个在途准备操作和一份结果；替换时取消旧等待，正在完成的原生图片准备结束后才准备最新选择。清除、离页或接口返回本机访问失效时释放预览对象 URL 和结果；旧响应不能覆盖当前输入。这些限制约束输入尺寸和数量，不是浏览器总内存的硬配额。

`POST /api/perception/images/detect` 接收原始图片字节，请求类型使用 `application/octet-stream`，返回 `image_detected`、`inputSha256`、实际宽高、`detections` 与 `timing`，不返回服务器临时路径。结果契约与字节、像素限额位于根目录 `packages/api`。HTTP 适配器有界读取请求并保存到权限受限的临时文件，调用现有文件解码和检测链路，检测结束后删除临时文件。图片不写入数据库，不创建视频轨迹，不成为可信摄像头证据，也不调用 Agent。

backend 同时只接纳一个上传分析请求，直到检测与输入清理完成才释放上传位置；重复请求或计算容量满返回 `perception_busy`（503）。无效图片返回 `perception_image_invalid`（400），字节超限返回 `request_too_large`（413），计算不可用、超时和失败分别返回 `perception_unavailable`（503）、`perception_timeout`（504）和 `perception_failed`（500）。整个请求的等待期限由 `BACKEND_REQUEST_TIMEOUT_MS` 控制，默认 130 秒，覆盖上传、模型准备和推理；网页等待也为 130 秒。既有模型初始化和检测任务期限仍单独生效，`timing` 计量检测链路，不包含 HTTP 上传与临时文件写入。

图片与配置的视频使用同一个共享计算池；未配置视频时第一次图片请求按需准备池，视频仍保持禁用。再次分析图片时会等待正在进行的计算恢复；恢复预算耗尽后，该次请求尝试恢复已有池，失败仍返回不可用。显式感知重试也恢复已有图片计算池，不要求启用视频。图片可进入池已有的有界等待位置，在下一个可用计算名额执行，视频继续处理最新帧。取消 HTTP 等待不强制终止已经接纳的原生计算，不关闭健康池；临时输入与上传位置由实际操作完成及池故障处理释放。

浏览器上传、方向处理、取消及持续视频联合负载尚未完成运行验收。窗口筛选与短期媒体的页面用法见 [Web 说明](../apps/web/README.md#窗口筛选与媒体)。

## 摄像头持续检测

当前摄像头检测仅调用本地 ONNX 模型，不向 LLM 发送帧或视频，也不产生 LLM token 用量。语义模型调用尚未接入，后续边界见[摄像头感知与推理接入计划](plans/media-perception.md)。

当前检测不依赖 Agent 进程、模型凭据或 checkpoint 数据库。Agent 服务不可达不影响检测启停与查询；仍需满足摄像头授权、backend 数据库、go2rtc、FFmpeg 与检测模型等实际依赖。单独运行见[本地运行](running.md#单独启动与检查)。基础查询/订阅提供检测、人宠跟踪、可选人物身份与音频观测；窗口与候选媒体通过独立[窗口接口](#本机接口)读取，当前不输出 Agent 判断。

启动前在 backend 宿主安装 FFmpeg（macOS 可用 `brew install ffmpeg`，Linux 使用系统软件包）；`PERCEPTION_FFMPEG_PATH` 默认 `ffmpeg`，可指定宿主可执行文件。只在 go2rtc 容器安装 FFmpeg 不满足此要求。`bun run setup` 将禁用示例复制为 Git 忽略的 `config/perception.json`，不覆盖已有配置。缺文件或 `sources: []` 表示禁用，不自动打开全部摄像头。

```json
{
  "cpuRatio": 0.5,
  "sources": [{ "deviceId": "替换为当前家庭设备标识", "channel": 1 }],
  "sampleFps": 3,
  "firstFrameTimeoutMs": 90000,
  "silenceTimeoutMs": 30000,
  "maxFrameAgeMs": 2000
}
```

`cpuRatio` 范围为 `(0, 1]`，默认 `0.5`。backend 启动时读取 `availableParallelism()`，原生模型并发总名额按 `floor(可用核数 × cpuRatio)` 计算：仅图片时最低一个，配置摄像头时为基础视频与 VAD 保留最低两个名额，即使比例很小也不禁用基础采集。正式感知服务先给启用的音频 VAD 预留一个名额，开启 ASR 再从总额中预留一个，剩余名额用于视频 worker；ReID 和启用的人物身份模型从视频名额中借用，不另加并发。视频至少需要一个名额，因此音视频加 ASR 至少需要三个；ASR 不提高最低名额。启用人物身份分析时，扣除 VAD／ASR 后还须容纳检测、ReID 和人脸三个视频名额；不足时在初始化报告错误，不等到第一张人脸出现才失败。预算不足使感知明确不可用，不静默超配；低核数主机需提高比例或关闭 ASR。独立图片命令／`createDetectionPool` 没有采集与 ASR，按自身预算创建 worker。

`modelMemoryMiB` 默认 `4096`，是模型加载规模的内存预留预算。当前每个检测 worker 预留 384 MiB，允许 ReID 的视频池另预留 256 MiB，启用的 VAD 预留 128 MiB，启用的 ASR 预留 1536 MiB，人物及宠物身份模型共同预留 768 MiB；视频 worker 数同时受剩余 CPU 名额和剩余内存预留约束。只有能容纳至少两个视频名额及 ReID 内存时才启用其预留；单视频 worker 沿用不加载 ReID 的规则。`GET /api/perception` 的 `resources` 显示总名额、各能力分配、内存预算与预留总量；`identityThreads` 表示视频池内的成员身份预留，不与 `videoWorkers` 重复相加，`compute.budget.workersPerProcess` 是实际视频 worker 数。配置在本次运行内固定，重试和来源增减不重新定容；修改后重启。

这些预留量用于限制模型接纳规模，属于容量规划值，并非操作系统 CPU 或 RSS 硬配额，也不保证目标平台的峰值内存；FFmpeg、编码缓冲、JavaScript 与服务基础开销需另外测量。ASR 空闲时退出进程释放实际内存，其预留名额不会临时扩张视频池。当前覆盖检测、ReID、人物身份、VAD 与 ASR；接入其他模型时必须从共同预算中划分容量，再核对联合运行峰值。

显式来源可以设置 `videoQuality: 1 | 2 | 3`，例如 `{ "deviceId": "替换为当前家庭设备标识", "channel": 1, "videoQuality": 3 }`。省略时保留当前来源已选画质，首次准备沿用 go2rtc 的型号默认值；普通预览和设备清单同步不会覆盖显式选择。`1`、`3` 对应小米 SDK 的低／高清档，具体分辨率及是否与 SD 录制码流一致由设备决定，不能仅凭数字断言。配置在 backend 启动时读取；显式改变来源画质会撤销旧来源并建立新的媒体代次，旧帧和旧识别结果不进入新运行。双摄保留每个镜头的选择，共享物理连接重新建立后两路分别恢复。

设置 `"sources": "household"` 可明确启用当前家庭全部有资格的摄像头通道。来源集合来自已提交的设备清单，并随家庭变更、设备增减、通道变化和撤权同步；移除时先撤销结果资格再清理执行资源。新增、移除和暂时断流均不重建计算池。显式设备列表只分析列出的通道。两种模式都受 8 路解码上限约束；家庭来源超过上限时报告不可用并停止分析，不静默截断设备清单。默认示例仍为禁用状态。

设备标识必须是实际米家数字标识，通道为 1 或 2；只接纳当前家庭已提交设备清单中有访问资格的摄像头通道。配置最多 64 KiB、8 路，不允许重复设备/通道或未知字段。每路采样默认上限 3 fps（每秒帧数），首张完整帧等待 90 秒，之后 30 秒无完整帧报告媒体故障；最大帧龄默认 2 秒。断流等待须大于采样间隔，低采样率需要同时调大等待。配置和 FFmpeg 路径修改后重启 backend。无效配置、FFmpeg 缺失或模型初始化失败只使感知不可用，家庭设备清单和预览继续运行。

采集独立于浏览器。米家适配器授予当前内部分析读取描述；计算子进程向 go2rtc 私有 `POST analysis` 发送已有 session/source 关联，通过 MPEG-TS（视频传输封装）读取 H264/H265 编码的视频。请求、来源、内部通道或 session 结束会关闭消费者，不增加分析 ID、DELETE 或心跳。物理摄像头连接和断流恢复仍由现有媒体模块管理；计算失败只恢复计算，不重连物理摄像头。

FFmpeg 在计算子进程下运行，单路独立解码，关闭音频与字幕、保留源尺寸，按 PTS（画面展示时间戳）通过 `select` 选择真实输入帧，再转换为 RGB24，使用 NUT（FFmpeg 的逐包音视频封装）在同一帧包中交付像素与 PTS。NodeAV 的 libavformat（FFmpeg 标准解封装库）读取帧包，应用校验 RGB24、`1/90000` 时间基准、递增 PTS 和检测像素限额；不自行实现容器解析。被跳过的帧不转换为 RGB，不复制或补帧；不能通过像素与日志的到达顺序配对。

go2rtc 的物理来源 attachment（一次取流连接）拥有独立 `media.generation`。重新取流、来源时间回退及 32 位 RTP（实时传输协议）时间回绕更换媒体代次，并在新时间的首个包转发前取消旧分析和观看。分析 MPEG-TS 保留 go2rtc 的读取请求内归零规则，以响应头 `X-Media-PTS-Origin` 记录首个实际送入复用器的来源 RTP 时间。复用器使用从 1 开始的局部输入时钟，避免其零值哨兵与设备时间零点冲突；输出 PTS 仍从 0 开始。FFmpeg 关闭时间平移，NUT 帧包保留相对 PTS；解码器把该值加上读取起点，恢复来源 90 kHz 整数时间，跨媒体代次的值明确拒绝。`mediaTime` 携带 `generation`、`pts`、`rtpTimestamp`、时间基准与 `quality: source_media`，当前映射要求 `pts === rtpTimestamp`。它用于同代次内关联，不是可信拍摄时钟，也不保证跨摄像头同步。`receivedAt` / `sampledAt` 继续表示宿主完整 RGB 帧可用的 Unix 毫秒时间，不能把结果帧龄当作物理拍摄延迟。

来源运行及采样后 `sequence` 仍独立存在：媒体代次标识视频时间的连续性，来源运行标识这一轮分析资格。观测存储先接纳本运行的媒体代次，再校验检测／跟踪的运行、媒体代次、序号与帧龄；旧媒体结果不能覆盖新来源。框使用原尺寸的 `decoded_rgb24` 坐标。共享契约见 `packages/api/src/contracts/media.ts`。

### 状态与资源所有权

- `mijia/perception-source.ts` 从已提交家庭状态判断资格；`perception/service.ts` 持有启用意图，协调运行授予、撤销、读取重试与计算重试。家庭作用域、媒体 revision、来源或计算代变化时先撤销结果资格，再清理资源。
- `observation-store.ts` 独占已授予运行、最新观测与公开健康，使用 `observations.ts` 的纯规则接纳结果。运行、任务序号或帧龄不符的结果不得替换当前证据；没有新帧也按期限过期。没有数据、有效空检测、过期和不可用分别表达。
- 子进程 `video/runtime.ts` 持有本代来源集合；每路 `video/source.ts` 的 XState actor（状态机运行实例）拥有生命周期、序号与在途关联，独占最新帧槽。`ffmpeg-decoder.ts` 独占 FFmpeg 与管道，`nut-frames.ts` 通过 NodeAV 解封装完整帧包；`scheduler.ts` 只保存就绪顺序，不复制像素。`video/events.ts` 定义应用执行事件，供观测接纳和 IPC 校验共同使用；视频运行模块接收读取闭包与检测能力，不依赖厂商访问描述或计算通信协议。XState 上下文赋值与帧槽、统计和唤醒动作分开。计算空闲或新来源就绪时触发轮转，忙时不轮询，也不为追新中断原生推理。
- 每路最多一张待处理完整帧、一个在途检测；新帧替换待处理帧。读取器持有当前原生帧包及一份可转移的 RGB 副本，另计 libavformat 探测与管道缓冲。管道使用背压；go2rtc 每个分析请求最多排队 32 个媒体块或 4 MiB，超限结束该消费者；写入最多等待 5 秒。每通道最多 4 个分析消费者。FFmpeg 单解码/编码线程和单滤镜线程，限制输入探测至 1 MiB、1 秒，单次分配 32 MiB、输入像素上限与图片检测一致；这些不是整个进程 RSS（驻留物理内存）硬限额。
- 检测 RGB 留在计算子进程，提交时把缓冲区所有权转移给本次任务选中的推理 worker。窗口采样在转移前取得独立副本，缩小后的有界窗口像素通过带确认的 IPC 交给主进程；原始检测像素不跨回主进程。主进程监督控制、结果和每次视频任务硬期限，统一管理初始化、任务、恢复及关闭预算。计算进程使用独立 POSIX 进程组，FFmpeg 继承该组；强制终止后确认组内没有存活进程，未确认时不重建。正常停止先取消分析读取、等待解码器退出，再排空计算并关闭模型。

`complete = sampled`（采样后交付的完整 RGB 帧）；`sampled = submitted + replaced + expired + discarded + pending`；`submitted = succeeded + failed + inFlight`。FFmpeg 内丢弃的帧不经过应用，当前不报告源帧总数或采样丢弃数，不把缺失统计写成零。`succeeded` 是模型完成，`published` 是主进程接纳发布；过期结果和其他拒收分别计数。计算异常退出时，最后收到的执行计数是已知快照，仍在途的任务不可解释成成功或无人。逐路计数按来源运行，不跨撤销或重建累加；顶层 `rejectedRetiredResults` 单独累计失效运行的迟到完成，不改写新运行的状态或计数。

逐路报告采样后完整帧数量、替换、丢弃、过期、计算成功/失败、在途和待处理数量、有效发布、拒收、最长调度等待、最长有效观测间隔、首次发布等待及等待首个结果的时长。帧龄 P50/P95 使用最近 512 个已完成或提交前过期样本，最大值覆盖本次来源运行；`ageSamples` 和 `elapsedMs` 说明样本规模和运行时长。`ageMs` 是发布时帧龄，`validity` 随当前时刻变化。子进程报告本地单调时钟测得的持续时间，主进程用同宿主接收时间补计 IPC（进程间通信）停留，时钟倒退的结果拒收；接纳后的过期计时用主进程单调时钟。

## 音频接入与本地分析

配置的摄像头同时接入音频，不依赖 Agent、浏览器或视频计算池就绪。backend 沿用已提交家庭设备清单的访问资格，通过独立音频进程读取 go2rtc 私有 `POST audio` 出口。私有摄像头源启用音频；单摄与双摄都根据真实媒体包声明音轨，视频已探测到但没有音轨时，给音轨 1 秒的补充探测期，在随后到达的媒体包处结束探测并继续视频。补充探测使用独立计时，不让传输连接超时；媒体传输失败仍报告为失败，不能当成缺音轨。

当前来源支持 PCMA（G.711 A-law 编码的 8 kHz 音频）和 Opus。PCMA 以原编码字节交付，Opus 包时长使用固定版本 `mediacommon` 的公开接口解析，单摄与双摄共用采样时钟适配；Pion WebRTC `v4.2.16` 的 Ogg 封装器按实际 Opus 包时长累计采样位置，包含首包，不修改输入 RTP 的包开始时间；FFmpeg 在音频进程下的独立子进程内完成解码、单声道转换和 16 kHz 重采样，libav 读取带采样时间的 NUT 容器。FFmpeg 先转换到单声道 16 kHz，再按 512 点分块，避免输入采样率决定 IPC 频率。实际输出固定为单声道 int16 PCM（解码后的采样），不手写解码器或重采样器；音频分析不保存音频文件；窗口自动生成采样媒体或按需编码时使用期限受限的临时文件。

每个设备在同一家庭访问范围内只有一个音轨运行，`run.trackRunId` 标识其状态所有者。双摄两个通道共享一次取流、PCM 解码和 VAD（语音活动检测），`sources[].audioTrackRunId` 引用同一个 `audio.tracks[]` 项，`channels` 只包含已选且有访问资格的通道。视频结果仍按通道独立发布；视频计算重建不替换音频运行。

### 连续分块与观察

- 能量按 480 点（30 ms）分块，计算均方根并除以 32768，阈值 `0.015`。每块返回 `rms` 和 `active`，低于阈值只表示能量低。
- 每音轨的 Silero 适配实例按 512 点（32 ms）处理，独占并保存 `[2,1,128]` 状态、64 点上下文及不足 512 点的余量。每块只推进一次模型，概率阈值 `0.4`，返回 `probability` 和 `aboveThreshold`。不足一块保持 `insufficient_input`；概率低于阈值与没有数据不同。
- 两种分块分别续接，不要求网络、FFmpeg 或 libav 的块边界一致。每块有 `startSample/endSample`，按 `sampleRate: 16000` 计算音轨内时间；缺包、PCM 时间缺口、断流及新运行都会结束旧连续状态。
- 源接收首包的同宿主时间保存在 `anchorReceivedAt`；`decodedStartOffsetMs` 记录解码丢弃的起始采样时长：PCMA 为 0，固定 Pion 封装器的 Opus pre-skip（解码后跳过的起始采样）为 3840 个 48 kHz 采样，即 80 ms。`observedAt` 根据首包接收锚点、该偏移及实际 PCM 采样位置估算本批输入的起始时间；`receivedAt` 仅记录本次 PCM 在音频进程交付的时间，不用于刷新媒体有效期。`timeQuality: host_receive_anchor` 说明使用接收时间基准，`synchronizationAccuracyMs: null` 说明同步精度未知；不宣称是拍摄时间，也不将音频的采样序号当作视频 RTP 时间。

音频接入与本地分析已在当前 macOS arm64 单摄／双摄范围验证。音轨分析输出分块事实，窗口聚合按不重叠的 4 秒窗口汇总能量峰值与至少 3 块过阈的人声判据，见[媒体窗口](#媒体窗口筛选与按需读取)；本地语音转写可按下节单独启用；声音类别判断和 Agent 声音理解尚未接入。模型来源、哈希、许可与实际张量见 [模型资产](../apps/backend/models/README.md#人声检测模型)。

### 状态、资源与生命周期

`GET /api/perception` 和既有 SSE 返回 `audio` 当前视图；音频通知最多每 100 ms 合并一次，视图保留每路最近一批分块，不能据此重建历史或假定订阅收到每个分块。`sequence` 与 `samples` 只在当前音轨运行递增，余量分别见 `energyRemainder/vadRemainder`。音频结果不进入设备公共 SSE，不携带编码字节、流地址或凭据。同一轮通知的多个 SSE 订阅复用一次快照校验与 JSON 序列化，只缓存当前投递轮次的一份结果，不跨轮次保留时间相关的有效性；新订阅重新读取当前状态。

| 字段／状态                                        | 含义                                                             |
| ------------------------------------------------- | ---------------------------------------------------------------- |
| `status: starting`                                | 正在准备来源或等待 PCM                                           |
| `status: reading`                                 | 正常交付 PCM，与视频就绪状态分别判断                             |
| `status: no_track`                                | 已连通来源没有可用音轨，视频继续                                 |
| `status: failed/unavailable`                      | 取流、解码、来源资格或计算不可用，不生成否定人声观测             |
| `vadStatus: insufficient_input/ready/unavailable` | 分别表示不足 512 点、可用分块概率、模型未知／不可用              |
| `validity: no_data/valid/expired/unavailable`     | 分别表示尚无结果、最近结果有效、超过配置最大年龄、链路或资格失效 |

感知应用通过 `perception/sources.ts` 定义的来源边界取得设备清单访问资格和媒体租约，米家来源适配器实现该边界；子进程入口负责组装厂商读取适配器。音频的米家 HTTP 协议在 `mijia/media/audio-stream.ts` 转换为 `audio/encoded-stream.ts` 的编码流契约，解码器只接收编码流和时间元数据。`audio/analysis.ts` 负责能量统计及人声概率阈值，`audio/silero-vad.ts` 负责模型分块、状态和上下文；音频与视频通过 `perception/source-lease.ts` 复用来源撤销处理，各自拥有解码、分析和恢复状态。

音频和基础检测使用独立的 OS 进程。全部音轨共享一个 ONNX Runtime CPU session（模型执行实例），单线程串行推理；不占检测池或人体外观名额，不按整机预算另建满额池。最多 8 个摄像头通道，按设备合并后最多 8 个音轨；每轨只有一个解码器和一个待执行分析。go2rtc 每镜头最多 2 个音频读取者，每读取者最多 64 个块或 256 KiB，慢写 5 秒截止。PCM 单包最多 4096 字节，模型状态、两种余量和当前分块均有界；FFmpeg/libav 工作区另计；最多仍有 8 个 FFmpeg 子进程，单线程模型配置不代表整条链路的 CPU/RSS 上限。保留每轨 FFmpeg 子进程用于独立回收解码器，NUT 承载解码后的采样时间，不在共享模型进程中改用新的原生解码调度。队列容量不等于实时性保证：解码出队与分析完成都按媒体估算时间检查 `maxFrameAgeMs`，过期或时间偏离接收锚点超过该预算时结束当前音轨，清空连续状态后按恢复策略重建。结果有效期也使用 `observedAt`，不会因解码、排队或推理而延长。接收锚点和采样时钟的长期漂移可能触发重建，不宣称精确跨轨同步。

首包及断流期限沿用 `firstFrameTimeoutMs/silenceTimeoutMs`，各音轨独立计时。无效音频包在源端丢弃，后续序号缺口或音频超时结束当前音轨，不使正常视频源重连。单轨失败或缺轨后至少等待 5 秒再创建新运行；来源撤权立即删除当前视图，取消旧读取，不把旧结果接纳到新运行。音频进程初始化限时 30 秒，心跳中断 5 秒或一次原生推理超过 2 秒时回收整个音频进程组，等待退出后再重建；累计 3 次进程失败后停止自动恢复，`POST /api/perception/retry` 可显式重试；VAD 模型不可用时，该入口也会重新初始化音频进程。无法确认清理时保持不可用，不释放新进程容量；每 5 秒重新确认退出，显式重试会取消该等待，进程迟到的退出确认仍可恢复容量。关闭停止重试，立即取消各轨的初始化等待，并行启动音频进程关闭与来源清理；未就绪进程直接回收，已就绪进程先限时回收解码器、释放模型，再确认进程退出。

macOS arm64 已接通工作室及另一台单摄的真实音轨，核对两路同时运行检测／跟踪／音频、分块余量续接、视频计算故障后的音频连续性、模型缺失时的未知状态与恢复后的显式重试、正式模型语音输出及正常关闭。真实双摄已核对两个视频通道引用同一个音轨运行，独立终止音频解码器后以新运行重置 PCM/VAD 状态并恢复，视频继续产生有效检测。音频原生进程停止响应后，外层监督已核对整组回收、以新运行恢复以及关闭后无遗留计算／解码子进程。业务回归覆盖清晰语音与静音、任意分块、跨源状态隔离、撤权、无音轨、陈旧输入、单轨卡住、初始化中关闭、退出迟报和慢订阅。真实单摄及双摄已核对 Opus 解码与浏览器音视频播放；基准可复现 1/8 路解码对照及多路订阅负载，入口和口径见[感知评估](../apps/backend/scripts/perception-evaluation/README.md#音频链路与资源)。日级运行、其他平台、更多真实摄像头与最终部署容量仍需按目标环境验证，短时或合成输入不能代替这些结论。

## 本地语音转写

可选语音转写由正式音频子进程管理，与 Agent、页面和视频检测独立。部署[固定 SenseVoice-Small INT8 资产](../apps/backend/models/README.md#语音转写模型)后，在现有 `config/perception.json` 中加入以下字段并重启 backend；保留原有 `sources` 和视频配置：

```json
{
  "speech": {
    "enabled": true,
    "idleUnloadMs": 60000
  }
}
```

默认关闭；`idleUnloadMs` 允许 5000–3600000 毫秒，默认 60000。音频子进程复用现有 Silero 人声活动检测（VAD）的状态和概率，以固定版本 `@ricky0123/vad-web` 的 FrameProcessor 切段。`speech/utterance.ts` 集中适配其纯 JavaScript 子模块，按事件及采样位置限制长度；升级时须核对切段事件和前置音频约定。自动语音识别（ASR）使用 sherpa-onnx 原生识别器，在同一进程组的独立子进程执行。backend 主进程只管理资格、监督和小型结果，不接收原始 PCM。

```text
backend 主进程：配置、资格、监督与结果
├─ 视频计算进程组：视频解码、检测与跟踪
└─ 音频进程组
   ├─ 各设备 FFmpeg：音频解码
   ├─ 音频主进程：能量、单一 VAD、语音切段和排队
   └─ ASR 子进程：按人声加载 SenseVoice，空闲后退出
```

正人声阈值为 `0.4`、负阈值为 `0.25`，最短人声 256 ms、结束静音 512 ms、前置音频最多 192 ms，固定每块 32 ms。切段器保留结束静音作为输入的一部分；观察结束时间取最后一个正人声块，不把结束静音或推理完成时间当作新发言时间。16 秒达到硬上限时交付带 `boundary: length_limit` 的片段，正常停顿为 `pause`；截断不能保证完整句子。转写不要求能量过阈，也不等待 4 秒场景窗口。

确认人声后开始加载模型，PCM 与 VAD 继续推进；只有语音段就绪时才提交转写。全部音轨共享一个单线程 ASR 进程，最多一个在途任务，每轨最多一个最新待处理段、总排队不超过 8 段。替换同轨待处理段保持队列位置，排队超过 3 秒丢弃并计数，不无限补发。每段 float32 输入最多 16 秒，切段缓冲按相同采样上限约束；进程通信副本和原生工作区另外计入资源。高并发长语音可能按期限丢弃，不能将队列容量视为实时交付保证。

安静期间继续采集、解码和 VAD，未确认人声时不启动 ASR。队列及在途任务结束并达到空闲期限后，退出 ASR 子进程并确认原生内存释放；下一次人声重新加载。全部来源结束时也释放识别进程。模型退出不更换音轨运行或打断采样，双摄共享音轨只有一份切段与转写。

`GET /api/perception` 及既有 SSE 提供 `audio.speech` 的加载／空闲／识别／恢复状态、ASR PID、资源和队列计数；每轨 `audio.tracks[].speech` 提供阶段、丢弃数和最近一次结果。结果包含音轨运行、媒体代次、实际输入区间、正人声结束位置、观察时间、完成时间、边界原因、模型指纹和处理版本。音轨快照只保留每轨最新结果；逐段交付另使用下文的有界短时收件箱，不保存生产录音或持久转写历史。当前结果有效性按观察结束后 15 秒独立判断，不沿用单帧检测的 2 秒门槛；转写有效不代表此刻仍在说话。空字符串是一次成功的空转写，与没有结果、未检出人声或模型失败不同。

来源撤销或重建清除对应缓冲与排队，取消该运行的在途识别，旧结果不会进入新运行。ASR 初始化限时 30 秒、识别限时 2 秒、空闲心跳期限 5 秒；失败先确认子进程退出再恢复，最多累计 3 次，之后清空待处理语音并报告不可用。`POST /api/perception/retry` 可重置语音恢复预算，不改变正在加载或识别的阶段；因 VAD、时钟或媒体代次异常而失效的语音轨须重建音轨运行后再接收证据；ASR 故障不重启正常的采集与 VAD，无法确认进程清理时交由音频进程组监督处理。VAD 不可用、语音采样时钟不连续或同一运行内媒体代次变化时，语音轨报告不可用并取消对应排队和在途识别，不能改成“无人说话”；全部语音轨失效时立即终止模型加载或识别并释放进程。关闭与孤儿回收包含 ASR 子进程。

当前不识别说话人或猫狗叫声类别，不把文字直接解释成控制指令。声音分析面板以能量与 VAD 为主，音轨原始 JSON 可查看最近转写；“筛选片段”的窗口详情按对应音轨和时间区间展示保留的语音文字。macOS arm64 已核对正式音频服务及视频联合入口、HTTP schema、源码与构建产物、双通道共享、来源撤销、断流、ASR 卡住、空闲卸载、再唤起及进程清理。验证使用受控 A-law 音频和合成视频；真实摄像头远场、电视声、多人重叠、日级运行与其他平台尚未验收。复现入口见[持续语音评估](../apps/backend/scripts/perception-evaluation/README.md#sensevoice-持续语音链路)。

### 语音片段交付与对话判断

`conversation/speech-inbox.ts` 拥有短时交付及判断状态。每次转写通过独立进程消息交付，接纳确认最多等待 1 秒；对话收件箱拒绝接纳或未在期限内确认时，计入 `audio.speech.inboxUnconfirmed`；此计数不表示窗口文字保存失败。超时不重启音频进程，迟到确认按片段身份忽略，发送失败仍由音频进程监督处理。识别完成即释放原生在途状态，撤销交接来源不取消其他音轨的识别。收件箱按音轨运行和样本位置去重，最多 64 段，保留至最后人声观察时间后 45 秒；满额拒绝新段。来源撤销、失效或重建会取消对应判断并移除片段。

`GET /api/perception/speech` 及 `/api/perception/speech/stream` 返回收件箱实例、配置、`revision`、片段序号、拒绝计数和逐段状态。状态变化及到期移除更新版本并发布；每 250 ms 独立检查到期，不等待 Agent 调用完成。消费者可在期限内重读完整快照；返回对象与内部状态隔离。音轨结果的 15 秒有效期与收件箱的 45 秒交付期限独立。backend 重启更换 `instanceId` 并清空片段，不提供跨重启可靠执行或长期历史。`ready` 只表示完整请求候选。

对话判断默认关闭，此时只记录 `captured`；空转写直接为 `ignored`。要启用 Agent 判断，在同一感知配置中设置并重启 backend：

```json
{
  "speech": { "enabled": true, "idleUnloadMs": 60000 },
  "dialogue": {
    "enabled": true,
    "assistantNames": ["家庭助手"],
    "callsPerMinute": 6
  }
}
```

Agent 使用已有模型配置，需独立运行。backend 一次处理一段，最多每分钟调用配置次数（1–30，默认 6），单次最多 12 秒，且不得晚于片段原期限；没有自动重试。限额用尽时待处理片段按原期限保留，不能无限补发。Agent 缺失、返回无效、超时或取消显示 `unavailable`，不产生请求候选。输入最多带同一音轨及媒体代次的三段前文，不能据此认定同一说话人。模型只接收按时间排序的文字、切段边界和相对当前片段的起止时差；设备标识、运行标识与模型指纹留在证据接纳和结果核对中，不作为语义判断输入。

Agent 通过单次结构化模型调用判断 `needsResponse`、`isComplete`、类别和依据；只有确为完整助手请求时才提供 `requestText` 并标为 `ready`。向助手提出但未完成的请求为 `incomplete`，聊天、转述和不确定内容为 `ignored`。静音边界 `pause` 不表示语义完整，16 秒截断 `length_limit` 不自动成为指令。该流程不调用聊天执行入口或设备工具，不建立成员身份关联；仅靠转写无法可靠排除电视播音或确认说话人。实时多轮对话、原始声音补证、回应与设备执行尚未接入。结构化判断和错误路径已接通，真实模型对称呼、电视转述和语义完整性的判断效果尚未验收。

## 单路帧关联与定格

在已登录、家庭设备清单已同步后，从看家页的镜头卡片点击“画面分析”，进入对应设备与通道的 `/cameras/$deviceId/$channel`。详情只接纳该来源的检测／跟踪结果；未配置感知时仍可在媒体就绪后观看及定格，不替换成配置首路。后台采集仍由配置和感知服务管理。页面提供连续视频、检测／跟踪叠加、定格、返回实时与帧关联诊断；页面不管理采集。独立图片上传见上节，声音分块查看见下节；选择详情的“筛选片段”入口可查看当前镜头的短期窗口摘要与按需媒体，操作和清理规则见 [Web 窗口说明](../apps/web/README.md#窗口筛选与媒体)。

观看复用现有 WebRTC 视频轨道。`MediaStreamTrackProcessor`（浏览器原生解码帧读取器）从该轨道交付 `VideoFrame`，通过同一对象的 `metadata().rtpTimestamp` 取得来源 RTP 时间。关联观看直接绘制这些帧，不另传编码视频、不运行第二个解码器，也不挂载隐藏视频。普通摄像头预览继续使用原生 `<video>`，两种显示方式接管看家父路由持有的同一观看连接。列表与分析页之间同一路在 1 秒交接期内接管，无需重新协商 WebRTC；Canvas 使用接收轨道的克隆，取消读取不停止原轨道。进入分析时保留列表当时正在播放的其他来源连接，解除其隐藏画面的显示和帧处理，返回时接管；不把此前滚动浏览过的来源加入保留集合。离开看家模块、隐藏标签页或撤权立即清理。关联页面要求目标浏览器支持这组 API，缺失帧身份时明确失败，不用本地显示时间推算 RTP 身份。

展示控制器同步复制解码帧为最多 640×360 的完整比例位图，缓冲 160 ms 后绘制到 Canvas（画布）。画面和结果各自保留身份，只有来源代次与 RTP 时间一致才称为“同帧”。后续连续帧可短暂沿用较早结果，上限 450 ms；不会使用未来结果。实时和定格画面均不叠加对齐提示，关联状态与媒体年龄可在“视频分析”的 JSON 中检查。该数据包含播放状态、后台最新分析 `source.analysis` 和当前画面及其关联结果 `presentation`；后台最新分析不一定对应当前画面，缺少画面关联结果不代表后台没有分析结果。输入画面超过 1 秒没有更新时清除实时框。没有匹配结果只说明暂无结果，不推断未采样或未检出。

定格与返回实时共用一个按钮：实时观看时显示“定格当前画面”，尚无画面时禁用；定格或暂停观看后，同一位置显示“返回实时”。按钮状态直接来自观看会话，在现有 `Button` 上保持稳定宽度，直接切换图标和文案。定格保留控制器最后绘制的确切位图及当时显示的检测与跟踪框，不重新筛选或清除已显示的关联结果；定格时同时保存完整 JSON，`presentation.matching` 保留同帧／沿用／无结果状态，`ageMs` 保留关联结果与画面的媒体时间差；画面、框和 JSON 均不再接纳迟到结果。定格和位图由页面持有，观看连接关闭不删除它们。定格或隐藏标签页释放观看，后台采集继续；只有“返回实时”恢复观看，并释放原定格。离页和已确认的来源撤权清理页面媒体。

观看端含当前展示帧最多保留 48 张位图、24 MiB；Canvas 工作面和展示面、浏览器原生解码工作区另计。原生帧读取队列最多 1 帧，交付尺寸上限 1920×1080。回调同步借用帧，结束即关闭；定格只持有一张显示尺寸位图。停止观看取消流读取并关闭轨道和 WebRTC 连接，页面独立清理位图。读包与 FFmpeg 退出共同完成后，后台才释放解码器所有权。

当前核对范围为 macOS arm64、Chrome 154、工作室摄像头 H265 848×480：原生帧的 RTP 时间与后台检测／跟踪身份一致，连续画面和定格可用。单路检测约 3 fps、视频约 20 fps 的实测结果到达延迟 P95 约 100 ms，160 ms 缓冲实际等待约 166 ms；显示位图逻辑峰值约 5.2 MiB，定格约 0.9 MiB。这些字节不包含浏览器原生解码和 GPU（图形处理器）占用。页面显示实时／定格状态，定格后提示画面与调试数据已固定；“视频分析”的 JSON 默认展开，展示取样时间、订阅与播放状态、来源运行与结果有效性、最新检测／跟踪结果，以及当前展示帧身份和已关联结果。处于实时模式且至少一个分析面板展开时，每 250 ms 共用一次画面与结果取样；两个面板全部折叠时停止取样。视频面板折叠后卸载其内容，不再生成视频 JSON；重新展开时，实时模式恢复更新，定格模式仍读取原定格快照；定格同时固定画面、框与 JSON，返回实时后恢复更新；已确认来源撤权时与画面一起清空，不常驻采集性能统计。实机已核对 JSON 默认展开和持续更新、画面像素及完整 JSON 保持不变而后台结果继续推进、返回实时恢复视频与 JSON 更新，以及离开详情不改变后台配置分析；已定格后切换标签页保留原画面及完整 JSON。定格保留当时显示的沿用框、设备侧断网恢复、重启后的时间重置、浏览器内存预算及其他浏览器尚未完成实机验收。窗口展示与实时画面相互独立，不把最新帧或检测结果叠加到过去窗口。

浏览器使用[HTTPS／HTTP/2 入口](running.md#https-与-http2-入口)。macOS arm64／Chrome 154 已核对三个工作室看家详情页与日志页同时打开：三个详情均出帧，家庭和感知订阅同步，画面与结果的来源代次一致，日志页正常加载。入口连接检查覆盖八路持续状态订阅与二十个并发健康请求，全部成功，最慢约 3.7 ms；另一次家庭与感知混合订阅首包均在 3 ms 内到达，不代表长期运行或检测展示时延保证。浏览器实际页面、JSON 与事件流请求均已确认使用 HTTP/2，开发热更新 WebSocket 正常。开发与生产入口均已核对 TLS 证书、HTTP/2、API 本机访问校验；生产另核对详情路由、预压缩资源与 API 不回退到 HTML。浏览器内存预算、设备断网、重启时间重置，以及图片能力的完整联合验收仍未覆盖。原始材料保存在 Git 忽略的 `data/perception/frame-boundary-acceptance/`。

### 声音分块查看

看家详情以独立的“视频分析”和“声音分析”面板展示两类结果，各自支持折叠；视频 JSON 不包含音轨，声音原始 JSON 在声音面板内按需展开。声音面板展示当前来源的音频服务、音轨、结果有效性及人声分析状态，有完整分块时分别展示能量、人声概率、后台阈值判定和分块时间区间。时间区间由 `startSample/endSample` 除以音轨 `sampleRate` 换算为解码后音轨内的相对秒数；换算为宿主接收时间基准下的时间时，还需加上 `anchorReceivedAt` 和解码起始偏移 `decodedStartOffsetMs`，并统一秒与毫秒单位。首包接收锚点、解码起始偏移、运行与媒体代次保留在 `source.audio` 的完整 JSON 中，同步精度未知，不能将声音区间当作某张视频帧的结果。两个镜头引用相同 `audioTrackRunId` 时使用同一音轨数据，并提示共享音轨。

两个分析面板共用详情的 250 ms 取样和定格快照；实时模式下全部折叠时停止取样，展开任一面板恢复取样。声音原始 JSON 仅在展开时挂载并生成，折叠后停止序列化；折叠整个声音面板会卸载其内容，重新展开时原始 JSON 恢复默认折叠。声音基础面板展示能量与人声活动检测；启用[本地语音转写](#本地语音转写)后，音轨原始 JSON 还包含最近转写，不识别说话人或描述环境声音。定格保存当时的音轨状态和最近分块，后台继续分析；返回实时恢复取样；确认来源撤权后随画面与 JSON 清空。读取核对已同步的家庭版本、移除版本、音轨运行所属家庭、设备和镜头，不因视频计算暂时不可用而隐藏仍可访问的音频结果。页面按后台状态区分无音轨、输入不足、过期与失败，不把缺失或不可用数据当作否定人声观测，也不将过期分块当作当前声音。声音分块只显示最近一批，新分块覆盖旧分块；实时音轨另保留每轨最近一段文字；窗口存储将已完成转写关联到相交的 4 秒区间，历史文字受窗口摘要期限与容量约束，不构成完整转写档案或语义结论。音频流请求失败的提示保留 HTTP 状态和服务端错误码；HTTP 404、`invalid_request` 的运行产物排查见[本地运行](running.md)。

macOS 工作室单摄已核对后台音轨读取、有效结果、能量与人声概率分块，以及浏览器分开展示和折叠视频后声音继续更新。双摄共享音轨的页面展示、对照实际说话的人声检测效果，以及声音面板的完整定格／撤权场景尚未完成实机验收；后端音轨验证范围见上文。

## 后台分析与结果校验

后台按配置持续分析，与浏览器是否打开、正在查看的页面及前端定格状态无关。看家列表和详情不提供采集管理、启停、能力或时长选择。进入、离开、定格及返回实时只影响前端资源与展示，不发送采集控制请求。未配置来源或暂无结果时明确显示当前状态，不切换来源，不触发一次性检测。

backend 根据配置协调来源，各路沿用现有 XState 生命周期。非空配置在服务启动时读取，家庭及来源就绪后持续检测与跟踪；`household` 跟随当前家庭的可访问镜头，最多 8 路。家庭切换撤销旧运行后重新协调，媒体及计算故障沿用既有恢复策略。空来源不因视频采集创建计算池；独立图片请求可按需准备共享池。页面不选择能力或时长，也不调用开始、停止或取消接口。

设备访问资格与版本校验始终自动执行，不提供用户开关。家庭公共状态负责设备访问资格，感知消息不授予访问。快照携带已核对的家庭版本 `scope_epoch + sequence`，来源携带授权版本和运行编号，两条订阅各自的序号不互相比较。确认设备／通道移除后清理画面和 JSON，看家模块共享状态记录移除版本；重新加入必须取得新授权与新运行。失同步时暂停实时结果接纳，家庭完整快照恢复后须取得不早于该快照的感知依据，旧响应与绘制回调不得恢复失效来源。媒体断流不等于访问撤销。

看家父路由持有一条感知订阅，列表与详情复用访问依据。连接首包及后续更新均为完整快照，家庭重新同步后等待事件流追上家庭版本，不另发 HTTP 刷新请求；离开看家模块取消流读取并清空结果和同步依据。前端仅保存结果、同步可信度及查看状态，不维护后台启停命令。定格由页面查看会话持有，后台继续产生新结果；确认撤权后清理画面与 JSON。

共享计算池独立于采集。容量拒绝不关闭健康池；单路媒体失败只撤销该路并按策略恢复；控制硬超时、通信异常或无法确认资源释放时按共享故障回收。停止最后一路跟踪会收尾在途工作，确认外观模型进程退出后才归还预留名额。FFmpeg 的启动、失败与资源清理由现有解码器负责，失败只影响该路并按来源策略恢复。网页图片上传复用该池已有的有界等待位置，不要求停止视频。

配置协调与共享计算恢复继续使用现有生命周期检查。设备移除后重新加入、切换家庭／退出及图片与多标签页联合负载尚未完成实机专项验收。

状态快照的 `instanceId` 标识 backend 实例，`sequence` 标识该实例内的更新顺序；同一连接内拒绝倒退版本及实例切换，重连首包可接纳新实例；旧连接在取消后不能再回写结果。家庭版本和来源运行身份独立校验，不另建采集编号、期限、命令版本或回执状态。

## 人宠跟踪与人体外观特征

当前返回的是来源内的局部观察；可选身份分析给出参考标签的候选与确认状态，不提供已接纳的家庭成员身份、房间定位或最后出现房间。人宠最后出现记录归家庭领域，尚待媒体证据与身份核验接入；当前本地身份依赖跟踪采样，跟踪未成立时不产生独立画面身份判断。设计见[人宠出现记录](plans/household-model.md#人宠出现记录与最后出现房间)。

摄像头检测完成后先发布基础观测，再独立执行人宠跟踪。每个来源运行独占人体、猫狗轨迹及人体外观历史，头部和人脸只作为检测框输出。人、猫、狗共用该运行的唯一编号分配器，每条轨迹通过 `className` 区分 `human / cat / dog`。轨迹由 `runId + trackId` 标识；运行替换后不能沿用，外观相似性也不等于人物身份。图片检测命令不创建轨迹。

内部 `tracking` 事件同时传递本帧新提取的合格人体外观证据，不增加 ReID 推理。每份证据包含家庭作用域、设备与通道、来源运行、媒体代次及 RTP 时间、帧序号、轨迹编号、原帧观察时间、模型指纹、处理版本和 128 维归一化向量；证据身份由完整来源、帧与目标字段确定。预测框、缓存复用、缺失特征和与其他人体检测框明显重叠的目标不产生新证据；重叠使用交并比（交集面积除以并集面积）至少 `0.3` 的保守过滤值，尚未经过成员归因实景校准。

IPC（进程间通信）校验向量维度、有限数值、归一化及同帧实测目标绑定，每事件最多 8 份。感知服务只在来源访问资格、当前运行、媒体代次、递增帧序号和帧龄均通过现有接纳后，向家庭身份的内部消费入口交付证据、当前家庭版本及接收端单调时钟下的剩余帧预算；旧运行、重复帧、时间倒退或超龄证据拒收。窗口只接收去掉向量的跟踪事件，并按自身原帧保留期接纳跟踪结果，不受实时外观证据接纳期限限制；公共查询、SSE 和窗口 JSON 均不包含向量。家庭身份领域在内存中消费此入口，建立短期参照和匹配诊断；未校准时不输出正式外观归属，相关接入与实景校准见[成员短期外观归因计划](plans/member-attribution.md)。

匹配求解使用 `munkres`，通过未匹配候选列保留“先最大匹配数量、再最小代价”及门控语义；卡尔曼预测与修正使用 `kalman-filter`。`tracking/assignment.ts` 和 `kalman.ts` 只承担框坐标、时间步长、噪声与库边界转换，不实现求解器。滤波库发布包没有类型声明，适配入口校验公开构造器和返回数值的形状及有限性，类型由校验规则推导。

DeepSORT 使用位置和速度的卡尔曼滤波（根据实测框与运动状态预测下一位置）、外观余弦距离与位置不确定性门控进行关联；按最近实测时间分组匹配，组内求全局最小代价，再用交并比关联上一轮仍实测的未匹配轨迹。速度以像素/秒表示，初始速度标准差取人体高度的一半；预测协方差按实际秒数积分位置与加速度噪声，避免直接照搬逐帧速度尺度。预测按两次输入的实际单调时间差推进，失配超过 2 秒即删除，过期后的重入使用新编号；丢帧不按固定帧率补算。来源断流或撤销只表示结果不可用，不生成“人已离开”的判断。

默认人体确认阈值为 0.5，`n_init=1`（第一次有效检测即建轨迹），外观距离上限 0.2，位置门控阈值 9.4877，IoU 距离上限 0.7。每路最多 8 条活跃人体轨迹，最多处理置信度最高的 8 个人体，每条保存最近 50 个归一化特征。容量不足时 `omittedHumans` 表示本次未形成实测轨迹的人体数，不影响基础检测框。

`fast` 模式仅在最近两次实测中心位移同时小于框对角线的 5% 和 10 像素、当前预匹配无歧义时复用原特征；发生交叠歧义时重新提取。`human_reid_skip_windows=4` 按跟踪更新次数计数，距最近一次提取达到 4 次就刷新，不按音视频窗口数计数；复用不增加特征历史，也不更新特征提取时间。

### 猫狗连续跟踪

猫、狗默认随摄像头检测进入位置跟踪，无需额外配置。复用原检测框和基于实际时间的卡尔曼预测，按同物种预测框的交并比进行全局匹配，并以位置不确定性门控排除不合理跳变。确认阈值为 0.5，IoU 至少 0.3，位置门控上限 9.4877；猫和狗始终不能互相继承编号。短暂漏检时输出预测状态，2 秒内只有符合位置匹配条件才续接，超过期限重新出现会分配新编号。

猫狗合计最多 8 条活跃轨迹，与 8 条人体轨迹分开限额，单路输出最多 16 条。`omittedPets` 统计本次未形成实测轨迹的猫狗检测数。帧尺寸变化清空轨迹状态，继续递增编号；停止或替换来源运行会清理全部轨迹。跨摄像头或跨运行不关联编号。

宠物不使用人体 ReID 模型，也不保存外观向量；其 `feature=not_applicable`、`featureAt=null`。纯宠物画面不会启动 ReID 进程或预留外观计算并发，只增加有界的位置关联计算，复用现有跟踪帧分支。人宠混合画面中，仅人体裁切送入 ReID。相似宠物密集交叉、完全遮挡、快速运动或检测类别抖动仍可能断轨或换号，轨迹编号不能当作宠物身份。

宠物专项测试覆盖同类交叉的运动关联、猫狗隔离、短暂丢失续接、超期重入、数量上限、全局编号以及人宠混合接口输出。真实运动检查使用 [VOT-LT2019 官方数据集](https://www.votchallenge.net/vot2019/dataset.html)的 `cat1` 和 `dog` 序列及逐帧人工框，从原始 30 fps 每 10 帧取一次，以 3 fps 和原始时间推进现有固定检测模型及宠物跟踪器。按可见目标框 IoU 至少 0.5 核对检测和实测轨迹，分别统计物种错误、2 秒内换号和超期后的重建；预测框不算检出。人工框直接驱动跟踪器的对照用于区分检测与关联问题。

这两段素材未通过连续跟踪质量检查：存在漏检、物种混淆和频繁换号，快速运动、小目标、镜头移动及遮挡尤其受限；人工框对照也存在换号，不能只归因于检测模型。资源与生命周期测试通过不代表真实宠物轨迹可靠。此检查只评估各序列指定的单个目标，不是 VOT 官方完整基准，也不能证明多猫狗交叉、其他未标注动物或家庭固定机位的质量；家庭实景和多宠验收仍待完成。公开素材、来源指纹、逐帧结果和带编号视频保存在 Git 忽略的 `data/perception/`，不把一次性报告纳入共享文档。

### 查询与有效性

`GET /api/perception` 和对应 SSE 的每路 `tracking` 与基础 `observation` 独立更新。两者通过来源运行和 `sequence` 关联，不能假定它们始终属于同一帧。`trackingValidity` 独立表达 `no_data / valid / expired / unavailable`；期限仍使用该帧的 `maxFrameAgeMs`，晚到或旧运行结果拒收。

- `status` 为 `tracked`、`degraded` 或 `failed`；外观模型尚未就绪、忙、预算不足或失败时为降级，允许仅凭位置和重叠关联，特征明确缺失。
- 轨迹 `state=measured` 时有本帧 `measuredBox`；`state=predicted` 时该字段为 `null`。`predictedBox` 始终是滤波预测/修正后的状态，可能越出画面，不能当成实际检出框。两者都使用原解码图像坐标，图像尺寸随结果返回。
- 跟踪的 `receivedAt / sampledAt` 沿用对应检测帧的本机接收时间，`mediaTime` 保留对应检测帧的来源媒体代次、PTS 与 RTP 时间，但不是可信拍摄时钟；不能据此保证跨摄像头拍摄同步。
- `lastMeasuredAt` 为最后实测帧的本机接收时间，预测期间保留原值，不因系统时钟校正重新换算；`feature` 区分人体的 `extracted / reused / missing` 与宠物的 `not_applicable`，`featureAt` 为最近实际提取时间。预测或本帧缺失特征不会刷新它。
- `skippedFrames` 累计因同源跟踪仍在途或帧龄超限跳过的输入；仅缺少外观帧副本时仍输出几何轨迹，不计为整帧跳过。没有新跟踪输入时旧结果自行过期，不补发旧像素。外观向量仅留在本地轨迹状态，不广播到查询接口。

### 离线策略校准

猫狗策略的离线校准入口为 `bun run --cwd apps/backend evaluate:pets`，对照固定区域检测、低分框续接与跨帧确认。输入布局、参数网格和指标含义见[宠物对照评估](../apps/backend/scripts/perception-evaluation/README.md)。线上仍采用上述默认参数；评估用低分候选和区域推理不通过当前摄像头配置启用。单目标标注的未匹配框数量不能直接解释为误报率。

候选模型的独立比较入口为 `bun run --cwd apps/backend evaluate:models`，使用人工核对的室内图片和完整人猫狗标注，分别报告检测精确率、召回率及同机耗时，见[室内模型对照](../apps/backend/scripts/perception-evaluation/README.md#室内检测模型)。它不修改正式模型，不以户外单目标跟踪分数推断室内检测效果。

### 计算与像素所有权

检测把像素转移给 Piscina 前，跟踪分支按容量复制对应原帧；全计算进程按实际 RGB 字节数接纳副本，每路最多 1 帧，每帧最多 3840×2160 RGB24，合计逻辑保留上限约 47.46 MiB（两张最大尺寸帧的字节数）。低分辨率来源可在同一字节预算内同时保留超过两张帧，供人体外观与身份分析使用。保留期限不超过该帧 `maxFrameAgeMs`，到期释放像素名额。名额按等待来源先后轮转，只保存有期限的来源资格，不排队保存像素；来源停止或资格过期即移除。未取得副本时仍处理本帧检测框：猫狗继续位置关联，人体可复用已有合格特征或明确报告缺失特征；检测结束后不能拿更新帧替代。停止或运行替换使结果立即失去发布资格，并释放本地保留像素；已提交外观进程的在途副本在原任务期限内结束并回收。

首次出现需要特征的人体时才启动一个独立 ReID 子进程，sharp 与 ONNX 均使用单线程。它从启动时计算的 N 个推理并发预算中预留 1 个，基础检测仍至少保留 1 个并发名额；N=1 时只输出位置跟踪并报告外观不可用。申请预留后，检测调度立即将后续执行上限降为 N−1，让已经接纳的检测与等待任务自然排空，不取消或拒绝它们；实际执行中的检测不超过 N−1 时才允许启动 ReID，避免持续负载抢回外观名额。预留保持到外观模型退出确认，最后一路停止、进程故障回收或计算运行关闭时归还；检测模型会话仍为 N 个，持有外观预留时最多 N−1 个同时执行。纯图片任务和从未需要人体特征的视频仍使用全部 N 个检测并发。

ReID 最多一项在途请求、每项最多 8 个裁切，无等待队列；初始化期限 30 秒，单项期限取 1 秒与帧剩余有效期的较小值。ReID 的 IPC 副本最多另加一帧，裁切/模型工作区和常驻模型内存另计；CPU 比例不是宿主 RSS 硬配额。基础检测不等待特征，ReID 忙时该跟踪输入使用缺失特征。外观进程故障或超时只终止自身。跟踪运行时确认旧进程退出并归还计算名额后，按 5／10／20 秒退避最多自动重建三次，不重放过期帧；持续成功推理达到一分钟后恢复重建预算。预算耗尽时保留位置跟踪并报告外观不可用，`POST /api/perception/retry` 可以重新开放外观重建。正常关闭确认子进程退出，外层计算进程组的强制回收也覆盖它。

### 验证范围

已核对真实模型张量、BGR 原始像素和裁切边界、128 维 L2 归一化、独立进程退出及硬期限。专项测试覆盖外观区分的交叉、遮挡、实际时间预测、超期重入、静止复用、缺失特征、轨迹上限、原帧转移、停止后晚到结果和独立有效期。双路视频链路使用固定室内人物图片（`000000465549.jpg`）编码的 H264 循环媒体，核对真实检测和 ReID、公开查询、外观进程故障时基础检测继续，以及关闭回收。

真实运动参考采用 [MOT15 官方 TUD-Stadtmitte 视频与人工标注](https://motchallenge.net/data/MOT15/)及 [OpenCV 4.12.0 的 vtest.avi](https://github.com/opencv/opencv/blob/4.12.0/samples/data/vtest.avi)。近距离 TUD 样本每 8 帧取一次（25 fps 原片，共 23 个样本），专项回归要求至少 100 个实测框与人工框的 IoU 达到 0.5，且同一人工目标在 2 秒内再次匹配时不能切换编号；此范围已通过。超过失配期限后重新建轨迹允许新编号，不当作身份延续。

TUD 原片 SHA-256 为 `057efff329eb73f3434649f9b21b37d0d3ca7de8f194524140161e2d13a6ae33`，MOT15Labels 中 `train/TUD-Stadtmitte/gt/gt.txt` 的 SHA-256 为 `009b3ef8df68c963fd8104350083fd6bc9798b6b435858b99dbd1385cfbde873`。测试显式传入这两个文件，缺少时跳过，不自动下载；素材与逐帧记录留在 Git 忽略的 `data/perception/`。

这不是完整 MOT 基准成绩，也不是跨场景可靠性保证。远距离 vtest 样本仍有明显人体漏检与轨迹中断；使用人工框隔离检测后，密集交叉仍存在关联错误，外观相似和遮挡不能保证编号连续。本机已测双路公开视频短时并行运行的检测时效和计算进程树（包括解码与 ReID）的 CPU/RSS，原始采样保存在本地验收材料中；它不包含模拟媒体服务之外的完整家庭接入负载。真实家庭双摄检测与跟踪联合负载及长时运行尚未测量，持续检测的双摄结论不能自动扩大到跟踪；剩余验收见[媒体计划](plans/media-perception.md#p2-剩余验收)。

## 处理与资源边界

```text
检测调用方 → 计算子进程 → Piscina → 读取/解码/模型推理
           ← 尺寸、检测框、输入哈希与耗时 ←

独立图片命令取得检测结果
  → 重新读取并核对输入哈希 → sharp 画框与 PNG 编码
  → write-file-atomic 保存最终标注图
```

Piscina 负责线程和任务队列；子进程负责隔离原生崩溃。父子进程通过 IPC（进程间通信）传递请求和结果。硬超时由 backend 回收整个计算子进程。

- `detection/detector.ts` 负责预处理、推理、框还原和 NMS（移除同类重叠框）；不依赖家庭领域或媒体协议。
- `detection/image-request.ts` 定义文件任务边界和可独立处理的图片错误，字节限额来自 `packages/api`；`detection/image.ts` 提供有界图片加载和文件检测，只依赖检测器的 `detect` 能力；`detection/model.ts` 在子进程中计算模型指纹。文件任务只接受本地普通文件，压缩字节不超过 32 MiB，输入尺寸和可选缩放后的尺寸均受帧限额约束。
- `detection/frame.ts` 的 schema（结构校验规则）定义 RGB24 帧格式，接收限额 `frameLimits` 来自 `packages/api`，与计算线程配置分开。宽高各不超过 8192，总像素不超过 `3840 × 2160`（8,294,400）；单帧 RGB 最多约 23.73 MiB。原始帧超过像素预算或使用共享内存时在入队前拒绝，不触发恢复。原始帧入口供媒体解码器接入；图片命令使用子进程内的文件任务入口。
- sharp 使用显式 `kernel: "linear"` 和 `fit: "fill"` 缩放至已计算尺寸，按比例缩放后取整尺寸，每条边至少保留 1 像素（包括极端细长图），居中补 114，转换成归一化 float32 NCHW（批次、通道、高、宽）张量。MiLoCo 从 BGR 转 RGB；此接口已是 RGB，不重复交换通道。
- 取每个候选框的最高类别分数，保留分数至少 0.5 的框。按原比例去补边，把连续框端点裁到 `[0,width]`、`[0,height]`；按置信度降序，用连续坐标计算 IoU（交并比），仅抑制同类 IoU 至少 0.7 的框。筛选结束后，保留框的左上角向下取整、右下角向上取整，宽高由整数端点相减；取整保留边缘像素，不参与 NMS 判定。
- `compute/pool.ts` 管理一个常驻计算子进程，`compute/process.ts` 在 backend 主线程统一限制活跃检测子进程数量为 1；第二次建池直接失败，调用方应共享同一个池。名额只在实际退出或确认启动失败后释放，IPC 断开不释放。文件处理和原始帧计算共享最多 N 项执行、一项等待的容量（N 为启动时的 worker 数）；计算容量满返回 `busy`。检测结果返回后释放计算名额；计算池不接收标注或输出路径。`compute/process.ts` 使用官方 `child_process.fork()` 接口，以当前 Bun 可执行文件启动子进程；消息由 `compute/protocol.ts` 校验。文件任务只传路径、选项和结果，原始帧使用高级 IPC 序列化传递 RGB 字节。图片传输最多保留 N + 1 项请求；实际图片/视频计算准入统一由子进程的 `inference-pool.ts` 管理。视频不提前填充计算等待队列，使用每路最新帧和就绪来源轮转。图片可进入已有等待位置，不因存在待处理视频而直接拒绝；已有等待任务先接手释放的名额，再通知视频继续。HTTP 适配器同时只接纳一个上传分析，额外图片请求或容量满时返回忙碌。视频 IPC 控制请求最多同时 16 项。
- `compute/budget.ts` 定义启动 CPU 预算和固定的线程内并发限制。整个 backend 主线程最多拥有一个计算子进程，子进程内创建 N 个模型 worker。sharp 每图并发、ORT 算子内线程数均为 1；ORT 使用 `sequential`。不将 worker 数再乘入模型内部线程数。
- `compute/process-entry.ts` 组装计算子进程；`compute/inference-pool.ts` 统一准入与派发。每个 worker 由独立的单线程 Piscina 实例持有，使用 `minThreads: 0`、`maxThreads: 1`、`idleTimeout: Infinity`；这样初始化和释放可以明确送达每一个模型会话。启动时全部初始化成功且模型元信息一致才报告就绪。全池只保留一个待处理图片任务，由下一个空闲 worker 接手；视频仅在有空闲名额时取走最新帧。关闭时先停止接收任务、排空全部在途与已接纳等待任务，再逐 worker 释放模型并关闭空闲线程。任意 worker 的池级故障由监督者回收整个计算进程组，确认退出后按相同启动预算重建。
- backend 的 `dev`、`start`、`detect:image` 命令在进程启动时设置 `ORT_DISABLE_TELEMETRY=1` 关闭原生遥测；直接执行构建产物时也需设置此变量，依据 [ONNX Runtime 隐私说明](https://github.com/microsoft/onnxruntime/blob/main/docs/Privacy.md)。

`scripts/perception-annotation.ts` 负责开发命令的标注图片。它在独立 CLI 进程中加载 sharp，按检测结果尺寸重新解码原图，核对输入哈希，画框并编码完整 PNG，再用项目已有的 `write-file-atomic` 保存。输出采用临时文件和重命名完成替换，失败由图片命令报告。命令串行处理图片；不建立跨检测池的文件预约、输出状态或清理重试接口。导出耗时不计入检测任务期限或 `timing.totalMs`。导出异常可能中断本次开发命令，但不会通过检测协议使共享推理 worker 失效。

文件检测的像素留在推理线程，不跨 IPC 往返。原始帧入口的父子进程 IPC 仍复制像素，Bun 的高级 IPC 序列化不支持转移缓冲区所有权；子进程通过 Piscina 的 `run(task, { transferList })` 把其独占副本交给工作线程，不再复制一份。这里的转移只发生在线程边界，不能消除父子进程间的复制。[Bun IPC](https://bun.com/docs/runtime/child-process#inter-process-communication-ipc)、[Piscina 任务参数](https://piscinajs.dev/api-reference/Methods/)

调用方原始缓冲区保持有效；原始帧检测 Promise 完成前不得修改像素。若输入只是较大底层缓冲区的局部视图，发送前用 `new Uint8Array(rgb)` 显式复制有效范围（包括 Buffer 输入），避免传输隐藏的大缓冲区。

单个 backend 主线程最多一个活跃计算子进程、N + 1 项图片/原始帧 IPC 请求；持续视频只传控制和结果，每路最多一个未完成任务。RGB 帧传输的逻辑像素预算最多为 `(N + 1) × 23.73 MiB`，IPC 副本另计；最多 N 个 worker 同时持有图片处理工作区和独立模型会话。独立图片命令仍按张串行提交，输出编码在命令进程内完成。这些限额不是 RSS 硬配额；增加比例会增加模型初始化时间及内存占用。不同 backend 进程的总资源由部署配置限制。

## 分段耗时

每个成功检测结果的 `timing` 包含以下毫秒值。文件任务计入完整读取、解码与检测；原始帧任务未执行的文件阶段记为 0：

| 字段                                             | 测量范围                                                                             |
| ------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `totalMs`                                        | 调用 `detect()` 或 `detectImage()`、开始输入校验，到调用方取得完整任务结果           |
| `readMs`                                         | 文件读取与图片哈希计算；模型哈希属于初始化，不逐帧重复                               |
| `decodeMs`                                       | 图片信息核对、解码、可选输出尺寸缩放和 RGB24 整理                                    |
| `preprocessMs` / `inferenceMs` / `postprocessMs` | 模型预处理、推理、输出检查与框后处理                                                 |
| `queueMs`                                        | 任务在 Piscina 等待队列中的累计驻留时间；直接分发为 0                                |
| `ipcRoundTripMs`                                 | 父进程发送至收到回复的耗时，减去子进程接收至准备回复的处理耗时                       |
| `workerDispatchMs`                               | Piscina 调用耗时，减去实际排队与推理线程内完整执行耗时                               |
| `dispatchMs`                                     | `totalMs` 减去读取、解码和模型三个阶段的汇总值；不与其包含的排队、传输等分段重复相加 |

输入在公开计算池入口校验，IPC 请求与响应在各自接收端校验；同一进程内的发送端和推理内部调用不重复解析已校验的数据。图片解码器限制文件与像素规模，检测器检查模型输入输出契约。

阶段计时用于定位瓶颈，不要求各段相加等于总耗时；输入校验、局部像素复制和资源释放仍计入总耗时，不逐项累计或计算剩余开销。各进程和线程只测量自身持续时间，不直接相减不同进程的 `performance.now()` 时间戳。`ipcRoundTripMs` 包含双向序列化、传输和两端消息调度，不能解释成纯字节传输耗时；`workerDispatchMs` 包含线程传输和 Piscina 回调调度。差值按 0 截断，避免计时精度误差产生负值。分位数分别计算，不能将各段 P95 相加当作总耗时 P95。

`compute/inference-queue.ts` 通过 Piscina 的公开 `taskQueue` 与 `queueOptionsSymbol` 接口记录 worker 内部排队时间，汇总时再加上全池等待空闲 worker 的时间。被取出后重新入队的任务累计每一段等待，移除任务时清理记录，不读取 Piscina 私有字段。[Piscina 自定义队列接口](https://piscinajs.dev/advanced-topics/Custom%20Task%20Queues/)

## 运行范围与限制

当前已验证的运行环境为 Bun 1.4.2 / macOS arm64 / CPU，支持源码和构建产物入口。Linux、GPU 和全天摄像头连续运行尚未验证。持续视频要求 POSIX 进程组支持；当前不支持 Windows 宿主。实际任务超时、计算子进程异常退出、重建和正常关闭已在当前 Mac 环境核对。

图片解码、缩放和标注统一使用 sharp，模型张量整理和补边由 TS 完成。预处理参数明确固定，不要求与 MiLoCo 逐像素一致；模型契约和实际检测效果是正确性依据，不保证遮挡或画面边缘目标的检出率。

## 计算池接口与故障行为

`createDetectionPool(options?)` 加载内部常量指定的 `det_4C.onnx`，返回 `metadata`、`detect(frame)`、`detectImage(input)`、`retry()`、`close()` 和 `getStatus()`。它负责这一固定检测模型的生命周期，不提供任意模型选择接口。导入和使用计算池不会在主线程加载 sharp 或 ONNX Runtime。帧边界定义在 `detection/frame.ts`；文件任务边界定义在 `detection/image-request.ts`。

`detectImage({ path, resize? })` 接受图片路径和可选的 `{ width, height }` 检测尺寸。输入为严格对象，未知字段会被拒绝。相对路径按调用进程工作目录解析；指定缩放时采用 `fill/lanczos3`，检测框对应返回的输出尺寸，默认对应原图。正常结果为 `image_detected`，只返回哈希、尺寸、框和路径，不返回整张 RGB 图片。`detect(frame)` 返回 `detected`，保留媒体解码器的原始帧接入能力。

计算子进程的 Piscina worker 内完成模型指纹、加载与推理；`metadata` 返回最近一次成功初始化的 `modelPath`、`sha256`、张量及执行配置，恢复成功后更新，`workerThreadIds` 列出该计算进程内全部已初始化工作线程，结合 `processId` 判断运行身份。

| 配置                  | 默认值 | 含义                                                                     |
| --------------------- | ------ | ------------------------------------------------------------------------ |
| `initializeTimeoutMs` | 30000  | 每次模型初始化的等待期限                                                 |
| `taskTimeoutMs`       | 10000  | 一次任务从提交起的期限，包含排队及完整文件处理                           |
| `closeTimeoutMs`      | 10000  | 完整关闭期限；也用于恢复前确认旧进程已退出                               |
| `recoveryDelayMs`     | 250    | 第一次重建前的等待，后续按两倍增加                                       |
| `maxRestarts`         | 2      | 连续故障期间的自动重建次数上限                                           |
| `recoveryResetMs`     | 60000  | 成功检测持续覆盖此时长后重置连续重建预算；仅空闲等待或模型加载成功不重置 |

初始化失败会清理本次子进程并拒绝创建。模型加载、张量契约校验和线程初始化失败通过故障消息保留具体原因；池级故障保留收到的底层原因。文件打不开、超过输入预算或解码失败返回 `invalid_image`，只结束当前任务，不消耗模型重建次数。推理或模型输出契约错误仍视为计算故障；任一类别置信度非有限数或超出 `[0,1]`、坐标非有限数都会拒绝本次结果，不能把异常输出当作成功的空检测。

检测任务超时、计算进程错误或退出、IPC 断开都会使当前计算运行失效，旧任务失败。输入文件读取和解码仍属于检测任务，其卡住或超时也会触发计算恢复。失败任务不会自动重放，恢复期间新请求返回不可用。只有实际子进程 `exit` 和整个计算进程组退出都已确认后才按预算重建；发送信号、IPC 断开和结束等待都不能代替退出确认。无法确认退出时保持不可用，不叠加新进程。输入格式错误和队列满不触发重建。

`retry()` 恢复已暂停的计算池，重置连续重建预算；即使自动重建次数设为 0，也允许一次显式尝试。并发调用合并到同一次恢复，仍先确认旧进程退出。关闭后不能重试。正常运行期间，连续成功检测跨越 `recoveryResetMs` 后才重置预算，任一计算故障重新开始稳定时长计量。

`getStatus()` 返回状态、累计重建次数 `restarts`、连续重建次数 `consecutiveRestarts`、最近错误、当前代 `processId`、在途检测数 `activeRequests`、其中的文件任务数 `activeImageRequests`，以及原始帧逻辑像素字节数 `activeRgbBytes`。文件任务通过路径提交，不计入 `activeRgbBytes`，这不代表子进程内没有图片内存。PID 用于诊断，不单独证明进程仍存活。状态包括 `starting`、`ready`、`recovering`、`unavailable`、`closing`、`closed`。`DetectionPoolError.code` 区分 `timeout`、`closed`、`busy`、`unavailable`、`worker_failed` 和 `invalid_image`；输入不符合 schema 时由 Zod 校验错误报告。

关闭立即停止恢复重试。完整关闭期限的前半段用于等待检测、恢复收尾和 session 释放，剩余预算用于确认子进程退出及请求结束。正常释放超时或运行故障时，对该计算子进程发送 `SIGKILL` 并等待实际 `exit`。正常释放超时但后续回收确认完成时，`close()` 报错而状态为 `closed`；退出或请求清理无法确认时为 `unavailable`。关闭只处理计算资源，不等待独立图片命令的导出。父连接断开时，子进程在事件循环恢复执行后退出；宿主异常退出且原生调用永久卡住的进程树清理仍需要部署环境的进程监督机制。

## 运行边界的依据

原生推理期间强制终止 JavaScript worker 可能使 ONNX Runtime 的原生绑定在失效的运行环境上继续工作，进而中止整个进程；当前资产与依赖在 Bun 和 Node 的线程终止复现中均出现进程崩溃。计算采用独立 OS 进程，使超时回收和原生崩溃不直接终止 backend。保留 Piscina 管理计算队列，但不对执行中的原生任务调用 `AbortSignal` 或 `Piscina.destroy()`；正常释放后才关闭空闲线程。

- [Piscina 方法文档](https://piscinajs.dev/api-reference/Methods/)区分等待任务的 `close()` 和中止任务的 `destroy()`；本实现把硬终止交给外层进程边界。
- [Bun Worker 文档](https://bun.com/docs/runtime/workers)说明线程终止仍属于实验性部分。
- [Node Worker 文档](https://nodejs.org/api/worker_threads.html)说明 `terminate()` 可在任意执行点停止线程；它不是 ONNX 推理的协作取消接口。
- [官方子进程接口](https://nodejs.org/api/child_process.html)提供独立进程和 IPC。发送终止信号不等于进程已经退出，资源回收以 `exit` 为准。
- [Bun IPC](https://bun.com/docs/runtime/child-process)支持父子 Bun 进程的高级序列化。本实现显式使用相同可执行文件，保持像素类型；进程传输会复制数据，应计入后续视频吞吐评估。

## 连续输入性能测量

```sh
bun run --cwd apps/backend benchmark:perception --seconds 20 /path/to/image.jpg
```

基准在 macOS/Linux 上使用真实模型，以 `workload.kind = "image-file"` 标识文件任务，分别按 1080p／10 fps、4K／10 fps、4K／30 fps 提交路径与目标尺寸。每次任务都在子进程读取、计算哈希、按 `fill/lanczos3` 解码缩放并检测，父进程不持有预解码 RGB。每组预热 5 帧，输出一行 JSON；`--seconds` 设置每组持续时间（5–300 秒）。总耗时包含文件读取、哈希和解码，同一池跨三组复用。输入可换成实际摄像头截图，运行期间输入哈希变化会使基准失败。

比较报告时先核对输入模式和计时范围。文件任务的完整处理耗时，不能与预解码 RGB 帧的入队检测耗时直接比较，也不代表摄像头持续解码吞吐。

帧计划按单调时钟推进，统计 `planned`（计划帧数）、`offered`（实际提交帧数）和 `missedDueToEventLoop`（定时回调迟到而未提交的帧数）。回调迟到时只提交最新到期帧，不集中补发历史帧；`planned = offered + missedDueToEventLoop`。已提交任务中的队列满拒绝另计为 `busy`，不能与未提交帧或成功帧混为一类。检测延迟仅描述已接收且完成的任务，应同时查看漏投、拒绝和实际吞吐。

每行报告在 `metadata` 中统一记录模型路径、哈希、张量信息及实际执行后端，另含输入图片路径与哈希、CPU 型号、系统版本和运行环境、ORT/Piscina/sharp 版本、计算预算和输入限额，便于核对比较条件；系统未提供 CPU 型号时为 `null`。`scripts/perception-report.ts` 为图片命令和基准共用的报告入口，使用子进程提供的模型元信息，父进程只读取依赖版本和宿主环境。

报告还包括检测端到端、读取、解码、模型三个阶段，以及排队、IPC 往返与线程分发各自的 p50/p95/p99/max、完成吞吐、原生 `monitorEventLoopDelay({ resolution: 10 })` 记录的事件循环延迟，以及每 250ms 采样的父/子进程 RSS（操作系统统计的驻留内存）。基准不执行标注导出。RSS 报告为采样峰值，可能漏掉瞬时尖峰；`eventLoopDelayMs` 将原生直方图的纳秒转换为毫秒，包含样本数、采样间隔及 p50/p95/p99/max；无样本时分位数与最大值为 null。该指标使用原生采样口径，不减去采样间隔，也不是 HTTP 响应时间。内存首尾四分之一均值帮助发现持续增长，不能单次据此断言泄漏。内存采样失败或非过载任务错误会让命令失败，不把缺失数据当零占用。

NMS 保持同类、按置信度排序的抑制规则，不为降低计算量截断候选或改变检测结果。用报告的 `postprocessMs` 判断该阶段是否值得进一步优化；固定图片短期测量不覆盖密集场景或全天摄像头稳定性。

## 媒体窗口筛选与按需读取

媒体窗口在 backend 内提供窗口事实、场景候选和短期媒体读取，不需要 Agent 或模型供应商凭据，不发送 LLM 请求。通过筛选的窗口自动进入有界媒体编码队列，不创建语义任务；基础检测和跟踪继续独立发布。候选表示本地筛选通过，不表示已识别活动、身份或“无人”。

### 窗口与筛选

窗口按同宿主接收时间划分为不重叠的 4 秒区间，等待最多 500 ms 接收慢轨及对应检测／跟踪结果。首窗和被来源停止时间截断的末窗标记 `incomplete`；已结束但仍等待宽限的完整窗口不因随后停止而改成不完整。截断同时裁去停止时间之外的视频帧、PCM 和声音分析块。窗口 `run` 属于来源访问范围，`videoRun` 单独关联视频计算运行，`audio.run` 关联音轨运行。视频解码或检测进程失败不停止有效音频的窗口采集；视频运行切换不截断音频窗口。同一窗口已有旧运行视频帧时，替换运行的帧从下一窗口接入，当前窗口记录 `video_run_changed`；帧与框不跨运行拼接。视频还保留实际来源 PTS（媒体时间戳）、媒体代次及帧序号；音频使用同宿主接收锚点与采样位置。`synchronizationAccuracyMs: null` 表示音视频同步精度未知，不宣称拍摄时刻精确一致。

视频在解码端按来源时间以最多 1 fps 选取真实帧，取得副本后交给原有检测链路；采样受原视频采样率与容量约束，不补帧。副本保留短边目标 512、长边最多 2048 的 RGB，以及 448×448 灰度图。全部通道共用两个采样名额，每项原生图像操作单线程，父进程确认接收后才释放名额；不建立等待像素队列。容量不足时记录缺口，但不推进该来源的采样时间，后续真实帧会重新尝试；只有接纳采样任务才开始下一采样间隔。检测和跟踪只按同一运行、帧序号和媒体时间关联，迟到结果不改写已关闭窗口。缺帧、容量跳过、缺少对应框和采样失败分别记录在 `gaps` 中。视频覆盖检查首尾接收时间、相邻接收时间与来源 PTS 间隔，按配置采样率推导窗口采样周期并允许 250 毫秒抖动，不以总帧数替代时间覆盖。

视觉阈值是相邻采样灰度图中绝对差大于 25 的像素比例达到 `0.005`。每路保留一张有界前置帧用于跨窗口比较；同一视频运行、媒体代次与尺寸，且接收时间和来源时间均连续时，把这张帧一起放入当前窗口的比较与回放。前置帧计入统一像素预算，容量不足时标记 `video_context_capacity` 并不作跨窗比较；过期、采样失败、来源停止或视频运行切换时释放。允许的相邻间隔由 `sampleFps` 与窗口采样目标共同推导，再加 250 毫秒抖动容差；低采样率的正常帧不会被当作断档。`gate.comparisons` 保留实际比较的帧编号、各自变化比例与区域，`changedRatio` 是这些比较的最大值；参与判断的两帧都包含在回放中。窗口时间范围仍按原四秒区间记账，媒体可以从前置帧的真实时间开始，声音从实际音频起点播放。至少两帧且实际变化达到阈值才放行，不保留变化后的静止窗口。采样或筛选失败不能默认放行视频；像素差异仍可能受到曝光与噪声影响，不代表已识别人类活动。

音频继续使用 480 点 RMS（均方根）块的 `0.015` 阈值，窗口汇总过阈块数和峰值；能量过阈只作为声音事实，不单独放行声音，音频缺口不被当作安静。窗口检查块间以及首尾覆盖，允许至多一个采样点的边界误差；故障、过期和音轨切换显式记录。中途故障不会被最后一次成功状态遮蔽，覆盖不足不会报告 `no_speech`；窗口已完整覆盖后的故障不改写该历史窗口。Silero 的 512 点块中至少三块概率达到 `0.4` 才标记 `speech`；不足、不可用与未检出语音分开表达。只有已接纳非空语音转写的窗口才可成为纯音频候选。双摄两路窗口关联同一音轨运行，PCM 只解码一次。

| 视觉与声音条件                         | `gate.candidate`                     |
| -------------------------------------- | ------------------------------------ |
| 实际视觉变化达到阈值                   | `video`，另列音轨是否可用和声音判定  |
| 视觉未通过、已有非空转写且音频完整可用 | `audio`，禁止申请视频和图片表示      |
| 无明显变化且无非空转写                 | `none`，丢弃媒体输入，不形成历史记录 |

`window/store.ts` 拥有来源访问范围、活动窗口和有限期输入，对外返回独立摘要及受失效信号约束的媒体借用，不暴露内部取消控制器。窗口关闭后，媒体输入只保留可编码的 RGB／PCM，释放聚合用灰度和重复的检测信息；历史检测、跟踪、身份和帧指纹仍保存在窗口摘要中。`window/aggregate.ts` 聚合窗口事实，`window/audio-coverage.ts` 判断声音覆盖与连续性，`gate/visual.ts` 负责筛选与裁切规则。`audio/pcm.ts` 定义音频进程实际使用的 PCM 输入边界。`media/window-media.ts` 拥有自动回看、表示复用、原始输入预算和窗口授权；backend 的 `src/media/resources.ts` 为窗口与 SD 回放分别管理任务、磁盘产物、容量预留、读取和清理，队列与预算彼此独立。`src/media/clip-files.ts` 准备独占缓存目录并清理中断遗留；`media/encoding-input.ts` 限定编码所需媒体与事实，`media/representation.ts` 计算媒体选择、裁切映射与输出参数；`media/encode-window.ts` 提供编码步骤，通过 `src/media/ffmpeg.ts` 执行进程，不维护存储的授权、计数和生命周期状态。共享 HTTP 契约在根目录 `packages/api/src/contracts/perception-window.ts`。

### 本机接口

接口继承 `/api/perception` 的本机来源校验与 `Cache-Control: no-store`，错误沿用公共 API 的 `code`、`message` 和可选 `issues` 结构，不返回摄像头地址、凭据或进程指针。媒体字节不进入公共 SSE 或聊天 JSON。

| 接口                                                             | 行为                                                               |
| ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| `GET /api/perception/windows`                                    | 指定来源的轻量窗口列表，以及全局筛选计数、保留字节和编码／读取占用 |
| `GET /api/perception/windows/:id`                                | 指定窗口原始来源、时间、逐帧事实、声音摘要、筛选和媒体输入状态     |
| `POST /api/perception/windows/:id/media`                         | 显式申请 `representation`，可选 `retry: true` 重试失败表示         |
| `GET /api/perception/windows/:id/media/:representation`          | 只读状态，不创建或重试编码                                         |
| `GET /api/perception/windows/:id/media/:representation/:mediaId` | 读取已生成的指定产物，不创建编码，不替换窗口                       |

窗口列表必须指定查询参数 `scopeEpoch`、`deviceId`、`channel`，只返回该家庭与镜头的窗口身份、时间、筛选、原始输入状态及 `sampledMedia` 后台采样媒体状态，同时给出 `revision`、`summaryUntil`、`speechCount`、`identityCount` 与已确认的 `identityLabels`；逐帧检测、轨迹、历史人物身份快照、转写文字与声音事实通过指定窗口详情读取。详情的 `frames[].identity` 和媒体状态的 `parameters.frames[].identity` 使用同一个紧凑身份契约；图片只带实际选取的最后一帧，纯音频没有视频帧。身份时间与缺失状态的含义见[窗口中的历史身份](#窗口中的历史身份)。来源过滤不代替访问校验，已撤销窗口不出现在列表或详情中。

允许 `image`、`crop_image`、`video`、`crop_video`、`audio`。自动回看的视频在窗口音轨完整时带声音，纯音频候选自动保存 AAC/MP4。列表与详情的 `sampledMedia.selection` 给出默认媒体选择，`sampledMedia.state`、`readableUntil`、`error` 给出生成进度、最晚读取时间和错误，跳过窗口为 `null`。手动申请的视频默认不带音轨；申请时可设置 `includeAudio: true`，状态查询和读取使用同名查询参数 `?includeAudio=true`。该参数仅控制视频是否携带可用音轨，不改变独立音频或图片表示；声音筛选和模型能力是否允许携带音轨由调用方决定。图片取窗口最后一张实际保留帧，视频使用全部保留帧；音频表示为 AAC/MP4。请求体最多 1 KiB；排队或生成中返回 202，已有状态返回 200，容量不足为 429，表示不适用或产物未就绪为 409，已知失效输入为 410，摘要已移除或不存在为 404。

媒体状态有 `not_generated`、`queued`、`generating`、`ready`、`failed`、`expired`、`evicted`、`revoked`。同窗及相同规范化参数（包括实际音轨选择）共享任务和产物；没有合适裁切区时，裁切请求复用全景表示。失败必须显式重试，窗口身份和期限不变。通过筛选即接纳默认表示的编码，不等待浏览器请求；队列满时记录失败，不能悄悄丢弃。申请者断开不取消共享编码。接纳后的有界编码操作持有自己的原始像素引用，原始缓存淘汰不取消该操作；明确撤权、操作超时和服务停止会取消。原始输入释放后不再接纳新的表示生成，已完成的磁盘产物遵循独立回看期限。

裁切使用窗口各采样帧的检测框（包含人及猫狗）与显著变化区域的并集，每侧按水平 `0.40`、垂直 `0.30` 扩展；区域占比控制在 `0.10`–`0.49`，不合适时用全景。变化区域使用灰度差异的包围范围，不复刻参考项目的连通域去噪。原帧缺少框时仍可使用变化区域或全景，不移用其他帧的检测。全景和裁切共享同档像素尺寸上限；裁切基于已经缩小的 RGB 副本，放大只突出区域，不能恢复原图的人脸、毛发等细节，不作为高分辨率身份识别输入的保证；产物返回实际 `cropPixels`、输出宽高和映射后裁到有效范围的检测框，坐标基准为 `encoded_pixels`。预测轨迹仍只在原窗口事实中保留，不冒充实测框。

图片和视频均由可终止的 FFmpeg 子进程编码，采集阶段继续用 sharp 缩放。按需编码直接读取有界 RGB 与 PCM 临时文件，不生成中间 PNG；图片使用 JPEG，视频使用 H.264/MP4。视频用公开 `setpts` 滤镜映射实际保留帧时间，输出不补帧，产物 `parameters.frames[].offsetMs` 对应原帧；`sampleFps: 1` 是采样目标，不表示文件固定一秒一帧。音视频使用同一输出时间原点，返回实际起止和音轨存在性，不把空缺音轨编码成静音。音轨中断或跨音轨代次时，视频不携带该音轨，单独音频申请明确失败；摘要保留声音事实和缺口。音频尾部可以长于视频最后一帧，不额外复制帧来虚构观察。

### 窗口中的语音文字与人物判断

窗口详情的 `speech` 保存本次运行是否启用转写、`acceptingUntil` 接纳截止时间、完整语音段 `segments` 及容量截断标志 `truncated`。文字直接来自音频进程完成的本地转写，与对话收件箱独立交付；Agent 不在线、对话判断关闭或收件箱到期不清除已经接纳的窗口文字。窗口存储是这些历史关联的所有者，不从实时音轨的 `latest` 倒填。窗口接口的 `counters.speechAssociations` 累计已写入关闭窗口的语音关联数，同一段跨窗分别计数；`pendingSpeechEvicted` 只统计待归窗缓存满额淘汰的片段数，与对话收件箱确认独立。

关联必须同时匹配设备、家庭范围、`trackRunId`、媒体 `generation`，且语音的观察区间与窗口实际保留音频的时间范围相交。一段语音可以跨多个窗口，各窗口保留同一段完整文字与原始时间，不切词、不制造逐字时间。视频计算重启不改变有效音轨的关联。音轨换代、其他家庭及其他设备的结果不能混入窗口；撤权后仍沿用窗口统一的访问限制。

语音切段与识别可能晚于窗口关闭，因此允许在截止前补充文字；接纳截止时间由语音模块的 `speechDeliveryDeadline` 统一计算，覆盖最大语音段、静音切段等待、模型启动、排队、推理及配置的新鲜度上限。窗口只索引同音轨、仍处于接纳期且保留了音频时间范围的关闭窗口；到期、撤权或删除时移除索引。每次补充递增窗口 `revision`，前端通过轻量列表发现变化后更新已选详情，保留播放器和已加载媒体。采样帧的身份快照依然不可回写；`identityCount` 与 `identityLabels` 在关闭窗口时生成一次，列表复用该摘要；标签仅汇总这些帧当时已确认的本地身份，不代表当前身份或语音的说话人。

画面变化达阈值或有非空转写的窗口摘要从关闭起最多保留 30 分钟；人物判断不单独构成接纳理由。除来源独立持有的一张短时比较用前置帧外，未通过的窗口立即丢弃 RGB、PCM、帧事实和人物判断，不生成媒体，也不开放列表或详情读取。启用转写且存在音轨时间区间时，只在转写接纳期限内保留有界关联元信息，迟到的非空转写到达后形成文字记录，期限仍从原窗口关闭时间计算；到期未收到文字则删除。此过程不恢复已释放的媒体，因此迟到的纯语音记录可能只有文字。窗口文字与身份属于采集证据，不能直接当作整段 SD 录像的字幕或人物标注。

### SD 录像中的观察帧定位

窗口详情的 `frames[].fingerprint` 可选地保留完整解码帧的内容摘要：`algorithm: md5_rgb24`、含 32 个十六进制字符的 `value` 和原始 `width`、`height`。MD5 在这里用于比较 RGB24 像素字节是否相同；RGB24 表示每个像素按红、绿、蓝顺序连续存放三个字节。摘要在原图缩放、裁切和送入检测前计算，随对应帧保留，不增加一份完整原图缓存。缺少摘要时不补造，缩小的窗口图片、相似图和裁切图都不能替代这份证据。

[SD 卡回放接口](mijia.md#sd-卡录像读取与回放)可以按窗口申请原摄像头、原镜头的录像。宿主接收时间只用于缩小候选片段范围，不能直接减去录像开始时间来得到精确位置。后台读取候选原始录像，用 FFmpeg 的 `framemd5` 对相同尺寸的完整 RGB24 解码帧生成摘要；不通过缩放或图像相似度制造匹配。直播和 SD 录像的分辨率、编码画面或像素转换结果不一致时，匹配可以明确失败。

只有同一媒体代次中至少两张带摘要的观察帧全部在候选录像中唯一命中，且帧序号、来源 PTS 和录像帧位置保持递增、相对时间差在实际录像帧时长范围内一致，才返回 `alignment.type: confirmed`。回放响应的 `eventFrameOffsets` 给出这些观察帧在生成文件中的位置，`seekOffsetMs` 指向第一张匹配帧；`uncertaintyMs` 是对应录像帧时长的边界，不是设备与 UTC 的时钟误差。只有单帧证据、缺少匹配、重复像素产生多个候选或时间关系不一致时，返回 `unknown`，不确认跳转位置。

这一定位结论只覆盖实际观察到的采样帧，不补齐未采样时刻，也不把窗口边界解释为真实活动的开始和结束。窗口的 `timeBasis: host_receive` 与历史事实保持不变；摄像头原始时钟、SD 索引时间和文件创建时间均未被证明精确同步到 UTC。取得原始时间字段或成功找到同一幅画面，不会自动获得真实世界时钟精度。

### 容量、停止与访问期限

`config/perception.json` 中 `window.retentionMs` 只控制原始 RGB/PCM 输入，默认 12000 ms，允许 1000–60000 ms，每镜头最多保留三个可读原始窗口。它不限制已经生成的压缩回看片段。回看片段从窗口关闭起最多保留 30 分钟，全部来源共享 1 GiB 磁盘预算；编码前按单窗输入与产物上限预留空间，超限优先删除最旧且未被读取的产物。无法腾出空间则失败，不突破限额。

压缩文件写入 `config/perception.json` 所在目录下的 `runtime/perception-clips/`。启动时将新建或已有缓存目录的权限设为仅当前用户访问，不接受缓存目录自身为符号链接。先在同一文件系统的临时子目录编码，完成并核对大小后以原生 rename 发布，读取通过原生文件流转换为 Web Stream，不把磁盘缓存整体载入内存。该目录由单个 backend 实例独占；正常退出清理产物，启动只清理该目录中匹配自有命名规则的上次中断文件，不恢复旧授权或旧媒体引用。初始化或清理失败记录错误，停止接纳后续编码，避免失去容量核算。

| 资源                               | 上限                                                                                           |
| ---------------------------------- | ---------------------------------------------------------------------------------------------- |
| 每来源待关闭窗口／可读原始窗口     | 各 3 个；待关闭积压消费最新就绪窗口                                                            |
| 每窗口转写／每来源待归窗转写       | 16 段／64 段；达到单窗上限标记 `speech.truncated`                                              |

原始像素不等待消费者无限保留。公共媒体资源管理器使用 p-queue 管理并发，取消传给实际 FFmpeg 操作；正常路径在进程退出且临时文件清理结束后完成任务。队列输入按引用持有，不复制整个原始缓存；共享引用仍保守计入独立编码预算。取消、失败和离页不会留下未处理的 Promise 拒绝。发送终止信号后最多等待三秒确认进程关闭；不能确认退出或临时文件清理失败时，隔离该资源、保留其容量预留并停止该管理器后续生成任务，不删除可能仍由进程使用的文件，关闭接口报告失败。磁盘容量仅在文件删除成功后归还。

磁盘淘汰跳过在途读取，摘要移除或媒体到期后不再接纳新读取；已经接纳的读取可在自身最多 30 秒的期限内完成。窗口存储独立持有在途读取的授权租约，即摘要移除后仍复核同一家庭与设备资格，流关闭时释放；真实撤权和服务停止仍立即取消读取。已完整交付浏览器的副本不随文件删除回收。上述限额不是进程 RSS 硬限制；摘要、模型、FFmpeg、解码器和浏览器解码工作区各自另计，需要联合测量。

正常来源停止会关闭末窗；同一访问范围内视频运行替换不改变窗口期限，已关闭窗口可按原期限读取或编码，不重新连接摄像头。家庭与设备访问资格依据已提交的家庭运行状态、账号及当前设备与镜头判断，设备清单刷新或同步错误不单独构成撤权。资格保持有效时，go2rtc 失联、重启或媒体连接换代不撤销已保存片段；实时采集仍由当前媒体连接及其失效信号约束。来源撤权、家庭切换和退出立即撤销相关输入、产物及读取。服务整体退出会清理内存、任务与自有磁盘产物。每次媒体申请与读取复核当前访问资格，停止后的历史读取不恢复原运行的实时结果资格。已完整下载的副本不延长服务端期限，服务端也不能收回客户端字节。

当前媒体窗口不登记可提交语义判断的证据账本，也不提供语义结果提交期限或家庭身份接纳。相关规划见[后续媒体计划](plans/media-perception.md#p5p6-证据登记与提交期限)。

### 验证范围

窗口媒体入口不依赖 Agent。现有采集初始化与音频生命周期测试覆盖初始化重试、音频撤权、断流恢复和缺轨行为；这些测试不验证全部窗口聚合与媒体编码场景。macOS arm64 上已核对真实小米智能摄像机 4（`chuangmi.camera.079ac1`）的短时联合链路：普通话转写、跨窗口文字关联、人脸样本采集、历史身份快照，以及浏览器解码带声音的后台采样视频；go2rtc 重启后直播恢复，已加载采样媒体保持可读。无参考库时身份维持未知，该验证不覆盖具体成员识别准确率。该设备未提供可回看的 SD 录像，不能据此确认 SD 回放、原帧定位或故障隔离通过。长时负载及其他窗口生命周期场景仍需专项验收，具体未完成项只在[媒体窗口剩余验收](plans/media-perception.md#p4-剩余验收)维护，不把类型检查或已有采集测试当作媒体功能验收。

## 家庭短期人体外观参照

`household/identity/appearance.ts` 单独拥有短期参照、匹配支持、冲突阻断和终态核对；`main.ts` 装配后由感知服务交付已接纳的跟踪、原始身份 `tracks/recent` 与新外观证据。查询只读状态，不积累支持。匹配参考快照的订阅变化先清理不匹配依赖，再发布变化；一次接纳中的跟踪／身份存储、外观规则及撤销处理完成后统一发布，避免新原始冲突与旧关联同时交付。

参照只来自有效的直接人脸 `confirmed` 的本次新支持，按运行、媒体代次、轨迹、证据原帧序号和 RTP 时间精确配对新人体特征；人脸结果先到或外观先到均在原帧期限内配对；冲突阻断期间可暂存新外观，但必须等待截止帧之后的新合法确认解除阻断，才允许建参照。缓存复用、预测目标、重复证据及外观推测不建立或刷新参照，不保存额外图片。参照记录完整人脸参考版本与独立 ReID 模型／处理版本，期限从原观察开始计算；运行内使用接收端单调时钟及剩余帧预算，不比较跨进程的单调时间原点。

资源上限为全局 256 个目标、8192 份临时样本、每成员 5 份参照和最多 32 名成员，满额拒绝新条目并累计 `capacitySkipped`；单份样本／参照元数据最多 4 KiB，领域序列化事件最多 1 MiB（UTF-8 JSON 字节），对象开销另计。每轨迹配对缓存按 `ceil(sampleFps × maxFrameAgeMs / 1000) + 1` 限制。参照满额优先保留不同来源样本，同来源按人脸质量和时间选择替换。10 分钟参照、5 秒支持窗口／推测期限是待校准时间候选；默认装配没有分数门槛，`calibrated=false`，只提供最高成员分数及领先差值诊断，`inferred` 始终为空。这些分数不是身份概率，来源级公共关联及成员活动已接入外观契约；默认未校准时仍不产生或保存外观归属。

`appearanceCalibrationSchema` 是后续实景校准的接入边界，集中接纳策略版本、绝对分数、领先差值及选定时间期限。注入完成校准的策略后，规则要求至少两份不同新帧、跨度至少 500 毫秒、共同且仍有效的参照，并同时满足最新帧有效、距最近实测不超过两秒及目标未结束；人脸确认优先。后续有效跟踪只更新跟踪边界，不延长新外观支持的原期限。新分数不足、候选接近或候选与有效直接身份不一致时清除支持和推测；单纯缺少新特征只按原期限失效。无参照、无新特征、版本不一致、支持不足、冲突及未校准均有明确诊断原因。当前未进行真实家庭校准或多人误归属验收，不承诺覆盖率或识别准确率。

原始人脸冲突即使没有标签和成员关联也阻断目标；`unknown` 或证据到期不解除，必须有观察版本更新、撤销截止帧之后的合法新直接确认。每次完整身份观察先处理 `tracks/recent` 的冲突和身份推翻，撤销来源目标建立的全部参照及跨目标实际依赖，再处理合法确认，最后结束核对。自然到期／容量淘汰只停止后续使用；外观目标只保留建参照时的成员标识 `referenceMember` 用于识别后续身份替换，不累计历史参照。活动服务自行保存当前归因和在途写入依赖的参照及来源，后续真实冲突仍按来源目标交付撤销。重复 `recent` 不重复撤销；参考快照为 `null` 或完整版本变化清理参照、支持和推测，但保留消费进度及冲突截止，恢复相同版本不能重放旧确认；失效和恢复时均记录已接收身份／跟踪帧的截止进度，等待边界之后的新支持。

跟踪目标消失后保留终态核对状态，最长等待现有 `recentTtlMs`（60 秒）。可信正常终态完成核对后保留参照供其他目标使用；缺失终态、来源停止或媒体代次变化会保守撤销未核对目标的参照，原因 `terminal_identity_unavailable`。结束摘要只用于核对和撤销，不重建参照或实时推测。来源退休拒收旧运行，家庭／来源撤权清理相关状态。家庭设备状态的普通 `sequence` 更新不改变访问资格；新证据仍由感知服务检查当前来源访问、运行和 `scope_epoch`，不把新家庭版本改写为旧证据资格。

内部 `perception.appearance.snapshot()` 不含向量，提供参照摘要、目标诊断、校准门槛状态和容量计数；它不进入公共 API。关联选择和活动终态检查通过 `target(sourceTargetKey)` 只读取得对应目标摘要，不复制整份参照库；返回副本不允许调用方修改领域状态。`subscribe` 同步交付 `reference_revoked`（来源目标键 `sourceTargetKey`、原因、本次仍存在且实际删除的参照 ID／依据，以及触发原始身份观察和目标状态；单份证据超出 4 KiB 时不保留该证据并用 `omittedEvidence` 标明数量，仍处理冲突及终态）、`references_invalidated`（参考版本、来源、媒体或 ReID 版本失效）、`target_identity`（来源目标键及目标本身的新合法直接确认或原始冲突，活动在终态处理前消费）、`target_ended`（目标键、运行／轨迹、最近观察时间、可用时的原终止观察时间与核对可信标记）及 `changed`。撤销先清除跨目标依赖，再通知订阅者，终态通知完成后释放目标；事件接收方应立即更新自己拥有的有界活动依赖。自然到期和容量淘汰不发冲突撤销事件。活动拥有者同步消费撤销与终态；这个进程内通知契约不是可靠持久事件日志。公共查询只输出选择后的来源级关联，不输出领域参照库或诊断状态。

### 外观校准输入与验收边界

当前外观策略未完成校准，正式装配不传入 `calibration`；上线使用的绝对分数门槛、领先差值、策略版本及时间期限均未选定。10 分钟参照、5 秒支持窗口和 5 秒推测期限仍是候选，不能以单镜头跟踪的距离门槛代替成员归因门槛。保持 `calibrated=false` 时不产生 `inferred`，因而不写入外观成员活动；已有直接识别不受这个门槛影响。

离线入口复用正式模型及领域规则，隔离于摄像头、家庭数据库和 Agent；固定素材、身份划分、冻结协议、实验结果与资源解释集中在[感知离线对照评估](../apps/backend/scripts/perception-evaluation/README.md#人体外观离线校准)。Real28 的身份独立留出仅针对本次调参，模型训练数据未知；静态图及低跨镜头覆盖不足以启用家庭策略。

视频入口保留原帧与实际呈现时间；MEVA 只测新特征和人脸检测交集，ChokePoint 加入真实人脸质量及正式确认规则，但没有确认后归因证据。AMI 单参照素材证明真实确认与短期参照可以形成，完整长段的固定时间策略对照仍未形成外观推测增量。公开视频缺少真实家庭及完整多身份真值，这些结果不选择上线分数或期限；运行方式、各分母及具体限制见[视频外观输入评估](../apps/backend/scripts/perception-evaluation/README.md#视频外观输入可用性)。

PP-LCNet 原生人体属性离线对照未观察到接纳增益，当前不接入属性模型；官方能力与执行契约见[人体可见属性参考](references/person-attributes.md)，冻结对照与本机资源结果见[人体可见属性评估](../apps/backend/scripts/perception-evaluation/README.md#人体可见属性对照)。静态属性一致不能代替直接确认，也不补齐时序、数据库和页面验收。

未验收范围包括：真实家庭同人同镜头重新出现／跨镜头、独立标注的相似衣着多人、换衣和长间隔的连续归因及跨数据集验收；真实家庭及独立多身份素材下的参照期限／支持窗口策略验收；真实家庭同帧直接确认和新外观共同可用比例、线上调度下的新特征间隔、推测闪断、可归属片段增量、错误归属、形成延迟及多路缓存峰值。这些指标没有实测值，不能把未采到或未提取算作分数失败。

冲突与重复交付、旧确认重放、`recent` 终态及终态丢失、运行／家庭／参考版本切换与 `null` 恢复、首次落库前累计纠正、队列为空时跨来源撤销、提交中撤销、失败后重试、自然到期与独立确认的组合，均未通过专项隔离运行验收。页面的无目标人脸推测、到期撤标、历史摘要及数据库纠正后的实时一致性也未完成实际状态验收。源码规则、类型检查、已有通用测试和页面空态不能替代这些证据。完整场景及完成条件继续由[成员短期外观归因计划](plans/member-attribution.md#5-校准与验收)维护。

## 持续成员身份分析

`perception/identity/` 消费现有跟踪回调交付的 RGB24、实测人宠框及 `runId + trackId`，不启动第二条视频采集。`analysis.ts` 拥有轨迹证据和判断，`runtime.ts` 协调采样、期限及计算名额，`process.ts` 管理唯一的 Bun 身份子进程，`process-entry.ts` 接纳进程间请求，`model.ts` 协调模型适配，人物使用 SFace，猫狗使用 `pet-model.ts` 的整只动物特征。家庭成员资料、权威身份和跨摄像头关联由家庭领域负责；人体 ReID 相似度只在家庭领域短期外观规则下作为待校准的推测依据，不作为直接人脸确认。

### 配置与模型

默认 `identity: null`。启用时，运行 `bun scripts/install-identity-models.ts` 安装 [models.json](../apps/backend/src/perception/identity/models.json) 中固定版本的 YuNet、SFace、宠物模型和许可证；文件按 SHA-256 校验。再配置：

```json
{
  "identity": {
    "modelDirectory": "../data/identity/models",
    "sampleIntervalMs": 1000,
    "evidenceTtlMs": 30000,
    "idleUnloadMs": 30000,
    "minimumSharpness": 50
  }
}
```

保留原有 `sources` 等配置。模型路径相对于配置文件所在目录。backend 启动时读取配置，构建独立的 Bun 身份入口并包含模型契约；部署使用已安装的 npm 依赖与模型权重，不需要 Python、NumPy 或 OpenCV 系统安装。模型适配器首次准备时分别校验自己的固定文件与许可证 SHA-256；人脸使用 YuNet／SFace，猫狗共用宠物模型。未使用的模型文件不参与该适配器的准备。

OpenCV.js 的 WebAssembly（由 Bun 运行的编译模块）提供官方 `FaceDetectorYN`、图像变换和清晰度运算；nudged 按 SFace 五点模板估计平移、旋转和等比缩放，再由 OpenCV `warpAffine` 对齐。SFace 使用已有 `onnxruntime-node` CPU 后端，输入为官方契约的未缩放 RGB float32 NCHW 数据，归一化由模型图承担。项目不手写检测后处理、相似变换求解或插值算法。身份子进程内计算串行，ONNX Runtime 与 Sharp 均限单线程，在线只加载一份 SFace。

### 家庭参考与匹配策略

唯一匹配来源是当前家庭数据库中的人物、猫和狗参考。`household/identity/matching.ts` 拥有策略、内容版本及运行资格，按成员 UUID 生成独立快照，经现有感知 IPC 交付计算进程；匹配不按显示名猜测身份。一次采样从准备输入到接纳结果使用同一份快照。人物与猫狗合计最多 32 位有参考的成员，每位 10 份特征；停用成员仍在同类评分集合中。`createReferences().rank` 按人物／猫／狗隔离，对每个成员取最高余弦分数，分数不是正确概率；最高分达到 `threshold` 且第一、第二名分差严格大于 `margin` 才能提供支持。最高分成员停用时保持未知，不改选下一名。

人物及猫狗保存参考后自动启用，使用固定匹配参数：SFace 余弦阈值 0.363 采用 [OpenCV 官方示例](https://docs.opencv.org/4.12.0/d0/dd4/tutorial_dnn_face.html)，猫狗余弦阈值 0.7、第一与第二名分差门槛 0.08 是工程参数，不是正确率或用户校准结果。参数版本由实现定义，仍核对参考内容、资格、模型及处理版本。匹配分数表示特征相似程度，不是身份正确概率。猫狗阈值及分差门槛尚无家庭标注素材的误认／漏认评估依据，公开模型指标不能验证这些参数在本项目中的效果。

样本增删、有参考的成员删除、家庭改绑及模型或处理版本变化更新参考内容版本。启停只更新资格版本，不改变评分集合或匹配参数；改名不改变任何匹配版本。变更持有家庭与成员锁时先撤销当前快照，提交后重新读取数据库；刷新失败保持匹配撤权并记录错误，不改变数据库写入的事务结果。失效清空当前支持及近期轨迹摘要，拒绝旧版本在途推理和 IPC 结果，无需重启。重新启用从新的实测支持开始，不恢复停用前确认。参考变化后按相同匹配参数重新采样；模型或参考处理版本不兼容时停止匹配，登记与删除仍可使用。配置初始化的数据库阶段失败后，既有重试入口会重新完成该阶段。

### 当前成员关联

感知主进程沿用来源授权、运行、媒体代次、快照顺序与期限门禁。家庭身份领域的 `association.ts` 校验直接支持证据，`associations.ts` 拥有来源级 `associations` 的选择与生命周期；内部原始 `identity` 可为空，且不包含成员关联。选择在已接纳状态更新时完成，查询只读取，不推进确认或累积支持。一次接纳中的存储、家庭身份处理及撤销全部完成后才通知公共订阅者。

公共判别契约按 `basis` 区分 `face`、`pet` 与 `appearance`：直接识别保留 `candidate / confirmed`、原支持证据及完整人脸参考版本；宠物依据明确标为 `pet`。人体外观仅为 `human` 的 `inferred`，包含目标新帧证据、实际参照 ID／摘要、分数、期限及策略版本，不包含向量。公开证明包含评分最高的一份共同有效参照及两份真实支持帧：`referenceIds`／`references` 各一份，`evidence` 为支持窗口中当前可用的最早和最新新帧，跨度至少 500 毫秒。分数来自所选参照的本次真实匹配，领先差值相对于第二成员最高分；期限受所选参照原期限、推测期限及跟踪有效边界共同限制。私有窗口仍校验全部支持共享当前有效参照，不放宽归因规则；每成员最多五份是内部参照库容量，不是公共证明数量。直接确认优先，其次为有效人体外观推测，再是直接候选；目标来源没有人脸观察也可返回外观关联。默认尚未注入实景校准策略，外观关联仍为空。

投影核对成员仍存在且启用、物种与轨迹相符及完整参考版本一致，逐份核对支持证据的运行、媒体代次、轨迹、原帧身份、顺序和分数。期限沿用最新支持的原始观察时间，较早支持的清理由原身份分析拥有。失去来源授权、换运行、媒体代次变化、轨迹结束、跟踪或对应依据过期后不再提供当前目标。名称更新不改变匹配版本；同名成员通过 UUID 区分。窗口保留冻结时的原始身份标签与判断，不把后来形成的归因回填成原帧人脸确认。

摄像头实时详情的“当前成员关联”面板独立消费父路由已有感知订阅，显示成员名、ID、轨迹、归因依据和观察时间；直接识别区分“疑似／已确认”，人体外观显示“推测是某人 · 人体外观匹配”，不把外观分数当作身份概率。定格后仍实时更新并明确提示不属于定格画面；失同步时清空当前目标。“筛选片段”只读取窗口历史身份。

停用保留参考图片与匹配参数，只换运行资格版本并清空在线支持；重新启用使用新的资格版本重新采样。删除先撤销图片读取与匹配资格，文件清理失败后的重试不会恢复资格；改绑沿用清空成员及其参考的行为。已冻结窗口不回写，也不推断位置。

### 成员最近活动

活动写入最多保留 256 个待完成任务。家庭作用域切换取消尚未执行的旧任务，已开始的事务保留串行名额直到实际结束，并在提交前核对作用域与证据有效性。

`household/identity/activity-service.ts` 独立消费来源级关联，不依赖浏览器观看或窗口变化筛选。同一家庭作用域、来源运行、媒体代次与轨迹复用一个活动 UUID；成员、参考版本和归因依据不定义活动身份。`activity.ts` 按实际依据构造观察：直接确认使用 `supported`，直接候选和外观推测使用 `tentative`；外观分支不要求目标来源有人脸观察，也不制造人脸证据。摄像头所属房间只标明来源，不登记目标位置或行为。

共享 `memberActivityDataSchema` 把 `attribution` 保存到现有 `context_records.data`，不新增表。首次接纳时固定 `original`，初始化 `current`、`revision=1`、`correctionCount=0` 和空 `lastCorrection`。两份归因快照复用同一个 known／unknown 判别 schema，各自保留原证据与版本；未知撤销保留原因及有界触发依据。成员改变、外观推测升级为直接确认及冲突撤销累计语义纠正；同归因新支持、直接候选升级确认和结束时间更新只增加版本。最近纠正保存前后快照、原因、触发依据及处理时间，不保存完整逐次时间线。所有摘要有条数及字符串上限，不含向量或媒体字节。

活动拥有者在入队前累计所有修订；队列可以合并到最新快照，但不能重建首次归因或丢掉首次写入前的纠正次数。PQueue 串行写入，最多保留 256 个活动；普通支持更新按 10 秒合并，状态变化、纠正及结束更新不受该节流限制。写入开始前核对最新版本和撤销状态，之后冻结该版本：持续新支持不取消仍合法的在途快照。回执只记录实际保存版本，旧提交成功后仍调度最新纠正；数据库失败每 5 秒重试最新快照，不阻塞采集。

活动为当前归因和在途快照保存实际参照摘要，按参照的来源目标键建立反向关联；保存成功不删除仍活动的依赖。`target_face_conflict`（目标自身的人脸冲突）同步撤销其外观活动归属，即使所用参照由其他目标建立；不因此删除其他目标的参照。新增合法直接确认先接纳活动归属，再处理终止摘要；首次只出现在 `recent` 中且没有既有活动的确认，也按当前家庭资格和容量限制创建活动，有既有活动时沿用原 UUID。`reference_revoked` 按 `sourceTargetKey` 查找当前或在途依赖，使用活动自己保存的参照摘要核对并同步生成更高版本未知归属，累计一次纠正；参照此前已经自然到期或被容量淘汰也不漏掉后续来源冲突，重复撤销不重复计数；若最新归因已由独立直接证据支持，保留它并撤销旧在途快照的资格。自然到期、容量淘汰及正常结束只停止后续使用，不把曾合法接纳的历史改为未知。终止核对或最新必要保存尚未完成时保留状态；正常路径只有终态核对和最新保存均完成后释放，已完成历史不批量追溯。

参考快照失效时停止旧归属的待写与重试，事务内继续检查冻结快照的实际支撑版本。失效本身不累计纠正；活动尚在运行时保留首次归因和累计状态，新的合法归因沿用原 UUID。目标结束而无新合法归因时，明确废弃未保存的失效快照并释放状态，不把废弃当作保存成功，也不使用旧版本补写结束字段；此前已提交的历史保持原值。

仓储在家庭绑定及成员锁下锁定读取活动，首插直接保存完整累计快照，更新只接纳更高版本并检查稳定身份、`original` 一致及计数不倒退。同版本同内容幂等；同版本不同内容、不可变字段冲突及旧版本拒收。新 known 归属只核对 `current` 的实际直接支持／参照人脸证据版本与当前成员资格，不用历史 `original` 版本放行或拒绝新归属。unknown 撤销核对家庭访问、活动身份、版本及领域撤销依据，不要求被撤销参照仍有效或未知结果有成员。摘要、确定性、当前证据、归因 JSON 及主体替换在同一事务完成，移除旧成员主体并保留摄像头来源；旧成员查询因此不再返回纠正后的活动。

数据库不可用时实时撤销先生效，历史可能暂未更新；保证限于进程正常运行并能在数据库恢复后继续保存。崩溃前未提交的归因及撤销没有恢复保证，不新增通用持久任务系统。家庭改绑清空上下文，满额拒绝新活动；不补写历史或承诺容量不足期间完整覆盖。当前没有活动纠正专项现有测试或隔离数据库竞态验收，类型、入口构建及感知服务恢复回归不能替代这些验证。既有实时面板消费来源级关联，区分人脸／宠物直接识别与人体外观推测；外观参照详情保留实际来源及确认依据观察时间，相似度不作为身份概率。活动页读取共享首次／当前归因、最近纠正前后依据、原因、处理时间及累计次数，媒体不可用时保留摘要。实时推测到期撤下，窗口原始人脸快照不回填；未知撤销按真实原因区分，包括终态不可得的保守失效。成员活动查询仍只按当前主体，撤销后的设备来源记录可在数据库浏览页查看，不恢复旧成员关系。新归因状态的浏览器展示及数据库纠正到页面的联动尚未完成运行验收。

### 人物参考登记

成员页的上传和摄像头登记通过同一感知计算池进入 `identity/runtime.ts`，复用模型启动、独占请求、超时退出、重试和空闲卸载；没有摄像头来源时，上传仍通过相同预算加载模型，人脸及宠物模型内存共同计入 768 MiB 身份资源预留，模型计算串行。`identity/model.ts` 协调串行请求，`face-model.ts` 和 `pet-model.ts` 分别拥有人脸与宠物模型。各适配器独立准备、释放及重试，可恢复的宠物文件或推理错误不丢弃已提取的人脸结果，反之亦然。准备请求使用 30 秒启动期限，不占用 1500 毫秒单帧推理期限；准备后仍核对原帧新鲜期，过期帧不推理或接纳。原生进程崩溃或硬超时仍会终止共用身份进程，不能提供进程级人宠故障隔离。有效匹配策略不作为登记前提。模型状态按人物／猫／狗分别读取适配器实际准备结果，未准备时为 `not_checked`；查询不会主动加载模型。可恢复错误在重试间隔后允许重新准备，不根据是否保存过文字资料推断。

上传沿用 32 MiB 文件、单边 8192 像素和总计 3840×2160 解码像素的限制。图片按 EXIF 方向归一化后，以 `contain/lanczos3` 保留整图比例、补黑边至 848×480，不裁掉画面中的其他人；单张照片必须只有一个人脸。摄像头登记从浏览器录制的 15 秒视频中每秒抽取一帧，使用相同补边处理，不依赖后台感知配置和人物轨迹；每帧最多提取 4 张人脸，由用户确认哪些属于当前成员。两种输入共用 YuNet、五点对齐、SFace、56 像素短边与清晰度门槛，不登记人体样本。输入适配和模型配置共同进入 `identityProcessingVersions`，登记保存的版本不由浏览器指定；特征版本不一致时不可匹配，必须提供与当前处理版本一致的参考；匹配使用固定参数。

候选由一次有界登记持有，录像上传上限 32 MiB、提取请求上限 90 秒，最多保留 12 张、合计 3 MiB 的人脸候选。从提取完成起 2 分钟内，用户可按剩余参考容量勾选多张并一次确认保存；页面明确区分录制、提取、挑选及完成。精确重复裁剪和已保存的同人物图片忽略，候选按清晰度保留。归属、文件与事务提交清理见 [Backend 人物识别参考存储](../apps/backend/README.md#人物识别参考存储)。

猫狗只通过上传照片登记，复用人物的候选挑选、保存、删除和启停流程；摄像头录制仅用于人物。猫狗登记先通过已有检测池定位对应物种，照片中有多只同类动物时拒绝，上传后提供可选择的裁剪。登记与在线采样都使用实测动物框，短边至少 56 个模型输入像素；与其他动物框重叠的样本不提取。裁剪缩放至 224×224，使用固定的 ImageNet 均值和标准差归一化，由 [Open Noodle pet-recognition-small](https://huggingface.co/open-noodle/pet-recognition-small/blob/9dd4c915be29a81b116b3e30eb996c59d0e7ede0/README.md) 提取 512 维特征。模型为 Apache-2.0，固定权重和许可摘要在模型清单维护。清晰度采用同一 OpenCV 运算，宠物门槛为 20；人脸仍使用 128 维 SFace 特征及原有质量门槛。照片在选择推理目标前使用完整检测结果检查同类动物数量及框重叠，不因计算容量截断校验范围。登记处理版本记录物种，修改物种会撤销旧支持及不再适用的暂存候选；保存事务核对当前物种的模型与处理版本，不把猫参考用于狗。未知物种不启用此入口。

### 身份验证范围与限制

已核对真实人物识别、成员观察的数据库写入及成员页读取；猫狗素材通过同一身份子进程完成 512 维特征提取，宠物登记与取消接口使用实际模型核对。清晰度不足、小目标、未检出对应物种时不产生登记候选。家庭具体宠物的连续匹配及活动记录仍需实机核对；公开素材的可运行性不提供家庭识别准确率、误认率或长期负载保证。

跨镜头连续身份、相似个体、遮挡、自然模糊和长期联合负载仍需分别核对。当前没有在线学习或自动积累参考样本。没有新增专项自动化测试，静态检查和已核对的入口不能代替未覆盖的生命周期组合。

### 采样与判断

模型输入固定为 848×480。来源原帧可以是高清画面；身份边界用 Sharp 的 `fill/lanczos3` 缩放，并按同一横纵比例转换人体框，848×480 原帧直接使用。尺寸和坐标转换只作用于身份输入，窗口指纹仍来自原帧。只有至少两次实测的人宠轨迹参与采样，预测框及存在遗漏人宠的帧不采样。YuNet 分数门槛 0.7、人脸短边至少 56 个模型输入像素，脸中心必须落入唯一人体框，每个人体保留最高分候选；五点对齐后用 OpenCV 拉普拉斯方差检查清晰度，低于 `minimumSharpness` 拒绝提取特征。默认门槛 50 是工程参数，不是跨摄像头质量保证；高清缩放后的家庭识别效果尚未实机验收。

每条轨迹默认每秒最多采样一次、每帧最多四个身份目标。同一来源时间戳和完全相同裁剪不重复增加证据。内部 `identityObservationSchema` 每轨迹保留最近五份、默认 30 秒内的标签支持；同一标签至少三份支持且首末跨度至少两个采样间隔才进入 `confirmed`（连续匹配）状态。这些观察不保证统计独立。有效证据与现有标签冲突时立即撤销确认并重新累积；未知观察不延长证据寿命，标签支持全部过期后回到未知。内部 `recent` 轨迹结束摘要最多保留 32 条、60 秒，供人宠匹配终态及活动核对，不作为实时公开历史；来源运行、媒体代次或尺寸改变清除旧判断。

确认规则不能消除跟踪串人：轨迹已串人、但尚无新可用脸时，仍可能短暂保留此前标签。家庭连续身份准确率、多人遮挡、跨摄像头关联和长期联合负载尚未验收。

### 计算与接口

首次出现合格采样需求才加载模型。默认连续 30 秒无需求且没有在途推理时卸载，确认退出后归还名额；有可用人体但没有脸时仍需要运行 YuNet。证据期限独立于模型装卸，人宠共用身份分析的一个现有计算名额；检测、人体 ReID、身份分析合计至少需三个名额。启用身份分析但启动预算不足时，感知初始化报告不可用；运行中等待已规划的身份计算名额不停止基础检测与跟踪。

同一时刻只接纳一帧，等待来源仅保留有期限的编号，不积压像素。模型加载限时 30 秒，单帧最多 1.5 秒并受原帧新鲜期限制；超时回收进程，五秒后按新输入重建。来源撤权和关闭立即取消加载与推理，等待退出后归还名额；不能确认退出时交给现有计算监督器恢复视频进程组，迟到结果不能写入新运行。

`GET /api/perception`、`/api/perception/stream` 和 `/api/perception/retry` 共用 `perceptionSnapshotSchema` 投影，提供来源级 `identity`、`identityValidity` 和 `associations`，状态变化每 500 ms 合并发布。公开 `identity` 只包含当前轨迹判断、来源状态、参考版本和有界统计，不包含 `recent` 或 `tracks[].evidence`；当前成员归因的完整支持依据统一位于 `source.associations`，不在身份摘要中重复传输。内部完整 `identityObservationSchema`、观测存储和 `service.snapshot()` 继续保留原始证据及结束摘要，供匹配、冲突撤销和人宠终态核对；窗口仍使用自己的原帧历史快照。

每份归因支持证据携带稳定证据键、来源运行、原始观察时间、帧内轨迹、媒体代次／时间及相应参考与模型版本。直接身份的 `referenceRevision` 是参考内容版本，`referenceVersions` 提供完整版本组。公开感知接口不输出特征向量或图片；轨迹观察随运行清理。成员参考图片由共同的家庭参考接口授权读取和保存。过期判断不能表示当前在场身份，无真实标签时统计不能计算准确率或误认率。

### 窗口中的历史身份

身份推理独立消费跟踪回调提供的原始 RGB24，沿用身份采样间隔和单帧在途限制。缩放期间保留这一份原帧引用，完成后以独立的 848×480 RGB24 字节缓冲区经 Bun IPC 提交模型，不转成 Base64 文本；缩放耗时计入原帧新鲜期，过期结果不接纳，不建立身份录像缓存。窗口保存的是最多 1 fps、独立缩放后的媒体副本，不能用它替换身份输入。静止场景是否通过窗口视觉筛选，不控制身份采样或延长身份证据期限。

有效跟踪结果交付时，`identity/runtime.ts` 同步冻结当时已知的判断，`video/runtime.ts` 通过独立的 `identity_frame` 事件交付，不经过实时身份广播的 500 ms 合并。`evaluatedAt` 是冻结判断的宿主处理时间，不是拍摄时钟；冻结前按当前单调时间清除过期证据。若本帧人脸推理刚提交，`inference: pending` 表示“当时尚未完成”，读取历史时不把它显示为仍在加载。该推理稍后返回的证据只影响后续帧的快照，不回填此前帧。

窗口只在关闭前接纳同一 `videoRun`、媒体代次、序号、PTS、接收时间和尺寸的快照。快照先于窗口帧到达时，每来源最多暂存 16 条、4.5 秒的元数据，视频运行更换或停止时清理；超过窗口结束后的 500 ms 宽限或已经关闭的窗口不再接纳。窗口帧可能未进入检测／跟踪，不能用最新身份补齐它：`identity: null` 表示没有收到准确对应帧的身份快照，`status: disabled` 对象表示当时未启用身份分析，`unknown` 则是身份分析给出的未知判断。身份结果缺失不使视频筛选失败，也不改变整个窗口的完整性。

历史快照保留当时的参考版本、标签、支持数及证据／确认／到期时间，不携带完整身份证据数组或累计统计。轨迹的 `expiresAt` 描述当时证据的有效期限，播放历史时不会据此清空旧判断，也不能把历史 `confirmed` 当作当前在场身份。历史身份元数据随窗口摘要保留，媒体生成、磁盘字节预算、读取和访问资格检查复用 `media/window-media.ts`，身份模块不另存媒体副本。原始窗口输入默认保留 12 秒、活动轨迹的身份证据默认保留 30 秒、已编码回看片段最多保留 30 分钟，三项期限分别约束不同资源，互不续期；具体容量与撤权规则见[容量、停止与访问期限](#容量停止与访问期限)。

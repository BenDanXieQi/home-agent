# 家庭感知与 Agent 实施计划

**状态：分步实施。** 已有米家账号、指定属性读取、MQTT 接入、家庭运行时、设备清单和规格管理、页面状态订阅，以及限时设备日志采集。持续采集、当前属性和房间事实快照已实现；房间 AI 总结首阶段已实现，可信来源的自动触发仍需实机验收。行为与验证边界见[设备事实](../reference/device-facts.md)和[房间 AI 上下文](../reference/room-analysis.md)。活动记录、人物画像与场景控制尚未交付。设备接入以[米家接入](../mijia.md)、[家庭运行时](../household.md)和[来源契约](../reference/mijia-source-contract.md)为准。

## 目标与范围

持续接收家庭信息，用确定性代码维护事实和明确规则；有相关事件或用户提问时才调用 AI。房间安静时不定时生成总结。提前维护自动开灯等动作的控制条件，触发发生时通过代码快速判断。

一个部署同时服务一个家庭。设置页可切换同账号家庭，保留登录凭据并清空业务数据库内容；切换需要 Agent 在线且没有运行中的任务。正常采集不依赖页面或 Agent 在线。设备属性直接复用 MIoT 规格。卧室和卫生间不部署摄像头；手机和其他新来源按场景需要验证，不作为全部功能的前置条件。人物、宠物、活动和行为要求的含义见[家庭模型](household-model.md)。

验证期先展示判断与拟执行结果，设备历史使用本地文件，不新增设备历史数据库。已有账号存储和 Agent checkpoint（运行检查点）继续沿用。真实动作只在执行权限、控制通路和结果核对能力接通后启用。

按下面的最小闭环逐步交付，页面随能力接入：

1. **设备事实可见。** 真实 MQTT 上报持续更新当前值和房间事实快照，显示缺失与过期；不等待历史或 AI。
2. **场景判断可见。** 登记必要人物与设备关系，用一个真实场景验证事件触发、规则或 AI 判断、结果接纳、失效和页面解释。
3. **经历可查询。** 接入本地短期记录及最近活动，回答“上一次记录到遛狗是什么时候”；只有实际具备证据的活动才生成记录。
4. **动作条件提前就绪。** 在进入事件前维护允许／禁止／未知条件，先核对拟执行结果，再按实际通路接入自动化。画像习惯随有效经历积累，不阻塞前面的步骤。

步骤编号表示职责，不要求完成全部设备、全部历史界面或通用规则编辑器后才能验证一个场景。具体场景要列出来源、问题、输出和验收行为；没有证据的功能明确未覆盖。

## 共同契约

- backend 是设备事实、当前判断和生效要求的确认方；Web 与 Agent 读取已提交状态。每类状态只由一个负责模块修改，房间视图不重复维护设备值。
- 使用稳定账号、家庭、设备和实体 ID；名称、供应商账号、临时跟踪编号都不能替代人物身份。
- `scope_epoch` 标识一轮家庭运行，`collection_generation` 标识一轮来源连接，拒绝旧任务回写。协议重连和凭据仍由现有米家模块负责。
- `input_sequence` 表示运行内观测接纳与处理顺序，`state_version={scope_epoch,sequence}` 表示公共状态版本，场景事件另有身份与顺序；不把它们当物理发生时间。
- 观测事实、当前有效性和推断可信程度分别表达。未知不能补成零、false 或模型猜测；缓存、重放和恢复值不能补造设备事件。
- 网络、文件和模型工作在状态提交之外执行；同次变化先原子提交，再通知和执行后续操作。异步结果核对实际依赖，不因无关房间更新一概丢弃。
- 停止、退出及访问撤销及时取消相关工作；采集临时故障使相关当前条件失效，但不抹掉已接纳证据或一概取消纯历史分析。
- 队列、记录、查询和模型上下文都有预算；丢失和裁减必须可见。慢文件写入、页面或 Agent 不阻塞实时采集。
- 状态 SSE 重连恢复当前状态，不补齐历史事件。历史与场景队列不承诺断电零丢失或跨重启可靠重放。
- 采集和触发策略使用校验后的本机配置，修改后重启相关运行。保存生效参数与版本以解释判断；不预建在线配置平台。

复用现有 XState 生命周期、共享不可变提交、Zod 边界校验、SSE 和 Agent 任务设施。属性计算和明确条件使用普通领域函数，不为每个属性建立状态机。具体模块、保存策略与验收以所属步骤为准，共同契约不在每篇重复展开。

## 家庭运行时剩余实机验收

[现有验证范围](../household.md#验证范围)仍有以下未覆盖项；它们不等同于所有场景都必须等待的门槛，但不能宣称已经验证：

- [ ] 实际设备新增、移除、跨家庭转出，以及访问撤销叠加设备清单保存失败。
- [ ] 自然凭据到期续期、供应商真实认证拒绝与限流。
- [ ] 另一米家账号扫码登录的完整流程。

## 每步共同检查

- [ ] 用实际启用的来源核对正常路径、断连、过期和撤销；注明未验证范围，不用源码审查冒充实机结果。
- [ ] 结果在页面或当前问答中可见；checkpoint 保存成功不等于已通知用户或已控制设备。
- [ ] 检查真实取消、旧任务隔离、顺序、已知缺口和资源上限；实现新契约时同步实际消费者。
- [ ] 修改代码执行适用的类型、lint 和构建检查；纯文档检查格式与引用。未经用户明确许可，不新增测试代码或故障注入脚本。
- [ ] 文档区分当前实现与计划，不保存会话流水；验证记录放在 Git 忽略的 `data/verification/household-step-<n>/<run_id>/report.json`，联合接入记录沿用 `household-access/<run_id>/report.json`。

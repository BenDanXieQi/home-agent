# 家庭感知与 Agent：按实际场景实施

**状态：实施计划。** 当前已有米家统一账号、指定属性读取、MQTT 接入、家庭运行时、设备清单持久化和页面状态订阅。持续集采、历史记录及自动触发 Agent 尚待接入；当前行为以[米家接入](../mijia.md)、[家庭运行时](../household.md)和[来源契约](../reference/mijia-source-contract.md)为准。本计划不表示固定家庭维护流程或后续能力已经实现。

## 产品边界

一个本地部署固定服务一个家庭。首次设置保存唯一绑定，正常运行不切换。选错家庭时停止服务、修改持久绑定后重启，不建立在线维护改绑流程。

后台在无人打开页面、Agent 未启动时仍维护设备状态。房间、设备类别和搜索仅是页面筛选。账号退出、设备访问撤销、连接恢复以及后台重启仍须正确清理资源和拒绝迟到结果；单家庭并不取消这些要求。

目标是让系统根据真实证据理解家庭情况，并支持后续受控行为。[家庭语义模型](household-model.md)保留成员与宠物、空间与覆盖、观察、判断、事件、有效要求及 Agent 长期记忆的职责边界。卧室和卫生间不部署摄像头；手机事件只能在来源验证后作为辅助证据，手机接入不是所有场景的前置条件。

## 按场景组织交付

Step 编号表示工作领域，不是必须全部完成后才能使用 Agent 的流水线。实施一个场景前列出实际设备、要回答的问题、所需来源、结果用途和验收行为，只交付它依赖的能力。

| 文档                                                 | 负责的能力                                 | 实际依赖                                         |
| ---------------------------------------------------- | ------------------------------------------ | ------------------------------------------------ |
| [接入基础](../mijia.md)                              | 已有账号、设备、读取、推送与媒体接入       | 对所选设备和通路核验来源契约                     |
| [02 运行时](household-steps/02-household-runtime.md) | 固定家庭绑定、设备清单、启停及已提交状态   | 账号和唯一绑定家庭可用；剩余实机边界见 02        |
| [03 采集](household-steps/03-collection.md)          | 所需属性的当前值、质量、变化和采集健康     | 运行时与对应真实来源；不等待观察满一天           |
| [04 历史](household-steps/04-history.md)             | 选定记录、缺口及有界查询                   | 仅依赖已接通的对应采集；需要历史的场景才要求接入 |
| [05 页面](household-steps/05-live-web.md)            | 当前状态、读取结果、按需历史展示           | 已有订阅；各界面随对应能力交付                   |
| [06 Agent](household-steps/06-agent.md)              | 具体场景触发、查询工具、一次分析及执行记录 | 场景需要的 03 能力；只在用到历史时依赖 04        |

第一条链路应使用已验证的实际设备，跑通“观测→可信当前状态或变化→一次场景分析→可追溯记录”。无需等待通用统计、完整历史页面、在线规则编辑或全部家庭语义完成。明确要保存的属性和事件可以立即记录；持续观察用于调整保存范围与资源预算。

家庭语义按同一方式逐场景接入。无摄像头卧室的休息判断可以使用已验证的灯光、存在或其他来源，并保留不确定性；需要手机证据时再完成手机接入。涉及真实动作的场景必须先明确有效要求、权限、结果确认和执行前检查，单独验收后才启用。

本阶段的自动分析结果保存为原任务的 checkpoint，完成可追溯的工程链路，尚不代表用户已获得日常可见的提醒或解释。用户主动提问继续通过已有聊天入口返回，该入口不会自动展示后台分析。具体场景需要用户看到结果时，接入最小的已有输出渠道并验收可见性，不因 checkpoint 中有结果就宣告用户功能已交付。主动通知、持续建议面板、物理设备写操作、长期记忆和跨重启可靠事件消费，须有具体场景与独立交付要求，不隐含在“Agent 接入”中。

## 共同契约

- backend 是设备事实、当前质量和来源资格的唯一确认方；Web 与 Agent 读取已提交数据，不自行采集小米或修改设备事实。
- 账号、家庭、设备保留稳定来源身份。名称不当作身份，数据预算按原始响应、发现资料及绑定家庭各自范围定义，不能把其他家庭的业务数据预算套到当前家庭。
- `scope_epoch` 标识本轮运行，启动、退出或明确访问失效使旧运行资格失效；停机修改绑定后重启使用新标识。它用于拒绝旧任务，不代表多家庭运行能力。
- `source_id/collection_generation` 标识来源与当前采集实例，防止同一运行中旧连接回写；协议重连由现有米家模块负责。
- `input_sequence` 是进程内提交顺序；`state_version={scope_epoch,sequence}` 标识公共状态；`event_sequence` 是场景事件流顺序。三者用途分开，不建立逐输入持久回执账本。
- 观测的 `quality` 随证据保存；`latest.observation_quality` 保留它，`latest.quality` 表示当前适用性。来源观测时间、接收 UTC 与处理顺序分别表达；超时和持续计时使用单调时钟。
- 读取不能无依据覆盖较新推送；快照、未知时间缓存和断线补读不能补造物理事件。未知不替换成零、false 或模型猜测。
- 停止、退出和明确访问撤销立即失效相应任务；临时采集故障只影响对应来源的当前条件、连续计时和旧采集任务，已接纳且证据充分的纯证据分析可继续。业务到期检查等待此前观测处理边界。每次公共状态更新原子生效，之后才发布通知和执行外部操作。
- SSE 重连恢复当前状态，不补偿历史事件。当前阶段复用已有状态订阅与共享增量应用，Agent 只提取任务需要的数据；全量副本是复用选择，不是所有任务的启动条件。
- 历史保存已接纳的选定记录，标明来源与已知缺口，不承诺任意过去时刻的完整状态重建。历史故障不停止正常采集。
- 资源有界、慢客户端隔离、真实取消和安全错误信息保留。默认大小、数量和退避是初始工程参数，按实际家庭测量调整；性能优化由实际瓶颈驱动。

采集策略和场景配置保存在本机文件，启动时校验并加载。修改后停止并重新启动相关运行，配置版本用于区分该次配置，场景事件及任务 checkpoint 同时保存模板标识、实现版本与必要生效参数以还原触发含义；不建设在线配置版本管理平台。选择保存与账号生命周期继续遵守其实际存储契约，不把普通诊断、历史或配置版本记录失败扩大为全部能力失效。

## 实现机制与职责

| 机制或模块                        | 职责                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------- |
| XState 家庭运行时                 | 生命周期、来源资格和一次同步状态提交；不执行耗时网络、数据库或模型调用           |
| 采集 actor 与米家适配器           | 观察和读取资源、启停与采集恢复；协议连接与凭据仍由现有账号模块维护               |
| Mutative／共享 immutable 封装     | 构造不可变公共状态与应用增量，保留未变化条目引用；不承诺 O(1) 更新或数据库原子性 |
| 普通领域函数                      | 属性仲裁、质量与实际场景的确定性条件；不为每个属性创建状态机                     |
| 应用级历史写入器、Drizzle／数据库 | 有界批量写入、事务与幂等；正常退出尽量写完，停机纠错前关闭旧写入                 |
| Jotai、TanStack Query、SSE 解析器 | 页面派生状态、按需查询与传输解析，不维护第二份家庭当前状态                       |
| LangGraph／现有 checkpointer      | 单次推理与工具流程、原任务的分析记录；不承担实时设备状态或可靠事件队列           |

actor 停止仍须解除订阅、传递取消信号并确认底层退出；异步结果回到所属模块并检查运行资格。共享不可变更新、Zod 边界校验和现有数据库能力优先复用。新增库只在能够减少实际重复代码且不改变业务语义时采用，不为此预建调度或统计框架。

## 接入与验证边界

复用当前米家扫码登录、后台 OAuth、凭据保存与续期流程；不新增独立登录或第二套凭据生命周期。授权拒绝、普通连接故障、topic 拒绝、读取或媒体失败的影响范围以[来源契约](../reference/mijia-source-contract.md#失败范围)为准。

当前 MQTT 接入在 MiLoCo 参考应用参数下验证，自有应用准入及设备覆盖仍有未验证范围。具体型号或能力的结论只有已验证可用、已验证不支持、未验证；局部未验证不阻塞其他已验证场景，也不能靠隐式增加轮询绕过来源限制。独立设备事件在没有真实通路前不启用。

当前实现见[家庭运行时](../household.md)。固定绑定与停机纠错的验收范围见 02；采集、历史与 Agent 目标须在各自实现后验收，正常运行不提供在线换家。

## 设备接入联合验收

- [ ] 按来源契约核对真实认证拒绝、续期、限流及连接恢复，不把实现审查说成实机结果。
- [ ] 检查退出、设备撤销、停止与重启后的读取、观察和媒体清理；纠错使用停机修改绑定后重启。
- [ ] 同一场景联合验证实际数据到达、状态可用性、需要的查询和 Agent 分析；局部接入成功不替代场景完成。

## 每步共同检查

- [ ] 场景目标、所需来源、输出与真实限制明确；不以未来可能需要的功能扩大本次完成门槛。
- [ ] 实机行为使用真实设备与现有页面、HTTP、数据库或进程工具核对；内部确定性分支可以用具体输入顺序和源码审查说明，不冒充运行复现。
- [ ] 完成所改功能的类型检查、lint 和构建；纯文档改动只检查文档。未经用户明确许可，不新增测试代码或故障注入脚本。
- [ ] 检查旧运行隔离、实际取消、已知缺口、状态提交与通知顺序，以及慢来源、数据库和客户端的故障隔离。
- [ ] 未实现或未验证能力如实标注；资料说明当前事实，计划只说明目标，不留执行流水账。
- [ ] 修改契约时同步步骤、消费者与引用，不添加旧 DTO、别名或双写兼容路径。

场景验证材料沿用 `data/verification/household-step-<n>/<run_id>/report.json`，记录适用范围、证据类型和结果；联合接入材料使用 `data/verification/household-access/<run_id>/report.json`，不提交一次性运行记录。每项分别标记通过、未通过、未验证或不适用；不适用须说明当前场景没有启用什么，不能掩盖已启用能力的错误。

# Backend 向 Agent 交付当前数据与可查询历史

**状态：待实施。** 交付 Backend 整理后的持续推送和按时间补查历史的能力，以及 Agent 接收与只读访问适配。完成条件是当前数据持续送达，相关历史可按时间与对象取回。Agent 如何关联材料、推理和回写另行确定。

## 本次范围

持续推送已有设备资料与当前报告、成员登记资料、音视频感知产出；另提供按时间与对象读取设备报告、成员出现及整体音视频窗口的历史入口。成员出现读取数据库记录，音视频读取当前仍在内存中保留的窗口；设备属性历史需接入本地记录保存与查询。本次不实施模型自动调查或语义回写。

## 数据来源清单与初始交付范围

| 数据 | 内部读取入口 | 必须保留 |
| --- | --- | --- |
| 家庭、房间、设备与规格 | `household/runtime.ts`、`specifications.ts` | 对象 ID、归属、属性含义、单位及枚举 |
| 设备属性观察 | 家庭投影 `latest`、采集与来源状态 | 最近报告、实际时间、覆盖、缺值及来源限制 |
| 成员登记 | `household/members/repository.ts` | 人物／宠物登记资料 |
| 音视频感知 | `perception.snapshot()`、`windows(selection)`、`window(id)` | 视觉、跟踪、身份、声音、转写、来源／音轨关联及媒体引用 |
| 感知形成的出现记录 | `household/identity/activity-repository.ts`，本次补充内部有界读取 | `member_sighting` 当前归因、依据、对象与来源引用 |

表中源码路径相对于 `apps/backend/src/`。未启用、不可用、读取失败和成功空结果分别表达。

音视频按既有整体产出接入，保留来源、音轨、窗口和身份关联。出现记录是同源历史视图，按已有引用与实时观察对应，不计为另一次观察。当前状态与历史分别表达，不用当前身份回填历史帧。

仅交付来源实际提供的字段及依据，不推断位置或生活事件。保留范围沿用来源；媒体只交付引用与可用状态。凭据、参考照片、特征向量和媒体字节不进入推送。

### 数据库读取与通知

- 成员登记复用现有仓库读取。出现记录在身份存储边界补充有界读取，复用家庭绑定校验，只读取 `member_sighting` 及关联；明确排序、数量和省略范围。
- 成员资料与出现记录在事务成功返回后发出变化通知。回滚不发成功通知；通知失败不改变已提交结果。
- 已提交写入不能因随后参考文件清理失败而漏发通知。出现记录的内部读取同时供快照和历史接口复用。

### 音视频接入边界

- `perception.snapshot()` 读取来源观察及音轨，通过已有 `audioTrackRunId` 保留关联，共享音轨不重复计数。
- `perception.windows(selection)` 只提供窗口索引。按 ID 调用 `perception.window(id)` 取得 `frames`、`audio`、`speech`、身份信息及媒体状态；列表计数不能替代正文。
- 晚到声音或转写更新原窗口，保留 ID、观察时间和已有视觉内容。读取期间过期或撤销如实表达缺失。
- `window/store.ts` 现有 `subscribe` 用于候选媒体捕获。本次补充窗口内容变化通知，经感知服务统一暴露，覆盖接纳、晚到补充、移除和失效；不改变捕获订阅或额外触发编码。
- `media/window-media.ts` 的产物状态可独立于窗口版本变化。生成完成、失败、过期和撤销也须触发刷新，可复用现有维护周期，不能只按窗口版本去重。

## 历史数据现状与缺口

现有 `context_records` 保存成员出现记录 `member_sighting`，`context_entities` 保存记录关联的对象与来源。目前没有设备属性报告或整体音视频窗口写入该表的生产者。

本次需把采集通路接纳的设备报告保存到 Backend 本地数据库，供 Agent 按时间读取。属性历史的存储设计由[设备历史计划](device-history.md)维护，尚待实施。

| 需要的材料 | 已核实的实现 | 本次需要补齐 |
| --- | --- | --- |
| 空调开关、模式、设定温度、温度传感器报告 | `HouseholdRuntime` 的 `latest` 是当前值；`subscribeFacts` 给出当次观测与前后状态，但不保存历史序列 | 接入本地属性记录保存、缺口及有界读取 |
| 某成员在相关时段是否出现 | member_sighting 已入库，含 firstObservedAt、lastObservedAt、endedAt、来源摄像头和当前归因。现有数据库浏览有实体与游标筛选，没有观察区间查询 | 在原身份仓库补按区间重叠、成员、摄像头筛选的读取；不把来源摄像头当当前位置 |
| 同期音视频及转写 | 窗口详情在内存里整体保留 `frames/audio/speech`，最长约 30 分钟，可因容量或访问资格提前移除，重启不恢复；媒体另有保留期限，见[感知文档](../perception.md) | 感知服务增加时间筛选，读取仍保留的完整相关窗口及媒体状态 |

转写历史随整体音视频窗口读取 `speech.segments`。成员记录按归因原地更新，历史查询返回当前修订。

没有保存过的设备报告不能通过新接口补回。历史开始保存之前、存储故障或尚无实际采集的设备报告明确说明缺失；音视频超期或进程重启后明确缺失。当前剩余最早一条记录不能证明它之前从未采集，也不能证明查询区间完整。

## 按时间补查历史

新增 `POST /api/agent/context/history`，通过 Backend 内部读取能力查询本地数据库记录及仍保留的感知窗口。实时通路使用 SSE（服务端持续向客户端推送数据）交付当前数据，历史查询独立读取已保留材料。

| 输入 | 用途 |
| --- | --- |
| kind | device_reports、member_sightings 或 perception_windows；音视频按整体窗口返回 |
| account_id、home_id | 预期的当前绑定账号与家庭；Backend 在查询及响应前核验，响应携带归属供 Agent 校验 |
| start、end | 必填 UTC 半开区间 `[start,end)`，匹配规则见下文 |
| 对象条件 | 设备报告用设备 ID 与属性标识；出现记录用可选成员或来源摄像头；音视频用可选摄像头来源，未限定则查当前家庭可访问来源 |
| limit、cursor | 有界分页；游标绑定查询条件，不能用一页结果声称完整历史 |

响应包含请求范围、记录、下一页入口和各来源实际覆盖说明。区分历史尚未开始、来源不可用、尚在写入、已知缺口、超期／淘汰与成功但无匹配项；无法确定覆盖时返回未知。每条记录带原时间、时间依据、对象与来源引用。游标绑定家庭身份及查询条件，每页重新核验访问资格；家庭切换后拒绝旧请求。

- **设备报告**按设备历史计划的 `received_at`（接收时间）查询与分页，同时返回原 `observed_at`（来源观测时间）。底层保留可回查的报告，默认以连续同值报告段返回，并支持原始点读取；分段、压缩与分页规则由设备历史计划维护。缓存／迟到候选与实际更新分开。
- **成员出现**按 firstObservedAt 至 lastObservedAt 与请求区间重叠筛选，不只过滤首次观察时间。该跨度不证明持续在场，endedAt 不证明离开房间。返回当前归因与原依据。
- **音视频**按原观察区间匹配。声音和转写可能跨过视觉窗口边界，还须检查其中实际声音／转写区间；返回整体窗口和匹配内容引用。共享音轨及跨窗口引用按原结果 ID 识别，不制造重复事件。

各来源原时间基准必须保留，统一格式不证明设备时钟精确同步。当前房间归属可以用于寻找候选传感器或摄像头，但不得追写为历史位置；没有当时映射时明确限制。分页过程中记录可能被纠正或过期，返回真实情况。

### 设备历史依赖

属性历史存储、保留期、写入故障和查询预算唯一维护在[设备历史计划](device-history.md)，本文件不另建一套设备历史。完成该计划的四个实施步骤，由专用历史入口调用内部读取方法，不等待历史页面或独立设备事件支持。

设备写入接 `HouseholdRuntime.subscribeFacts` 的原接纳结果，不从合并后的推送快照反推历史，也不只保存可信变化边沿。当前家庭实际接纳的全部属性报告按该计划保留，包括同值报告和读取候选；采集及写入丢失明确记录。查询只返回已保存的记录，在途提交显示未确认状态。数据库不可用期间停止历史提交、不暂存或补写，恢复后仅保存新报告，缺失期间通过缺口说明。

空调场景要求调查时段内历史保存已运行，实际采集到空调开关／设定温度及相关环境温度属性。属性 ID 从真实规格选取；不存在对应温度传感器时如实说明，不把空调设定温度替代室温。

## 专用推送与接收

### Backend

新增 `apps/backend/src/agent-context/`。在 `main.ts` 创建一个常驻整理服务，注入家庭运行时、成员与身份仓库、感知服务；在 `app.ts` 挂载 `GET /api/agent/context/stream`，复用本机访问校验。

整理服务直接调用内部读取能力，监听家庭运行时、数据库提交及感知变化；不回读现有 HTTP 接口，不订阅或复制 `/api/mijia/events`。复用来源能力与适用 util，保留现有前端接口。

- 启动先登记监听，再读取初始数据；通知标记对应部分待刷新，异步读取完成后发布。
- 每个来源最多一个在途读取，期间通知合并，完成后继续处理待刷新。回调不等待查询或发送。
- 来源失败发布失败状态并有界退避重试，其他来源继续工作；各部分保留实际读取时间。
- 多条 SSE 连接共享整理结果和来源监听；连接关闭仅释放本连接资源。Backend 退出时释放监听、停止重试并隔离迟到读取。
- `household/stream.ts`、`http/snapshot-stream.ts` 可参考或复用。后者要求同步快照，数据库异步读取须先在整理服务完成。

### 共享契约

新增 `packages/api/src/contracts/agent-context.ts`，从已有 schema 派生。首版使用同一连接内的部分快照替换，初始数据与更新共用结构；替换包含记录移除。

快照刷新可合并多次通知，因此推送不保证包含每一条设备报告。逐条报告由独立历史写入通路保存，Agent 按时间查询；历史写入不依赖推送连接或 Agent 在线。

契约明确各数据部分及状态：等待读取、成功、未启用／不可用、失败。连接状态与数据接收状态分开。待发内容、缓存和单次传输有界；超限报错或说明省略范围，慢连接断开后重建快照。

家庭切换、解绑或撤权时，先清除对应缓存并通知接收端，隔离旧在途结果，再读取仍有资格访问的数据。连接顺序与旧回调隔离由传输适配处理。

### Agent

新增专用接收模块，在 `apps/agent/src/main.ts` 装配，Backend 地址由 `config.ts` 提供。启动订阅，退出释放；不依赖模型配置或聊天请求，不修改 `assistant.ts` 模型行为。

维护最新内存数据及连接状态。断线标未同步；重连重新取得当前快照，未重新收到的部分不得显示为已同步。重启重新读取，不保存 SSE 消费进度或重放全部断线变化；历史访问独立查询实际保留的数据。

提供本机只读 `GET /api/received-context`，返回收到的各部分、最近接收时间和状态，复用 Agent 本机访问限制。此入口用于验收，无新增页面或持久日志。另增加只读历史客户端／工具适配，调用 history 接口返回来源材料，供后续模型访问；本次用确定参数直接验证该适配，不设计自动查询或关联推理策略。

## 实施顺序

1. 核对来源字段，派生推送与历史读取共享契约，补齐成员记录读取、数据库提交和窗口／媒体变化通知。
2. 装配 Backend 整理服务与专用 SSE，完成初始读取、持续刷新、失败恢复和退出清理。
3. 接入设备属性历史的最小保存与查询能力；在身份仓库、感知服务补时间范围读取，装配专用 history 接口。
4. 装配 Agent 接收模块、诊断入口和只读历史访问适配。查询失败或没有历史时返回明确限制，不用最新值兜底。
5. 验收实时送达和下述跨来源历史读取后更新 README。仅完成 SSE 不代表本次数据能力全部完成。

## 验收与交付

用真实来源逐项比对 Backend 发布值与 Agent 接收值；缺少实机来源的部分标明未验证。

- 设备报告、成员资料、音视频及已保存出现记录无需聊天或页面刷新即可更新；成员记录核对数据库当前归因，窗口核对实际观察和转写正文。
- 数据库提交后到达，回滚不发成功通知；已提交写入不因后续文件清理失败漏发。
- 晚到声音／转写更新同一窗口并保留视觉内容；媒体独立状态变化可达，不额外编码。
- 初始接收状态、来源失败与恢复、删除／过期、家庭切换／解绑／撤权、Backend 重启及 Agent 重连正确；多连接共享来源监听。
- Agent 无模型配置也能接收，不调用模型或写回；停止 Agent 不影响采集，现有 Web 功能正常。诊断不泄露凭据，不把家庭数据写入共享文档或无界日志。

以一次真实空调开启／设定温度变化的报告为锚点，在已启用设备历史、音视频仍保留时查询前后几分钟：取回空调报告序列、环境温度、相关成员出现和整体音视频窗口中的转写。核对同一区间的原时间与来源，包括可能出现的“小爱同学”请求。再核对历史尚未开始、存储不可用、跨区间成员记录、超期窗口和分页的返回行为。

验收是材料可查，不是证明因果：当前属性报告没有证明操作发起者；人出现、语音请求与设备变化时间接近，不等于 Backend 能确认由谁通过小爱执行。未查到转写也不证明无人说过。

按仓库规则运行受影响的类型检查、定向 lint、必要构建及最小相关现有测试；未经许可不新增测试。

# 家庭情景与自动化：第一方 Agent 协作计划

本文只维护尚未交付的家庭情景、Agent 持续工作与问询、来源扩展及专项验收。当前规则树、自然语言草稿、动作执行、Agent 动作选择和有界周期复核见[自动化当前能力](../automations.md)；实际设备输出、真实模型效果和完整语义生命周期仍未验收。计划中的接口、字段和模块不表示可调用能力。

领域定义以[家庭模型](household-model.md)为准，媒体证据以[摄像头计划](media-perception.md)为准，设备事实沿用[来源契约](../contracts/device-facts.md)。backend 拥有已接纳的家庭状态、自动化和动作结果，Agent 拥有语义理解及后续持续工作的调查、问询和等待，不另建 backend 语义 LLM 流程。

## 家庭资料、记忆与查询约束

后台保存确认后的身份、设备关联和明确偏好；Agent 记忆维护有依据的推测习惯。一次操作先记为经历，多次独立经历才可提出条件化偏好；操作者不明时不归入某人画像。新增经历、纠正或明确指令触发更新，不定时重写全部记忆。

活动由本文的情景事件所有者维护候选、进行中、结束及修正，不归设备原始历史写入器。证据撤回影响相关判断及“上一次”索引；明细清理后保留必要证据摘要和追溯限制。当前位置、上一次遛狗和未开灯原因分别查询情景、活动索引和执行记录，按对象、时间及大小取证；答案区分事实、推测与未知，不扫描全量日志或因记录缺失断言从未发生。

切换家庭遵守[清理流程](../household-runtime.md#切换家庭与清理数据)。新增画像、长期记忆、情景、活动索引、任务与执行记录都必须纳入清理，不能跨家庭复用。

米家自身独立运行的自动化不受本项目拦截。需要遵守本项目动作条件时，必须验证对方支持条件接入，或使用本项目经过核验的执行路径。喂食等动作仍需检查近期投喂量、储粮／食碗状态、上限与权限；建议、请求发出、设备响应和效果核对分别记录，结果未知先核对，历史纠正不重执行动作。

## 1. 交付决定与首个场景

采用现有 backend 与 Agent 两个本机进程，HTTP/SSE 通信。backend 持续运行本地感知和家庭状态；第一方 Agent 拥有目标理解、上下文选择、模型与工具编排。Agent 可以主动提出或调整受控观察请求，backend 按已实现的模板持续执行。模型、提示词、工具、观察策略和效果评估由同一项目共同演进。

Home Agent 的目标是持续负责家庭事务的 personal agent（具有持续职责、记忆和主动工作能力的个人助手）。家庭变化、用户消息、回答、调查结果及到期条件可以唤醒它；Agent 发现需要处理的问题，按问题启动独立调查，主动问询、等待并调整下一步，直到完成或撤销承诺。持续运行不要求模型一直推理，也不要求只有一条无限增长的聊天记录；家庭情景不完整时仍可按授权查证。

主线是“有来源的家庭变化与已有情景 → Agent 持续关注、调查和问询／backend 已启用自动化 → 统一执行与结果反馈”。首期成员位置是按身份汇总最后出现房间及时间，独立于具体提醒；不要求跨镜头保持连续轨迹或还原跨房间经过。本地跟踪用于选帧和减少重复核验，合格的新证据需要语义理解时才调用 Agent。业务到期或触发时读取已有情景并核对所需时效，最后出现记录不能直接证明当前位置；不临时启动识别并等待其完成。临时观察补充范围或证据，不是所有家庭任务的父对象。

基础维护须在实际授权范围内启用；位置未知、覆盖缺失或证据过期时如实降级。卧室和卫生间不增加摄像头；跨房间维护不等于所有房间都可定位。尚未实现的来源与推断不能列为可用能力。

完成后应具备：

1. 用户经已有聊天 API 提出目标，Agent 查询能力和家庭上下文，启用基础维护或提交有限期观察请求，并向用户说明接纳结果及不可观察区域。
2. backend 持续检测、跟踪，按已接纳身份保存出现记录并汇总最近房间；身份核验沿用本地轨迹采样，不逐帧调用模型。
3. 未知或冲突目标出现有用新证据时，backend 产生核验候选；本地识别执行器与 Agent harness 分别按任务、证据和各自预算准入，可独立启用或并行运行。
4. 本地身份模型读取合格图片及版本化参考资料，Agent 读取对应媒体、成员参考及任务上下文；各自提交身份候选，场景理解由 Agent 提交；backend 接纳后更新家庭状态。
5. 用户再次提问时，Agent 通过工具读取当前／最后已知状态，给出带时间与限制的回答；不会为了回答已有状态而默认再拍一段视频。
6. Agent 暂停后，本地感知、关联有效性和到期处理继续；已启用的本地身份识别继续，新 LLM 核验暂停。恢复时只处理仍有效且有新价值的候选。

最终场景分批交付：场景观察闭环与成员身份／位置按各自依赖接入，本地身份路径不等待场景 LLM 闭环。首批同时验证基于已有情景的确定性策略处理结果，但不发送命令；情景更新异步进行，即时处理不等待 LLM。本观察批次不扩展设备输出渠道、未知人物永久建档、自动样本晋升或长期习惯学习；现有自动化能力见当前功能文档。它们不成为持续本地感知的前置条件。

## 2. 模块与状态所有权

| 位置                                            | 拥有的状态及职责                                                       | 不承担的职责                                 |
| ----------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------- |
| backend `perception/tracking/`                  | 每来源运行的局部轨迹、实测框／预测框、近期外观特征                     | 家庭成员真值、LLM 调用                       |
| backend `perception/window/`、`gate/`、`media/` | 有界媒体、窗口、变化与质量指标、证据描述                               | 用户目标解释、供应商模型协议                 |
| backend `perception/identity/`                  | 本地身份模型适配、选帧质量检查、特征计算及有界执行                     | 正式成员身份、LLM 调用                       |
| backend `household/identity/`                   | 成员参考资料、观察目标与成员关联、冲突与纠正                           | 复制 tracker、独立语义提示词                 |
| backend `household/presence/`                   | 出现记录、最后被看见及最后已定位的汇总                                 | 以摄像头安装房间直接代替目标位置             |
| backend `household/observation-requests/`       | 已接纳的持续观察请求、模板条件、候选当前视图和变化通知                 | Agent 执行队列、推理记录                     |
| backend `household/assessments/`、`events/`     | 已接纳情景的有效性、领域事件和修正依赖                                 | 模型推理与任务 checkpoint                    |
| backend `household/automations/`、`actions/`    | 已启用自动化与 AI 条件定义、确定性条件、持久期限、动作意图和结果       | Agent 调查计划、待回答问题、运行模型生成代码 |
| Agent `runtime/`                                | 持续工作、输入接纳与唤醒、调查执行、等待与问询、并发、取消、预算和恢复 | 权威家庭状态、设备动作账本                   |
| Agent `household/`                              | 目标解释、观察工具、上下文组织、LLM 身份／场景任务与结果提交           | 直接改 backend 数据库                        |
| `packages/api/src/contracts/`                   | 跨应用请求、响应和事件 schema，类型从 schema 推导                      | 运行对象或厂商协议                           |

`household/observation-requests/` 管理持续观察需求，设备采集计划的 `household/observations.ts` 继续表示设备观测规则。不把采集、身份与位置塞进同一个家庭 actor；各所有者同步提交自己的数据，跨域引用按版本与资格检查。

持续观察请求与一次执行分开：backend 保存“已启用的基础维护或临时关注，以及当前生效的参数”；Agent 保存“为了这次证据执行了什么”。`watch_id` 标识观察请求，`task_id` 标识一次执行，`thread_id` 标识该次 Agent 执行的 checkpoint。本地身份执行使用独立执行身份，不创建聊天或 Agent checkpoint；其准入不依赖 Agent 在线。观察请求可以产生多次执行，不共享一条无限增长的聊天记录。

### 持续工作与主动问询

持续工作由 Agent 运行层拥有，表示需要继续承担的目标、关注事项或承诺，例如“这周留意猫进食是否异常”。一次调查完成后，持续责任可继续；一次模型调用超时或进程退出也不自动取消承诺。backend 的 `automation_id` 表示已接纳的自动化配置，`watch_id` 表示实际观察配置，二者都不代替 Agent 的工作计划。本文其余“长期任务”指 backend 已接纳配置；用户的一项长期目标可以关联多个配置和多次调查，也可以只包含问询与查证，不要求先创建自动化。

Agent 持续工作使用稳定 `work_id` 和工作版本，保存稳定家庭归属、目标与来源、授权范围、进度、未决问题、证据与配置引用、等待条件、截止时间和完成／撤销依据。一次有限执行沿用 `task_id`，关联所属工作及输入身份；`thread_id` 只标识执行会话。工作跨重启使用稳定家庭身份，当前执行的 `scope_epoch` 仍由 backend 核对，不能把旧运行资格一并恢复。首个场景定义必要字段与有界 schema，不以聊天摘要或长期记忆代替可恢复的工作状态，不提前创建通用任务平台。

工作至少区分可继续、执行中、等待外部输入或条件、受限、已完成、已撤销。等待状态明确等待什么、怎样关联输入、何时到期以及超时如何处理；等待不占用模型并发槽或保持 HTTP 请求。已有一次执行的时间与调用次数上限约束本次计算，不限制持续工作的总寿命。多个工作可以独立等待或调查，主 Agent 继续接待用户；一次调查的输出包含结论、证据引用、未决事项和是否需要后续处理，不把全部工具输出复制到主会话。

Agent 可以在已授权职责内创建调查、调整关注、请求受控观察及安排复核；普通代码完成已明确的匹配、到期和预算检查，需要开放判断时才调用模型。后台结果或相关新证据回到所属工作，可能完成承诺、改变计划或形成新的调查。通知用户前判断是否有实质新情况、确需回答或达到已约定的通知条件；普通重复进展保持静默。新来源、额外费用及实际操作仍遵守各自授权，不因主动性自动扩大范围。

主动问询先可靠保存 `question_id`、所属工作与版本、问题内容、目标回答者或身份未知、输出渠道、回答关联和期限，再经 backend 动作入口投递，并关联播放／投递结果。Agent 拥有问题及对话状态，backend 拥有播报／通知动作结果，双方通过稳定身份关联。投递失败、结果不明、已投递待回答、已回答、超时、撤销分别表达；保存问题不表示人已听到，投递超时不自动重播。

网页和语音回答进入同一工作输入契约。网页可显式携带问题身份；语音依赖实际播放、时间窗口、渠道和可用身份线索关联，不能仅凭转写认定说话人或所属问题。“好”“先不要”“另一台”等回答须结合待回答问题理解，不沿用当前独立助手请求分类来过滤。多个问题匹配、迟到或问题已撤销时，不自动恢复错误工作；保留输入并按交互规则澄清或结束。回答可补充信息、改变目标、追问、取消或另起话题，不能只建模为批准／拒绝。保存回答也不等于修改家庭要求；涉及要求或自动化的变化须取得 backend 接纳回执。

例：“这周留意猫进食”形成 Agent 工作，引用已启用观察与事件查询。发现证据不足后询问家人；回答“已经喂过，今天先别提醒”接续调查，并按实际含义提交用户来源的喂食报告及明确提醒要求，不能把喂食报告自动升级为已确认进食或视觉事实。到期或新证据出现时继续评估；若形成家庭判断，提交 backend 接纳，若只完成调查或答复，不强制更新家庭情景。通知与设备动作仍独立核对结果。

### 输入分类与可靠交接

事件驱动表示变化、回答和结果能使持续工作继续，不要求把每帧媒体或全部设备报告永久追加到主聊天，也不要求所有状态均由事件重放重建。三种家庭分析入口继续见[定期综合](#三种分析入口与定期情景综合)，持续工作另接纳用户回答、调查结果和自己的复核期限；输入是否需要模型判断由工作语义与预算决定。

| 输入                                       | 传输与恢复要求                                                                       | 责任边界                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------------ | -------------------------------------------------- |
| 高频设备／媒体变化、短期分析候选           | 有界筛选、合并、到期；允许按来源契约丢弃，恢复读取当前仍有效候选并说明缺口           | backend 保存来源证据与候选，Agent 决定当前分析价值 |
| 已接纳且需业务处理的家庭事件、规则决策请求 | 生产方可靠登记待交接项；消费方持久接纳后回执，重送复用原身份                         | backend 拥有事件／请求，Agent 拥有接纳后的执行     |
| 用户消息、问题回答、调查结果               | 在各自接纳边界保存输入及所属工作／问题／执行引用，再确认接纳；可核对、去重并恢复处理 | Agent 运行层拥有工作输入，渠道适配器处理传输       |
| Agent 工作复核与等待期限                   | 持久保存工作版本、等待条件与唤醒时间，恢复时核对当前资格                             | Agent 运行层拥有，backend 自动化计时仍归 backend   |

backend 不必先识别完整的行为语义才提供输入：合格画面变化、未知对象的新证据、矛盾或覆盖缺口都可引起 Agent 关注。原始来源时间、证据身份和资格随输入保留；未识别语义不等于没有活动。首个场景限定来源、候选类型、容量与保留期限，不将任意日志当作可靠事件。

可靠输入区分生产方已登记、消费方已接纳、已处理及失败／过期／取消／结果不明。接纳使用稳定交接身份并核对载荷一致性；重复输入返回已有状态，不重复启动付费执行或增加独立证据。生产方在消费方确认接纳前保留可查询的待交接项；双方的查询和去重记录保留至交接、工作处理及回执核对期限结束。保存失败不确认接纳，容量不足明确拒绝或显示受限；只有接纳后才能承诺恢复。原始感知未送达、来源没有重放能力的缺口仍如实保留，不承诺端到端零漏报。

现有和拟议 SSE 负责变化通知，不能单独保证上述可靠交接。可靠输入按所属存储的事务能力提交，跨 backend 与 Agent 不假设共享事务；登记、回执与按身份查询恢复各自有明确边界。Agent 运行框架承担持久等待、唤醒和执行恢复，优先复用其原生能力或成熟运行底座；不把 backend 的 Graphile Worker 扩成 Agent 工作状态的第二所有者，也不手写另一套通用队列。首个工作场景同时定义未完成工作、待回答问题、可靠输入及结果的数量／字节上限、保留期限和过载反馈，清理不得删除仍需核对的交接或动作依据。框架选型仍需验证，见[基础设施参考](../references/personal-agent-architecture.md)。

重启后核对未完成工作、已接纳输入、待回答问题及 backend 配置／动作回执，按当前仍有效的依据继续；计算或投递已开始但结果不明时先查证，不盲目重跑。旧工作版本、已撤销问题和原家庭的输入不能恢复到新工作。家庭改绑停止旧工作并清理其输入、问题、唤醒与执行状态；已有的家庭清理接口须扩展到这些数据。

### 任务定义与两条执行路径

当前规则树已包含 AI 判断条件，并支持可选 Agent 动作选择，配置、权限及运行边界见[当前能力](../automations.md)。持续调查与问询属于 Agent 工作，不为了保存目标创建一条没有可执行条件的 backend 规则。

后续扩展继续优先使用普通代码、本地能力和已有有效情景完成确定性判断；只有尚需解释证据或开放决策的部分调用模型。读取上下文、比较时间、匹配结构化事件和按有效位置选择音箱不构成付费推理的理由。缺少确定性模板属于能力缺口，不能因此自动改走 LLM。

尚需交付可审阅的依赖准备、目标对象与适用期限、来源授权及重复策略；缺少准备条件时保存未就绪意图，不让半装配配置提前执行。持续工作使用 `work_id`，问题使用 `question_id`，受控观察使用 `watch_id`，一次调查使用 `task_id`，与 backend 自动化、事件和动作身份分别关联，不能互相代替。

语义分析直接附带已授权处置请求仍待接入。该入口须核对候选、任务版本、原始证据、权限与共同预算，同次判断、事件和动作需要一致时共同接纳；不强制再调用一轮模型，也不能与后续规则消费重复提醒。现有周期维护只产生事件，当前聊天工具只保存停用草稿，不能据此声称已有开放动作工具。

### 规则树与自然语言配置

规则树编辑、触发／状态标签、语义生成及属性能力约束已经接入，唯一使用说明见[规则树与条件角色](../automations.md#规则树与条件角色)。本计划不保留已实现节点、编辑器和共享契约的施工清单；真实模型与浏览器交互的剩余验收见文末。新增语义条件必须有明确来源和生命周期，不将任意文本直接作为可执行条件。

### backend 本地规则运行器

当前 backend 直接在内存中求值规则，Graphile Worker 派发命中后的决策请求、动作和周期维护；使用与恢复边界见[保存、恢复与接口](../automations.md#保存恢复与接口)。运行器不向米家云部署规则，调度库不拥有 Agent 工作状态。

后续按场景增加已确认活动的期限重算、按有效位置选择设备、备用渠道和禁令策略。新增能力继续复用现有事件接纳与动作记录，供应商适配器只处理具体请求与结果；不增加通用工作流引擎或第二套任务队列。

### 三种分析入口与定期情景综合

选定设备属性的有界周期复核已作为 AI 条件接入规则树，配置、预算和判断有效期见[AI 判断条件](../automations.md#ai-判断条件)。这一路径没有媒体输入，也没有完整家庭情景与活动索引。

后续家庭分析补齐三类来源的共用接纳：真实设备／家庭事件、合格媒体候选和周期综合。周期综合继续拥有独立维护配置，不要求先存在提醒任务；多个消费者引用同一维护，不复制生产者。backend 拥有来源范围和到期时间，Agent 拥有证据解释及必要的受控补证，不在 Agent 另存可独立修改的维护配置。

输入须扩展到可核对的家庭判断、经历、支持／冲突证据、各领域版本、查询范围和覆盖缺口。媒体按自己的资格和期限提供；纯上下文复核不默认重新取帧。未查询或未保留不等于未发生，旧推断只能作背景，不能成为新的独立支持。

尚需实现语义判断的支持更新、冲突、结束、纠正、撤回和失效，以及时间条件变化引起的场景级复核。当前显式定期复核开关不能代替完整的分析价值判定。恢复只处理当前仍有价值的问题，后续新周期也不能借新 ID 重跑结果不明的旧计算。

### 多来源判断与事件：猫可能饿了

| 信息                                   | 接纳后的含义                                                 |
| -------------------------------------- | ------------------------------------------------------------ |
| 喂食器报告出粮完成                     | 设备来源观察／事件，证明设备报告了出粮，不证明猫已经吃下     |
| 本地规则发现距已确认进食超过设定时长   | 确定性派生，保留基线事件与规则版本；未记录进食不直接等于饥饿 |
| Agent 视频分析发现猫反复靠近食盆或叫唤 | 带原媒体区间与依据的行为解释，不自动定位为某只已登记猫       |
| Agent 关联食盆信息、近期行为和进食经过 | “猫可能饥饿”的候选判断，可由事件、媒体或定期综合入口产生     |
| 首次接纳饥饿迹象，或该次迹象明显变化   | 按已实现事件规则生成／更新家庭事件，供已启用提醒任务消费     |

判断与家庭事件使用共同的来源语义，区分设备上报、本地规则推导和 Agent 推断；Agent 的输入入口另行记录，允许一次推断同时引用设备和媒体。记录原始证据身份、推导依赖及版本、证据适用区间、评估时间和接纳时间；不为不同生产者建设可独立修改的“猫饿了”状态副本。设备上报也有来源质量，推断不会因为入库或转成事件而变为确定事实。

“猫可能饥饿”作为情景判断保存主体、维度、支持／冲突证据、不确定性和失效条件。用于自动化的事件采用已实现的类型化契约，例如 `hunger_signs_detected` 表示发现饥饿迹象，不宣称测得生理饥饿或精确起始时间；未支持的开放描述可保存为分析说明，但不能冒充已实现规则条件。无法区分多只猫时使用带来源运行的猫轨迹或区域级判断；没有可靠个体关联时保留匿名，不凭轨迹编号把进食量或饥饿判断归给某只已登记猫。

backend 判断接纳模块拥有该维度的当前版本，事件模块维护同一次迹象的稳定事件身份及更新。Agent 提交时引用已有判断／事件及其预期版本；首次成立、有实质新支持、矛盾、结束或纠正分别处理。纯复述、提示词变化或新执行 ID 不产生新事件、不提高置信度、不重置提醒周期；到期只变为未知，不伪造“猫不饿了”。再次成立是否属于新一轮迹象，须有该场景明确的结束和重新成立依据。

上次判断和 Agent 长期记忆只作背景或待复核假设，不能成为新的独立支持；保留原证据引用，防止“模型认为猫饿了 → 下次总结仍饿 → 多次确认”的循环。新的时间评估可以改变推断，但必须记录时间条件与观察覆盖，不刷新原始来源时间；静止、无新消息和反复读同一记录不能自行延长观察有效性。

同一结果需要同时更新情景并产生对应事件时，通过一个受控接纳操作在同一数据库事务保存判断版本、事件及必要待评估项，成功后发布当前视图；失败不单独发布已成立事件。多个入口对同一主体／维度的并发结果按证据与版本检查接纳或保留冲突，不按返回先后覆盖。事件后续规则处理和动作继续遵守下节的可靠交接，不把每次分析完成当作提醒触发。

### 规则到 Agent 动作决策的交接

规则触发后的动作候选选择、稳定请求身份、结果查询与共同动作登记已经接入，见[动作与 Agent 决策](../automations.md#动作与-agent-决策)。现有模型只选择已配置动作 ID，不生成任意新动作；结果不明不重新推理。

后续语义分析同时提交判断与处置时，须与事件消费共用 backend 认可的触发变化身份和动作槽，避免同一迹象提醒两次。语义纠正、升级、结束与重新成立应按场景规则撤销或替换待执行动作，并与任务版本、当前权限及期限共同复核。真实模型的接纳前后中断、取消与迟到结果仍需专项验收，不以 checkpoint 存在代替完整可靠交接。

### 依赖启用与运行健康

长期任务的启停意图与实际可执行状态分开。启用或修改时，backend 不仅核对能力是否已实现，还要解析实际依赖：适用家庭与区域、需要的基础维护及版本、来源是否启用、维护运行状态，以及所需模型服务和自动预算是否可用。已有共用维护直接引用；没有启用时，只能在用户已授权的来源、用途和费用范围内经同一观察接纳入口启用，不为每个提醒复制位置维护。需要另行启用的依赖先取得可靠回执，再重新核验任务资格；不假设跨模块保存天然原子。依赖未就绪时，可保存用户意图，但不能返回正常运行成功。

每项依赖明确必需程度及允许的降级方式。已有授权的备用方式能满足该任务时，可以降级启用，并在回执说明实际行为；否则暂停受影响分支。缺少遛狗事件生产者，不能仅以“音箱位置未知时换渠道”掩盖；除非任务明确接受按已有记录提醒，否则不得宣称正在正常监测遛狗。未授权的来源或付费范围不自动扩大。

任务查询与接纳回执同时返回启停意图、当前运行状态、受影响分支、依赖身份／版本、原因及最近核对时间。运行状态按 `ready / degraded / suspended / recovering` 表达；关闭意图始终禁止执行，不被健康恢复重新打开。区分两类信息：当前位置暂时未知属于情景质量；位置维护被停用、来源不可用、Agent 离线或自动预算耗尽属于生产能力健康。已有有效判断仍可按自身期限使用，不能因模型不可用而一并抹掉；需要新语义的分支必须显示受限，不能以旧判断冒充正常监测。

基础维护停用、来源撤权、模板或范围变更、模型失联及预算变化时，重新计算依赖任务的健康与执行资格。backend 使用所属模块的状态；Agent 提供带有效期限的模型可用性和预算摘要，摘要过期标为未知，实际付费准入仍由 Agent 负责。具体动作及新语义任务启动前再核对，不能只相信创建时的回执。停止业务任务不撤销其他消费者使用的基础维护；用户明确停用基础维护后，不因仍有依赖任务而偷偷重启它。

重启后先标记恢复中，核对持久定义、来源、实际运行和依赖版本后再转为就绪或降级。恢复不直接重放历史提醒，只按任务期限和重复策略处理仍有价值的待办；当次提醒遇未知或过期位置仍立即走已配置分支，不等待 Agent 补证。上述健康为可重新计算的运行视图，任务意图和依赖配置由长期任务模块可靠保存。

### 情景、事件与统一执行

已实现的事件身份去重、事件提交后通知内存规则引擎、Graphile Worker 派发及动作记录见[当前实现](../automations.md#保存恢复与接口)。当前 AI 判断直接更新条件状态，不生成家庭事件；家庭事件生产者、设备独立事件与完整语义事件修正仍待接入。

待扩展事件保存主体／区域、发生区间、支持与冲突证据、不确定性及修正关系，区分设备报告、本地推导和 Agent 判断。判断描述当前有效结论，事件描述发生经过；纠正保留原记录并重算依赖，不覆盖历史，也不重执行已经完成的动作。

`event_id` 标识同一次经过或持续迹象；新增 `trigger_occurrence_id` 标识经 backend 认可的一次可执行变化，例如首次成立、有效升级或明确允许的重复周期；提交 ID 只标识写入重试。普通补充说明、新执行 ID、提示词变化或同证据复述不产生新触发。升级、结束后再次成立和周期提醒分别要求场景依据，不能用全局冷却吞掉不同事故。

语义结果同时附带动作、事件随后由规则消费时，必须共用触发变化和动作项身份。事件／修正接纳与必要待评估项共同提交；到期执行遇相关已接纳但未处理的纠正，先重算有效基线与期限，迟到纠正撤销尚未发送的过时动作。新规则采用历史事件须显式初始化，不遍历历史重放通知。

例如“上次遛狗八小时后提醒”从有效遛狗事件原时间计算，重启不重置期限，撤回或纠正按有效事件重算。按当前位置选音箱需有效位置及实际播放回执，成功后不因位置变化重播；未知位置使用已授权备用方式，不等待识别。声音输出和供应商效果确认须单独实现并验收，超时不证明未执行。

### 四类需求的具体契约

| 需求                                | 提前维护的信息                                     | 触发与执行                                                                            |
| ----------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 人来灯亮、人走灯灭                  | 区域占用、活动及有效要求                           | backend 按占用边沿、离开确认和延时模板执行；缺失不当作离开，重复检测不重复开灯        |
| 超过 8 小时没遛狗，在我所在房间播报 | 已接纳遛狗事件、持续维护的用户位置、音箱及作用区域 | backend 从最近一次有效遛狗完成时间计算期限，到期读已有位置选音箱，不调用 LLM 找人     |
| 卫生间门开着，猫狗进去就提醒        | 有效门状态、动物类别及区域／通行证据               | 证据已结构化时本地规则执行；需理解画面时 Agent 识别后提交事件及提醒请求，共用执行入口 |
| 有人出现疑似危险状态时提醒          | 可用来源、人物／区域上下文及近期证据               | Agent 按任务目标判断疑似异常并请求提醒；backend 保存事件、检查授权、去重及执行        |

遛狗完成的判据随真实来源实现，普通出门不等于遛狗；明确针对哪只狗、是否限定执行成员及可接纳的证据。没有历史或观察覆盖有缺口时只能说“未记录到”，不能断言没遛；任务明确允许按记录提醒或指定其他处理后才能启用。时间从实际事件算起，不从模型返回算起；迟到或纠正事件重算期限、撤销尚未发出的过时提醒，已发出记录保留。与设备连续条件计时不同，该期限保存事件依据和到期时间，重启后按配置补发一次仍有用的提醒或跳过，不重新计满 8 小时；检查时钟跳变，重复间隔、结束条件和首次缺记录处理是任务参数。

猫狗场景消费 P2 已实现的猫狗位置轨迹，并校验物种、来源运行、实测状态与有效期；预测框不单独证明动物进入，轨迹编号也不代表已登记宠物身份。卫生间只使用允许区域的门口视野或验证过的其他来源；看不清门状态或方向时不承诺识别进入。若接受“发现动物在区域中也提醒”，须显式配置，不能伪造进入事件。门开且进入要求两种证据在相关时间适用，不拼接过期位置与门状态。

危险任务的候选触发不能要求 backend 已知道危险才唤醒 Agent。启用时明确可实现的本地异常／变化筛选、代表证据，以及是否需要有预算的定期观察；仅变化筛选可能遗漏静止异常，覆盖方案未验证时不能宣称持续危险监测可用。定期语义观察按独立模板交付，不改变身份核验的新证据要求。可信本地报警也可走规则路径。分别记录证据发生、候选产生、识别完成及投递时间；识别后立即处置不等于从危险发生起保证实时发现。Agent 不可用时显示语义监测不可用，不把旧判断当作正常。

### 基础维护与临时观察

基础维护与临时观察复用同一套模板、候选与执行设施。基础维护由用户或部署配置明确启用，在原家庭与授权范围内持续到停用，不要求每天经聊天续期；临时观察表达额外目标，必须有截止时间。基础维护持续启用不表示持续调用模型，仍由证据变化、质量和预算决定调用。部署配置通过同一接纳入口保存，不能另建一份可独立修改的运行状态。

第一批只实现 `scene_context` 模板：在指定来源上，P4 场景筛选产生合格窗口时，请求一次与观察目标相关的场景理解。身份场景接入后增加 `member_presence`：持续维护所选成员的位置，并对符合条件的身份问题提出核验。每个模板是代码中已实现、带版本的领域规则，不接受脚本、任意布尔表达式或自然语言直接充当触发器。

自然语言目的只指导 Agent 分析，backend 不把“有人在做饭”等语义直接编译成已实现的本地条件。现有模板无法表达的需求，Agent 明确说明缺少能力；不能创建一条表面接纳却永不正确触发的观察。

Agent 工具 `list_observation_capabilities` 返回当前支持的模板、实际可用来源／区域、可选参数及其允许范围。`put_observation` 只提交这些能力允许的数据：

| 字段                            | 含义                                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `watch_id`、`expected_revision` | 客户端首次生成 UUID；新建预期版本为 0，更新须匹配当前版本                                                |
| `scope_epoch`                   | 本次修改所针对的有效家庭运行；backend 独立核验账号与家庭                                                 |
| `template`、`parameters`        | `scene_context` 的来源、区域和判断有效期；`member_presence` 的来源、区域和已登记成员 ID；按模板判别校验  |
| `purpose`、`origin`             | 有界的任务目的及原始用户请求关联；用于模型任务输入和解释，不作为权限证明                                 |
| `mode`、`expires_at`、`enabled` | `baseline` 表示持续到停用的基础维护，不携带到期时间；`temporary` 必须携带 UTC 到期时间；两者都有启停意图 |
| `requested_limits`              | 请求的调用频率与单次证据规模，只能在部署允许范围内收紧                                                   |

`scene_context.parameters` 使用 `{ sources: [{ device_id, channel }], area_id, validity: { occupancy_max_age_ms, rest_max_age_ms } }`，区域须有用户确认的覆盖依据，两个有效期必须在部署允许范围内；`member_presence.parameters` 使用 `{ sources, area_ids, member_ids }`。来源保存稳定设备／通道引用，运行时由 backend 解析为当前 `source_id/source_run_id`，不把短命运行 ID 保存成跨重启配置。观察请求初始最多 16 个启用项、单项 16 KiB、总计 256 KiB；临时观察单次有效期最长 24 小时，续期须有对应用户意图；基础维护无固定到期时间，模型不得把临时任务自行升级为基础维护。模式按判别 schema 校验。

backend 返回 `{ watch_id, revision, mode, status, effective_limits }`，临时观察另返回 `expires_at`。同 ID、相同预期版本与相同内容的提交重试返回已保存回执；同 ID/版本而内容不同则冲突。可靠保存后才生效，失败保留旧请求；撤销也可靠保存后返回。运行中权限撤销立即禁止访问，不等待保存。

首期只支持可信本机单用户。Agent 提议须在用户已经授权的来源与任务范围内；超出范围向用户说明并取得授权，不能靠 `origin` 文本扩大权限。持续开启的基础观察也必须由用户或部署配置明确启用，不因登录或启用 P1 自动产生付费任务。

观察请求可在线更新，但不修改设备采集计划的采集策略、本地模型阈值、米家账号或摄像头启用范围。它与下文设备事件启动时读取的本机场景配置是不同对象；复用模板中的纯条件函数，不为此改造为通用规则编辑器。

请求保存稳定家庭身份及模板版本。backend 重启后重新校验来源、模板版本、期限和当前权限，基础维护仍启用或临时观察未到期，且其余条件满足时才在新 epoch 激活；运行基线和持续计时重新建立，不回放旧触发。模板版本改变时暂停并要求重新接纳；到期、改绑或来源不适用时停用，不恢复到其他家庭。用户长期任务的恢复不等于一次 Agent 执行自动恢复。

### 一次实际执行的时序

1. 批次 B 中，用户或部署配置启用客厅 `scene_context` 基础维护；也可由聊天创建一小时临时观察。接纳后返回有效范围及生命周期。首个闭环不依赖动态观察编辑工具先完成，基础维护可由部署配置经同一服务启用。
2. P4 窗口通过筛选，backend 发布包含 watch 版本的候选。Agent 准入层在读取媒体前检查预算与期限，选择对应任务处理器；用户聊天已经结束，不影响后台观察。
3. 场景任务取得该窗口媒体与允许读取的家庭上下文，调用模型并提交结果。backend 接纳后按下节规则维护当前判断，另一次聊天或确定性策略读取其值、原证据时间和有效性，不将窗口说明冒充持续实时画面。
4. 批次 C 按需增加 `member_presence`，不替换仍需运行的基础场景维护。客厅画面中的目标被确认属于成员 A，接纳为出现记录；厨房后来取得合格新画面时，可独立核验其中目标，不要求先关联客厅轨迹。
5. 厨房身份结果返回后，backend 核对原证据、时间依据、覆盖与身份版本，接纳后按观察先后汇总 A 的最后出现房间。迟到结果不覆盖更新观察，同一时间的重叠视野不虚构通行；最新观察区域未知时保留较早的最后已定位记录及原时间。
6. 用户停止观察，工具返回保存回执，新候选停止并取消对应任务。已接纳出现记录保留原时间，不能因停止观察反写成“无人”，也不再声称正在更新位置。

### 首个情景的维护与即时消费

批次 B 选择允许部署摄像头且实际覆盖明确的客厅区域，维护“区域占用”和“可能有人休息”两个独立判断；不依赖成员姓名或 P2。模型可以依据代表画面及可用设备上下文提出休息迹象，但只能表示推断，不确认睡眠。没有相应证据时保持未知。

| 情况                                   | backend 的维护规则                                                             |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| 新的实测人体检测覆盖目标区域           | 按实际覆盖更新占用支持；不能因此确认某个人或延续休息判断                       |
| 新的实测猫狗检测或轨迹覆盖目标区域     | 更新对应物种的占用证据；不能当作“有人”或确认某只宠物，预测框不能单独刷新占用   |
| 取得足以支持未占用的有效证据           | 按已验证覆盖、遮挡与场景规则建立未占用基线；一次空检测、旧值或缺帧不构成该证据 |
| Agent 提交有效的休息迹象判断           | 记录目标区域、原证据时间、支持与冲突证据、依赖和有效期；后续查询不续期         |
| 同值上报、无画面变化、同一目标持续存在 | 不构成新的休息证据，不自动延长活动判断有效期                                   |
| 新人或新的存在信号出现                 | 更新对应占用证据，不单独清除原休息判断，也不证明所有人已醒                     |
| 来源中断、遮挡或覆盖失效               | 依赖该来源的当前判断降级为未知或待重评；不把缺失当作无人或休息结束             |
| 取得适用的新语义证据，明确不再支持休息 | 按该维度的版本与证据规则更新；存在矛盾则保留冲突，不按响应先后覆盖             |
| 判断到期而无新的支持证据               | 移出当前可用判断，保留最后已知；不自动变成“无人休息”，也不强制调用模型刷新     |

首个场景配置须分别声明占用证据最大年龄和休息判断最大年龄，并在真实机位验证后启用；未设置时不提供可用于策略的当前判断。有效期从支持证据的时间计算，不能从模型返回时间起算。来源变化只更新实际支持的维度，人物身份、位置和活动不互相自动续期。

批次 B 同时实现一个只记录结果的具体策略：区域占用从有效未占用变为有效占用时触发；重复检测只更新证据，启动／断流恢复首次取得占用只建立基线，未知不冒充未占用。策略以本机配置中的稳定 ID、模板版本、区域、启停和参数启用，由 backend 策略模块拥有；后续长期任务接入同一规则函数，不并存两份启用状态。触发时，若休息判断仍有支持、为暂定、未知、冲突或过期，记录“抑制自动开主灯”；只有有效证据支持无休息者且没有禁止要求时，记录“允许进入后续开灯资格检查”。这不直接生成开灯授权。策略记录本次已提交情景、要求和策略版本、触发证据及理由，不等待模型、不发送命令；此默认处理仅用于首个场景。

真实命令在后续动作阶段启用：backend 重新检查当前条件与权限，按已启用策略执行并确认结果。Agent 不可用不阻塞上述确定性处理；异步重评只影响后续上下文，迟到结果不自动重放已经处理的动作。验收分别记录事件接纳到策略决定的延迟及异步语义更新延迟，不把模型完成时间当及时响应时间。

## 4. 身份与位置的本地处理

以下描述人宠身份能力的整体目标。[人物参考登记、当前识别关联](../perception.md#持续成员身份分析)已实现，验证范围见当前功能文档。人物关联已生成成员页观察记录，最后出现房间汇总仍是后续必需能力，人物及猫狗共用当前本地链路，LLM 生产者另行实施。后续生产者可复用家庭身份领域的关联校验职责，并按其真实来源补充接纳边界；现有本地入口不表示通用任务设施已实现。

批次 C 的整体目标是“最后出现房间”，字段和不变量唯一维护在[人宠出现记录](household-model.md#人宠出现记录与最后出现房间)。人类成员和已登记猫狗统一使用稳定 `member_id`；`member_presence` 首期维护出现记录，不承诺当前在场。各来源独立核验成员，再按身份汇总，不要求跨摄像头保持同一轨迹编号。

首期流程为：合格画面与来源时间 → 对照人宠参考核验身份及覆盖区域 → backend 接纳出现记录 → 普通代码汇总 `latest_sighting` 与 `last_located_sighting`。来源时间不可靠、身份或区域未知时保留限制；模型返回时间不参与出现先后排序。本地身份使用局部轨迹键 `{scope_epoch, source_id, source_run_id, track_id}` 关联目标，并保留原帧证据；`className`（`human / cat / dog`）表示类别，同一画面多目标不能共用一个身份结果。

身份核验不能仅凭物种或跟踪外观相似度命名；人物须匹配已登记的人脸参考，猫狗须有适用的个体识别依据。人体 ReID 只提供人体外观相似性，猫狗个体匹配使用独立宠物模型的整只动物特征。低质量、相似个体无法区分或无参考资料时保持未知；未知观察不更新某个指定成员。本地路径沿用轨迹选帧与候选去重；跟踪未成立或失效时保持未知，不要求另建独立画面识别入口。

后续扩展设计中，本地模型与 LLM 是可分别启用、可并行运行的身份候选生产者，不互相等待，也不默认对每张图片同时调用。人物本地路径复用已有 YuNet＋SFace，猫狗另行验证适用模型；正式成员接纳与猫狗个体识别仍待实施，模型资产、预处理、阈值、未知处理及实景效果通过核对后才接入，不作为 P2/P4 前置条件。参考库较小时先在有界内存集合比较，不预建向量数据库。

本地路径消费与原帧关联的有界图片，不等待 4 秒窗口关闭、场景变化放行或视频编码；LLM 路径根据已启用配置和自身预算消费适用证据。本地优先后按条件启用 LLM、仅启用其中一种或并行对照均须明确配置，不能把本地返回未知自动转换成一次付费调用。两条路径均记录生产者、执行身份、证据与目标、模型／处理版本、参考资料版本、匹配依据及未知状态。本地计算有独立容量与期限，失败不停止采集或另一生产者。

两种生产者调用同一家庭领域身份接纳操作；本地路径在进程内调用，不绕经 Agent 或为其伪造 HTTP 任务。HTTP 仅适配外部提交。相同底层证据的多模型结果不算多次独立确认，不能刷新观察时间；各模型分数按自身经验证的规则解释，不直接比较大小。冲突保留原依据并按身份接纳／纠正规则处理，没有验证过的裁决规则时保持未知或争议，不按谁最后返回覆盖，也不默认调用 LLM 仲裁。其他功能只读取已接纳身份及其限制。

最后出现位置是历史证据汇总，不设到期后自动删除历史事实的“在场有效期”。新观察区域未知时，同时保留较早的最后已定位记录及原时间；冲突、撤销和身份纠正触发重算。受控接纳入口复核证据、家庭资格、资料和覆盖版本，保存记录、受影响汇总及接纳回执后再发布。重复提交或重复证据不刷新时间；保留期限内的迟到结果可解释原区间，不要求目标现在仍有活动轨迹。

后续 E 再按需要交付可靠轨迹上的身份延续、跨镜头对象关联与通行事件；只沿验证过的连续性复用身份，交叉、遮挡、类别抖动或重建后重评。跨源匹配须检查物种、时间质量、覆盖关系和候选歧义，不能直接套用人体相似度到宠物，也不凭排名第一接纳。不同镜头的像素轨迹不能直接拼接。Frigate 可作为后续来源适配，沿用同一证据与出现记录契约，不成为首期依赖。

## 5. 候选触发与执行准入

本节定义首期场景维护和身份核验；后续语义任务的候选方式按第三节逐场景实现。场景筛选和身份核验使用不同模板条件，但都由 backend 普通代码检查。场景理解沿用 P4 的画面／声音筛选。身份核验要求启用 `member_presence`，且有待解决的身份问题和足够质量的视觉证据；画面静止不阻止清晰人脸或宠物的可区分外观成为核验依据。

| 条件                                                 | 处理                                             |
| ---------------------------------------------------- | ------------------------------------------------ |
| 已接纳身份且没有实质新证据                           | 不重复核验；后续经验证的连续性规则才可沿轨迹更新 |
| 后续跨镜头匹配满足已验证接纳规则                     | 本地关联，不调用 LLM                             |
| 未知目标短暂出现、模糊、没有有效参考资料             | 等待或保持未知，不因未知反复调用                 |
| 未知目标持续出现，取得合格代表帧，有待解决的身份问题 | 创建身份核验候选                                 |
| 已有身份与新观测冲突、疑似目标串号                   | 先降级关联；取得适用证据后创建候选               |
| 上次回答未知，未出现新证据                           | 抑制重复；冷却结束本身不重新调用                 |
| 更清晰视角、有效新参考、新的实质冲突                 | 更新证据版本，重新检查准入                       |
| 最近观察变旧、模型失败或预算不足                     | 保留历史时间并报告限制；不强制付费刷新           |

模板按物种使用已实现的帧尺寸、清晰度、实测目标可见性和持续观察指标判断证据是否改善。人体可使用适用的人脸和人体外观特征；猫狗使用全身、面部、毛色花纹及必要视角的可见证据，不要求人脸框，也不假定已有宠物外观向量。质量阈值按实际来源配置和验证，未配置合格标准的来源不自动核验。首次实施记录每次放行／抑制原因，不让“新帧 ID”直接等于“新证据”。

backend 保存有界的当前候选：`candidate_id, watch_id, watch_revision, scope_epoch, purpose, subject_key, evidence_revision, reason, evidence_refs, available_until`。场景候选按观察请求及来源合并；身份候选按观察请求、目标和核验目的合并，不能按摄像头只留一个，否则同镜头多人会互相覆盖。跨镜头只有关联依据充分时才合并为同一问题；不能为省调用先假定是同一个人。

观察候选最多 64 项／2 MiB（初始工程上限，媒体另计）；满额清理过期项，同问题更新替换，仍满则拒绝新项并计数。证据资源先就绪，再同步登记候选版本并发布通知；只增大版本、不在事件中携带媒体字节。

事件只通知候选变化，不直接命令调用模型。Agent 首次连接或重连先取得当前候选快照再接续变化；注册与快照边界内的更新有界暂存。序列缺口重新取快照，不补发全部旧窗口。SSE 复用现有解析、大小及慢连接清理机制，候选流有自己的版本，不塞入设备公共快照。

本地执行器与 Agent 普通代码分别检查观察仍有效、证据可取、是否已处理、在途任务和预算，然后创建一次执行。每个生产者对同一问题最多一个在途执行和一个等待更新；去重同时关联证据指纹，单纯 track ID 重建不作为再次调用的充分理由；等待期间选取更有价值的证据，开始执行时冻结证据版本。跨多个观察请求引用相同目标、目的及证据时，可共用模型结果；每个请求的使用资格分别核对，取消一个请求不撤销其他合法使用。首期不跨不同问题盲目合并。

本地执行器通过应用边界消费同一版本化身份候选，Agent 通过上述订阅消费；互相不以执行完成或结果接纳为启动前提。未启用的生产者不领取候选，失败或超预算不自动转交另一生产者。

## 6. 具体接口与工具

Agent 持续工作阶段定义工作创建／查询／修改／撤销、可靠输入接纳及回执查询、问题发布／回答关联、调查结果提交和等待恢复的契约。共享边界 schema 放在 `packages/api`，调用方可经 backend 转发，但 Agent 运行层拥有工作与问题；不能把它们写入 `household/automations/` 或通用 `context_records` 代替执行状态。契约携带稳定输入身份、适用 work/question/task 引用及预期版本，返回已保存的实际状态；具体路由、表名及框架内部执行接口随 D2 的选型和首个网页场景确定，不提前发布空接口。涉及观察配置、家庭要求、判断或动作时引用下列 backend 接纳入口及各自回执，不把 Agent 工作保存成功当作领域修改成功。

当前规则、能力、运行记录和维护接口见[自动化接口](../automations.md#保存恢复与接口)，不再另建一组规则 CRUD。后续按实际场景增加受控的事件／修正／动作共同接纳、回执查询，以及带纠正状态和覆盖缺口的活动历史查询；具体路由随共享契约确定。提交须引用有效任务版本、当前权限及 backend 可核对的证据，自报任务身份不能构成授权。下表所列观察与判断接口仍是待实施设计。

人物参考登记已经使用[现有参考接口](../../apps/backend/README.md#人物识别参考存储)，Agent 不能凭猜测登记真实身份。以下是尚待实施的本机 API，按交付批次注册；全部复用现有本机访问校验和错误结构，修改操作校验 epoch，所有证据读取与结果接纳重新核对资格。

| backend 接口                                  | Agent 工具／调用方              | 最小返回与行为                                                                                           |
| --------------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `PUT /api/household/coverage/:id`             | 批次 B 的最小覆盖登记入口       | 保存用户确认的设备／通道与区域覆盖，不从安装房间自动生成                                                 |
| `GET /api/household/observation-capabilities` | `list_observation_capabilities` | 已实现模板、来源、参数范围与不可用原因                                                                   |
| `PUT /api/household/observation-requests/:id` | `put_observation`               | 新建、修改或 `enabled=false` 撤销；返回可靠保存后的有效版本与额度                                        |
| `GET /api/household/observation-requests`     | `list_observations`             | 当前绑定家庭的请求及暂停／到期原因，有界分页                                                             |
| `GET /api/household/candidates/events`        | Agent 输入适配器                | 当前候选快照、变化、心跳；不是 LLM 工具                                                                  |
| `GET /api/household/context`                  | `get_household_context`         | 按来源／成员／区域选取状态、证据引用、缺失项和各领域版本                                                 |
| `POST /api/household/evidence/read`           | `read_evidence`                 | 给定已发出的引用，单次读取一个已确认表示的有限媒体流；对应不可变描述通过候选／上下文返回，不接受任意 URL |
| `PUT /api/household/assessments/:id`          | `submit_assessment`             | 接纳或拒绝及原因；以稳定结果 ID 去重，返回正式判断与版本                                                 |
| `GET /api/household/assessments/:id`          | 执行器确认回执                  | 同一运行内查询接纳结果，响应丢失不重跑模型                                                               |

接口字段以共用 Zod schema 定义，HTTP 路由只作转换。媒体通过工具内部的有界资源句柄交给模型适配器，不进入普通聊天 JSON、工具文本或日志。证据准备／保留期限遵循[媒体与判断期限](media-perception.md#p5p6-证据登记与提交期限)；流未读完整视为未取得证据，不能发起模型请求。

Agent HTTP 结果提交的公共字段为 `task_id, scope_epoch, evidence_refs, expected_subject_revision, result`，提交 ID 由接口路径提供。`origin` 按来源判别：`observation` 携带 `watch_id, watch_revision, candidate_id, evidence_revision`；`device_event` 携带已接纳的事件身份及规则版本；`interactive` 携带聊天任务与该任务实际取得的证据身份。仅相应来源携带对应字段，不为聊天或设备事件伪造观察请求。来源关联由 backend 已发出的事件、证据记录及调用资格核验，Agent 自报任务身份不构成授权。`result` 按 `scene_assessment / identity_association` 判别；身份只能引用本次允许的成员及证据中同物种目标（按相应生产者的已实现目标定位方式校验），也可返回 unknown；批次 C 接纳后登记出现记录并汇总最后出现位置。backend 校验目标版本、来源、证据与对应任务资格后，在一次领域提交中记录接纳回执并更新判断。观察来源的提交还校验观察有效性，失效观察拒绝其迟到新提交；其他来源按自身资格和期限校验。已经接纳的身份与位置按自身证据策略继续有效，不因停止观察自动抹掉事实。

本地身份候选复用同一身份接纳 schema 与领域操作。生产者按本地模型／Agent 判别，本地分支携带实际本地执行身份、已登记证据、候选版本与参考资料版本，不伪造 Agent `task_id` 或聊天来源。共同身份结果允许匹配成员或 unknown，并保留模型／处理版本与匹配依据；字段在批次 C 定义一次，HTTP 与本地适配复用。证据提交期的容量和资格校验随首次身份路径接入，不等待批次 B 或 Agent 消费；本地来源也不能越过家庭、证据、目标和版本检查。

首期非持久接纳回执只保证当前 epoch 内去重，backend 重启会使旧提交失效。需要跨重启保存的确认记录与回执采用同一数据库事务，成功后再发布；保存结果不确定先核对，不盲目重复累计确认。失败只影响该次语义接纳，不停本地检测。

## 7. 第一方 harness 的执行路径与费用

本节约束后续观察与持续工作的共用执行设施。当前自动化使用有界生成、决策和复核接口，额度与恢复限制见[当前能力](../automations.md#动作与-agent-决策)；尚未统一聊天、媒体补证和全部模型请求的费用账本。

Agent 共用执行入口保留现有对话行为、会话并发、取消及持久执行完成语义，HTTP 路由保留传输职责；后台调查有独立执行上下文，不把后台更新直接追加到用户聊天。当前 `graph/home-agent.ts` 使用 LangGraph，现有聊天通过 checkpoint 保存；后续框架接入时核对已有会话读取与执行边界，不把当前图结构规定为持续工作的唯一实现。新增工具与任务处理接入同一运行设施；现有聊天工具循环不表示已经具备持续工作、主动问询、后台唤醒或执行恢复。按实际来源增加场景、LLM 身份核验、设备事件与定期情景综合任务处理器，均由同一模型适配、预算、工具与追踪设施执行，不建 backend 的 Omni 客户端或另一个外部执行 Agent。主 Agent 按上文的工作与输入契约接续；身份或场景处理器的一次有限调用只是可选步骤，不能把所有开放调查限制为固定分析模板。开放调查的单次执行也须定义调用和时间上限，继续工作通过新输入或已登记等待恢复，不能无限延长一次执行来绕过预算。

### 持续责任、会话与模型上下文

持续身份与责任、会话历史、本次模型上下文分别管理。`work_id` 及其持久状态承载关注和承诺；会话保存一次交互或调查的消息；模型上下文是本次实际选取的职责、工作状态、相关变化和证据。主 Agent 可以跨新会话继续负责，也可以在已有会话中接续，不以一条长期增长的消息数组定义主 Agent。

事件处理采用分层选择：backend 筛选高频来源并保留证据；Agent 输入适配器按关联工作、输入身份、期限、优先级和预算完成准入；主 Agent 读取相关变化、调查结论和未决问题，调查执行按需读取原始材料。批量合并只减少重复唤醒，不合并独立物理事件或不同问题的回答。输入队列上限只控制待处理量，不能作为已进入模型的历史大小保证。

| 上下文部分               | 本次输入与保留方式                                                             |
| ------------------------ | ------------------------------------------------------------------------------ |
| 稳定职责、能力与有效约束 | 按执行角色加载；家庭要求读取 backend 已接纳版本，不由聊天摘要代替              |
| 持续工作与待回答问题     | 选取相关工作的最新状态和问题身份；持久原记录独立于消息历史                     |
| 当前家庭状态与近期变化   | 按对象、时间和质量有界查询，附版本、证据与覆盖缺口；不重复追加全屋快照         |
| 调查执行与结果           | 调查使用独立上下文；回传结论、证据引用、未决事项和后续需要，不复制全部工具结果 |
| 历史经历与长期记忆       | 按任务检索；摘要可作为背景和导航，具体判断仍引用可核对证据                     |

入口筛选、任务分流、独立会话、当前状态替换、近期范围限制和按需检索共同控制上下文。摘要与会话压缩可以辅助控制输入大小，但不代替事件准入、证据保留或工作状态；无摘要、换会话或历史被裁减时，已接纳承诺与待回答问题仍须可恢复。摘要不是新独立证据，也不能刷新原观察时间或掩盖来源缺口。

首个工作场景定义各输入部分及整次模型请求的 token／字节上限、选择顺序和不足时的处理，记录实际读取范围与裁减。换会话前保存可恢复的进度、等待和必要引用；不能以删除会话并重跑的方式恢复结果不明的付费调用或外部动作。运行框架自身的压缩、裁剪及历史加载行为在选型时核对，不因使用持久会话或较大窗口就宣称上下文受控。外部参考见[MiLoCo 的会话与上下文管理](../references/miloco-perception.md#agent-事件会话与上下文管理)。

### 有限分析与请求预算

聊天入口可以理解目标、调用观察工具、查询已接纳状态；后台入口直接带类型化任务进入对应处理器，不先花一次模型调用解释事件。启用的 LLM 身份核验默认一次结构化多模态调用；场景任务按明确需要允许有限补证。每次自动执行先准备不可变的输入证据及其最晚提交时间；60 秒运行期限不延长观察或证据的截止时间。相同媒体、期限与上下文可兼容时可以合并场景和身份请求，否则各自准入，不强制每次核验都做场景分析。

LLM 身份核验只携带定位清楚的代表帧、必要全景及候选参考资料，屏蔽该目标此前的身份猜测和习惯先验；位置与场景推理才按任务加入已接纳判断和其他设备证据。统一 harness 不意味着共享全部提示词或会话。模型返回理由及置信分数仅是候选说明，不作为准确率或自动入样本库的证明。

初始工程配置如下，随真实素材测量调整，不表示性能保证或固定费用承诺：

以下输入与调用上限仅约束 Agent 的 LLM 路径；本地身份执行的图片、参考特征、并发与时限按实际模型另行配置和验证，仍计入宿主总资源预算。

| 对象             | 初始设置                                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Agent 总执行并发 | 2；后台最多 1，给用户交互留出执行名额                                                                                                           |
| 身份任务等待     | 最多 32 项／2 MiB；以证据截止时间为硬边界，满额拒绝并计数                                                                                       |
| 每问题执行       | 最多 1 个在途和 1 个待更新；未知后至少冷却 60 秒，且必须有实质新证据                                                                            |
| 一次身份模型输入 | 最多 3 张目标代表帧、每候选成员最多 2 张参考图、最多 4 个候选成员；合计编码媒体最多 8 MiB                                                       |
| 模型与任务期限   | 单次多模态模型请求最多 30 秒；一次有限执行最多 60 秒，包含媒体、模型、提交和执行状态保存；提交还受 backend 单独期限限制，持续工作和等待寿命另定 |
| 调用次数         | 身份任务最多 1 次实际模型请求；场景任务最多 2 次；失败执行不自动完整重跑                                                                        |
| 自动调用预算     | 默认关闭；启用前由部署者设定小时／日请求上限及输入／输出预算，模型不能调高                                                                      |

参考成员多于输入上限时必须说明候选不完整，不能强选最近似成员；模型可返回“不在候选内”。没有足够候选筛选依据时跳过自动核验或通过明确用户任务缩小范围，不把成员上限伪装成完整家庭资料。

harness 所有实际模型请求共用预算入口，包括聊天、补证和周期复核；自动任务另受自动调用额度限制，用户交互不因自动额度耗尽而绕过总额度。SDK 自动重试关闭，一项任务失败后不重复请求。小时／日预算的已用量由 Agent 持久化，发送前预留次数，超时结果不明仍计入；重启不清零，存储不可用时不发新的付费请求。token 预估与供应商用量分开记录，无用量报告时不宣称精确费用。

### 模型故障与恢复

模型返回未知属于合法判断，等待实质新证据。传输失败、限流与配置错误分别记录，并结束本次任务，不退避、不重投、不轮询补查结果。限流期间拒绝新的调用，配置错误等待修正；后续只处理新的有效任务或正常周期，不补跑失败任务。取消传到底层，实际调用结束前仍占并发名额。模型故障不停止 backend 情景有效性维护或已启用的即时策略。

### 设备事件输入

当前规则已消费具备资格的实时属性、时间条件和AI 判断条件；米家独立设备事件 `siid/eiid` 尚未接入，见[当前事件边界](../automations.md#保存恢复与接口)。设备规格声明事件存在不表示来源可用，不能把属性同值上报当作独立物理事件。

后续按[设备采集计划](device-collection.md)核实按钮、门铃、出粮完成等真实来源的身份、时间、重放、去重和使用限制，再以稳定事件身份进入现有接纳边界。临时断流使当前资格和连续性失效，但不改写已交付的历史证据；来源缺口如实保留，不承诺零漏报。

需要分析的来源输入交给 Agent 共用执行边界，携带原设备事件、来源质量、采样区间、规则版本和最晚接纳时间，不伪造 `watch_id`。若增加短期 `semantic_event` 通知流，它只表示分析候选，不能替代已登记的家庭事件或可靠工作交接；SSE 本身不保证重放，关键输入必须持久接纳并可查询回执。

设备场景模板沿用现有规则和维护定义，不新增本机文件中的另一份规则配置。视觉补证、一次性读取和历史查询只在场景明确许可且对应能力已交付时注册。验收须覆盖真实触发、同值独立事件、缺口、重复和重启，以及最终判断／输出可用；无摄像头场景不等待媒体或身份能力。

## 8. 数据保存与长期记忆

| 数据                                   | 所有者与存储                                                                                                                                 |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| backend 长期自动化、家庭事件及动作记录 | backend 数据库保存定义与依赖、事件及修正、待评估项与处理终态、触发变化、决策请求及回执、期限依据、动作意图和结果，不以 Agent checkpoint 代替 |
| 当前情景判断                           | backend 维护有效视图，保存所需证据摘要与版本；重启核验来源和依赖后才作为当前判断                                                             |
| `household_observations`               | backend 数据库：观察模式、用户／部署来源关联、版本、临时期限及启停意图；不保存每次执行状态                                                   |
| 成员档案、参考样本及元数据             | backend 数据库保存身份、版本和来源；受控本地文件保存图片，按样本资格与容量清理                                                               |
| 活动轨迹、外观特征、核验候选           | backend 有界内存；按来源和证据期限清理，非永久成员身份库                                                                                     |
| 当前关联、位置及关键确认／纠正         | backend 维护当前视图；需要恢复解释的记录保存到数据库，重启只恢复“最后已知”                                                                   |
| 持续工作、问题与可靠输入               | Agent 运行层持久保存 work/question 身份、版本、进度、等待、回答、交接回执及唤醒；不复制 backend 配置或家庭事实                               |
| 一次调查／分析执行与结果               | Agent 所选运行框架保存输入快照、执行状态、结果及 work/task/watch 等实际关联；现有聊天仍使用 LangGraph checkpoint，不直接覆盖家庭状态         |
| 请求预算账本                           | Agent 持久业务存储保存窗口及预留次数，不伪装成框架执行状态                                                                                   |
| 习惯、偏好与经验推断                   | Agent 长期记忆，后续单独实施；引用 backend 经历并保留反例与修正，不作为实时身份依据                                                          |

首期人类成员及猫狗资料由用户明确登记；不自动把陌生人命名或将一次模型判断保存为永久训练样本。动态身份关联的可用时间与参考样本保存时间分开，参考资料可以长期保存，但不能因此证明成员现在仍在家。

用户撤销观察停止该观察的新任务，并重评依赖长期任务的健康与执行资格；删除成员参考资料使依赖该版本的核验和关联重新检查。保存必要记录不要求设备历史计划保存全部设备观测，也不建设逐帧轨迹历史。原始媒体短期释放后仍须能解释已接纳结果的来源和范围。

## 9. 实施顺序与改动位置

批次 C 的[本地人物参考、当前关联](../perception.md#持续成员身份分析)已实现，人物关联已生成成员页观察记录；最后出现房间汇总及其他历史纠错仍待实施。现有本地能力不依赖 Agent 观察任务、候选订阅、模型预算或 HTTP 提交回执；本章人宠双生产者机制属于后续扩展。家庭改绑清空成员及参考、现有轨迹采样和来源配置仍按当前功能文档执行，不增加多家庭资料保留或无轨迹识别入口。

本地人体外观归因作为批次 C 的增量，当前代码与未启用限制见[家庭短期人体外观参照](../perception.md#家庭短期人体外观参照)，剩余校准与专项验收见[成员短期外观归因](member-attribution.md)。它可在任意来源确认后由任意来源使用短期参照，不依赖房间汇总或 Agent；批次 E 的通行事件与进一步跨镜头优化仍独立安排。

按下表实施，各批按实际依赖接入。B 只依赖 A 中纯视频 P4 的证据能力；C 依赖可读画面、成员参考与身份接纳；本地路径可在 B 之前或与 B 并行交付，按需接入最小覆盖、本地身份配置与证据接纳，不要求通用观察任务、场景判断或 Agent 工具先完成；后续 LLM 路径另依赖 Agent 执行设施；当前本地身份使用已实现的 P2 人体轨迹，不依赖跨镜头关联；其他物种按其实际接入方式验收。下一步先完成 P4 的无 Agent 证据出口，跟踪的实景验收按媒体计划继续。编号仅属于本文的交付批次，不改变已有本地能力的完成状态。

D1 的基础能力已接入，剩余验收与扩展不阻塞 D2 的首个网页工作闭环。D2 按需引用现有设备事实、自动化与动作回执；持续工作的计划和等待由 Agent 拥有，自动化定义与执行资格由 backend 拥有。当前聊天工具仅保存停用草稿，D2 需要的工作授权和动作接口须另行落实，不能借现有工具绕过启用边界。

B 的共用执行边界接入时即核对持续工作的原生能力，不为有限分析先自建一套通用执行器。D2 落实运行框架对持久工作、等待、输入接纳、结果回传与恢复的原生支持，不以当前 LangGraph 图或 backend 调度库锁定 Agent 选型。先用网页完成“关注 → 调查 → 主动问询 → 回答改方向 → 等待新证据 → 继续”的闭环；文本问询不等待音箱、语音或全屋身份能力。语音问询随后接入实际输出渠道、播放结果与回答关联，不把转写入口当作闭环。工作与动作可复用同一数据库，但唯一所有权分别保留。

当前周期复核只消费选定设备属性和近期事件；扩展猫饥饿等场景须先验证进食及行为来源，不凭通用总结宣称有效。

D1 中遛狗播报依赖真实遛狗证据和播报适配；按位置选音箱还须另行验证当前位置与时效规则，C 的最后出现记录不能单独满足该条件；猫狗与危险场景分别验证来源和候选覆盖，不以通用场景描述验收代替。现有网页通知记录不依赖身份；实际播报仍须验证渠道，无需等待跨镜头优化。真实动作按设备／渠道验收后启用；危险监测另核对漏检、误报和端到端延迟，不能沿用普通场景筛选直接宣称支持。

P3 音频及设备事件按场景需要接入共用入口。无摄像头卧室依赖真实设备集采和相应判断规则，不假设已有视觉覆盖；不必等待摄像头或身份能力。

## 10. 分阶段验收

已有[本地人物身份能力的验证范围](../perception.md#身份验证范围与限制)不覆盖出现记录、房间汇总、历史纠错、聊天、Agent 调用或双生产者场景。以下清单覆盖更广的 B/C 目标，只在对应能力实施时执行。使用真实授权来源和现有聊天 API、HTTP 查询及执行记录验收；本设计不授权新增测试代码或实机设备动作。首期 B/C 按下列观察与判断条件验收；真实动作在具体设备／渠道和相应授权范围内单独验收。

- [ ] 基础维护经一次启用可跨日持续并在重启后重新核验恢复；临时观察按期结束，不能自动转为基础维护。
- [ ] 占用与休息分别维护；同值、无变化与持续可见不延长活动判断，过期不变成无人休息。
- [ ] 真实占用事件读取已有情景产生策略处理记录；暂停 Agent 或让模型任务尚未结束时仍可处理，不发送设备命令；未知、冲突与过期分支可核对。
- [ ] 观察、设备事件与聊天来源可分别提交适用判断，不伪造 watch 或候选；证据缺失与任务资格失效时拒绝。
- [ ] 聊天创建、修改、停止观察后，backend 的保存回执、有效参数和实际行为一致；未支持模板及来源不能假装成功。
- [ ] 没有任何已启用自动任务来源（观察、设备事件或语义任务），或者未启用自动预算时，P1/P2/P4 继续，自动模型请求为零；Agent 不在线不影响本地链路。
- [ ] 已接纳的同一证据、同值上报、仅新帧编号变化不重复核验；冷却到期而无新证据也不调用。
- [ ] 本地模型与 LLM 可独立启用或并行运行；本地身份不依赖场景变化放行、视频编码或 Agent 在线；未启用／失败不隐式转交另一生产者。
- [ ] 同一底层证据的双生产者结果不重复计数或刷新观察时间；分数不跨模型直接比较，冲突不按返回顺序覆盖，无裁决规则时保持未知或争议。
- [ ] 同镜头多人、多只猫狗分别获得候选处理；身份候选按物种过滤，跨镜头重复证据不会按每帧重复计费，证据不足时不强行合并成员。
- [ ] 猫狗的检测、连续轨迹与已登记个体身份分别核对；同类宠物交叉、遮挡、重入或类别抖动后不盲目延续身份，未知宠物仍可参与适用的区域级场景。
- [ ] 未知目标模糊时不调用，取得合格新画面后可进入核验；场景无变化不阻挡已启用的身份质量筛选。
- [ ] 本地跟踪未成立或失效时保持未知；已取得的原时段证据不因目标随后结束而被改写。改绑、撤权、观察修改及参考资料变更按接纳资格检查，迟到结果不覆盖更新观察。
- [ ] 重叠视野不制造位置冲突；镜头覆盖未知或媒体时间不可靠时保留限制，不补造跨房间路径。
- [ ] 媒体在模型返回前淘汰，仍可在证据提交期内核对结果；超期、重复提交及回执丢失分别处理。
- [ ] backend 重启恢复观察意图但重建运行资格；Agent 重启不清空付费预算、不重跑过期任务；断线恢复查询当前候选。
- [ ] 用户可查询人及猫狗的最后出现房间及原时间；更新观察区域未知时保留其未知事实和较早的最后已定位记录。断流不生成离开，身份纠正重算汇总，最后出现不当作当前仍在。
- [ ] 每次调用关联实际任务来源、适用的 watch／候选、证据版本、task、结果接纳状态与策略版本；记录跳过原因、实际请求数和可得用量。

### D1 规则树自动化验收

基础实现与已覆盖验证范围见[当前能力](../automations.md#验证范围与限制)。这里只保留真实场景验收和未交付扩展，不以静态检查或隔离数据库通知闭环代替实机结论。

- [ ] 在浏览器与真实模型下验证创建、自然语言修改、保存、重新加载、角色切换及解释一致性；歧义返回澄清，聊天不能启用规则。
- [ ] 以缓存基线和实际设备上报验证进入、退出、持续、状态阻断、未知恢复、OR 触发分支和时间边界；缓存更新不得自行触发，执行排队期间跨阶段失效不得放行旧触发。
- [ ] 分别验收米家属性写入与动作调用、离线／撤权／家庭切换，以及供应商接纳后的实际效果；结果不明不能盲目重发。
- [ ] 使用真实模型核对 Agent 动作选择和周期复核的证据正确性、费用、取消、服务中断与稳定请求恢复；未接纳、运行中和结果不明分别处理。
- [ ] 补齐语义判断的支持更新、冲突、结束、纠正、撤回及过期，旧推断不循环佐证自身；同一迹象升级与重新成立具有可验证依据。
- [ ] 补齐语义判断同时附处置请求，与事件消费共享触发及动作身份；并发接纳不发布部分成立结果、不重复提醒。
- [ ] 依赖维护停用、来源撤权、模型离线、预算耗尽或健康摘要过期时，显示受影响分支；来源不可用与当前值未知分别表达。
- [ ] 真实遛狗、进食等事件与活动期限按原发生时间计算；重复、迟到、纠正及重启后先重算，不按旧期限提醒。
- [ ] 接入实际通知／播报渠道，按有效位置选择音箱和备用方式，核对播放结果；不以网页记录成功代替已经听到。
- [ ] 猫狗、区域进入及开放异常各自验证来源覆盖、语义效果、误报、漏报、费用和端到端延迟；无媒体或身份依据时不得扩大结论。

### D2 Agent 持续工作与问询验收

- [ ] 关注事项跨多次有限执行和重启保留；调查结束与持续责任完成分别表达，停止或到期按明确规则结束。
- [ ] 等待用户回答或家庭变化时释放执行资源，仍可处理其他工作；调查结果可靠唤醒所属工作并改变下一步。
- [ ] 网页主动问题已保存且实际可见；回答可补充信息、追问、改变目标、取消或另起话题，旧版本和迟到回答不恢复错误工作。
- [ ] 语音回答结合问题与实际投递关联；“好”“先不要”等不被独立请求分类丢弃，身份和归属不明时澄清。
- [ ] 用户输入、回答和调查结果在接纳后可恢复；回执丢失、重送、容量不足及服务重启不重复付费执行或投递动作，未知结果先核对。
- [ ] 短期候选缺口如实显示；关键业务事件走持久交接，SSE 断线不冒充可靠接纳。
- [ ] 工作、backend 自动化与观察分别有唯一所有者；修改和停止核对各自回执，共用观察不因单个工作结束被误停。
- [ ] 无完整家庭情景或无 backend 语义结论时仍能按已授权证据调查；无新价值时静默，通知按约定条件和渠道交付。
- [ ] 大量来源变化只产生有界候选与相关工作输入，不逐条追加到主会话；队列容量、已加载历史和模型上下文预算分别核对。
- [ ] 换会话、裁减或摘要缺失后，承诺、问题和等待仍可恢复；调查只回传必要结论和引用，按需查询原证据。
- [ ] 输入选择与裁减保留范围和缺口；摘要不作为新证据或执行授权，结果不明不靠重建会话自动重跑。
- [ ] 改绑清理工作、问题、输入和唤醒；重启核对家庭资格、工作版本及动作结果，不恢复旧家庭承诺。

“协同进化”的验收是：同一场景能比较不同 Agent 提示词／上下文／工具策略与本地筛选策略的组合，定位误认或费用来自哪一步；调整策略无需把 backend 变成另一套语义模型服务。运行指标不证明长期准确率，模型及本地关联阈值仍须在本项目真实条件下验证。

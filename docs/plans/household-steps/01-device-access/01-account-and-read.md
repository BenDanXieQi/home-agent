# 任务 1.1：统一账号、目录与属性读取

[阶段入口](README.md) · [目录职责](architecture.md) · [协议参考](reference.md)

当前已实现统一账号／目录及正式内部属性读取。代表设备读取和在线摄像头联合通路具有实机证据，跨账号替换等场景仍未验证；不把实现审查扩大为实机通过。

## 当前实现

- `MijiaService` 持有已接纳账号及凭据提交；`account/maintenance.ts` 管理恢复／续期任务，`account/session.ts` 准备候选。扫码尝试失败或取消不替换当前可用账号。
- 家庭运行时持有已提交业务目录与规格；`DeviceDiscovery` 获取完整云端目录并维护供应商访问索引，确认撤销时立即取消访问。持久家庭选择限制所有设备访问。
- `readProperties(properties, signal)` 校验明确设备集合和 readable 规格，复用当前 MiCloud 实例的 Cookie、serviceToken、ssecurity 与 RC4 请求 `/miotspec/prop/get`。不新增读取专用授权、HTTP 路由或周期轮询。
- 规格预检按设备分组，只读家庭模块已准备的能力，不在属性请求中获取云端规格。家庭模块按 model／URN 共享规格并限制三组并发准备；协议客户端内的相同在途请求合并，各调用者可独立取消。可选翻译失败或耗尽自身预算时仍保留已取得的能力规格。
- 所有属性读取共用串行批次，每批最多 150 项、单次 HTTP 最长 30 秒。预算覆盖传输和响应体，不包括规格预检、排队或多批次总耗时；调用方可提前取消。
- reader 按稳定来源遵守 `Retry-After`，等待期间返回未发送的逐项观测，不隐藏重试；账号恢复与续期也遵守最早重试期限。超长计时分段调度。
- 逐项结果匹配本批地址，按[返回码规则](reference.md#属性读取返回码)判定；缺失 value 不补 null，部分失败不清除成功项。
- `datasource=1` 是缓存优先、未命中可能触发 RPC；结果保守标为 `baseline/cloud_cache`、`observed_at=null`，保留请求开始和接收时间，不宣称设备实时观测。
- 请求前及异步交付前重验账号、读取范围和设备归属。会话撤销、家庭变化、设备移除或规格／型号变化使旧结果失效；同账号续期保留稳定来源身份。

详细字段、适用型号和供应商依据统一维护于[米家来源契约](../../../mijia-source-contract.md)。

## 已有证据及边界

| 能力               | 实机证据范围                                                | 仍不能据此保证                                       |
| ------------------ | ----------------------------------------------------------- | ---------------------------------------------------- |
| 保存账号恢复与目录 | 原账号恢复、家庭及设备目录同步                              | 跨账号替换                                           |
| 指定属性读取       | 灯、空气检测仪、温湿度计、人在传感器的 13 项属性成功        | 其他型号、网关、固件及值的新鲜度                     |
| 逐项失败隔离       | 同批普通失败负码和成功项并存                                | 接受类负码、非失败码缺值的真实供应商样本             |
| 同账号续期         | 正式续期后旧实例拒用、新实例读取成功                        | 自然定时触发、供应商真实认证拒绝及限流               |
| 取消及关闭         | 正式读取取消、退出／关闭期间的在途读取撤销                  | 精确竞态分支的实机覆盖；这些仍需实现审查或确定性验证 |
| 超时               | 调用方期限终止真实云请求、go2rtc 默认超时                   | 云属性请求自然耗尽默认 30 秒                         |
| 摄像头播放及释放   | C700 单摄、C500 双摄出帧；C500 两镜头共享物理连接并独立释放 | 离线摄像头、其他型号取流、跨机器连接共享             |
| 退出与媒体清理     | 授权删除、目录清空、播放资源撤销；go2rtc 故障后的清理重试   | 供应商所有异常组合                                   |

单个播放资源收到 DELETE 后立即撤销本地观看资格，GET 返回 404；远端清理完成前保留待清理状态。同一资源的并发 DELETE 合并，失败后可再次 DELETE，并在既有成功心跳后重试；整段媒体会话删除确认后清除对应待清理记录。

`logout` 仅在授权撤销与远端媒体清理成功后报告成功。清理失败不恢复已经撤销的账号，保留可重试状态；go2rtc 租约提供最终回收机制，但不代替主动清理成功确认。

实机证据保存在 Git 忽略的 `data/verification/household-access/<run_id>/report.json`，格式和使用方法见[共同参考](reference.md#验证规范)。共享文档仅维护当前能力结论及限制，不保存逐次运行流水。

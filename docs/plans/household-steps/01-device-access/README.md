## 账号接入前提

现有米家扫码流程是唯一用户登录入口。`MijiaService` 统一管理 MiCloud 与 OAuth 凭据的保存、恢复、续期和清除，目录、属性读取、属性／在线推送及媒体使用同一账号身份，不新增独立登录入口或第二套 token 仓库。

扫码成功后，后端完成 OAuth 授权并取得 MQTT 所需 token，无需第二次扫码或额外授权页面。Cookie 不能作为 MQTT 密码，连接成功不能代替实际订阅与收包证据。当前接入采用 MiLoCo 应用参数；Home Agent 自有应用准入仍未验证，具体条件见[来源契约](../../../mijia-source-contract.md)。

MiLoCo 用于核对属性语义、消息、订阅和恢复行为，不要求照搬其用户登录方式。其只读 checkout 由 `AGENTS.local.md` 指定；实现及审查遵守仓库 `AGENTS.md`。

## 共同范围

- [目录架构](architecture.md) 规定当前模块、所有权和依赖；[共同参考](reference.md) 保存协议依据、来源契约及验证规范。
- 家庭运行时是已提交业务目录与规格的所有者；`DeviceDiscovery` 获取云端目录并维护访问索引。持久家庭选择限制设备访问范围，读取与观察只接受经当前范围校验的明确设备集合。
- 接入层提供指定属性读取、属性／在线订阅、连接恢复和取消，不拥有家庭 latest、availability、属性版本仲裁或历史数据库。
- [Step 2](../02-household-runtime.md) 已实现家庭运行时、目录持久化、后台规格及 SSE 公共状态订阅；Step 3 的自动采集／上线补缺／重连补读尚未实施。
- 独立设备事件和带 `/` 的 did 没有已验证接入通路，不伪造支持结论。手机、视觉等其他来源不阻塞本阶段。

## 阶段验收要求

账号与设备目录各有一个业务所有者；扫码登录、设备／规格读取、摄像头播放与释放、属性读取、MQTT 属性与在线推送、连接恢复及同账号续期须联合验证。不能以单个 topic、编译通过或模拟数据代替全部通路的实机证据。

实机结论限定于[来源契约](../../../mijia-source-contract.md)所列型号及条件，无法触发的场景保留未验证。读取结果可保持“云端最后已知值、设备时间未知”，不冒充实时设备观测；局部失败不得关闭其他已可用来源。

读取无法安全使用当前扫码账号、MQTT 鉴权及基本推送未验证，或活动／失效实例不能隔离时，不得宣布本阶段通过。剩余联合验收项目集中维护于 [03-recovery.md](03-recovery.md#待完成的联合生命周期验收)。

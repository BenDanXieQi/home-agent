# Step 1：统一米家设备接入

[返回总览](../../backend-household-perception.md)

目标：复用现有米家扫码会话，将设备目录、视频与属性读取／推送整合为统一米家接入层。属性读取沿用现有 MiCloud 凭据；MiLoCo 作为属性语义、推送及恢复行为参考，MQTT 鉴权与当前会话的适配须单独核实。Step 1 是一个阶段，以下每个编号文件是一次独立任务，按顺序在新上下文执行。

| 顺序 | 任务文件                                           | 本次完成后具备什么                                       |
| ---- | -------------------------------------------------- | -------------------------------------------------------- |
| 1.1  | [统一账号、目录与属性读取](01-account-and-read.md) | 统一目录组织与账号管理，已有目录／视频正常，新增属性读取 |
| 1.2  | [属性与在线推送](02-mqtt-push.md)                  | MQTT 连接、订阅确认、真实属性及在线消息                  |
| 1.3  | [MQTT 最小连接恢复](03-recovery.md)                | 1—120 秒退避、活动观察重订及取消停止重试                 |

## 账号接入前提

复用 Home Agent 已有的米家扫码登录流程及其保存、恢复、续期和退出机制，是任务 1.1、1.2、1.3 与后续家庭功能的共同前提。现有扫码流程是唯一用户登录入口；目录、属性读取、属性／在线推送和媒体由同一账号所有者协调，不新增独立 OAuth、额外授权页面、第二套 token 仓库或账号生命周期。

扫码成功后由后端完成 OAuth 授权并取得 MQTT 所需 token，和 MiCloud 会话统一保存、恢复、续期及清除；无第二次扫码或独立授权页面。当前账号与 MiLoCo 应用参数下的 MQTT 连接已实机验证，任务 1.2 已完成正式内部观察、订阅确认与属性推送验收；床头灯在线／离线通知也已实机验证，其他型号保持具体适用范围。Cookie 不能作为 MQTT 密码，连接成功不能替代实际订阅与收包证据。

MiLoCo 用于核对属性语义、消息、订阅与恢复行为；参考其能力不要求照搬其登录方式。

## 新上下文如何执行

把对应任务文件交给新任务即可，例如：“执行 docs/plans/household-steps/01-device-access/01-account-and-read.md”。任务文件列明必读材料、前置条件、范围和完成条件，无需依赖聊天历史。

每次先遵守仓库 AGENTS.md，读取 AGENTS.local.md 获取只读 MiLoCo checkout；参考已核实的源码，不重新设计小米协议。前置交付以工作区实现及验证报告为准，不只看勾选状态。完成当前任务后停止，由用户新开上下文推进下一项。

## 共同范围

- [目录架构与迁移安排](architecture.md) 规定最终目录、所有权和依赖；三个任务执行前均须读取相关职责。

- [共同参考](reference.md) 集中保存源码映射、协议参数、来源契约及验证报告格式，三个任务不各自复制或重定这些规则。
- 目录、属性读取、推送与媒体遵守上述账号接入前提，由唯一账号所有者协调。任务 1.2 在复用已有登录流程的约束下核实 MQTT 凭据与准入条件，不能把额外 OAuth 作为实施分支。
- 本阶段不引入 XState、SSE、历史数据库或独立设备事件接入；现有家庭选择约束接入范围，家庭运行时归 Step 2；自动初始化、上线补缺、重连补读、属性版本仲裁及 availability 归 Step 3。Step 1 只提供指定设备／属性的读取、订阅、连接恢复和取消能力。
- 对齐接入通路，不冒充已经完成家庭语义；手机、视觉等其他来源另做，不阻塞本阶段。

## 阶段完成条件

**完成条件：** 目标目录重构完成，账号与设备目录只有一个业务所有者，现有扫码登录、设备／规格读取、摄像头播放与释放通过联合验收；同一 MiCloud 会话的缓存属性读取、完成鉴权核实的属性推送、在线通知订阅、重连重订、指定属性重新读取及取消入口均有实现；以实际设备完成三条设备通路及连接恢复场景的实机验收，同账号续期后通路恢复。不能仅一条读取或一个属性 topic 成功就宣称全部接入能力可用。现场无法触发的在线／离线或续期场景列为未验证，不能标成整体实机验收完成。独立设备事件和带 / 的 did 是参考实现缺口，不伪造通过；其他设备的局部失败不关闭已经可用的来源。本步读取结果可以保持“云端最后已知值，设备时间未知”，不要求变成设备实时观测。

**失败门槛：** 读取不能安全使用当前扫码账号、MQTT 鉴权与属性推送基础通路未验证可用，或活动／失效实例无法隔离时，本阶段不能通过。推送及在线通路未验证不阻断任务 1.1 的读取实施与验收；独立设备事件缺少参考实现不阻塞已有三条设备通路。后续集采不以属性轮询绕过接入失败。

三项任务全部通过后，进入 [Step 2](../02-household-runtime.md)。

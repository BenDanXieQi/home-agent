# Step 1：MiLoCo 设备接入

[返回总览](../../backend-household-perception.md)

目标：将现有登录、设备目录和视频与新增 OAuth、属性读取／推送整合为统一米家接入层；小米接入协议按 MiLoCo 对齐。Step 1 是一个阶段，以下每个编号文件是一次独立任务，按顺序在新上下文执行。

| 顺序 | 任务文件                                           | 本次完成后具备什么                                       |
| ---- | -------------------------------------------------- | -------------------------------------------------------- |
| 1.1  | [统一账号、目录与属性读取](01-account-and-read.md) | 统一目录组织与账号管理，已有目录／视频正常，新增属性读取 |
| 1.2  | [属性与在线推送](02-mqtt-push.md)                  | MQTT 连接、订阅确认、真实属性及在线消息                  |
| 1.3  | [恢复与生命周期](03-recovery.md)                   | 连接恢复、重订及登录／目录／属性／视频联合验收           |

## 新上下文如何执行

把对应任务文件交给新任务即可，例如：“执行 docs/plans/household-steps/01-device-access/01-account-and-read.md”。任务文件列明必读材料、前置条件、范围和完成条件，无需依赖聊天历史。

每次先遵守仓库 AGENTS.md，读取 AGENTS.local.md 获取只读 MiLoCo checkout；参考已核实的源码，不重新设计小米协议。前置交付以工作区实现及验证报告为准，不只看勾选状态。完成当前任务后停止，由用户新开上下文推进下一项。

## 共同范围

- [目录架构与迁移安排](architecture.md) 规定最终目录、所有权和依赖；三个任务执行前均须读取相关职责。

- [共同参考](reference.md) 集中保存源码映射、协议参数、来源契约及验证报告格式，三个任务不各自复制或重定这些规则。
- 保留现有扫码目录与媒体职责；新增 OAuth 用于属性读取与 MQTT，统一由现有账号所有者协调。
- 本阶段不引入 XState、SSE、历史数据库或独立设备事件接入；家庭选择与运行时归 Step 2；自动初始化、上线补缺、重连补读、属性版本仲裁及 availability 归 Step 3。Step 1 只提供指定设备／属性的读取、订阅、连接恢复和取消能力。
- 对齐接入通路，不冒充已经完成家庭语义；手机、视觉等其他来源另做，不阻塞本阶段。

## 阶段完成条件

**完成条件：** 目标目录重构完成，账号与设备目录只有一个业务所有者，现有扫码登录、设备／规格读取、摄像头播放与释放通过联合验收；OAuth 授权、uid 绑定、缓存属性读取、属性推送、在线通知订阅、重连重订、指定属性重新读取及取消入口均有实现；以实际设备完成三条设备通路及连接恢复场景的实机验收，同账号续期后通路恢复。不能仅一条读取或一个属性 topic 成功就宣称 MiLoCo 接入能力对齐。现场无法触发的在线／离线或续期场景列为未验证，不能标成整体实机验收完成。独立设备事件和带 / 的 did 是参考实现缺口，不伪造通过；其他设备的局部失败不关闭已经可用的来源。本步读取结果可以保持“云端最后已知值，设备时间未知”，不要求变成设备实时观测。

**失败门槛：** OAuth 身份不能绑定当前账号、属性推送基础通路不可用，或活动／失效实例无法隔离时，本步不能通过。在线通路暂未验证时可继续完成和验证其他实现，但不能宣称本步全部对齐；独立设备事件缺少参考实现不阻塞已有三条设备通路。后续集采不以属性轮询绕过接入失败。

三项任务全部通过后，进入 [Step 2](../02-household-runtime.md)。

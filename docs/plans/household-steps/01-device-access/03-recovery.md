## 本次范围

统一登录、目录、属性和视频的连接生命周期，验收真实通路恢复。没有家庭 latest，不实现“哪些值缺失”“哪些属性待确认”、availability 或属性版本仲裁。家庭初始化、上线补缺、重连自动补读及其验收全部归 Step 3。

## 实施清单

- [ ] 接入单一重连任务，按参考 1—120 秒退避；连接恢复后重订仍然活动的观察设备集合，输出逐 topic 确认结果，不叠加库自动重连／重订。
- [ ] MiCloud 会话续期后，目录与属性读取使用新会话，旧会话的读取不得提交。按任务 1.2 已核实的会话复用方式接通 MQTT 凭据更新及重连重订；认证失败交还现有账号所有者，不引入独立 OAuth 续期器。目录变更、扫码会话恢复或显式重试触发订阅对账，不另造按秒重试器。
- [ ] 统一账号退出、身份更换、设备访问撤销及观察取消的处理：撤销对应请求、订阅、播放与定时任务，旧实例的读取结果／消息／确认不得继续交付。
- [ ] readProperties 与 observeDevices 返回连接身份、来源、请求／接收时间和逐项结果；读取后不改写任何家庭值。不同通路的成功分别表达，连接恢复不等于所有订阅成功。

## 实机验收

- [ ] 按共同参考的正式内部入口，以本机报告中明确的设备集合验收，不创建临时家庭选择、状态容器或验收接口。
- [ ] 验证断线后的实际重订及真实属性／在线消息再次到达。记录断线前后观察到的消息，不推断期间发生过的完整变化。
- [ ] 连接恢复后显式调用 readProperties 重新读取同一组属性，证明缓存读取通路恢复；没有“只补缺值”或自动补读判定，不宣称业务状态已恢复。
- [ ] 联合验证进程重启、扫码凭据续期、已启用 MQTT 凭据的更新、属性读取／MQTT／go2rtc 局部故障、退出及换账号；实际观察摄像头出帧、播放释放和旧账号资源清理。
- [ ] 检查部分读取／订阅失败、身份不匹配、旧实例拒收及取消清理。按总览区分实机与实现审查证据，不新增测试。
- [ ] 保存 task_id=1.3 报告，汇总前两项实机结果；更新来源契约与真实限制，执行 [总览共同检查](../../backend-household-perception.md#每步共同检查) 和 [阶段完成条件](README.md#阶段完成条件)。

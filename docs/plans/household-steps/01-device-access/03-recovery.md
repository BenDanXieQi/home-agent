# 任务 1.3：MQTT 连接恢复

[阶段入口](README.md) · [读取能力](01-account-and-read.md) · [推送能力](02-mqtt-push.md)

当前已实现最小连接恢复。该能力不等于整个阶段的联合生命周期验收全部完成，也不包含家庭状态恢复。

## 当前实现

- `properties/observation.ts` 持有活动观察集合及唯一重连计时器。断线按 1、2、4…120 秒退避；连接成功重置为 1 秒。MQTT 库的自动重连和重订关闭。
- 新连接重新订阅仍活动的设备集合和目录通知主题，重新取得逐 topic 确认；旧连接的迟到消息和确认不能进入新代次。
- 每次连接从 service 获取当前 OAuth 凭据。同账号 MiCloud 续期保留观察；OAuth token 更新时重建 MQTT。
- 明确认证拒绝暂停普通重试并交回已有账号维护，强制刷新被拒绝 token。拒绝状态跨在途续期及 `Retry-After` 等待保留；刷新仍返回被拒绝 token 时进入重新认证。
- 目录通知与属性观察共享连接；最后一个观察（含目录通知）取消时关闭连接、清除计时器，保留当前账号作用域内的永久订阅拒绝；退出账号或撤销作用域才清除这些记录。空闲时凭据更新只清除旧拒绝和认证错误，不建立连接。回调内同步取消也清理刚建立的观察绑定。
- 观察接纳使用设备索引，交付校验活动范围。目录刷新期间保留有效观察，成功目录更新确认的范围撤销立即失效；续期期间排队的观察采用提交后的当前凭据。

自动补读、家庭 latest、availability 及属性版本仲裁属于 Step 3 的计划，不属于当前连接恢复行为。

## 已有证据及边界

真实 TCP 中断后，正式内部观察恢复连接、重新确认代表设备的活动订阅，并继续收到实际属性消息。同值上报保留；多个观察者共享 topic，取消最后一个观察可结束待执行重连。

同账号 MiCloud 续期保留活动观察。经既有认证恢复入口主动刷新 OAuth 后，新凭据持久化、MQTT 重建并恢复订阅和消息。该证据不等于供应商真实发出认证拒绝。新进程恢复持久化账号后可重新订阅、收包并显式读取代表属性；不据此推断断线期间的完整设备变化。

退避上限、精确取消竞态及供应商拒绝分支可通过实现审查或确定性探针验证，但不能替代相应的真实环境证据。客户端取消、连接恢复和主动读取成功均不代表家庭状态已恢复。来源语义统一见[来源契约](../../../mijia-source-contract.md)，报告规范见[共同参考](reference.md#验证规范)。

## 待完成的联合生命周期验收

- 供应商真实拒绝 token，以及认证恢复中的 `Retry-After` 等待。
- 联合验证退出、跨账号替换、设备访问撤销及旧账号资源清理；进程重启证据目前仅覆盖账号、属性读取及 MQTT。
- 联合验证属性读取、MQTT、go2rtc 的局部故障隔离，以及摄像头出帧、观看释放与失败重试。
- 自然连续故障中的退避递增上限及恢复行为。
- 按共同参考保存联合验收报告，分别记录实机通过、失败、未验证及确定性验证，不能将局部能力结论提升为全阶段完成。

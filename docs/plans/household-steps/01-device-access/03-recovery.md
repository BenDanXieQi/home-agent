# 任务 1.3：MQTT 最小连接恢复

**状态：最小范围已完成。** 不自动实施 Step 2。

[阶段入口](README.md) · 前置：[1.1](01-account-and-read.md)、[1.2](02-mqtt-push.md)

## 范围与实现

- `properties/observation.ts` 持有活动观察集合及唯一重连计时器。断线按 1、2、4 秒递增，最多 120 秒；连接成功后恢复到 1 秒。MQTT 库自身的自动重连与重订保持关闭。
- 新连接重新订阅仍活动的设备集合，沿用逐 topic 确认与消息交付入口。
- 每次连接从 service 获取当前 OAuth 凭据。同账号续期保留观察，token 更新后重连；明确认证拒绝暂停普通退避并交还已有账号维护流程，强制刷新被拒绝 token；拒绝状态跨在途续期及 Retry-After 等待保留，不新增续期器。
- 最后一个观察取消或账号退出时，关闭连接并清除重连计时器。回调内同步取消也清理新连接刚建立的观察绑定。
- 观察接纳使用设备目录索引，交付按作用域代次校验；目录刷新期间继续交付有效观察，实际范围撤销立即失效。同账号续期期间排队的观察使用当前凭据，不引用已销毁的账号实例。

不加入自动属性补读、家庭 latest、availability 或属性版本仲裁。这些能力归 Step 3。

## 验收条件

- [x] 真实连接中断后自动重连，活动订阅重新确认，真实属性消息恢复到达。
- [x] 取消观察后，订阅与观察数量归零，无待执行重连。
- [x] 同账号 MiCloud 续期保留活动观察；主动刷新 OAuth 后重建连接、重新确认订阅并收到真实属性消息。
- [x] 观察请求排队等待真实续期提交后仍能接纳、订阅并收到消息。
- [x] 新进程恢复已持久化的 OAuth 后可重新订阅、收包；断线恢复后显式读取同组 13 项属性均成功。
- [x] 后端类型检查、lint 和构建通过。

实机验证覆盖床头灯、空气检测仪、温湿度计和人在传感器的 8 个订阅，均取得 QoS 2 确认；观察窗口收到空气检测仪和人在传感器的属性消息，同值上报保留。真实 TCP 连接中断后约 1 秒开始重连，重新确认全部订阅并恢复收包；重连等待期间取消最后一个观察会清除计时器。多个观察者共享原有 topic，不重复建立订阅。

同账号 MiCloud 续期后原 MQTT 连接和观察保持有效。主动调用既有认证拒绝处理入口完成真实 OAuth 刷新后，新 token 被持久化，MQTT 重建并恢复订阅与收包；这不等于供应商真实发出了认证拒绝。续期并发验收使用真实会话，在凭据写入边界控制排队时序。退避递增上限、供应商真实认证拒绝及 Retry-After 等待仍未实机覆盖；不推断断线期间的完整设备变化。

进程重启、换账号、摄像头播放与释放等联合生命周期验收不属于本任务的最小完成条件，也未据此宣称整个阶段完成联合实机验收。具体来源语义见[来源契约](../../../mijia-source-contract.md)。

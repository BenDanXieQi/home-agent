# 任务 1.3：MQTT 最小连接恢复

**状态：最小范围已完成。** 不自动实施 Step 2。

[阶段入口](README.md) · 前置：[1.1](01-account-and-read.md)、[1.2](02-mqtt-push.md)

## 范围与实现

- `properties/observation.ts` 持有活动观察集合及唯一重连计时器。断线按 1、2、4 秒递增，最多 120 秒；连接成功后恢复到 1 秒。MQTT 库自身的自动重连与重订保持关闭。
- 新连接重新订阅仍活动的设备集合，沿用逐 topic 确认与消息交付入口。
- 每次连接从 service 获取当前 OAuth 凭据。同账号续期保留观察，token 更新后重连；明确认证拒绝暂停普通退避并交还已有账号维护流程，不新增续期器。
- 最后一个观察取消或账号退出时，关闭连接并清除重连计时器。

不加入自动属性补读、家庭 latest、availability 或属性版本仲裁。这些能力归 Step 3。

## 验收条件

- [x] 真实连接中断后自动重连，活动订阅重新确认，真实属性消息恢复到达。
- [x] 取消观察后，订阅与观察数量归零，无待执行重连。
- [x] 后端类型检查、lint 和构建通过。

实机验证覆盖床头灯与空气检测仪的 4 个订阅，恢复后收到了空气检测仪属性消息。仅据此确认连接与订阅恢复，不推断断线期间的完整设备变化。退避递增上限、认证拒绝交接及凭据更新接线通过实现审查；未进行真实 token 失效／续期场景验收。

进程重启、换账号、摄像头播放与释放等联合生命周期验收不属于本任务的最小完成条件，也未据此宣称整个阶段完成联合实机验收。具体来源语义见[来源契约](../../../mijia-source-contract.md)。

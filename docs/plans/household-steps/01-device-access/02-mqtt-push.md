## 实施清单

- [ ] 使用 MQTT.js 的 MQTT 5/TLS 接口，按共同参考配置并锁定通过 Bun 实机接入的版本。实例 UUID 独立持久化，连接使用真实 OAuth app ID/token，不使用扫码 cookie。
- [ ] 交付正式内部 observeDevices(deviceIds, onObservation, signal)，为操作者明确选定、service 经当前账号目录校验的设备集建立属性与在线 topic。设备来自 1.1 的本机报告，不依赖尚未实现的“当前家庭”；结束观察即取消相应订阅。
- [ ] 在一个适配器内维护期望／已确认订阅、在途请求和失败原因。按 16 个在途名额、10 秒确认期限执行对账；只有匹配活动实例的 SUBACK QoS 0/1/2 才记成功，单项失败不清除其他订阅。
- [ ] 先注册推送回调再订阅；按 MiLoCo 分发活动实例内、仍在期望订阅集合且校验合法的早到消息，不以尚未收到 SUBACK 为由丢包或另设缓冲。消息到达不替代订阅确认；逐 topic 确认结果独立输出，供 Step 3 安排初始化读取及质量判定使用。
- [ ] 属性解码校验 method、did、siid/piid 与 value，接受 params 对象或数组，不以 notify 白名单过滤；在线消息只接受 online/offline。带 / 的 did 按参考实现限制报告，不猜转义。
- [ ] 正常活动连接的合法推送交付为 live，observed_at=null，保留真实 received_at；上游事件 ID／序号没有就为 null。保留消息与已识别重放按共同参考分类，不把本机时间当设备时间。
- [ ] 暴露按 topic 的健康与覆盖结果，连接成功不等于订阅成功。断连／撤销令实例失效；取消时退订、清理回调，迟到消息／确认不能复活旧来源。此基础隔离随本次实现，不能等任务 1.3 才补。

- [ ] 属性订阅与视频使用同一设备目录；MQTT 局部失败不错误关闭媒体，账号退出则统一停止两者。

- [ ] 用任务 1.1 的真实账号与设备取得属性及在线 topic 的 SUBACK，并观察属性变化、同值上报及适用的在线／离线消息；各自记录，不能互相替代。

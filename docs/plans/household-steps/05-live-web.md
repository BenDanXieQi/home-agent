# Step 5：把后台状态显示到页面

**状态：账号、设备清单与媒体的状态订阅基础已交付；首次固定绑定已实现；采集与历史界面待实施。** 当前行为与限制见 Step 2 和当前实现文档。界面随对应场景能力接入，不阻塞不依赖它的 Agent 分析。

[返回总览](../backend-household-perception.md)

页面和 Agent 都订阅后台维护的同一份状态。这里使用 SSE（服务器发送事件）：客户端建立一个持续连接，后台有变化就推送，不需要页面反复询问。

“设备清单”指家庭、房间、设备及其归属；“来源”说明数据来自哪条设备消息连接或读取通路。家庭状态机是 Step 2 启动的 XState 实例，供页面和 Agent 读取的已提交数据称为“公共状态”。

正常流程只有三步：

1. 连接成功，先收到一份完整状态，称为 **快照**。
2. 此后只接收变化，例如一个温度更新、一个设备移除。
3. 断线后重新连接，重新拿完整快照。退出或应用停止时清空运行显示；重新配置后按新运行初始化。

账号、登录、设备清单和播放沿用 Step 2 已交付的订阅实现；H6 的首次设置已实现，纠错使用停机修改绑定后重启。本步补上场景需要的采集、一次性读取与历史入口，并按实际交付范围检查。前后端同批更新，共用一套协议。

本步只发布下表中的设备和运行状态。[家庭语义模型](../household-model.md)中的人员、宠物、区域和媒体样本在对应阶段另行定义，不自动塞进这份状态。

## 页面和 Agent 收到什么

### G1、G3：一份可公开的状态

- [ ] **G1：在 `packages/api` 定义共享数据格式。** 用 Zod 校验发出的消息和收到的数据。保留 MiLoCo 设备清单、规格字段的原义；本项目新增的质量、版本等字段单独定义。
- [ ] **G3：状态统一从家庭状态机取得。** 账号、登录、设备清单、媒体等模块先把变化提交给 Step 2 的家庭状态机，再从已提交状态生成对外数据。未就绪部分明确标注状态，不阻塞整张快照。

协议字段 `projection` 承载这份公共状态。它只包含明确允许公开的字段，当前已实现账号、登录、连接、媒体、家庭、健康与设备清单；下表采集、历史和规则类别在对应步骤接入。完整规格仅由后端持有。内容如下：

| 数据类别（`entity`）                                                        | 标识与内容                                                                                                                                      |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `account`、`login`、`connection`、`media`、`household`、`projection_health` | 各只有一份，使用固定 key；分别表示账号、登录、连接操作、媒体、家庭选择和整体健康。退出时更新为空状态。                                          |
| `home`、`room`、`device`                                                    | key 分别为 `{ account_id, home_id }`、`{ account_id, home_id, room_id }`、`{ account_id, device_id }`；保留云端字段、归属和本地补充信息。       |
| `latest`                                                                    | 用 `{ device_id, siid, piid }` 标识属性；包含最近值、来源、时间、observation_quality 与当前 quality。                                           |
| `source_health`                                                             | 用 `source_id` 标识来源；包含连接、认证、订阅覆盖，以及当前这一轮采集连接（`collection_generation`）的状态。                                    |
| `history_health`                                                            | 固定 key，按 Step 4 发布当前家庭的写入状态、积压量、最近保存时间和安全错误原因，不携带完整缺口列表。                                            |
| `rule_status`                                                               | 只包含启用规则，key 为 rule_id；值为 `{ rule_id, rule_version, status, reason }`，status 为 active 或 suspended。停止后重新加载配置时重建集合。 |

页面和 Agent 共享后台事实与字段语义。本阶段复用同一全量快照和增量协议，以共用校验、版本处理与重连实现；这是传输范围的选择，不是每项业务必须依赖全部状态的要求。Agent 按任务提取所需设备与能力，事件按 Step 6 的本轮配置与运行身份处理，不等待无关状态追平。规则事件通过独立连接发送，不与状态变化混用。

几个容易误读的字段按以下口径使用：

- `device.availability` 是 Step 3 定义的设备在线状态。没有可靠依据时显示 `unknown`。云端设备清单的 `isOnline` 只作带时间的诊断信息，不能覆盖它；未知在线状态也不单独禁止播放或一次性读取。
- `device.read_enabled_properties` 是已配置可读的 `{ siid, piid }` 列表。Step 2 或尚未配置时为空，不重复发送完整采集策略。
- `history_health` 在 Step 4 接入，由历史写入器提供事实，经家庭状态机提交后发布；新运行清除旧摘要，迟到写入结果不能覆盖新运行。
- `rule_status` 在未接入场景时为空；Step 6 只发布本轮本机配置的场景状态。配置修改在停止重启后生效，不提供在线规则编辑与分页管理。
- 暂时无法对应规格的 `latest` 可以用于诊断，质量为 `unknown`、原因为 `unmapped`；不作为规则或模型的有效事实。原始诊断样本不放进公共状态。

### G2：每条消息说明哪次变化

`state_version = { scope_epoch, sequence }` 表示状态版本。`scope_epoch` 是 Step 2 定义的当前账号和家庭这一轮运行的标识，重启、退出或明确运行失效时换新标识；`sequence` 是从 0 开始的整数，每次提交公共变化加 1。SSE 消息直接携带这两个字段。

- [ ] **G2：实现以下四种消息。** 一次提交涉及的变化放进同一条 `state_change`，一起校验、一起生效。例如移除设备时，同时移除它的属性和能力引用。心跳、重连通知和没有公共变化的处理不增加版本；同值上报若更新时间或质量，仍是公共变化。

| SSE 消息名        | 必需字段                                | 含义                                              |
| ----------------- | --------------------------------------- | ------------------------------------------------- |
| `snapshot`        | `scope_epoch`、`sequence`、`projection` | 完整快照，替换客户端保存的整份状态。              |
| `state_change`    | `scope_epoch`、`sequence`、`changes`    | 该版本的全部变化，全部成功后才更新页面。          |
| `resync_required` | `scope_epoch`、`sequence`、`reason`     | 要求重新连接；可附 `retry_after_ms`，不推进版本。 |
| `heartbeat`       | `scope_epoch`、`sequence`               | 表示连接仍在工作，不表示设备在线或数据新鲜。      |

`changes` 只支持两种操作：`{ op: "upsert", entity, key, value }` 新增或替换一个完整条目；`{ op: "remove", entity, key }` 删除条目。每类数据都有固定的 key/value 格式，key 必须与值中的身份相符。整批数据校验失败时不应用其中任何一项。Web 与 Agent 共用 packages/api 中的消息 schema 和 applyChanges，通过同一 Mutative 封装应用不可变批次；作用域、连续版本和消息合法性在应用批次前检查。共享的是数据应用规则，连接资源仍由各自客户端管理。

## 首次连接、断线和重新初始化

- [ ] **G4：先接好变化通知，再取快照。** 服务端同步完成订阅注册和已提交快照的读取，中间不等待异步操作。快照发送期间暂存后续变化，随后按顺序发送比快照更新的消息，避免首次连接漏掉变化。整个快照来自同一次提交；运行失效时关闭旧连接，重新初始化后取得新快照。
- [ ] **G5：只按连续版本更新。** 客户端先校验并应用快照，此后只接受同一 `scope_epoch` 下的下一版本，已应用的重复版本可以忽略。出现版本缺口、新家庭标识、非法变化或 `resync_required` 时，停止更新，标记未同步并重新连接。心跳不推进版本；心跳中的家庭标识变了，也要重新同步。
- [ ] **G6：每次重连都取当前快照。** 不保存断线重放队列，也不使用 `Last-Event-ID` 补历史。重连间隔从 1 秒逐步增加到最多 30 秒，并加入少量随机错开；遵守服务器给出的最短等待时间。完整收到快照并稳定同步 60 秒后恢复初始间隔，不因刚连上 TCP 就反复快速重试。
- [ ] **G8：检测断流并释放资源。** 服务端每 15 秒发心跳；客户端 45 秒没有有效消息就重新连接。取消、异常和断开都执行同一清理逻辑：退订、清计时器、释放缓冲并停止发送。客户端取消旧连接后忽略其迟到结果；后台退出时主动结束长连接。
- [ ] **G9：使用现有 HTTP 框架发送。** Hono 使用 `streamSSE`，连接前沿用本机访问校验，连接后的错误发送安全提示或直接关闭。禁用缓存，并确认 Vite 代理及时转发消息。

断线恢复的是当前状态，不保证补齐断线期间的全部设备事件；事件历史使用 Step 4 的查询接口。页面断线时可以保留旧数据显示“尚未同步”，但退出或应用停止时立即清空旧运行，不靠旧快照维持可用。

## 防止大数据和慢连接拖住后台

这些限制是项目的初始资源预算，用于防止异常响应或慢客户端持续占用内存；须以真实家庭数据大小、连接数量、处理与发送延迟校准，不表示供应商或框架规定的容量。Step 2、Step 3 和 SSE 共用配置，分别限制数据大小、条目数和连接数；数据大小按 UTF-8 JSON 序列化后的字节数计算。1 MiB 为 1,048,576 字节。

| 项目                   | 默认限制                                                             | 达到限制时                                       |
| ---------------------- | -------------------------------------------------------------------- | ------------------------------------------------ |
| `latest`               | 2 MiB，最多 20,000 个属性，两者先到者生效                            | 拒绝本次超限更新，标明哪些设备属性因此未能更新。 |
| 设备清单               | 4 MiB、最多 1024 台                                                  | 整批拒收超限数据，已确认撤销仍生效               |
| 后端完整规格           | 独立 4 MiB，不进入公共快照                                           | 拒收新资料，报告规格错误                         |
| 设置候选列表、账号资料 | 各 2 MiB                                                             | 在各自入口拒收超限资料                           |
| 完整快照或单条业务消息 | 8 MiB，包含版本和消息结构                                            | 不能截断后冒充完整状态。                         |
| 每连接待发变化         | 最多 256 条或 2 MiB，包含正在发送的变化；另允许一份最多 8 MiB 的快照 | 关闭该连接，客户端稍后从新快照恢复。             |
| SSE 连接               | 状态连接最多 16 条；Step 6 的规则事件连接另最多 2 条                 | 建立订阅前返回 503，默认 `Retry-After: 30`。     |

当前 Step 2 在设备清单、后端规格、设置候选与账号资料入口分别检查大小，不维护统一字节账本、控制空间预留或每设备预留。公共设备记录仅含有界的规格标识、分类、标签及准备状态。任务开始、结束、退出、停止和撤销不因资料已满而拒绝。

最终 SSE 编码独立检查消息大小。Step 3 的 latest、Step 4 的 history_health 和 Step 6 的 rule_status 在对应步骤接入时落实大小及条目数限制，不提前发布空字段。绑定和访问资格仍以 Step 2 为准。

- [ ] **G7：每条连接按顺序发送。** 快照、变化、心跳和提示共用一个发送队列，单次写入最多等待 15 秒。超时、队列满或单条变化超过待发队列的大小上限就关闭连接；重连提示发不出去也照常清理。慢连接不能阻塞其他连接或触发额外云端读取；状态流断开只说明该副本未同步，不撤销已交付给 Agent 的事件证据。
- [ ] **G11：连接先限额，再分配资源。** Web 和 Agent 使用同一状态连接上限，获准后才注册订阅、准备快照和缓冲。所有关闭和失败路径都释放占用。

## 登录材料单独读取

- [ ] **G10：公共状态使用字段白名单。** SSE 不包含凭据、Cookie、token、SDP 或内部连接对象。登录公开状态只有 `id`、`status`、脱敏 `error` 和 `material_version`。二维码或验证材料准备好、发生变化时，登录模块更新 `material_version` 并通知状态机。

页面据此调用 `GET /api/mijia/login/:id/material`，响应为 `{ id, material_version, qr_image_url, verification_url, expires_at }`。不适用字段为 `null`，`expires_at` 为 UTC 时间或 `null`；响应设置 `no-store`，沿用本机访问校验。只返回当前有效尝试的材料，Agent 不接收这些资料。

## 页面如何使用

### 复用状态订阅与绑定设置

- [ ] **H1：应用统一管理订阅。** 使用 Hono RPC 客户端的 fetch 建立连接，前后端共用接口类型；由 `eventsource-parser` 解析 SSE、共享 Zod 格式校验消息。组件不自行连 SSE。长连接直接读取 `Response.body`，不经过普通 JSON 请求的 12 秒总超时。连接、取消、超时和重连由同一个管理器负责。接入时确认解析库的缓冲限制用法并锁定依赖版本。
- [ ] **H1a：等待和解析都有上限。** 响应头最多等待 10 秒，只接受成功状态和 `text/event-stream`；503 按服务器要求稍后重试。响应头到达后最多等 30 秒收齐第一份快照，之后使用 G8 的断流期限。分段交给标准解析器，缓冲上限默认是 9 × 1,024 × 1,024 个字符；库按字符计数，所以收到完整消息后仍要检查其 UTF-8 数据不超过 8 MiB，再解析 JSON。出错或取消就释放读取器和解析器，走同一重连流程。
- [ ] **H2：每个标签页只存一份状态。** 一个浏览器标签页只建一条状态连接。快照和变化更新同一份缓存，现有 Jotai 从中派生显示值；不在 TanStack Query 或另一状态库中维护第二份家庭当前状态。
- [ ] **H3：移除被订阅替代的轮询。** 删除米家状态的 `refetchInterval` 和窗口聚焦、重连时的重复 HTTP 拉取。标签页重新可见时检查 SSE，必要时重连；无关的服务设置查询继续保留。
- [ ] **H4：显示状态与命令结果分开。** `AccountGate` 和 `use-login.ts` 从 SSE 公共状态派生页面，命令响应不覆盖这份状态。退出、手动登录和重试连接不要求 SSE 已同步；取消和验证登录须指定尝试 ID。HTTP 请求结束即结算本地命令，另行确认订阅版本已达到回执，或 HTTP 结算后重新订阅取得完整当前快照。未确认只提示状态尚未同步，不能将已接受的命令改报失败或一直锁住其他命令；自动取码仍须使用已同步状态。二维码材料按当前 `id` 和 `material_version` 读取，同版本请求合并；显示前再次匹配，尝试变化时清除旧材料。失败显示错误、允许重试。账号页面沿用现有扫码登录与后端静默 OAuth 组成的统一会话，不新增独立授权页面或第二套登录状态；扫码材料、Cookie 和 token 不进入家庭状态。推送鉴权及状态采用 Step 1 在此前提下实际核实并启用的契约；未具备的能力展示具体限制，不提示用户另做 OAuth，完整会话接纳也不能代替推送连接与订阅确认。
- [ ] **H5：播放跟随家庭和媒体状态。** 新播放须满足 Step 2 B6，且家庭标识、媒体 revision（媒体模块的当前版本）和绑定状态仍有效。播放可用性由媒体连接决定，不用设备清单的在线字段或轮询时间判断。SSE 短暂中断时保留已有播放器；退出或应用停止时立即释放。
- [x] **H6：首次固定绑定。** 设置页按需读取候选并保存一个家庭；正常页面只显示绑定家庭，接口拒绝换家。保存失败可重新选择，保存后的清单失败只刷新重试。纠错停止服务、修改绑定后重启，不建立在线维护页面。筛选与搜索仅影响显示。

### 本步增加采集与历史显示

- [ ] **H7：说明数据来自哪里、是否可用。** 设备详情显示在线状态、属性最后上报和变化时间、采集来源、订阅覆盖及不可用原因。订阅失败时提供 `connection/retry`；采集过载按 `source_health` 显示丢弃范围、继续接收或暂停状态；仅在安排了恢复时显示进展及下次重试时间，持续过载暂停后提供人工重试。Step 4 接入后从 history_health 实时显示历史写入异常和恢复进度，无需打开历史查询或轮询；详细缺口仍按需查询。浏览器断线显示“状态未同步”，不要写成设备故障；设备离线、数据过期和数据超出大小或数量上限分别说明。
- [ ] **H7a：一次性读取显示逐项结果。** 根据 `read_enabled_properties` 提供读取入口，按 Step 3 发起命令。使用共享契约的 35 秒 HTTP 期限，不自动重发；响应后最多再等 5 秒，让本页订阅状态追上响应的 `state_version`，再显示逐项结论。部分失败不能说整批已刷新；未追上显示“状态未同步”，HTTP 超时显示“读取结果未确认”。等待期间运行失效就丢弃旧结果，正常 SSE 同步继续。
- [ ] **H8：页面只更新需要的部分。** 温度变化只更新相关显示，不重复传输、重建规格等静态资料。
- [ ] **H9：历史按需查询。** 仅在 Step 4 已接入时，在相关设备详情使用现有 TanStack Query／useInfiniteQuery 查询与分页。缓存键包含绑定身份、能力和时间范围，取消信号传至请求；关闭周期、聚焦和重连自动刷新，由用户发起查询。显示记录的来源、质量、保存范围和已知缺口；无记录不补零，也不把区间前旧值延长成持续状态。历史响应不写回当前状态，不要求汇总图表。

## 接口清单

按所属步骤实现接口，不提前注册空路由。已有命令继续使用，页面状态统一通过订阅更新。

| 接口                                                     | 用途                                           |
| -------------------------------------------------------- | ---------------------------------------------- |
| `GET /api/mijia/events`                                  | 本文件的状态 SSE，未登录也可连接。             |

## 完成条件

- [ ] 初次打开、断线重连、标签页恢复可见都能取得完整状态；Web／Agent 共用批次应用规则，同一次变更不会只生效一半，未变化条目保留引用。
- [ ] 多开页面不会增加云端读取，没有用于状态恢复的 HTTP 定时轮询。
- [ ] 首次设置仅允许保存唯一绑定；纠错停机修改绑定后重启。退出后观看清空，旧连接和登录材料不会覆盖新状态。
- [ ] 设备未知在线状态、浏览器断线、属性过期和订阅失败能区分；一次性读取的部分失败、超时不会误报成功或自动重发。
- [ ] 超大数据、慢连接和写超时都有明确处理，内存不会随积压持续增长，其他连接仍能工作；容量限制不阻断退出、停止或访问撤销。
- [ ] 历史写入失败、积压与恢复可经订阅显示，完整缺口不进入快照。
- [ ] 快照不泄露凭据和登录私密材料；连接关闭后订阅、计时器和缓冲都释放。
- [ ] 执行总览中的共同检查，更新当前实现文档与仍未验证的限制。

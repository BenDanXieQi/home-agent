# Step 5：展示房间上下文与活动

**状态：账号、设备清单、媒体订阅与房间事实页面已交付；场景判断和活动界面待实施。** 当前行为见[家庭运行时](../../household.md)和[设备事实与房间快照](../../reference/device-facts.md)，本步随 03、04、06 的能力逐项接入。[返回总览](../backend-household-perception.md)

## 展示范围

页面用于看清后台收到了什么、怎样判断、为什么允许或跳过动作。设备日志继续提供逐条观察入口，房间视图提供当前上下文，避免用户只能从大量日志中寻找状态。

| 视图       | 主要内容                                                       |
| ---------- | -------------------------------------------------------------- |
| 房间事实   | 设备原生属性、值、单位、上报时间、有效性、来源与未覆盖项       |
| 当前判断   | 相关人物／宠物、位置和活动、房间判断、证据、冲突与失效状态     |
| 控制条件   | 具体动作的允许／禁止／未知、原因、适用范围和结束条件           |
| 活动记录   | 近期经过、上一次已确认活动、必要证据及修正入口                 |
| 家庭档案   | 已确认身份、设备关联、明确偏好；推测习惯单独标注               |
| 分析与动作 | 触发原因、分析状态、接纳或拒绝原因，以及动作建议或实际执行结果 |

只显示已接通能力。床铺有人、可能休息和确认睡眠分开表达；未知不显示为无人、关闭或零。建议动作、发出命令、设备响应和效果核对分别展示，验证阶段不能显示成已经执行。

## 状态与传输

复用[公共接口与 SSE](../../household.md#公共接口与-sse)。SSE 是后台有变化时主动推送的连接；既有快照、增量版本、重连、慢客户端和连接上限沿用现有实现，不另建页面轮询链路。

- 共享输入输出在 `packages/api` 定义一次，前后端同批接入；只发布允许公开的字段，完整规格和凭据不随状态广播。
- 房间事实从同一已提交设备状态派生，页面不维护第二份事实源。属性名称、单位和枚举复用规格，详细资料按需读取。
- 判断、画像和控制条件由各自负责模块提交，带自身依据和有效性；页面不通过自然语言摘要反推它们。
- 后台版本用于同步，属性时间用于判断新鲜度；收到心跳或重新取得快照不能让旧值变新。
- 局部来源失败不清空其他有效事实，浏览器连接落后与设备离线分别提示。重新同步期间不把旧视图称为实时。
- 异步响应核对家庭、房间／实体及适用版本，离开页面或切换对象后不写入错误视图。

Agent 通过 06 的有范围限制的工具读取同义数据，不为每个任务接收整个家庭的所有日志。状态重连补的是当前快照，不承诺补发断线期间的全部活动。

## 操作与查询

一次性读取沿用 03 的入口与逐项结果，显示已采纳、候选、未改变或失败，以及值的质量。页面以后台提交和状态订阅为准；请求超时或订阅暂时落后时不自动重发读取。

历史和活动使用 04 的分页查询，展示实际保留范围及已知缺口，不在浏览器下载并解析全部文件。查询结果不覆盖当前房间状态，不将相邻历史点之间画成已确认持续状态。

用户提问在对话中返回答案与证据，后台事件分析在对应房间或活动入口展示结果。分析结果只写入 Agent checkpoint（运行检查点）不算交付，必须能看见接纳的判断或明确失败原因。

验证先提供必要的身份确认、偏好修改、活动纠正和规则启用信息，不把完整规则编辑器、户型编辑器作为房间观察的前置条件。修改须由后台校验并重新评估受影响判断。

## 验收

- [ ] 无需刷新即可看到真实设备值和质量变化，房间归属、缺值与覆盖清楚。
- [ ] 事实、推断、用户要求、建议和执行结果能明确区分。
- [ ] 断线重连、局部来源失败与旧响应不会制造错误的实时状态。
- [ ] 一次性读取不产生重复请求，历史分页不改写当前事实。
- [ ] 能查看场景判断、控制条件及其变化原因，过期结果不会继续显示为有效。
- [ ] “上一次”活动及人物偏好显示来源和不足，完成总计划的适用共同检查。

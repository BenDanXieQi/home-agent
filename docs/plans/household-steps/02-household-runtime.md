# Step 2：固定家庭与后台运行

**状态：唯一绑定、设备清单、后台规格准备和页面订阅已实现；实机验收仍有未完成项。** 当前使用说明见[家庭运行时](../../household.md)。

[返回总览](../backend-household-perception.md)

本步只有三个交付目标：保存本实例唯一的家庭绑定；在后台持续维护该家庭的设备清单和规格；让页面订阅真实运行状态。

一个局域网部署服务一个家庭。云端账号有多个家庭，只意味着首次设置需要选择。正常运行不提供换家、更换绑定账号或在线维护改绑流程。选错家庭时，停止服务、修改数据库中的绑定，再重新启动。房间、分类和搜索只影响页面显示。

## 保存和恢复唯一绑定

- [x] **B1：保存绑定。** 绑定包含供应商稳定账号身份与 `home_id`，凭据仍由加密凭据存储负责。米家账号键由区域和用户 ID 编码；续期不改变绑定身份。绑定读写使用部署级事务锁，拒绝不同账号或另一家庭覆盖已有绑定。退出和授权失效只撤销授权，不删除家庭绑定。
- [x] **B4：首次设置。** 恢复数据库中已有的绑定；没有绑定时，云端只有一个家庭则可靠保存后自动采用，有多个则等待设置页选择。`GET /api/mijia/setup/homes` 只读已获取的候选列表，不触发云请求；已有绑定时返回空列表。候选家庭不放入 SSE 公共快照。首次保存失败通过 HTTP 报错，仍可重新提交选择；保存成功后只重试设备清单，不重复保存绑定。
- [x] **B5：停机纠错。** 正常页面只显示绑定家庭，接口拒绝运行期换家。纠错使用现有进程停止和数据库配置能力，具体操作见[绑定纠错](../../household.md#绑定纠错)。不建立维护状态、旧新家庭并行队列或在线重新绑定接口。
- [x] **B2：设备清单是缓存。** 保存当前完整的家庭、房间、设备及归属，保留 `last_seen_at`。每次成功写入替换当前清单，不累积已移除条目；历史归属属于 Step 4。绑定与凭据必须可靠保存，可重新获取的清单缓存不决定运行资格。

### B6：运行资格

已保存绑定、账号授权有效、当前运行取得完整且通过校验的云端设备清单并提交后，允许设备任务、主动读取与新播放。规格按设备单独准备，不阻挡整个家庭启动；读取前必须有适用于当前设备定义的规格。`running` 与 Web 或 Agent 是否连接无关。

启动时可以展示同账号、同家庭的缓存，但缓存本身不能授权新任务。缓存读取或写入失败报告 `storage_degraded`；已确认的云端清单仍能进入运行，新设备和新归属也能生效。最近云同步时间与最近成功保存时间分别记录，失败不能伪造保存时间；后续后台或显式清单刷新重试保存。

退出时凭据删除失败且账号仍有授权，立即重新同步完整云端设备清单，通过正常完整性和当前运行校验后恢复运行。首次云端初始化失败保留初始化状态，允许刷新重试。正常运行的普通云端刷新失败保留已确认清单和已有任务。失去设备访问时撤销该设备；失去整个家庭访问时保留绑定、进入不可运行的 `initializing` 并报告 `home_unavailable`，等待原账号权限恢复。不能自动进入选择另一个家庭的流程。

## 后台设备清单与规格

- [x] **B3：完整清单一次生效。** 取齐并校验家庭、房间和设备，绑定家庭及其房间内的设备引用必须有详情；在计算撤销和保存缓存之前检查，不完整的本家庭清单整批拒收，不能据此认定设备移除。其他家庭的缺失详情不阻断账号恢复或本家庭运行；首次选择后按所选家庭检查。提交前检查账号、运行标识、请求是否已取消及大小上限。旧结果不能覆盖当前状态。
- [x] **B10：复用发现服务。** `DeviceDiscovery` 负责账号恢复、五分钟后台发现、结构变化通知和显式刷新。重复请求合并为进行中任务和至多一次后续刷新；供应商退避期限仍然有效。清单缓存保存失败不阻挡当前清单提交，下一次刷新会再次保存当前完整清单。
- [x] **B11：撤销及时生效。** 完整清单确认移除、转出或失去家庭访问后，先从允许读取、观察和播放的范围移除，再取消对应资源。保存失败和迟到结果不能恢复资格。型号或规格定义变化只撤销受影响设备的旧任务，其他设备继续运行。
- [x] **B7：后端持有完整规格。** `HouseholdSpecifications` 按带版本的 URN 共享已接纳规格，管理设备引用与解析任务；最后一个引用消失后释放资料。完整能力表不在公共快照中，后端通过 `specification()` 在读取预检查时使用。页面只收到 `spec_id/spec_status/spec_error`、分类及能力标签。
- [x] **B8：后台准备和刷新。** 最多并发 3 个任务，瞬时失败额外在 2 秒、10 秒重试；重复清单不重置失败次数。相同 `spec_type` 共用解析任务，缺少它时按型号共享；同一最终 URN 在刷新批次内获取一次。任务开始、完成、失败不受规格资料配额阻挡。只有新资料接纳检查规格大小，失败保留旧展示摘要并报告错误。型号或 URN 改变后，旧资料不能自动授权新读取。
- [x] **B9：派生设备摘要。** 从完整规格派生类别及 readable/writeable/notify/action/event 标签，按规格对象缓存，只更新受影响设备的摘要。容量检查复用未变化规格对象的大小。规格标识和分类有长度边界；别名、用途和允许读取属性的本机配置在 Step 3 接入。

### 资源限制

| 边界                   | 上限                                                | 行为                                                                 |
| ---------------------- | --------------------------------------------------- | -------------------------------------------------------------------- |
| 清单接纳与缓存         | 4 MiB、最多 1024 台设备                             | 拒收超限清单、报告 `capacity_degraded`，不截断实体；已确认撤销仍生效 |
| 后端规格资料           | 合计 4 MiB，单次响应最多 4 MiB                      | 拒收新增资料，保留已接纳规格和真实任务错误                           |
| 设置候选列表、账号资料 | 各 2 MiB                                            | 候选列表超限报错；超大账号资料不阻挡认证状态更新及资源清理           |
| 数据库事务             | 5 秒，包含锁等待                                    | 结束事务后释放队列；提交结果不确定时先核对再写入                     |
| SSE                    | 快照 8 MiB、变化队列 256 条或 2 MiB、最多 16 条连接 | 消息过大、队列满或写入超过 15 秒则关闭该连接                         |

参数集中在 `household/config.ts`，公共传输参数见共享 `householdStreamPolicy`。状态机不维护精确字节账本，也没有统一资料准入或控制空间预留；退出、停止、撤销和规格任务结果照常提交。设备清单、规格与传输分别在自己的边界限制资源。有界摘要和设备数量限制公共状态的增长。

绑定与缓存写入沿用事务级 advisory lock 和提交结果核对。未确认写入在核对完成前不得执行下一次 INSERT；该约束保护数据库中的保存结果，不影响已经确认的云端清单运行资格。

### 刷新入口

`POST /api/mijia/devices/refresh` 接收 `{ scope_epoch, target }`，`target` 为 `directory`、`specs` 或 `all`。接纳后返回 HTTP 202 `{ state_version }`，完成或失败由订阅显示。相同目标的在途任务合并，停止和授权撤销拒绝迟到结果。刷新不改变家庭绑定。

## 状态机、公共状态和订阅

| 模块                              | 职责                                         |
| --------------------------------- | -------------------------------------------- |
| `machine.ts`                      | XState 生命周期与原子状态提交                |
| `runtime.ts`                      | 首次绑定、任务调度、清单接纳、规格摘要及关闭 |
| `source.ts`、`mijia/household.ts` | 家庭领域与米家账号、设备清单、媒体的边界     |
| `directory.ts`、`repository.ts`   | 设备清单白名单和缓存                         |
| `specifications.ts`               | 后端完整规格、设备引用及任务                 |
| `projection.ts`                   | 公共状态初值、变化条目校验与不可变提交       |
| `capacity.ts`                     | 设备清单大小检查与按需字节诊断               |
| `routes.ts`、`stream.ts`          | 首次设置、刷新、诊断和有界 SSE               |

- [x] **C1/C2/C8：随应用启动。** XState 管理有限生命周期；先订阅来源通知再读取初值。账号凭据、网络请求和媒体连接由各自模块负责。浏览器访问不启动后台，也不触发云端刷新。

| 状态               | 含义                                                           |
| ------------------ | -------------------------------------------------------------- |
| `unbound`          | 没有可用授权；数据库中可以仍有家庭绑定                         |
| `waiting_for_home` | 已登录，但首次家庭绑定尚未完成                                 |
| `initializing`     | 等待绑定家庭的完整清单；初始化失败或家庭不可访问时显示错误     |
| `running`          | 授权与当前完整清单已确认；缓存写入、单个规格或媒体故障单独显示 |
| `stopping`         | 应用停止接收新工作并释放资源                                   |

- [x] **C4/C5：状态和运行标识。** 公共版本 `{ scope_epoch, sequence }` 隔离重启、授权失效和新登录会话的旧结果。同账号续期保留运行标识，受影响连接和读取使用自己的版本。家庭绑定不会随来源通知清空；失去家庭权限也不能修改绑定。
- [x] **C6/C12：原子提交后执行操作。** `enqueueActions` 为输入准备一次候选，内部 `commit` 在同一 macrostep 提交；guard 只判断。`status` 由状态节点生成。提交后才通知订阅者和分发后续操作，以内部 `input_sequence` 防止重复分发。没有公共变化的有效命令仍执行；迟到事件不提交。首次绑定等待存储确认后提交结果，不使用运行期切家操作编号或阶段重试。
- [x] **C13：边界资源限制。** 资料在清单、规格和账号资料入口检查大小；SSE 独立限制编码消息及发送队列。`GET /api/mijia/diagnostics` 按需计算设备清单、元数据、完整公共状态和后端规格字节数，内存每 60 秒采样。采样是整个进程的用量，不代表家庭独占内存或瞬时峰值。
- [x] **C7/C9：关闭与媒体。** 停止、退出和撤销取消请求、订阅、计时器及观看资源，迟到结果只能作用于原运行。新播放同时检查运行资格、设备身份和媒体 revision。设备清单的在线字段不单独阻止播放。

Mutative `produce` 构造候选并复用未变化条目；变化条目经 schema 白名单及身份校验后成为独立的不可变对象。浏览器也按整批增量更新，保留未变化条目的引用。完整规格、凭据、登录材料、Promise、取消控制器和连接不进入公共状态。

公共状态只包含账号、登录、连接操作、媒体、家庭、健康，以及家庭／房间／设备记录。候选家庭只在设置页按需读取。`latest`、`source_health` 和 `rule_status` 尚未进入协议；C10/C11 在 [Step 3](03-collection.md)、C14 在 [Step 6](06-agent.md) 实施。当前 `availability=unknown`、`read_enabled_properties=[]` 不表示已经采集。

页面每标签页共用 SSE，先完整快照再连续增量；缺失版本、运行标识变化或非法消息则重新同步。HTTP 命令结果不回填公共状态；退出后的新播放需等订阅确认。断流不统一禁用控制命令，后台按命令所需标识检查。慢连接不阻塞其他连接，也不触发云端请求。

- [x] 首次绑定保存失败可重试；保存后设备清单同步失败只重试设备清单同步；迟到结果被丢弃。
- [x] 首次缓存写入失败仍运行，后续保存恢复；访问撤销与设备定义变化不受缓存失败阻挡。
- [x] 后端完整规格与公共摘要分离；无未来状态占位；大小限制分别作用于资料和传输。
- [x] 不可变输入所有权、纯 guard、原子状态发布、无公共变化命令分发及停止清理。
- [x] 无浏览器连接、无刷新命令时的五分钟后台自动发现已实机验证。
- [x] SSE 完整快照与连续增量、刷新命令、只读 GET 不触发同步、连接上限与取消回收已实机验证；真实换房通知已有基础验证。

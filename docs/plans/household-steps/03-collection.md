# Step 3：持续采集与房间事实快照

**状态：实现已交付，边界故障实机验收待补。** 持续采集、当前值、房间查询、一次性读取与页面入口已接入；当前行为和本机配置见[设备事实与房间快照](../../reference/device-facts.md)。诊断日志继续独立运行。[返回总览](../backend-household-perception.md)

## 目标与范围

让真实设备上报持续更新可信当前值，形成按房间查询的事实快照，并给后续场景提供变化依据。覆盖当前家庭已接通通路的全部可订阅设备，不以页面筛选、已定义场景或是否保存历史决定接收范围。

本步只运行确定性代码。人物画像、睡眠判断、AI 触发和提前维护开灯条件由 [06](06-agent.md) 及[家庭模型](../household-model.md)负责，保存与查询由 [04](04-history.md) 负责；它们未接入时，采集仍可独立使用。

## 输入与职责

复用 `observeDevices/readProperties` 和已有 MIoT 规格。属性名称、类型、单位、枚举、范围及读写／推送能力直接取自规格，不手工重建灯、空调等属性模型。规格说明支持什么，不能证明通路已验证或数值新鲜。

- `collection.ts` 管理本轮订阅、必要读取和取消；协议重连与凭据仍由现有米家模块维护。
- `observations.ts` 校验身份、消息结构、规格适用性与大小，计算前后值及质量，再交给家庭运行时提交。
- 家庭状态机统一维护当前值、质量与公共版本；房间视图只读，不为每个属性或房间新增状态机。
- 来源分为属性报告、独立设备事件和在线通知。独立事件须有真实通路；不能把属性变化伪装成按钮或告警事件。

能力以设备和原生 `siid/piid` 或 `siid/eiid` 标识，不按中文名称猜含义。规格缺失的合法属性可在预算内保留原值，标记未知；与已确认规格冲突的值报错，不裁剪成合法值或刷新有效期。全量接收不保证供应商上报所有属性，未覆盖设备和失败订阅必须可见。

## 持续运行与必要读取

家庭初始化完成后启动观察，设备加入、移除或规格变化时协调相应资源；关闭页面、Agent 未启动或诊断录制结束都不停止采集。停止、退出与访问撤销取消受影响订阅、读取和计时，旧连接回调不得回写。

先订阅，确认后默认分批补读缺值或待确认的原生可读属性；本机策略可排除特定属性，规格较晚就绪时也须补读。批次完成后继续推进，不能因全家庭属性超过同时在途上限而遗漏剩余项。读取仅由初始化、恢复、设备上线或用户请求触发，不增加周期轮询；相同属性的在途读取合并。明确离线时暂缓读取，在线未知仍可尝试。来源的限流、超时和批量限制沿用来源契约。

使用已校验的本机配置补充读取、新鲜度、显示和规则资格。规格已有的信息不重复配置；配置不是接收白名单。未验证能力可展示原始观察，但不作为有效规则事实。配置启动时加载并记录版本，修改后重启相关运行。

## 当前值与有效性

每次接纳观测分配 `observation_id`，保留来源、连接代次、原生能力、交付性质、时间和当时质量。供应商提供可靠身份时才据此去重，同值报告和同参数事件不能直接当成重传。

`latest` 按设备和属性保存一份当前记录：

| 内容       | 要求                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 值         | `has_value/value` 分开；缺值用 `has_value=false, value=null` 表示，不能冒充设备报告 false 或 0 |
| 时间       | 来源时间、接收时间、采纳时间、最后上报／变化／读取时间；首次赋值不算变化                       |
| 来源与证据 | 观测 ID、push／读取来源、连接代次、live／baseline／replayed／unknown、规格和策略版本           |
| 质量       | `observation_quality` 保留当时证据质量，`quality` 表示当前是否还能使用                         |
| 读取候选   | 无法确认比当前值新的读取结果最多保留一份，供诊断；不延长当前值有效期                           |

质量为 `valid / unconfirmed / unavailable / unknown`，分别表示有效、待确认、来源不可用、缺值或含义未知。保留具体原因；未知能力或缺值、离线／连接故障、订阅未确认、过期／缺口等按实际依赖解释，不以一个“在线”标记替代属性有效性。

周期测量采用有依据的有效时长；变化上报只有初值、订阅和恢复语义已验证，才可保持到明确缺口。依据不足时保留观测而不外推为持续事实。观测当时可信不等于当前仍有效，连接恢复或订阅确认本身不刷新旧值时间。

来源没有可信观测时间时 `observed_at=null`；已验证实时通路可以使用接收时间，不能冒充精确物理发生时间。UTC 用于展示，提交序号用于处理顺序，持续时长用单调时钟；系统时钟跳变或来源时间异常须标注，不能制造虚假持续时长。

`availability` 单独表示 online／offline／unknown；`source_health` 表示连接、授权、订阅覆盖和缺口。设备清单中的在线缓存、成功读值或视频连接不自动证明设备当前在线。连接或订阅失效时，受影响在线证据转未知，属性按各自来源判断。

## 顺序与变化规则

| 情况                       | 处理                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 同值实时上报               | 更新接收时间及适用质量，不生成新的属性变化                         |
| 首次值、恢复基线           | 建立比较起点，不推测此前发生过什么                                 |
| 有效前值后收到可信实时新值 | 顺序明确且中间没有已知缺口时，输出属性边沿，即后台观察到的前后变化 |
| 读取期间出现新推送         | 晚返回的读取不能无依据覆盖较新推送                                 |
| 未知时间云缓存             | 没有值时可作为待确认初值；已有值时仅保留读取候选                   |
| 已确认晚到、重放或交付未知 | 不凭接收较晚覆盖当前状态，不触发即时变化                           |
| 断线、过期或丢报           | 失效依赖它的当前条件；恢复后重新建立基线，不补造缺口内事件         |

当前米家读取按来源契约属于未知时间云缓存。真正即时读取只有通路已验证且未被更新证据超过时才能更新当前值；推送故障不自动否定独立读取证据。没有新观测也能因到期而降低质量，但不能提升事实可信度。

按接收顺序处理观测，每次计算、提交前后状态后再发布通知。快速“开→关”不得合成一个最终值。到期和持续条件检查先处理此前已入队的观测，避免关门消息已收到却仍触发持续开门；停止、撤销和缺口处理不等待积压。

## 房间事实快照

按稳定房间身份，从同一次已提交状态同步组装只读视图，携带现有 `state_version`。复用设备当前值，不另存可写房间副本、不另建房间版本计数；查询不触发云端读取或模型调用。

快照包含房间身份、设备清单与规格引用、属性值及时间／质量／证据、在线与来源健康，以及缺值、过期和未覆盖项。完整规格单独保存，按需附名称、单位与枚举说明。未分配房间的设备单列，不猜归属。

默认读取房间已有属性，也可限定设备或能力；范围和裁减情况必须可见。规格或目标集合不完整时不能宣称全覆盖。“主灯关闭”不能扩大为“所有灯关闭”，刚取得快照不代表每项数值都新鲜。换房和移除跟随已提交清单，历史证据保留当时归属。

页面通过现有状态订阅派生房间视图；Agent 通过 06 的有范围限制的工具获取同义数据。当前状态、待确认事实和缺失项均可解释，但不在这里输出睡眠、身份或开灯许可。

## 向后续步骤交付

提交后提供本次相关的变化依据：可信属性边沿、独立设备事件、质量失效／恢复，以及设备归属、规格和访问资格变化。关联原运行、提交版本、前后状态、当时及变更后归属与可用证据；没有新观测的到期或连接事件不伪造观测 ID。

这些依据供 06 判断是否重评场景或触发 Agent，不直接等同于语义活动或模型调用。明确规则可在同次提交的前后数据上计算；耗时任务在提交后运行。04 保存接纳后的记录，文件故障不阻塞当前值。

用户主动读取沿用 `POST /api/mijia/properties/read`，返回逐项 applied／candidate／unchanged／failed 和提交版本；成功收到结果仍需看质量。页面从状态订阅确认值，超时或尚未同步时不自动重发整条命令。

## 资源边界

复用总计划的运行隔离和现有状态传输限制。新增初始预算集中配置，按实测调整：

| 对象               | 初始上限                                                    |
| ------------------ | ----------------------------------------------------------- |
| 当前值（包含候选） | 20,000 项或 2 MiB                                           |
| 单值／单条消息     | 16 KiB／256 KiB；协议更小限制优先                           |
| 观测队列           | 2,048 条或 4 MiB；低流量立即处理，每轮最多 128 条后让出执行 |
| 脱敏异常样本       | 100 条或 256 KiB                                            |

超限不静默截断为完整数据。观测队列溢出先记录受影响范围与缺口，失效相关连续性，并清除缺口前积压以免重新建立错误基线；短暂过载继续接收，持续过载才暂停并提供恢复入口。反复恢复仍失败须停止自动重试，不能无限积压或重连。

诊断按需使用现有日志入口，只记录必要字段与统计，不逐条打印高频消息。限时录制结束不停止采集；持续滚动日志的期限、总容量与清理统一见 04，不在本步重复建立保存系统。

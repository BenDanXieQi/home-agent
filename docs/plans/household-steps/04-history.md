# Step 4：短期日志与活动记录

**状态：待实施。** 依赖 03 的真实采集；活动记录随 06 接入。现有设备日志用于诊断，本步增加持续滚动保存和有范围限制的查询。[返回总览](../backend-household-perception.md)

## 目标与保存范围

验证期使用本地文件，不新增设备历史数据库。当前事实仍由 03 维护，历史只回答“曾收到什么、识别过什么”，不能回写当前状态或证明没有记录的时段从未变化。

初始保存参数如下，实施时集中配置，并按实际消息量调整；容量限制可能使实际范围更短：

| 内容                                 | 初始保留方式                                                 |
| ------------------------------------ | ------------------------------------------------------------ |
| 接纳的设备观测                       | 24 小时；覆盖已接通设备，保留同值上报，不按是否命中场景筛选  |
| 有效属性变化、独立设备事件与家庭活动 | 7 天；保留各自来源、质量及修正关系                           |
| 上一次已确认活动                     | 每个已登记对象、已启用活动类型保留一份，直到替换、纠正或删除 |
| 当前设备状态                         | 由 03 维护，不受日志清理影响；重启不直接信任旧日志为当前值   |
| 身份、明确偏好与推测习惯             | 按家庭模型分别维护；不复制全量日志，推测习惯需复核           |

“上一次”活动只保留时间、参与者、地点、结论及必要证据摘录，不长期保存全部明细。它表示最后一次已知活动；存在采集缺口时，不能保证是现实中最后一次。未识别活动不能在原日志清理后凭空恢复。

## 记录内容

设备观测复用 03 的规范化结果，记录观测 ID、账号／家庭／设备／原生能力、当时房间、运行身份与处理序号、来源与交付性质、原值、必要规格说明、时间及质量。是否采纳为当前值、对应提交版本与策略版本一起保留，未知来源时间保持为空。

不逐份保存完整规格、凭据或未经筛选的协议包。首次值、缓存、迟到报告、可信边沿和独立设备事件必须可区分；属性变化不伪装成供应商事件。时间接近不能证明物理因果顺序。

活动由确定性规则或 06 提出，经后台接纳后保存；存储模块不自行推断。活动使用稳定 ID，记录候选／进行中／已结束、开始与结束依据、参与者、地点、支持与冲突证据、修正关系。重复画面和重复摘要不生成新活动，无证据时不补结束时间。

只有符合该活动确认规则的记录进入“上一次”索引。修正或撤回时同步更新索引；如更早明细已清理，无法找到替代记录就返回未知，不继续展示已被否定的结果。

## 文件写入与资源边界

观测和变化按时间分段追加为 JSONL（每行一条 JSON 记录），活动修正引用原 ID。小型活动索引通过临时文件替换更新，只接纳已保存的活动并保留必要摘录；可用保留明细增量修复，但不能删除索引中仍有效的较早活动。重试沿用原 ID，读取时识别重复，不把重试当成新经历。

| 对象                   | 初始预算                                                         |
| ---------------------- | ---------------------------------------------------------------- |
| 滚动明细               | 总计 512 MiB；期限或容量任一达到即清理最旧分段                   |
| 待写队列（含在途批次） | 10,000 条或 16 MiB                                               |
| 批次／关闭等待         | 最多 500 条或 1 秒一次；退出最多等待 10 秒                       |
| 明细查询               | 每页默认 500 条、最多 2,000 条或 4 MiB；最多 20 个能力、7 天跨度 |

画像和“上一次”索引不随明细滚动删除，但限于已登记对象与启用的活动类型，并限制条目大小和总量；不能把无限历史藏进单个条目。文件操作、重试和查询都有期限与并发上限，不建立无限等待队列。

队列满或写入失败时公开影响范围、未确认数量和原因，不能阻塞设备状态提交。异常退出后的不完整尾行可忽略并标明未确认尾部，不能宣称进程退出前的记录全部落盘。停止、改绑和撤销访问后，旧运行记录不得写入新家庭的文件。

## 覆盖、查询与清理

保存每次采集运行的起止、是否正常退出，以及断连、输入丢弃和写入失败的已知缺口。连续同类故障可合并为有界摘要；丢失数量未知就保持未知。摘要保留到不再解释现有记录，仍未结束的缺口不能按创建时间直接清除。

查询分为设备观测／变化、家庭活动和“上一次”活动，按房间、设备／实体、能力／活动类型及时间筛选。时间范围为 UTC 的左闭右开区间；分页使用时间和稳定身份排序，返回原始处理序号，排序本身不代表物理因果。

每次请求及返回前核验当前绑定和访问资格。游标绑定家庭、过滤条件与排序键，同一家庭重启可继续查询；改绑不开放旧家庭记录。返回实际保留范围、已知缺口、裁减情况和保存健康，无法证明覆盖时不标为完整。

没有记录的区间不能用前值插补为持续事实。界面和 Agent 都按需分页，不一次读取全部日志。清理失败和写入恢复可见，恢复后的新记录不填平旧缺口；视频、音频和完整图像不纳入本步默认保存。

## 验收

- [ ] 全量接纳观测与同值上报在预算内保存，原生事件和派生变化不混淆。
- [ ] 时间、容量和分页限制有效，返回实际范围；文件故障不阻塞当前事实。
- [ ] 重复写入、活动修正和撤回不造成重复经历或错误的“上一次”。
- [ ] 断连、过载、异常退出及清理造成的不足可解释，不声称连续重建。
- [ ] 用户可查询最近一次有证据的活动，原明细清理后仍能看到必要说明。
- [ ] 访问隔离与关闭符合总计划；接入 05 的展示和 06 的查询工具。

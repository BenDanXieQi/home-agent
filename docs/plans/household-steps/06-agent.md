# Step 6：事件分析、家庭记忆与控制条件

**状态：房间分析首阶段已实现；可信来源的自动触发仍待实机验收。** 已实现可信变化筛选、合并任务、有界上下文、结构化模型输出、依赖校验及 `/rooms` 的脱敏观测描述，当前限制见[房间 AI 上下文](../../reference/room-analysis.md)。首阶段总结保存在后台内存，使用单次 Agent 图；场景推断、画像、活动、问答及控制条件仍按下述计划实施。领域含义见[家庭模型](../household-model.md)。[返回总览](../backend-household-perception.md)

## 目标与分工

家庭领域维护可供消费的情景上下文；独立 Agent 提出判断并决定动作意图，backend 负责接纳判断、核验执行条件和调用设备协议。切换家庭清空当前 Agent 检查点数据，后续新增的长期记忆也必须纳入清理流程，不能跨家庭复用。

先选一个有真实证据的场景，交付从事件、上下文、判断到可见解释的完整过程。确定性代码负责事实更新、规则计算、去重和有效性；AI 只处理需要推断的部分，不按固定周期总结安静房间，也不逐条消费 MQTT 日志。

本步分阶段增加人物／宠物档案、当前判断、活动记录、问答和提前维护的控制条件。验证阶段输出判断与动作建议；真实控制须在对应能力、权限、控制路径和效果核对接通后启用。

## 代码如何选择分析时机

先区分“更新事实”“已有规则能决定”和“需要进一步分析”。触发策略按房间、能力和场景配置，启动时校验并记录版本；不是要求先知道每条日志对应什么行为。

| 输入                       | 确定性处理                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| 同值报告、无关遥测         | 更新适用时间和质量，不重复唤醒 AI                                                            |
| 房间内有意义的离散变化     | 占用、门、灯或设备工作状态等可信变化进入候选；验证初期可覆盖所选房间的这些变化，逐步调整范围 |
| 数值变化                   | 用阈值、滞回、持续时间、累计变化或趋势筛选；与上次处理基线比较，避免缓慢升温被逐次忽略       |
| 独立设备事件或宠物再次到访 | 按可靠事件身份或已定义活动边界去重，保留每次独立发生                                         |
| 判断依赖变化、证据失效     | 先使相关判断和条件失效或重算；只有需要推断时再调用 AI                                        |
| 用户提问、纠正或明确要求   | 读取相关资料；直接可更新的结构化事实先由后台处理                                             |

“有人进入”必须有相应证据，不能把首次读到有人当作刚进入。“猫再次到访”需要感知来源和到访分段，MQTT 本身不会提供缺失的视觉语义；重复帧不能计为多次。

规则输出区分真实设备事件、可信属性边沿、条件开始成立和持续条件到期。条件从未知变为成立只说明现在可确认，不能冒充物理变化；持续计时不跨越证据缺口。具体阈值依赖实际设备与场景，不建立通用嵌套规则语言。

候选变化可在短窗口内合并一次分析，初始窗口 1—2 秒，并设置最长等待。合并保留事件顺序和关键前后值，不丢掉“开后关”或独立到访。运行中的新变化记录为待处理，冷却不能直接丢弃；任务结束后重评是否需要下一次分析。

事实提交、明确规则和动作条件检查不等待上述窗口。证据到期可用计时器触发失效，但失效不等于必须调用 AI，安静且无相关变化时不重复分析。

## 上下文与模型输出

每次任务只取相关房间和实体的资料：触发事件、事实快照及缺失项、必要前后变化、近期活动、相关画像、用户要求和有效控制条件。需要更多证据时按范围调用工具，不把所有日志、完整规格或整个家庭历史塞入提示词。

输入记录触发 ID、证据引用、实际依赖版本、配置版本和时间范围。工具限制房间、设备／能力、时间、条数及响应大小，返回裁减和覆盖信息；缺少资料就保持未知，不用模型补齐设备事实。

AI 返回结构化候选判断、活动或动作建议，包含目标、结论、支持／冲突证据、适用时间和失效条件。后台在接纳时核对：

- 当前家庭、访问资格和任务是否仍有效。
- 引用证据确实来自本次可用资料，输出符合共享结构和允许修改的领域范围。
- 实际依赖是否变化或过期；无关房间变化不使整次分析作废。
- 是否与明确要求冲突，以及同一触发是否已经产生对应结果。

校验通过不保证模型判断客观正确。过期结果不能覆盖当前判断；有明确历史价值时可作为历史候选保留。模型不能直接修改原生设备值、获得执行权限或用自评分把未知事实变成已确认。

任务身份、活动身份和设备观测身份分别维护。重试不产生重复活动，AI 对自身摘要的转述不作为新证据或再次触发自己的理由。判断接纳、冲突和拒绝都在 05 可见，不能只留在运行检查点中。

## 画像、活动与提问

后台保存确认后的身份、设备关联和明确偏好；Agent 记忆模块维护有依据的推测习惯。一次调温先记为经历，多次独立经历才可提出条件化偏好；操作者不明时不归入某人画像。新增有效经历、纠正或明确指令触发更新，不定时重写全部记忆。

活动记录复用 04，保留候选、进行中、结束及修正；证据撤回要影响相关判断和“上一次”索引。日志明细已清理时保留必要说明，不能再声称可追溯全部原文。

提问由 AI 解析对象、时间和意图，再调用对应工具：

| 问题                 | 优先资料                                                   |
| -------------------- | ---------------------------------------------------------- |
| 有人在卧室睡觉吗     | 当前相关人物状态、房间判断与事实；过期或矛盾时补查必要证据 |
| 小狗在哪里           | 宠物当前／最后确认位置、时间和覆盖；看不见不等于不在       |
| 上一次遛狗是什么时候 | 已确认活动索引和必要证据，再按需查询短期记录               |
| 为什么没有开灯       | 当时的触发、控制条件、用户要求及执行记录                   |

答案区分事实、推测与未知，并说明影响结论的缺口。不默认扫描全量日志，不以没有命中记录证明从未发生，也不为此先建设向量库。

## 提前维护控制条件

在场景、要求或相关证据变化时，提前计算具体动作的允许／禁止／未知，记录原因、依据、有效期和结束条件。例如妈妈可能在卧室休息时，按已启用策略维护“禁止自动开主灯”；爸爸进入时直接由代码读取最新条件。

触发到来后再次核对当前证据、权限与条件。明确禁止不能被推测习惯覆盖；冲突、未知或过期时按预先配置的策略跳过、使用允许的替代动作或请求确认，不等待模型临时决定快速开关灯。主灯、夜灯、窗帘和手动控制分别限定范围。

米家原有确定性自动化可以继续运行。需要遵守本项目场景条件的动作，须验证米家规则是否支持接入这些条件，或改由经过条件检查的路径执行；本项目不能拦截独立运行的米家自动化。

喂食等可接受延迟的动作可由 AI 提议，代码仍检查食碗与储粮状态、近期投喂量、上限和权限。执行记录区分建议、请求发出、设备响应和效果核对；结果未知时先核对，不盲目重发可能重复执行的命令。历史纠正不重新执行动作。

## 运行边界与验收

触发有独立 ID，不把状态 SSE 当作可靠事件队列。首阶段最多维护 50 个房间任务状态、待处理变化 512 KiB、并发 2 个，开始任务前重新读取事实并去除超过 60 秒或依据失效的变化。后续活动与工具任务继续设置独立有界预算，复用 Agent 的相应执行设施。过载、取消和失败可见，不承诺进程中断后零丢失。

停止或访问撤销取消相关任务，旧结果不能回写。临时来源故障只影响依赖它的当前判断；已经成立的历史证据不自动删除。任务完成前相关输入发生变化时重评依赖，不用一个全局版本变化否定所有独立任务。

- [ ] 同值与安静房间不触发重复模型调用，缓慢变化和独立重复到访不被过滤掉。
- [ ] 一个真实场景能从输入到判断完整展示，未知身份和不足证据不被强行确认。
- [ ] 新事实、失效与用户纠正及时影响判断，模型迟到、重试和自引用不污染当前状态。
- [ ] 可回答当前位置与“上一次”活动，引用范围、采集缺口和记忆依据清楚。
- [ ] 进入事件到来前已有适用的灯光条件，快速路径只做代码核验；独立米家规则的控制边界明确。
- [ ] 验证结果与实际执行明确区分，队列、取消和访问隔离符合总计划。

# 家庭模型：事实、画像、活动与控制条件

**状态：设备事实与房间快照已实现，其余为领域设计。** 本文定义数据含义和负责模块；交付顺序见[总计划](backend-household-perception.md)，采集、保存、展示和场景处理分别在 03—06 实施。只为实际场景定义所需结构与校验，不一次建立所有人物、视觉和记忆能力。

## 目标场景

系统应能解释谁或什么、在哪里、发生了什么、依据是什么、现在是否仍成立，以及允许做什么：

| 场景                            | 所需证据与输出边界                                                 |
| ------------------------------- | ------------------------------------------------------------------ |
| 爸爸去了卫生间                  | 需要身份与位置／通行证据；仅门磁变化或占用不能直接归因或确认如厕   |
| 室温 30℃ 时，妈妈把空调调到 24℃ | 关联当时有效室温和目标温度变化；缺少操作来源时，操作者保持未知     |
| 爸爸进入卧室，妈妈可能在休息    | 保留原有休息判断，提前维护灯光条件；新占用信号不自动表示妈妈醒来   |
| 猫两次到喂食机，食碗没有粮      | 需要独立到访、食碗与储粮状态和近期喂食量；两个画面不算两次到访     |
| 上一次遛狗是什么时候            | 查询有证据的活动记录；人和狗外出可先记为候选活动，不能自动证明遛狗 |

卧室和卫生间使用实际可用的非视觉来源。手机亮屏／息屏需验证后台上报、时间、补发和断连语义；视觉仅用于允许部署且覆盖明确的空间。这些来源均不能由现有 MQTT 属性接口推定为已支持。

## 信息分层与归属

| 信息           | 内容                                           | 负责维护                        |
| -------------- | ---------------------------------------------- | ------------------------------- |
| 设备事实       | 原生属性、观测、当前有效性、设备与房间归属     | backend 采集与家庭运行时        |
| 家庭档案       | 人物／宠物身份、设备关联、空间与覆盖、明确偏好 | backend 家庭档案                |
| 当前判断       | 位置、占用、活动、可能休息及支持／冲突证据     | backend 确认；规则或 Agent 提出 |
| 活动记录       | 开始、进展、结束、参与者、地点、证据与修正     | backend 接纳，04 保存           |
| 要求与控制条件 | 用户要求，以及对具体自动动作的允许／禁止／未知 | backend 条件与执行模块          |
| 推测习惯与经验 | 从独立经历提炼的候选偏好、规律和效果           | Agent 记忆模块                  |

各模块在现有 backend／Agent 中实现，不新增家庭建模服务。共享输入与输出在 `packages/api` 定义一次；人物不伪装成设备，语义不编造 `siid/piid`。验证期采用有范围限制的本地文件保存档案和记忆，不把新增数据库作为前置条件。

## 人物、宠物与空间

人和宠物拥有稳定身份，允许访客和未识别对象；姓名、角色、物种和外观是属性。临时跟踪编号与家庭身份分开，跨镜头或跨房间不能仅凭编号合并。用户登记或确认发现后建立关联；身份合并、拆分与纠正保留依据。

人物画像分为身份与设备关联、明确偏好、推测习惯；当前所在位置和活动单独维护。每条偏好记录来源、适用条件和更新时间。一次空调操作只是一段经历，重复转述同一经历不增加证据次数。明确偏好保存到修改或撤销，推测习惯按使用情境和新证据复核。

人物／宠物当前状态按位置、活动、姿态、可见性等维度表达，保留最近确认时间。状态随同一个实体跨房间使用，不在各房间复制画像。手机属于谁不能证明当前操作者或位置；看不见、息屏和静止不能单独证明离开或睡着。

空间可以包含房间、床区、门口等区域。门的连接两侧与方向、设备安装位置、测量范围、视觉覆盖和作用范围分别记录；设备在某房间不代表覆盖整个房间。户型图可作为输入，不是前置条件；自动发现的布局先待确认，变更后重评依赖它的判断，历史保留当时归属和版本。

## 房间上下文与当前判断

房间上下文按需组合三部分：

1. **事实快照**：03 提供的设备当前值、时间、质量与覆盖。
2. **相关实体和判断**：人物／宠物状态、正在发生的活动，以及房间综合判断。
3. **有效要求和控制条件**：当前自动化应遵守的明确条件。

事实快照从设备状态派生，不另存一套可写设备值。房间综合判断可以单独保存，但只有一个模块负责更新；自然语言摘要由结构化记录生成，不充当新的证据。

每项判断表达目标、维度和值、适用时间、支持与冲突证据、推导方式、实际依赖版本及失效条件，区分暂定、冲突和未知。来源有效、模型识别把握和判断当前有效性分别表达；模型自评分不等于经过校准的准确率。

相关证据变化、失效或用户纠正时重算或标待评估。模型尚未返回时，不把旧判断标为与新事实同步；重启后档案可恢复，动态状态须重新核验。观测缺口不能延长持续计时，最后已知位置不能无限当作当前位置。

“灯都关着”需要明确灯具集合和有效覆盖；“床铺有人”不能证明具体身份；一部手机亮屏不表示其他人醒来。房间还可能有未识别人员，不能只统计已命名成员的位置。冲突来源保留各自陈述，不能用最后收到的消息覆盖所有证据。

## 活动、归因与环境

区分设备观测、家庭活动和唤醒 Agent 的触发：不是每条活动都需 AI，也不能把重复摘要当成新活动。活动有稳定身份、候选／进行中／已结束等状态、时间范围和证据；无法确认结束时保留未知，不凭静默补结束时间。

操作者、方向与渠道允许未知。门开不证明谁通过；设备被设置不证明命令成功；供应商未给外部操作记录时不强行归因。系统发出的命令分别记录意图、发出、设备响应和状态核对。更正历史活动不重复执行原动作。

环境趋势按具体窗口、单位、覆盖和缺口计算。进入／退出阈值、持续时间与基线由场景配置确定；数据不足时为未知，不把离线当作恢复，也不让长期异常自动变成正常。单次读数不能证明持续状态，时间接近不能单独证明因果或措施效果。

## 提前维护控制条件

场景或用户要求变化时，先计算具体动作的允许／禁止／未知条件；有人进入等触发到来时，代码检查最新有效条件，不等待 AI 临时决定是否开灯。主灯、夜灯、窗帘分别配置，禁止自动开主灯不自动禁止手动控制或所有照明。

用户要求记录提出者、作用对象、动作范围、生效和结束条件、来源及冲突处理。“接下来一小时不自动开主灯”即使无人也继续有效；事实判断与用户要求分开。明确禁止不能被推测偏好覆盖；冲突、未知、证据过期和手动操作的处理须在场景启用时配置。

这些条件只约束实际经过它们的控制路径。保留米家已有确定性自动化，但涉及场景限制的规则必须验证能否接入前提条件或改由受控路径执行；不能宣称可以拦截独立运行的米家规则。食碗为空与储粮仓为空也必须区分，补喂还受投喂上限和执行条件约束。

## AI 与记忆

Agent 按事件或用户提问读取相关快照、变化、近期活动与画像。能确定计算的部分由代码处理；需要推理时，Agent 产生待校验判断，backend 核对权限、证据、实际依赖版本和结果年龄后接纳。校验通过不证明物理判断一定正确。

记忆是按需查询的资料，不是长期塞在提示词中的全量日志。活动经过复用 04；backend 持有确认后的身份与明确偏好；Agent 单独维护推测习惯，使用时带来源和不确定性。行为要求由 backend 执行，不依赖 Agent 在线记住。

明确偏好或有效的新经历可以触发更新，安静时不定时重写画像。证据重复、修正、删除和过期要反映到相关判断与记忆；原文已清理时明确说明。推测习惯不能直接取得设备控制权限。

## 后续实施拆分与验收目标

先交付房间事实，再为一个真实场景接入判断、必要档案、可见解释和失效处理；需要回顾时增加活动记录，需要控制时增加对应执行能力。手机、视觉、自动布局识别和复杂习惯学习按实际依赖接入。

- [ ] 人物／宠物与设备身份明确，未知对象和定位不足不被强行归因。
- [ ] 房间事实、当前判断、明确要求和画像能分别解释来源、时间及有效性。
- [ ] 新进入信号不会自行清除已有休息判断；判断失效不伪装成确认无人。
- [ ] “上一次”活动回答标明证据、修正和采集覆盖，不承诺恢复已删除日志中的漏识别活动。
- [ ] 自动动作检查当前条件，模型结果过期、明确要求撤销或权限变化不会被忽略。
- [ ] 验收结果包含用户可见解释，未接通来源和未启用动作如实标注。

# 家庭语义目标：实体、观察、判断与行为约束

**状态：领域设计，尚未实现。** 本文定义项目的家庭语义终极目标、所有权、分阶段交付及设备基础与语义层的关系，不是数据库迁移或接口已交付的说明。字段名称表达所需语义，具体 schema、容量和实现模块在对应实施计划中确定。

**层次边界：** backend 负责家庭实体、空间、来源观察、当前判断、事件历史和生效中的行为约束；Agent 既消费已接纳的家庭语义，也根据证据计算并提交部分语义候选；同时负责任务推理、上下文组装，以及另行设计的长期记忆。本文只定义 backend 如何为 Agent 提供可解释的数据，以及 Agent 建议如何通过受控命令进入 backend，不设计 Agent 的记忆系统。

[设备感知实施计划](backend-household-perception.md)的 Step 1—5 先完成采集、状态、历史与同步，Step 6 再完成设备级 Agent 接入；随后实现本文的家庭语义闭环，最后接入受控动作。六步完成不等于家庭语义目标已经完成，也无需等待完整语义 schema 才能推进六步。六步中的设备协议不自动扩大为人物或视觉协议，也不承担 Agent 记忆协议。修改现有实施契约时，须同步修改全部引用后再实施，不能由某一步自行换方案。

## 目标与范围

系统逐步理解家庭的成员、空间、设备和当前活动，回答：谁或什么，在什么位置，发生了什么，依据是什么，现在是否仍然成立，以及系统被允许做什么。

家庭构成可配置，不把人数、物种或数量写进类型。两位人类成员、一只狗、两只猫是一个实例；模型也允许访客、未识别的人或动物，以及暂时无法归属的占用证据。身份、布局和设备位置既可由用户预设，也可从观察中形成候选并逐步确认。

卧室和卫生间不部署摄像头，这些空间的判断与验收不依赖视觉输入。手机主动上传的亮屏／息屏事件、已有灯光与其他实际可用传感器可作为辅助证据；手机上报能力需单独验证，不视为现有接入已支持。视觉来源仅用于实际允许部署摄像头且覆盖明确的其他空间。

主要目标场景：

- 卧室已有可能休息的证据时，新的进入／存在信号不会单独触发主灯；没有成员定位证据时，不强行认定谁在床区或谁刚进入。
- 静止、手机没有新事件、传感器盲区或短暂失联不被直接解释为人员离开；单次异常存在信号也不直接构成可靠占用事实。
- 描述门的变化、人员通行方向，以及设备被调整的经过；只有证据足够时才归因到操作者和渠道。
- 将环境读数转换成有时间范围、覆盖说明和上下文的趋势或事件。
- 保存可解释的观察和事件历史，供 Agent 查询和提炼长期记忆；历史存储本身不承担记忆提炼。

## 实现位置与 schema 边界

沿用现有 backend 与 Agent 两个服务，不新增家庭建模服务。下面是后续交付的职责位置，不要求在六步中提前创建空模块、空表或通用语义引擎。

| 位置                                   | 职责                                                                                           |
| -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `apps/backend/src/household/`          | 实体与关系、已接纳观察和判断、有效要求、依赖失效、受控提交与查询；复用现有家庭作用域与提交约定 |
| `apps/backend/src/db/schema.ts` 及迁移 | 持久档案、要求、选定判断与领域事件历史；复用数据库，不把全部语义塞入设备时序表                 |
| `apps/agent/src/household/`            | 家庭上下文读取、异步语义评估、候选提交及任务协调；复用 Agent 运行资源，不混入用户聊天记录      |
| `packages/api/src/contracts/`          | 前后端及 Agent 共用的类型化 schema；设备契约按六步实现，家庭语义契约按具体场景增加             |

语义 schema 分为实体／关系、来源观察、判断候选／已接纳判断、领域事件和有效要求。先为首个场景定义所需的具体判别类型、字段与校验，不建立任意 JSON 事实袋，不一次实现全部人物、视觉或记忆结构。名称不是身份；观察、推断和要求不能互相代替。新增类型的投影、版本、容量、保留和权限随该功能一并定义。

Agent 候选至少表达目标实体、判断维度与值、证据引用、适用时间、所用依赖版本和不确定性；backend 校验后分配正式判断身份、版本与接纳时间，并决定有效期。模型不能自行赋予正式版本、延长证据寿命或获得控制权限。schema 校验和接纳成功表示符合系统接纳规则，不证明推断在物理世界中必然正确。

| -------- | ---------------------------------------------------- | ------------------------------------------------ |
| 家庭档案 | 成员、宠物、设备、空间和稳定关系                     | 用户登记、设备目录、经确认的发现；名称不是身份键 |
| 来源观察 | 设备上报、手机状态事件、视觉观察、语音输入、控制日志 | 保留来源、采集时间、覆盖与质量；不改写原始证据   |
| 当前判断 | 成员位置与活动、区域占用、房间综合状态               | 从观察推导，带支持与冲突证据、有效性和版本       |

长期记忆位于 Agent 层。记忆中的“某成员可能偏好较暗灯光”只是推理背景；只有经授权转换为具体、可校验的配置或要求后，才成为 backend 的执行依据。

来源有效不等于推断正确。例如摄像头连接正常且画面时间可信，只证明图像来源可用，不证明模型把两只猫分对了。设备读数质量、识别把握程度和派生判断的有效性分别表达，不能共用一个“可信”布尔值。

## 实体与关系

### 成员与可观察对象

人和动物使用稳定的实体身份，种类、名称、角色和外观描述作为属性。已登记成员身份与摄像头临时跟踪 ID 分开；同一个对象跨镜头出现不能仅凭临时编号合并。

观察到未知对象时允许建立临时观察对象，记录候选身份而不强行命名。重复看见可以帮助聚类和提出身份候选，但不能据此认定是家庭成员、绑定手机所有者或取得控制权限。身份合并、拆分与纠错保留依据；历史保留当时识别结果，并能关联后来的修正，不悄悄重写过去。

成员当前状态按维度表示：位置、活动、姿态或休息迹象、最近确认时间及当前可见性。不要把“在卧室、躺着、可能休息、被遮挡”塞进一个互斥枚举；也不要把没有观察到等同于不在家。睡眠相关表达默认是休息迹象或推断，不宣称仅凭息屏、关灯、静止或画面确认真实睡眠；无对应来源的姿态、可见性与精确位置保持未知。

### 空间、布局与覆盖

空间支持家庭、楼层、房间和区域，例如卧室内的床区、门口与走道。连接关系表示哪些空间通过哪扇门相连，包含明确的两侧与方向基准；“内／外”必须指明相对于哪扇门或哪个空间，未知时不猜。

户型图是布局的输入与参考附件，不是必须存在的前置条件。没有精确尺寸时可以只有拓扑关系；有图纸时保存其版本、坐标基准及标注关系，不能把图片像素直接当真实距离。识图或运行观察得到的房间连通、区域边界先作为候选。

设备关系至少区分安装位置、测量范围、视觉覆盖、遮挡区域和作用范围。摄像头位于客厅不代表能看到整间客厅；空调的作用区域也不必等于安装点。成员所有权、手机归属和设备控制权限分别建模，不从物理位置推断权限。

布局和覆盖发生变化时，应重评依赖它们的当前判断；历史仍引用采集时的布局版本。

### 与供应商目录的关系

首期仍按现有计划管理一个供应商账号下的一个家庭。供应商账号不是家庭成员，供应商房间也不是完整的空间布局模型。成员、局部区域和本地关系使用自己的稳定身份，设备与房间通过显式来源引用连接供应商目录，不把成员伪装成设备或编造 siid/piid。

供应商名称和规格保持原语义，本地别名、布局和用户确认信息单独维护。断网或目录暂时失败不会删除本地家庭知识；明确访问撤销立即停止相关来源与动作资格。未来若接入多个供应商，需要独立定义家庭映射与权限，不能按名称自动合并。本篇不交付多账号或多家庭同时守护。

## 观察与当前判断

设备观察沿用 Step 3；手机状态事件、视觉、语音与操作日志需新增各自的判别类型及来源契约，不强套 MQTT 订阅、设备属性新鲜度或数值采样规则。

每份观察须能说明：来源、所在家庭与空间、采集时间或区间、接收时间、数据覆盖、处理版本，以及可引用的证据。视觉结果额外记录摄像头、布局／覆盖版本和识别依据；媒体留存与访问策略另定，不承诺永久保存原始画面。

当前判断表达“系统根据证据认为”：主体、判断维度和值、成立时间范围、支持与冲突证据、推导方式及版本、最近评估时间和失效条件。至少可区分有支持、暂定、冲突和未知；最终枚举在语义实施阶段统一确定，不由自然语言生成任意新状态。

具体规则：

- 缺少传感器活动、画面没看到人，只有结合覆盖和遮挡条件才可能构成离开证据。
- 有既往位置证据但当前传感器无法确认时，可保留“最后确认在该区域、现在无法确认”，不能无限保留为已确认占用。
- 依赖失效时降级判断并终止不再成立的持续计时；所采取的保守照明行为属于行为策略，不把保守行为写成事实。
- 冲突不靠“最后收到的覆盖一切”解决。保留各来源陈述，由明确的融合策略选择结论或保持未知。
- 模型输出的自评概率不直接视为已校准准确率；未建立校准依据时使用定性判断和证据说明。

### 无摄像头空间的辅助判断

手机亮屏／息屏只描述该手机的状态。来源契约须验证平台权限、后台上报、延迟／补发和断连行为，区分事件发生时间与 backend 接收时间；久未收到消息不表示持续息屏。手机与成员由用户明确绑定，设备归属不证明当前操作者，也不证明该成员正在卧室。

卧室休息判断可结合已验证的手机事件、主灯／床头灯状态及变化、已有存在／门磁等来源和时间情境。各证据必须具有适用空间与有效期；没有定位证据的手机事件只能作为成员层面的辅助信息，不能自行定位到卧室或床区。卫生间同样只使用该空间实际可用的非视觉证据。

- 主灯关闭、床头灯随后关闭、相关手机息屏且存在证据支持有人，可支持“卧室可能有人准备休息”；组合仍是推断，不等于确认睡眠。
- 一部手机亮屏不否定其他人仍在休息，也不直接构成自动开主灯的授权；关灯状态不证明是谁操作。
- 手机失联、延迟补发或证据冲突时，不刷新为新的休息／醒来事实。保守照明行为由明确策略决定，与休息判断及用户禁开要求分开。

### 房间综合状态与受控冗余

允许保留成员状态之外的房间／区域综合状态，供照明、音箱、窗帘和 Agent 直接使用。它是带依据的派生结果，有唯一写入所有者、依赖集合、计算版本与失效规则；其他消费者只读，不各自改一份。

例如已有证据支持“卧室可能有人休息”，随后出现新的进入／存在信号，不能自动清除原休息判断；只有存在相应身份与位置证据时，才进一步描述为“A 可能在床区休息、B 进入”。房间占用还可包含未识别人员证据，因此不能只统计已命名成员的位置。

依赖变化时重算或先标记待评估；异步模型还没返回时，不把旧综合状态标成与新事实完全同步。自然语言说明由结构化判断生成，不充当独立事实库。重启后档案可恢复，动态判断必须重新核验，不把持久旧状态自动标为实时。

## 事件与归因

设备状态初值、恢复值与边沿沿用 Step 3/6 的区分：收到“开”只证明收到该状态，满足连续基线与边沿条件后才记录“观察到关→开”，不能从恢复快照补造变化。

领域事件回答谁／什么、何时、在哪里、发生了什么，附带前后状态、相关实体与证据。参与者、地点、方向和渠道允许未知或候选；不为生成流畅句子填补缺失信息。

区分三种记录：来源观察、整理后的领域事件、需要唤醒 Agent 的任务触发。领域事件不必每条都唤醒 Agent；同一个领域事件也不能仅因重新摘要或展示就变成新事件。首期 Step 6 的 semantic_event 是规则触发传输协议，不等于已经具有完整的家庭事件历史。

| 场景                | 可直接记录           | 额外结论需要的证据                                                                       |
| ------------------- | -------------------- | ---------------------------------------------------------------------------------------- |
| 门磁报开            | 收到该门为开的状态   | 谁打开、从哪侧开、谁通过，需要身份、两侧布局、轨迹或其他关联来源；开门人不一定是通过的人 |
| 空调设定改变        | 设定从某值变为另一值 | 操作者及语音、手机、遥控器、自动化等渠道，需要相应命令／审计链路；仅时间接近不能证明因果 |
| 听到调整空调的语音  | 某条请求被识别       | 是否送出命令、设备是否执行、是否达到目标，必须分别确认                                   |
| 多人进入后 CO₂ 上升 | 两类事件的时间关联   | 关联可以提供解释线索，不能仅凭先后顺序认定因果                                           |

系统自己的动作应关联任务、指令、发出渠道、设备响应和状态验证；供应商未暴露外部操作日志时，外部操作者与渠道保持未知。重新识别后的事件修正保留关联，不再次触发原物理动作。

## 环境语义与触发

保留原始单位、读数质量、有效覆盖和空间范围，在其上计算当前水平、趋势、持续时长及措施后的变化。房间内某个传感器的读数不能无依据扩展成全屋状态。

事件策略按能力、房间和用途配置，首期候选包括持续越界、变化速率、偏离历史基线和恢复。每条策略需要明确窗口、最低有效覆盖、进入／退出阈值、持续时间、重复提醒间隔和缺口处理；具体参数由实测与用户偏好确定，本篇不预设温度或 CO₂ 的通用健康阈值。

离线、过期或数据不足时返回未知，不能计算成稳定、正常或恢复。异常判断的历史基线要区分时段和使用情境；不能让持续异常自动训练成正常。Step 4 的采样趋势不支持任意精确条件时长，需采用采样前的连续有效输入或已有明确口径的摘要。

开窗、空调调整等事件可用来观察后续效果；没有可比较的前后覆盖时，效果标为未知，不据此形成可靠经验。趋势与基线检测超出现有 Step 6 的标量比较规则，必须独立实现计算与验收。

## 用户要求与动作决策

用户要求是独立的规范信息，不是观察结论。至少记录提出者、目标空间／设备／成员、允许或禁止的行为、生效时间、结束条件、来源和确认状态。临时要求按明确时区解释并给出实际截止时间；含糊的“今晚”等需采用可见约定或澄清，不能悄悄变成永久规则。

“A 在卧室休息”可以支持勿扰判断；“卧室接下来一小时不要自动开主灯”即使无人也继续有效。不要用同一个 room_mode 字段同时表达事实和要求。

明确有效的禁止约束不能被自动学习的偏好覆盖。同级明确要求发生冲突时，标记冲突并暂停受影响的自动动作或请求澄清；不能只按最后一段模型文本覆盖。撤销、到期和成员权限变化均需要触发重评。手动关灯可作为用户意图的候选证据，其自动抑制范围与期限须由明确策略决定，不能从一次关灯推断永久偏好。

动作资格在实际执行前再次检查最新约束、来源有效性及任务期限。模型提出建议不等于获得权限。设备命令幂等、执行结果不明、重试和结果确认属于单独动作实施计划；现有六步不交付这些能力。

## 自动建模与 Agent 长期记忆的边界

家庭模型的自动建立与 Agent 长期记忆是两件事。前者形成成员候选、空间标注、设备覆盖和当前活动等领域数据；后者从经历中提炼偏好、习惯和经验，辅助后续推理。两者可以使用模型计算，但不能因此合并所有权。

初始化支持手动登记、导入户型或设备目录，以及运行中发现。发现结果先保存为有证据的候选；自动确认的范围须有明确策略。反复出现的未知对象不自动变成家庭成员，模型估计的设备布局不自动覆盖用户确认位置。候选产生者可以是感知任务或 Agent，backend 负责验证、接纳、版本和纠错。

backend 向 Agent 提供有来源的当前判断、事件和有界历史查询。事件重传和同一观察的多次摘要保留关联，不能伪装成多个独立经历；证据被修正或删除时须可被消费者识别，证据过期则明确不可获取。Agent 如何提炼、检索、遗忘和修正长期记忆，另写 Agent 层设计，不由设备历史 writer 或家庭 actor 实现。

两层通过以下边界协作：

| 信息或操作                   | 权威所有者                       | 跨层规则                                                                                    |
| ---------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------- |
| 成员登记、房间连接、设备覆盖 | backend 家庭模型                 | Agent 可提出候选，通过受控命令确认；不能只写一条记忆就改变身份或布局                        |
| 当前观察、活动判断与事件历史 | backend 家庭模型                 | Agent 按任务读取；模型转述不成为新证据，也不刷新观察时间                                    |
| 成员偏好、习惯和经验的推测   | Agent 记忆层                     | backend 不将其直接当事实或规则；Agent 使用时保留不确定性                                    |
| “接下来一小时不要开主灯”     | backend 生效要求                 | Agent 理解语言后提交明确目标、期限和来源，backend 接纳后才生效；不依赖 Agent 持续在线记住它 |
| 根据记忆提出的自动化建议     | Agent 提出，backend 接纳具体规则 | 明确权限、条件、作用对象和有效期后才能进入执行层，不能隐式生效                              |

原始媒体、领域事件和身份样本由相应 backend 模块确定保留与访问范围；Agent 记忆单独定义保留策略。身份样本不因 Web 能看设备状态就全部广播。历史可支撑记忆，但不保证 Agent 自动获得全部历史或断线期间的事件。

## 所有者、异步推理与 Agent 上下文

backend 维护已提交的设备事实和家庭模型；专门的感知／推导任务可以异步计算候选，提交时验证家庭作用域、输入证据版本、布局版本及结果年龄。失效结果不能覆盖新状态，可按历史策略留作过去的观察。不要因为家庭其他无关字段更新就丢弃所有模型结果，应核对该任务实际依赖。

需要模型的语义计算放在现有 Agent 服务内的独立评估任务；backend 的所有权指验证、接纳、发布与失效管理，不要求模型计算运行在 backend 进程。明确的确定性派生由 backend 普通代码处理，不为简单条件调用模型。耗时视觉和 LLM 推理不进入 Step 2/3 的同步提交或规则 hook。其返回值作为新的、有来源的语义输入处理；模型不可直接修改整个家庭对象。轻量确定性派生可以同步计算，房间综合状态仍由一个所有者提交。

backend 提供触发证据、家庭概览、相关当前判断和有效要求；Agent 将这些材料与自己检索的长期记忆组合成任务上下文，并能继续按需查证。backend 不拥有 Agent 的记忆库，也不负责统一生成最终模型提示词。全屋概览帮助发现跨房间关联；原始媒体、全部规格和无限历史不默认进入提示词。上下文不足、被裁减或来源过期须明确表示，不能因没带某实体就推断它不存在。

设备状态版本不自动涵盖另外存储的布局与要求。backend 返回的家庭上下文至少标明生成时间、scope_epoch、设备 state_version 以及实际使用的各领域版本；引用关系应可核对。Agent 另行标记本次使用的记忆来源，不把记忆检索结果冒充同一家庭状态版本。依赖版本不匹配的判断标为待重评或失效，不作为当前有效事实及动作前提；列出版本号本身不能代替一致性校验。这只是系统已知信息的一致组合，不证明所有传感器在物理同一时刻采样。

### 生成与消费闭环

1. backend 接纳设备或手机等来源观察，维护来源时间、质量与作用域。
2. 相关证据变化、明确要求变化或判断到期触发重评；确定性规则直接计算，需要综合推理时交给 Agent 的有界评估任务，不对每条重复上报调用模型。
3. Agent 读取相关证据、既有判断和要求，产生结构化候选；未知身份与位置保持未知，不直接改写家庭对象。
4. backend 校验提交权限、作用域、引用证据、实际依赖版本及结果年龄，接纳候选或返回拒绝原因。相关输入已过时的结果不覆盖当前判断。
5. backend 发布已接纳判断，供页面与 Agent 后续任务消费；依赖改变、过期或被修正时，由 backend 降级或失效，不依赖下一次聊天才更新。

派生结果保留原始证据关联。重复提交、模型转述及同一观察的多次摘要不构成独立新证据，不刷新有效期，也不单凭自身发布再次触发同一评估循环。评估调度、提交身份与重复处理在首个语义场景的实施契约中确定，复用已有有界任务和作用域机制。

### 设备副本与语义上下文

保留 Step 2/3/5/6 与总览规定的“独立 Agent＋完整只读设备状态副本＋独立事件流”。副本只读不禁止 Agent 经受控命令提交语义候选；最终状态仍由 backend 接纳并发布。

新增家庭语义按任务从 backend 的已提交状态读取有界上下文，与设备副本的证据及版本关联。它不自动进入设备公共投影，不扩大原有 8 MiB 预算；如需新增订阅实体，在语义实施阶段定义明确的访问范围与同步契约。设备数据继续走已定通路，不并行维护第二套设备镜像。上下文组装属于 Agent，既不把全部家庭资料默认放入模型提示词，也不把模型 token 窗口当作网络快照容量。

## 六步架构适配检查

结论：现有计划是可复用的设备感知基础，尚不能单独交付完整家庭模型或情境照明。以下是能力边界与后续设计工作，不表示现有步骤已完成，也不扩大它们的验收承诺。

| 步骤                                                 | 已规划、可复用的基础                           | 完整家庭模型所需但尚未覆盖的部分                                               | 实施约束                                                                   |
| ---------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| [1 接入](household-steps/01-device-access/README.md) | 来源契约、真实推送、读取与恢复验证             | 身份证据、手机状态事件、视觉覆盖、语音与操作渠道来源                           | 设备数据不能自动证明操作者、通行方向；其他来源另做契约                     |
| [2 运行时](household-steps/02-household-runtime.md)  | 稳定身份、目录归属、作用域、唯一提交点         | 人和动物、局部区域、布局版本、候选发现、要求及派生判断所有者                   | account_id 不是成员 ID；持久目录不能替代动态认知；耗时推理在提交外         |
| [3 集采](household-steps/03-collection.md)           | 质量、时间、逐输入处理、缺口与有界队列         | 手机与视觉观察、身份关联、活动判断、多源冲突与受控冗余                         | 不把语义判断塞进 latest 属性；设备有效性不等于识别正确                     |
| [4 历史](household-steps/04-history.md)              | 设备时序、质量时间线、采样与覆盖说明           | 领域事件历史、证据修正、身份／布局版本；向 Agent 提供可引用的历史              | 时序摘要不是长期记忆；采样明细不能证明任意精确活动时长                     |
| [5 Web](household-steps/05-live-web.md)              | 完整设备公共投影、原子增量和恢复               | 人宠与空间编辑、要求管理、候选确认和语义解释；不同消费者的数据范围             | 当前实体白名单和 8 MiB 预算未包含新增模型，不能直接塞入；先定义投影与预算  |
| [6 Agent](household-steps/06-agent.md)               | 有证据的设备规则触发、任务期限与取消、查询工具 | 语义候选生成与接纳、家庭上下文、语义条件与有效要求；动作执行和长期记忆另行实施 | 现有规则只引用设备能力，不能假装已支持“有人睡觉”；只读建议不能验收自动照明 |

其中 Step 4 的设备历史与 Step 6 的尽力而为事件交付，不构成可重放的家庭经历库。若 Agent 记忆消费要求不漏事件，需要另外定义 backend 事件持久化、Agent 消费进度及重复处理边界；这些交付保证与记忆提炼算法分别设计。

## 后续实施拆分与验收目标

实施顺序固定如下。后续阶段按真实场景形成独立实施计划，不将全部领域能力变成设备六步的前置条件。

| 阶段               | 交付                                                 | 完成边界                                                                 |
| ------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| 设备基础：Step 1—5 | 真实接入、家庭目录、当前状态与质量、历史、Web 同步   | 无消费者也持续采集，来源与缺口可解释；不声称已理解人员活动               |
| Agent 基础：Step 6 | 完整设备副本、设备规则事件、只读工具、有界推理任务   | 可依据真实设备证据给建议；不要求人物 schema 或语义候选写入               |
| 首个家庭语义闭环   | 无摄像头卧室的休息相关判断、明确要求、候选接纳与消费 | Agent 能生成部分语义并消费已接纳结果；后台独立维护有效性，不执行物理控制 |
| 受控情境动作       | 约束检查、手动操作处理、命令与实际结果确认           | 在明确授权下控制设备，失效判断不成为动作依据                             |
| 按场景扩展         | 更多空间与成员、允许区域的视觉、归因与环境语义       | 每项独立定义来源、schema 和验收；自动建模及长期记忆按需要另行推进        |

首个家庭语义闭环按以下顺序落地：

1. 手动配置卧室与实际区域、主灯／床头灯作用范围、手机归属和已有传感器覆盖。无需图纸、跨镜头身份识别或自动布局发现；缺少区域或成员定位证据时只作房间级判断。
2. 验证手机亮屏／息屏事件的授权、后台投递、延迟、补发与断连，接入独立来源观察；不修改米家设备 siid/piid 协议来伪装手机事件。
3. 定义该场景的共享 schema、backend 存取与失效逻辑、Agent 评估与候选提交接口，跑通“证据→候选→接纳→失效→消费”。确定性规则能解决的判断不强制调用模型。
4. 接入有明确作用对象和期限的禁开要求，提供当前判断、证据、限制和有效要求的查询与展示。规则或 Agent 可以给照明建议，此阶段不发送控制命令。
5. 验收息屏但位置未知、另一部手机亮屏、上报中断与补发、输入变化后模型迟到、要求撤销等场景，再进入独立动作实施计划。

验收使用真实可复核场景，下表覆盖最终语义与动作目标，不授权新增测试代码。首个语义闭环只验收判断、要求及建议；涉及实际开关灯和执行前资格的行为，在受控情境动作阶段验收：

| 场景                                                   | 必须满足的行为                                                                         |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 无摄像头卧室已有可能休息的证据，随后出现进入／存在信号 | 不由新信号直接清除休息判断或打开主灯；缺少身份／位置证据时不强行归因到 A、B 或床区     |
| 主灯与床头灯关闭、相关手机息屏                         | 结合空间与占用证据形成暂定休息判断，不报告确认睡眠；手机归属不代替成员定位             |
| 一部手机亮屏，或手机失联后补发事件                     | 不推断所有人醒来或无人休息；按来源时间处理补发，失联不算持续息屏                       |
| 画面被遮挡、存在传感器短暂转无人                       | 明确可见性与证据不足，不宣称确认离开；保守动作不反写为占用事实                         |
| 传感器长期误报存在                                     | 保留冲突和来源诊断，不无限续期为已确认占用；按已定义策略重新核验或降级                 |
| 未识别的人或宠物出现                                   | 可表达所在区域与活动，不擅自绑定家庭身份；未知对象不等于无人                           |
| 所有人离开，但一小时禁开主灯仍有效                     | 要求继续有效；到期、撤销后重评，不伪造有人状态来维持禁令                               |
| 收到已验证的开门变化但无操作者／方向证据               | 记录门的变化，未知归因保持未知，不用最近出现的人填补                                   |
| 空调变化缺少手机／语音操作日志                         | 保留变化事实，渠道未知；自己发出的命令与实际结果分开确认                               |
| CO₂ 趋势窗口中断                                       | 覆盖不足时停止连续趋势结论，恢复后按策略重新建立依据                                   |
| 修改布局或纠正猫的身份                                 | 当前派生判断重评，历史保留当时证据，相关修正可供 Agent 查询，不直接操作 Agent 的记忆库 |
| 推理中切家、要求被撤销或结果过期                       | 旧结果不成为新作用域的有效建议，实际动作前再次核验资格                                 |

尚需确定的产品参数包括：第一批可观测设备与区域、自动确认身份／布局的范围、房间未知时的灯光行为、手动控制抑制期限、要求冲突处理细节、环境事件阈值和 backend 证据保留策略。它们不阻塞设备来源验证，但必须在相应自动判断或动作启用前明确。

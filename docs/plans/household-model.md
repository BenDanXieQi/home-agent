# 家庭助手的信息边界与状态归属

**状态：待实施设计。** 家庭助手以有来源的记录为材料，围绕用户交付的职责查询、调查和行动。系统维护自己已接纳的责任，不承诺持续重建每个人、宠物和房间的完整现实状态。专门的活动或共享判断结构只为明确的产品需求建立。

[家庭观察与 Agent 工作协作设计](household-automation.md)维护流程、接口用途和唯一交付顺序；[家庭记录与 Agent 工作存储设计](household-storage.md)维护字段、事务和清理。当前实现与缺口集中在[实现基线](household-automation.md#当前实现与缺口)，本计划不表示新增能力已可使用。

<a id="scope"></a>

## 本地家庭与来源

一个 backend 服务一个本地家庭。成员、用户报告和持续职责归属本地家庭；米家、摄像头及其他系统提供观察或动作能力。稳定家庭身份与来源绑定、运行标识分别管理：运行标识用于拒绝旧回调，不能充当跨重启的家庭身份。

目标是来源可选：没有米家账号时，仍可管理本地成员、用户报告和已配置渠道的提醒；设备查询与媒体读取则返回来源不可用。当前实现仍有米家绑定和页面访问门禁，迁移任务见[家庭生命周期](household-automation.md#家庭生命周期)，不能把这一目标写成现有行为。

来源暂时中断只影响相应材料的新鲜度和可获取性。解绑撤销来源访问，使依赖它的工作受限；保留在本地家庭的记录仍带原来源和访问限制，不因为保留记录就保留原媒体的读取权。明确家庭重置才删除本地资料、记录、工作和记忆，阻止旧请求进入新家庭。

房间编号、摄像头安装位置与实际可见区域不同。当前设备清单继续由来源适配维护；首批查询以原摄像头标识和当时名称说明来源，不预建空间拓扑或通行覆盖模型。需要稳定本地房间或位置动作时，再按该消费者定义映射及变更责任。

<a id="information-kinds"></a>

## 信息含义

| 信息           | 含义与例子                               | 使用限制                                                       |
| -------------- | ---------------------------------------- | -------------------------------------------------------------- |
| 成员与来源资料 | 某个人、宠物、设备及其登记资料           | 资料不证明当前在场或活动                                       |
| 来源记录       | 设备报告、成员出现归因、用户说八点遛过狗 | 保留生产者、时间、修订及不确定性；含推断的记录不能统称原始事实 |
| 短期材料       | 窗口帧事实、转写文字、图片与音视频       | 摘要和媒体各有期限；可查询不代表可跨重启恢复                   |
| 任务判断       | 本次调查认为猫可能想吃东西               | 默认保存在该次执行中，不自动成为全家庭事实                     |
| 经验与笔记     | 主人说猫有时需要陪着吃饭                 | 用于检索与调查提示，不作为设备控制的充分条件                   |
| 明确要求       | 到期提醒、暂停职责、今晚禁止开主灯       | 有授权、生效范围与期限，由确定性程序核对                       |
| 执行与动作结果 | 调查结束、通知渠道接纳、设备结果未知     | 处理完成、请求接纳与物理效果分别表达                           |

相同来源输入的重复交付不产生新记录；两条不同记录也不证明发生了两次现实活动。查询可以说明它们可能相关，不必消除这种歧义。精确次数统计只有在活动确认与关联能力已专门交付后才能承诺。

<a id="ownership"></a>

## 状态所有权

| 所有者                 | 拥有的状态与决定                                   | 消费边界                                                     |
| ---------------------- | -------------------------------------------------- | ------------------------------------------------------------ |
| backend 家庭运行时     | 设备清单、当前属性、来源质量、访问资格             | 页面与 Agent 读取同一份事实，不另维护可修改副本              |
| backend 感知与身份领域 | 媒体生命周期、本地检测、跟踪、已接纳成员归因及纠正 | 继续复用现有接纳规则，不要求先经大模型理解                   |
| backend 记录领域       | 已保存来源记录、实体关联、修订、记录变化与查询     | 新增记录类型必须有实际生产者与消费者                         |
| Agent 应用层           | 用户职责、调查进度、等待、执行输入、暂时解释与记忆 | 需要恢复的状态由程序保存，检查点和聊天记录不能替代工作责任   |
| backend 动作领域       | 授权边界、动作接纳、派发、取消与结果               | Agent 提交意图，不能自行改变执行权限或重复执行结果未知的动作 |
| 来源与渠道适配器       | 厂商协议、媒体编码、消息发送与回执转换             | 不拥有家庭判断或工作语义                                     |

确定性调度交给成熟执行设施，业务状态仍归相应领域。队列运行在哪个进程不改变责任归属；HTTP 和数据库也不定义领域含义。跨应用只通过受控接口交换数据，共享 schema 放在根目录 `packages/`。

<a id="identity-space"></a>

## 身份与位置依据

检测到猫不等于认出了某只猫；局部轨迹编号不代表跨镜头成员身份。家庭唯一某物种的归属和人体外观匹配必须保留各自推定依据，不能包装成确定的人脸或宠物个体识别。

沿用已实现的成员归因与纠正。归因被撤销后，记录保留原发生经过和纠正信息，但不能继续出现在错误成员的当前归属查询里。窗口中的历史身份快照反映当时分析，不跟随当前身份静默改写。

身份、可见性、位置与活动各需自己的依据。认出某人不证明他位于摄像头安装房间；缺少空间依据时只说“在某摄像头中看到”。未来使用覆盖标注时须保留当时版本，不能用今天的标注追认过去的位置。

<a id="evidence-time"></a>

## 时间、质量与缺口

区分观察时间、收到时间、保存时间和分析完成时间。用户在十点报告八点的事情，观察时间来自其陈述；无法确定的时间保持未知或区间，不能补成保存时间。设备缓存的来源时间未知时保留未知，不把查询成功当成即时物理采样。

媒体读取期限、记录保留期、设备值新鲜度和任务截止分别管理。媒体过期不抹掉已保存的文字和当时结论；旧媒体尚可读也不证明当前状态。来源故障、筛选未通过、材料过期、截断和没有匹配记录分别报告。

每次执行保存实际使用的有界输入。补查形成新的输入快照，保留各自读取时间，不覆盖此前输入或假装它们来自同一时刻。引用其他执行结论时标明它是解释，不当作新增实测证据。已知依据撤销后，相关在途工作须重新核对；历史解释保留当时输入，不要求重算全部历史。

记录变更顺序用于发现旧记录修订，观察时间用于回答何时发生，两者不可互换。连续补读有明确保留边界，越界意味着存在处理缺口；能按编号查到更老的记录，不证明变化流完整。

<a id="last-sighting"></a>

## 最近出现查询

“最近一次出现”是历史查询，按记录中的最后实际观察时间及当前归因选择，不能用首次出现、创建时间或模型完成时间代替。具体已实现字段及查询改动见[记录查询](household-automation.md#记录查询)。

较新记录的位置未知时，仍返回它；如另附更早的已知位置，须给出原时间并明确是另一条历史记录。时间不可比较或证据冲突时显示候选与限制，不强选一个房间。媒体已过期时仍可解释保留下来的记录，但不能声称重新看过原画面。

最近出现不等于当前位置。断流、轨迹结束和长时间没有新记录都不生成离开事实；按位置选择音箱等动作需要额外的时效和空间依据，不能直接用最近摄像头名称决定。

<a id="proactive-agent"></a>

## 职责、调查与接纳

职责说明系统答应做什么：关注对象、材料范围、唤醒方式、期限、通知策略及停止条件。用户请求、到期时间和来源变化都是输入；没有新观察不应阻止已承诺提醒到期。后台自主观察须由用户或部署者明确启用，不要求已有设备自动化规则，也不默认持续向模型发送所有窗口。

记录变化需要可补读，唤醒选择由工作关注范围、处理进度与预算决定。过滤和合并只决定是否、何时处理，不替 backend 建立另一套通用生活含义分类。登记变化、接纳输入、完成分析和动作成功分别确认。

调查可以等待新材料或用户回答，但等待必须有截止和退出结果。未回答、断流或预算不足可以导致受限、到期或未解决，不能解释为问题已经消失。提问与回答保留问题身份；只有实际交付的、可对应的问题才可接续，来源不明的语音不能直接修改授权或时间锚点。

取消、暂停、修改锚点和恢复由程序管理。工作修改不产生新的现实活动，也不能借更换执行编号重发同一次通知。通知频率可按明确时间间隔和用途限制，无须先证明每段猫叫属于同一次现实经过。

<a id="assessment-scope"></a>

## 任务判断与共享结果

模型解释默认留在执行结果或 Agent 笔记中。它可以指导补查、询问或提出动作，但不必先成为 backend 的共享家庭状态。需要共享某类结果时，单独定义实际消费者、来源、接纳条件、修订及撤销责任；已实现成员归因继续由其领域接纳。

精简的是默认输入，不是省略来源和限制。摘要提供足够定位依据的标识与时间，详情按需读取；材料过大、缺失或已撤权必须显示，不能暗中以更晚画面替代。

<a id="experience-requirements"></a>

## 经验与明确要求

经验保留来源、对象、形成时间、引用修订及待复核状态。它可以提示“接下来查什么”，不能声称完整覆盖某段生活，也不建设通用统计支持范围证明。已知被引用记录纠正时标记待复核；消费存在缺口时，无法核对的笔记也不继续作为可靠依据。使用前仍核对本次任务需要的材料。

明确要求有实际执行含义。例如“今晚不要自动开主灯”是禁令，“睡眠模式”是用户设置，均不是睡眠识别。禁令不能只存成可能不被检索到的自然语言笔记。模型提出规则或修改要求时必须经过权限和能力校验。

有限流程只保存该职责需要的状态。计时、重复接纳、期限检查和动作限制由普通代码执行；不把每句自然语言条件编译为全局家庭状态，也不为尚未选定的场景建立通用规则语言。

## 场景及能力限制

<a id="dog-walk"></a>

### 用户报告与到期提醒

用户明确确认“八点遛过狗，请八小时后提醒”，保存其陈述及采用的时间锚点，下一次到期为十六点。出发还是返回、日期或时区有歧义时先澄清，不用安装或重启时间填补。提醒表达“距上次记录已八小时”，不声称证明期间没有再遛狗。

纠正为九点后，更新尚未派发的提醒期限；已发送通知保留结果，不靠修订编号生成第二次相同通知。首次流程只承担一次到期提醒，持续重复提醒须另有用户认可的重复与停止策略。自动识别每次遛狗、统计次数和关联返程均不是这个流程的前提。

<a id="cat-feeding"></a>

### 猫叫与进食调查

现有人声检测和转写不能识别猫叫，静止画面中的叫声可能在当前窗口筛选处漏接。非人声入口和模型音频能力须独立接入与验证；猫和人同框也不证明在找主人，声音本身不能确定是哪只宠物。

用户请求调查时，可读取实际已有材料并说明不足。食盆重量、粮仓余量、设备出粮和实际进食分别表达：出粮不证明吃过，重量下降不证明某只猫吃下了差值，没有进食记录不证明没有进食。没有实际称重属性或食盆区域识别时不承诺对应观察。

“可能想吃东西”可作为本次解释；是否通知与是否允许出粮另行核验。通知按职责和频率限制处理，不建设跨镜头猫叫合拆或完整索食生命周期。

### 灯光与无人判断

未检测到不等于无人，静止、遮挡、灯关闭或手机息屏也不证明睡着。没有合格的无人判断能力时，不启用“确认无人后关灯”。用户另行选择“未检测到活动若干分钟后关灯”时必须明确这是一项超时策略，不能替代无人识别；本计划不预建通用占用计数、通行闭合与重建。

<a id="action-boundary"></a>

## 动作与结果

backend 在派发前核对目标能力、当前授权、要求、期限和实际依据；Agent 只能提出请求。条件可能随时间变化时须取得新鲜依据，不能只因原任务接纳成功就直接执行。

动作身份属于用户认可的那次效果，不属于模型调用轮次。重复投递复用已有接纳结果；外部结果未知时保留未知，不盲目重发。通知渠道接纳不代表用户已读，厂商接纳不代表物理效果已确认。取消只能阻止尚未派发的动作，已发请求不能承诺撤回。

通知去重按用途与目标隔离，一条结果未知的普通提醒不应阻止同一手机独立的其他通知。设备操作的冲突控制按具体设备协议定义，不复用通知锁或把“可能饿了”转成自动喂食授权。

<a id="capability-validation"></a>

## 能力说明与验证

每项功能分别核对接口是否存在、来源是否覆盖、访问是否获准及当前材料是否可用。缺少非人声输入、位置依据、设备写入或通知渠道时，说明无法完成的部分；接口成功与模型输出格式正确都不是实景效果证明。

验证从已可靠接纳的信息开始，包含缺失、纠正、迟到、重复、取消、重启及结果未知。未接到的现实观察无法补造；本地感知的专项验收独立推进，Agent 能力按真实消费者逐项接入。

# 音视频分析 Agent 后续计划

当前用法与限制见 [Agent README](../../apps/agent/README.md#音视频分析-agent)。本文仅维护尚未实现的主动补看、事件出口和最新观察写回；设备执行、长期记忆及跨重启恢复另行交付。

## 职责边界

Backend 拥有原始记录、身份归因、媒体和通用录像接口；Agent 拥有观察结论、进一步观察的判断及事件交接；Host 负责请求适配与装配。每次分析保持独立上下文，不注入其他轮次的结果。原始记录和内部编号只供服务读取、去重及追踪，不交给模型或主 Agent。

## 一、主动补看与补读

需要更多信息时，允许指定问题、摄像头、时间、媒体形式及裁切，复用 Backend 的录像接口。输入由 Agent 定义，Host 转换请求并校验响应；保留实际图片时间、媒体区间和音轨状态，不以其他时刻或来源的材料冒充请求结果。

本地录像可能尚未封段。目标时间距首次请求为 0～15 秒且返回 `perception_media_unavailable` 时，可登记原问题和参数，30 秒后最多补读一次，2 分钟后过期；同一请求合并，不刷新首次失败时间。取得材料后用全新上下文分析，失败保留明确缺口，不无限重试。

## 二、工具与事件

需要工具决策时，使用现有 Pi Durable 会话和扩展能力，继续遵守独立分析上下文的边界。`read_camera_media` 读取指定媒体并回答问题；`emit_event` 只交接具有新进展、需要主 Agent 处理的情况。普通描述不发事件，身份不确定时不改写 Backend 归因。

工具调用和实际媒体模态均须在所选端点验证。提示词保持一份固定指令，工具描述随版本管理。

## 三、预算与取消

在每次分析的截止限制内增加工具预算：最多 6 次工具调用、4 次媒体分析、2 次主动媒体读取、2 次事件发送；主动范围最多 30 秒、图片最多 16 张、视频最多 15 秒；每份媒体最多 32 MiB，单次分析累计最多 64 MiB。预算归 Agent，Host 只执行传入限制。

读取、模型调用和事件交接服从本轮及当前上下文的中止信号。补读和事件去重由服务管理，家庭上下文失效时清除，旧轮不能写回或发事件。

## 四、事件交接

事件包含实际时间、位置、相关成员或未知身份、事情说明、交接理由及不确定性，主 Agent 可以直接读懂，不必回查原始材料。记录和媒体依据只保留在结构化日志与追踪中。

Host 注入事件接收函数，发送成功后才记录已交接；失败不标记成功。同一事情没有新进展时由服务抑制重复。主 Agent 接收入口及跨重启可靠交付另行实现。

## 五、最新观察写回 Backend

Agent 输出当前是中文描述。需要写回时再定义必要的输入校验、时间和来源关联，关联由服务维护，不要求模型返回内部 ID。Backend 保存整理后的最新观察，作为家庭上下文的新部分交付；待确认事项和补读安排留在服务内部。

模型视图的“最新观察”届时改读写回结论，不再从本地身份归因直接拼接。新部分的变化不触发分析，避免循环消费自身输出。观察须保留不确定性；最后一次出现不表示当前位置，也不证明区间完整。

写回检查当前绑定与记录修订，拒绝旧家庭资格或旧轮的迟到结果；家庭上下文失效时清除对应观察。不增加账号或家庭分区，不向公网开放可信本机写入入口。

## 验收

只运行直接相关的检查；新增测试须先取得用户明确许可。核对媒体实际进入模型、每轮无其他轮次历史、预算和取消生效，且缺失媒体不会被元数据或其他时刻画面替代。事件与写回能力以实际实现及部署验证为准。

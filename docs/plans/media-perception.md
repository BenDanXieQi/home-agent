# 音视频感知与证据处理计划

> 状态：P0、P1 已完成；P1 已通过当前 macOS arm64 双摄范围的功能与短时运行验收；P2 代码、专项测试及公开运动样本验证已交付，家庭实景与联合负载验收待完成；P3–P7 待实施。当前功能、模型契约和计算池限制以[本地目标检测](../perception.md)为准。

## 范围与能力依赖

本文只定义待实施的媒体与本地感知契约，以及 Agent 的媒体输入要求。已实现检测与跟踪的配置、接口、资源生命周期和验证范围统一见[当前感知说明](../perception.md)；任务、人宠出现记录与调用预算统一见[协作实施计划](household-automation.md)。MiLoCo 的实际流程、模型请求与身份重审行为集中见[外部实现参考](../references/miloco-perception.md)，本文保留本项目采用的契约与参数。

P0/P1 的完成范围是本地图片检测与摄像头持续检测，不包含音频、语义前置筛选或 LLM 调用。后续音视频路由及模型能力的验收分别属于 P3–P5，不追溯扩大 P0/P1 的完成条件。

```text
backend：摄像头 → go2rtc → 解码/采样 → 本地检测/跟踪、音频能量/VAD
                            └→ 有界媒体窗口 → 本地前置筛选
                                                 ├→ 未通过：跳过
                                                 └→ 候选证据与有限期媒体引用
                                                                  ↓
第一方 Agent：任务准入与调用预算 → 取得媒体、家庭上下文与人宠参考 → LLM 理解
                                                                  ↓
backend：家庭领域校验并接纳判断 ← Agent 提交带证据的判断；按任务决定是否请求设备动作
```

交付边界是带来源、时间、证据和有效性的感知结果。基础检测完成即发布，不等待跟踪、音频或多模态推理；后续结果独立关联到对应来源和时间区间。成功未检出、没有数据、结果过期和计算失败分别表达，来源中断不等于目标消失。

持续采集和本地检测不触发逐帧或逐窗 LLM（大语言模型）调用。首期 `scene_context` 自动场景分析必须先经过 P4 的画面／声音筛选；身份核验则按 P6 的身份问题与视觉证据质量筛选。未通过对应筛选的证据不编码为模型输入、不积压等待补发。MiLoCo 的实时主流程在筛选后执行检测/跟踪与多模态推理；本项目让 P1/P2 独立持续运行是本地计算链路的差异，语义调用仍须前置筛选。

本项目的全部 LLM 理解与推理由第一方 Agent 负责，backend 的感知判断止于小模型与确定性规则，不建设独立的 backend 语义 LLM 流程。Agent 的 harness（管理任务、上下文、工具、模型调用和执行记录的运行框架）统一承载画面/声音理解、身份推断与任务决策，可以结合其他设备观察、已有判断和用户要求决定是否分析、分析什么。统一归属不要求所有任务共用一个对话或固定调用同一个模型，也不要求先完成一个独立视觉 LLM 调用再启动执行 Agent。

运行方式沿用现有 `apps/backend` 与 `apps/agent` 两个本机进程及 HTTP 通信；Agent 是本项目代码的一部分，模型、提示词、工具和上下文策略一同演进。Agent 停止时 backend 继续采集与筛选，媒体按原限额过期，新的 LLM 语义和动作推理暂停。共享边界契约放在根目录 `packages/`；不跨应用直接导入服务实现，也不为未采用的同进程运行预建第二套适配。

第一方 Agent 的双向协作、观察请求、核验触发、人宠位置与实施批次见[协作实施计划](household-automation.md)。本文定义媒体与小模型能力；Agent 可以经受控工具选择任务关注点，backend 执行已实现的本地条件，不把所有摄像头变化自动变成模型任务。

### Agent 暂缓时的交付边界

已实现的 P2 以及待实施的 P3、P4 可以在 Agent 未实现家庭任务、未运行或没有模型凭据时独立交付。P2/P3 互不依赖；纯视频 P4 只依赖 P1，人体或猫狗轨迹裁切才需要 P2，音频候选才需要 P3。P4 先完成本地窗口、筛选、候选查看与媒体读取，不等待 P5 的提示词、模型选型、token 预算、checkpoint 或完整家庭语义模型。P7 按实际已启用能力测量，只有本地链路时不要求先完成 P5/P6。

未启用 Agent 消费时，候选仅保留在有界的本地当前视图中，媒体按期限淘汰，不发模型请求，不建立离线待办队列。P4 验收通过本机受控查询/读取核对候选、筛选原因与实际媒体；不以伪造 Agent 回答代替验收，也不为验证前置链路预建 Agent 空壳。P5 才交付真实 Agent 的消费入口与模型端到端验证，P6 才交付基于已登记人及猫狗参考资料的身份推理。

### 实施约束

- P1 已完成，P2 已实现；P3 可独立推进。P4 可先交付纯视频窗口及视觉前置筛选，未接通的音轨明确不可用；启用轨迹裁切或音频输入时再满足相应依赖。首期 P5 可先输出不带人宠身份的语义，但不能跳过其 P4 筛选；P6 再增加参考资料与身份识别。
- 每个阶段都验证自己的效果、失败路径和资源清理；P7 负责多能力同时运行的联合测量，不承接前面遗漏的基本验收。
- P0/P1 沿用 `det_4C.onnx`、sharp、ONNX Runtime CPU、Bun 单计算子进程及 Piscina 模型 worker；worker 数在启动时按可用逻辑核数与 `cpuRatio`（默认 0.5）计算。后续模型按所属能力接入，不把现有检测池改成任意模型路径接口，不让音频或语义长任务占住检测名额。
- P2 模型契约见当前感知说明；P3 核对 `silero_vad.onnx` 的连续状态与实际音轨。模型资产使用固定来源并记录哈希，不在运行时隐式下载。
- P4 的窗口与媒体编码预算归 backend；P5 的任务准入、模型请求与 token 预算归 Agent harness；同源场景窗口按序处理，等待项合并最新有效窗口；身份核验按目标与目的去重，同镜头多人、多只猫狗分别保留候选，两者不与用户聊天共用会话锁。P6 的推理归 Agent，已接纳身份、参考资料版本与样本保存归 backend 家庭领域，保存不阻塞下一轮推理。
- P4 接入时沿用已实现的帧所有权边界，明确检测、人宠裁切和窗口使用的图像及其所有者；保留或复制像素须有字节、数量和存活时间上限，任务结束或来源失效时释放。不能在缓冲区已转移给推理 worker 后继续读取，也不能用新帧替代检测框对应的原帧。已有跟踪副本不等于 P4 的跨帧媒体窗口。
- P2 的预算见当前感知说明；P3/P4 的图像保留、VAD 与编码资源计入宿主总 CPU/RSS 预算，不能各自按整机预算建立满额计算池。实际接入时核对它们与 P1 的并行负载；额外任务按自己的容量跳过，不能占满检测名额。模块分离不自动证明资源隔离。
- 每项能力只保存运行所需状态；本文不建设通用事件历史或通知系统。文件按实际阶段创建，P1 不预建后续模块。
- MiLoCo 作为媒体处理及推理能力参考，沿用已核对的模型契约，效果与资源行为按本项目验收，不逐项复刻其实现。

## 后续能力契约

本节的 MiLoCo 路径相对于 `backend/miloco/src/miloco/perception/`，参数来自文末固定提交的源码及配置默认值，不代表用户运行时覆盖值或本项目实测结论。按表述明确采用的默认值先实施，再用对应能力的实际效果调整；不要求用户预先填写全部技术参数。模型资产接入时核验实际张量、哈希和许可，参考代码中的形状声明不能替代资产检查。

### 模块职责与依赖

以下均为仓库相对路径，随对应阶段创建。沿用[家庭语义模型](household-model.md)的第一方 Agent 与 backend 边界，不把语义推理放入 P1 的 `video/source.ts` 或 `observation-store.ts`。

| 阶段与位置                                                                             | 状态所有者与规则                                                                       | 外部边界                                                                                      |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 已实现 P2 `apps/backend/src/perception/tracking/`                                      | 每来源运行独占轨迹集合、预测状态和外观特征历史                                         | ReID 适配负责像素转换和小模型推理；轨迹不等于人或宠物身份                                     |
| P3 `apps/backend/src/perception/audio/`                                                | 每音轨运行独占 PCM 余量、VAD 状态与上下文                                              | 媒体适配负责读取/解码，本地模型按音轨状态执行                                                 |
| P4 `apps/backend/src/perception/{window,gate,media}/`                                  | 有界窗口、媒体引用、筛选基准与放行计时；输出候选证据，不输出 LLM 结论                  | 提供受控媒体读取与裁切/编码；不持有供应商提示词、凭据或请求状态                               |
| P5 `apps/agent/src/household/` 及现有 Agent 模型调用模块                               | harness 拥有任务、上下文快照、模型选择、提示词、请求预算、失败恢复和执行记录           | 读取 backend 证据及上下文，提交结构化候选判断；共享 schema 放在 `packages/api/src/contracts/` |
| P6 `apps/agent/src/household/identity-task.ts`、`apps/backend/src/household/identity/` | Agent 拥有识别与重审任务；backend 独占已接纳身份状态、参考资料版本、确认计数和样本资格 | Agent 提交模型证据；backend 用确定性规则校验与保存，不调用 LLM、不另建成员身份真值            |
| P7 各能力所属模块                                                                      | 指标属于实际运行，配置调整仍由所属能力应用；联合测量不新增业务状态所有者               | 复用各模块指标及正式入口，不为验收另建通用调度或状态管理平台                                  |

backend 在 P4 定义来源/通道、运行标识、候选身份、窗口时间、检测/跟踪/音频观察、筛选原因、缺失项及有限期媒体引用，提供本机受控查看与读取。P5 的 Agent 消费同一份证据契约，不在 backend 再建一份等待 Agent 确认的任务队列。候选身份在重读、订阅与同窗多种媒体表示之间保持一致；Agent 在本轮运行内按候选身份有界去重并拥有任务准入，读取候选不等于必须建任务。重连只读取仍有效的当前候选并接续新候选，记录缺口，不补发停机期间全部窗口；不承诺跨重启恰好处理一次。

媒体读取时复核访问资格、窗口身份和期限；失效引用返回不可用，不用新画面替换旧证据，不传摄像头凭据、任意流 URL 或进程内像素指针。流式读取、临时文件、已交付媒体及 Agent 输入副本各有大小、并发和期限限制；请求结束或取消后释放读取资源，不因慢消费者无限保留窗口。P4 的候选查看与媒体读取不沿用 P1 的纯检测摘要冒充已实现能力，也不把媒体字节广播到设备公共 SSE 或聊天 JSON。

Agent 不修改基础观测，也不控制物理连接。P1 检测独立发布；跟踪消费对应帧的检测结果，窗口按媒体时间收集输入，不等待检测完成才接收媒体。各消费者按自身预算处理，过载可以跳过输入并报告缺口，不能反压基础发布或无限占住媒体引用。纯规则不读时钟、文件、网络或全局可变状态；应用编排传入所需数据，资源适配负责外部系统。

P6 合并进 P5 调用时，Agent 从 backend 取得参考资料、画面证据及可选轨迹上下文，按任务隔离模型可见信息；身份核验屏蔽该目标此前的身份猜测及习惯先验，避免循环佐证，位置与场景任务可读取适用的已接纳判断，再分别提交结构化结果。backend 按实际依赖的证据、运行资格和资料版本分别接纳场景与身份结果，成员参考资料失效不直接抹掉其他有效语义。Agent checkpoint 保存任务与执行记录，不成为另一份权威家庭状态；P5 未接入 P6 时可以独立运行，结果不依赖身份字段。

### P2 剩余验收

人体外观跟踪、猫狗位置跟踪、固定 ReID 模型、独立发布、预算与生命周期实现统一见[当前感知说明](../perception.md#人宠跟踪与人体外观特征)，不在此保留已完成的施工步骤。

- 用家庭多人及猫狗交叉、遮挡、离开与重入素材核对轨迹连续性和误关联。猫狗公开运动素材已暴露漏检、物种混淆和编号碎裂，需改善检测适用性及运动关联后复核；具体覆盖与限制见当前感知说明，不能用人类近距离样本或合成用例代替宠物实景验收。
- 在真实双摄同时运行 P1/P2，测量基础检测时效、跟踪缺口、总 CPU/RSS 与像素释放；按实际负载核对预留外观并发后的检测容量。

### P3 音频与人声观测

音轨解码、单声道转换和 16 kHz 重采样使用现有 FFmpeg／libav 能力，不手写音频解码器或重采样器。人声检测使用 [Silero VAD](https://github.com/snakers4/silero-vad) 官方模型和对应版本的公开推理契约，经现有 ONNX Runtime 执行；固定资产版本、哈希、许可与连续状态接口后接入，不复制 MiLoCo 的 VAD 实现。下面的张量和阈值是待核验的适配要求，资产不匹配时修正配置与契约，不加入猜测版本的兼容分支。

参考 `engine/gate/{audio_gate.py,speech_vad.py}` 和 `engine/config.py`。本项目当前 go2rtc 私有源设置 `audio=0`，双摄 `dual_camera.go` 设置 `enableaudio:0` 且只声明视频媒体；P3 必须完成源端启用、真实音频包探测/分发、分析出口及 PCM（解码后的音频采样）链路，不能只增加 VAD 调用。双摄共享音轨只解码和分析一次，两个通道引用同一音轨；视频和音频分别判断就绪与断流。

- 初始采用 16 kHz 单声道 int16 PCM。能量检测沿用 30 毫秒分块，计算每块均方根能量并除以 32768，窗口取峰值，阈值 `0.015`；它只表示声音能量，不区分哭声、犬吠或语音内容。
- `silero_vad.onnx` 使用每块 512 个采样，前置上块末尾 64 个采样，float32 输入 `[1,576]`、值除以 32768；状态 `[2,1,128]`，采样率输入为 int64 `16000`。输入名 `input/state/sr`，输出名 `output/stateN`。初始概率阈值 `0.4`；参考窗口内至少 3 块过阈才判有人声。
- MiLoCo 每次 `evaluate_speech` 重置状态，在窗口内续接，且忽略不足一块的尾部。本项目持续音频链路按音轨运行保存状态、64 点上下文和不足 512 点的余量；连续块只处理一次，断流/运行替换时重置。P3 及时发布分块概率和能量，P4 按 4 秒窗口汇总并应用至少 3 块过阈的判据，重叠窗口不重复推进模型状态；不足一块时保持输入不足，不输出否定人声结论。
- MiLoCo 在 VAD 不可用时放行语音字段；本项目输出未知/不可用，不生成肯定人声观测。能量低、人声未检出、输入不足及无音轨分别表达；识别具体声音类别和转写内容属于 P5。

### P4 窗口、前置筛选与裁切

视频裁切、缩放、抽帧、编码与封装使用 [FFmpeg 的公开滤镜和封装器](https://ffmpeg.org/ffmpeg-filters.html)；静态代表图继续使用已有 sharp。应用只计算裁切区域和允许参数，再交给库执行，不手写像素搬运、编码器或 MP4 封装。原始证据采样保留真实帧时间；不得为取得固定输出帧率把补帧当作新观测。窗口资格、声音能量的明确口径、视觉差异阈值和媒体容量仍属于本项目规则，不能拿不同库算法的默认值静默替换。只有使用方申请且输入仍有效时才编码，沿用下面的共享任务与取消边界。

参考 `collect/stream_buffer.py`、`engine/{config.py,pipeline.py}`、`engine/gate/{gate.py,visual_gate.py}` 及 `engine/omni/{crop_enhance.py,prompt_builder.py}`。初始采用 4 秒窗口、最多 3 个待处理窗口和 500 毫秒慢轨道宽限；消费最新就绪窗口，积压时丢弃旧窗口并计数。还需限制总字节、编码任务和在途引用，不能把窗口数量上限当作内存上限。缺轨和首个不完整窗口显式标记，本项目不因缺少音轨长期等待纯视频分析。

窗口消费解码侧的有界媒体分支，在像素转移给检测 worker 前取得自身所需数据，不从仅保留最新帧的槽位倒推过去 4 秒。窗口不等待检测/跟踪结果；框与帧按来源运行及帧序号关联，检测被跳过或迟到时明确缺失，使用实际画面与变化区域，必要时保留全景，不能移用其他帧的框。跨音视频使用可核对的来源时间或同宿主接收时间基准；未知同步精度须保留，不比较不同进程各自的单调时钟起点。

backend 按下表独立输出场景窗口的本地筛选结果，不依赖 Agent 的模型配置或 token 预算。P4 只提供媒体事实及有界的通用读取/编码选项；供应商 content block、模型输入组合、提示词与是否真正调用归 P5。

| 窗口条件                                             | P4 本地输出                                          |
| ---------------------------------------------------- | ---------------------------------------------------- |
| 视觉有变化，或仍在视觉变化后的放行期内且本窗有视频帧 | 视频候选；分别标明音频能量与 VAD 判定、实际可用音轨  |
| 视觉未放行，但音频能量过阈                           | 纯音频候选，不附带静止视频或视觉身份候选             |
| 视觉未放行，音频也未过阈或不可用                     | 无自动候选；不为模型编码，不生成“无人”或“无活动”结论 |
| 无有效媒体，或筛选失败且没有其他已通过的媒体         | 无候选并报告缺失或失败，不默认放行原始视频           |

音频能量决定是否需要分析声音，VAD 进一步决定是否请求语音内容；未检出人声不阻止对犬吠等非语音声音的分析。筛选通过不代表已识别活动或人物。

本项目参考 MiLoCo 的[媒体筛选与模型输入](../references/miloco-perception.md#媒体筛选与模型输入)组织视频或纯音频候选；P4 输出通用媒体与筛选事实，P5 再按具体供应商已验证的能力选择输入，不把参考提交的默认模型或 content block 当作 backend 契约。

- 视觉筛选参考 1 fps 检查、448×448 灰度帧、像素差大于 25 的比例达到 `0.005`；保留跨窗比较基准，首个有效窗口放行。沿用 MiLoCo 的 90 秒视觉放行期：从最近一次视觉变化起计时，期内静止但有帧的窗口仍可进入视频分析；仅因处于放行期而通过的窗口不续期。它不是“每 90 秒调用一次”，持续运动可持续续期，仍须受 P5 调用预算约束。所有筛选只控制语义调用，不停止 P1 检测或 P2 跟踪。
- 多模态视频初始采用 1 fps、短边 512，与检测采样及模型张量尺寸分开配置；音视频时间关联使用实际时间，不按帧数虚构时长。编码后的音轨、帧率、时长和裁切坐标应一致，缺轨不可伪造为静音。
- MiLoCo 智能裁切使用窗口内逐帧检测框与运动区域的并集，而非仅用末帧人体轨迹；本项目同样保留宠物等检测框及全景参考。初始采用水平/垂直扩展 `0.40/0.30`、最小区域占比 `0.10`、最大 `0.49`；无合适区域时使用全景，映射后的框裁到有效范围。全景与裁切使用同档尺寸预算，裁切失败不拖住基础链路。

#### 媒体与判断的期限

P1 的 2 秒最大帧龄仅约束单帧检测提交和发布，不是 P4 窗口、媒体缓存或 P5 语义判断的期限。窗口必须保留其实际起止时间和覆盖缺口；4 秒窗口不能因为首帧已超过 2 秒就被整体作废。

P4 媒体初始最长保留至窗口关闭后 12 秒（本项目默认值，可配置），同时受最多 3 个就绪窗口及字节预算限制，可提前淘汰；引用须说明最晚读取时间，不能承诺期限内一定未被淘汰。Agent 排队后取媒体时重新检查引用，已过期或淘汰就跳过，不沿用设备事件任务的 60 秒启动等待去强留媒体。已完整读取的有界副本受 Agent 任务期限与输入预算约束，不要求在 12 秒内完成推理；backend 缓存释放不延长或撤销已取得证据的观察时间。

模型请求期限、媒体可读取期限和判断适用期限分别校验。已取得的过去片段可以支持“该窗口发生过什么”，不因缓存释放抹掉事实，也不能把晚返回结论标成现在仍成立。当前判断按实际依赖的证据年龄和连续性接纳；临时断流使当前连续性未知，明确撤权、停止或运行替换则拒绝旧运行的当前结果。已保存执行记录仍属于原任务，不回写新运行。

媒体字节与证据描述分开管理。P4 为窗口及实际交付的媒体表示提供稳定关联，描述来源运行、时间区间、覆盖缺口、筛选事实、处理版本及裁切／编码参数；同一窗口的不同表示不生成新的独立观察。P5 接入时，backend 在交付可用于提交判断的证据前，先为不可变证据描述及必要校验依据预留容量，并返回最晚提交时间；记录不因媒体淘汰一并删除。Agent 只引用 backend 已发出的证据身份，不能自行补造或修改来源事实；描述校验不等于重新验证模型是否看懂画面。

最晚媒体读取时间、结果最晚提交时间及判断有效期分别返回和校验。提交期限由 backend 的场景策略限定，不能由 Agent 重试续期；描述保存受独立条数和字节上限约束，容量不足时拒绝新的可提交证据交付，不拖住采集。已取得的描述在承诺的提交期内保留；明确撤权或运行结束仍可立即撤销接纳资格。期限外或 backend 重启后缺少校验依据时明确拒绝，不凭 Agent 的 checkpoint 恢复接纳资格。

已接纳判断保存足够解释其来源的证据摘要及原身份，随判断的保留策略清理；媒体可用性独立表示。仅有 P4 时只交付有界窗口描述与媒体，不维护等待 Agent 的任务；提交期内的证据保留随 P5 实现，不要求设备历史计划历史库或永久媒体存档。

#### 按需媒体表示与读取生命周期

窗口描述与编码产物分开管理。消费者根据描述选择允许的全景、裁切或音频表示，backend 校验资格、输入、剩余期限及编码容量后才接纳；不为摘要展示提前编码，不把纯音频候选扩成视频候选。HTTP 边界见[感知调试计划](perception-debug-ui.md#4-接口与实现边界)。

同一窗口、来源媒体代次、处理版本和规范化参数共用一项在途编码或已有产物。返回明确的未生成、生成中、就绪、失败、过期、淘汰或撤销状态；容量不足返回忙碌，不建立无限队列。失败后只接受显式重试，不改变窗口身份或期限。状态查询和媒体 GET 只读，不触发编码。

媒体管理器拥有共享编码任务，单个消费者断线不取消其他消费者需要的工作；任务始终受输入、产物、并发和原期限限制，完成后再次校验资格与期限才发行引用。取消或失败时清理部分产物。读取拥有不晚于媒体原期限的截止时间，慢读取不无限锁住缓存；编码和读取都接收撤权及到期信号。

#### 运行结束与历史媒体读取

当前结果接纳与历史读取分别校验。正常停止结束来源采集和实时结果接纳，已关闭窗口的输入及产物继续按原容量和期限保留，允许完成或按需生成该窗口的媒体表示。编码只使用已保留输入，不重新打开摄像头，不延长窗口期限；不完整的末尾窗口按其实际覆盖范围交付。

| 事件                     | 编码                                         | 已生成媒体的读取                                   | 浏览器已完整取得的副本                     |
| ------------------------ | -------------------------------------------- | -------------------------------------------------- | ------------------------------------------ |
| 手动或到期停止           | 原窗口输入仍有效时允许按需编码及完成在途编码 | 同一访问范围内可新读或完成在途读取，均不超过原期限 | 可作历史查看                               |
| 同一访问范围内的运行替换 | 同正常停止，旧窗口不迁移                     | 保留原身份和期限，不用新媒体替换                   | 可作历史查看，不追加新运行结果             |
| 家庭切换、退出或来源撤权 | 取消任务并拒绝新申请                         | 撤销引用，取消在途读取                             | 页面清空相关副本；服务端不能收回已下载字节 |
| 到期或容量淘汰           | 取消依赖该媒体的任务，不重新生成             | 拒绝新读取并结束依赖已释放资源的在途读取           | 不延长服务端引用期限                       |

停止后无法取得所需输入时按过期、淘汰或缺失说明原因，不能为查看历史重启来源。撤权与其他事件同时发生时按撤权处理。摘要期限与媒体期限分别表达，摘要存在不保证媒体存在；backend 重启后旧内存引用失效。历史读取不恢复原运行的实时或判断提交资格。

#### 无 Agent 的 P4 完成条件

- 真实来源可查看窗口起止、有效媒体、筛选原因、候选/跳过/淘汰计数；静止且安静的窗口在放行期结束后不再产生自动候选。
- 有声音但无视觉放行时只产生音频候选；无音轨、输入不足与处理失败分别表达。P3 未启用时可单独验收纯视频范围，不宣称音频通过。
- 本机受控读取可核对通用媒体的实际帧、时间、裁切坐标和有无音轨；只有请求了媒体才进行相应编码，不需要真实 LLM 或供应商协议。
- 候选及媒体在没有消费者、慢消费者、断流与来源停止时仍受数量、字节和期限约束；不阻塞 P1，淘汰后不能读到替代窗口。
- P2 未启用时使用全景或基于已有检测/变化区域的裁切，不要求先完成身份识别；不为验收创建模拟 Agent。

### P5 第一方 Agent 语义推理

P5 对应协作计划的首个情景闭环。本节仅定义媒体输入；任务准入、上下文工具、费用和输出契约不在此重复。供应商适配留在 Agent，backend 不维护另一套语义模型客户端。

上述变化筛选约束首期场景维护，不限制用户明确要求查看当前画面的按需任务。后续开放异常任务如需定期观察，须按[长期任务契约](household-automation.md#四类需求的具体契约)实现独立候选模板，明确覆盖、频率和费用上限；它消费相同的有界媒体能力，但不假装通过了变化筛选，也不视为首期 P4 已支持。后者以显式任务原因取得限定来源、数量和时长的新媒体，即使画面静止也可分析；同样受授权、新鲜度与预算限制。设备事件触发的任务只有在场景明确允许视觉补证时才可使用该入口，不能把每个被筛掉的窗口转成“按需任务”。身份重审到期先更新有效性，是否调用按 P6 的身份问题与证据质量条件判断；静止但更清晰的目标可通过身份筛选，不能把到期本身变成周期调用。

模型能力按具体型号与端点分别验证无音轨视频、纯音频、带音轨视频；支持前两项不能推定支持第三项。官方能力说明作为接入依据，实际素材中的画面、声音及语音内容须分别核对，HTTP 成功不等于理解正确。带音轨视频未验证或不支持时，视频请求只提交无音轨画面并省略声音/语音输出；已通过筛选的音频仅在显式配置且已验证的独立音频调用下分析，否则报告音频语义不可用，不自动新增一次模型请求。独立音频调用属于本项目按模型能力选择的接入方式，不宣称是 MiLoCo 参考提交的默认流程；启用时同样遵守调用预算，结果按来源和实际时间窗口关联。

Agent 按 P4 的实际媒体与筛选标记选择输入：视频候选仅在音频能量通过且已验证带音轨视频能力时携带音轨，否则使用无音轨视频；纯音频候选不请求视频与视觉身份字段。模型能力缺失只影响相应语义任务，不反向改变 backend 已发布的筛选事实，也不使 P4 验收失败。

语义结果须区分本窗可见内容与跨来源推断，分别引用证据；解析失败不变成无人结论。判断接纳与当前适用性由[家庭模型](household-model.md#判断接纳与并发更新)定义，任务入口、预算、失败处理及交付验收由[协作计划](household-automation.md)定义。

### P6 人宠参考与身份识别

P6 对应[协作计划的成员位置批次](household-automation.md#9-实施顺序与改动位置)，首期只要求识别人宠并提供可接纳的出现证据。最后出现房间由 household 汇总，数据语义见[出现记录与最后出现房间](household-model.md#人宠出现记录与最后出现房间)。P2 可辅助选帧与去重，没有可靠连续轨迹不阻断独立画面核验；跨镜头连续关联和通行事件不作为前置条件。范围包括已登记人类成员及猫、狗，分别使用适用的参考图片和质量条件；猫狗类别、局部轨迹编号或人体 ReID 相似度都不能确认某只宠物。宠物专用外观模型如需引入，须单独核对资产与效果，不作为已有猫狗位置跟踪的前置条件。身份核验使用专用问题与证据质量条件，不依赖画面变化放行；局部轨迹、关联、位置与参考资料由各自领域拥有。具体条件、输入上限、未知处理和迟到结果均以该计划为准。

身份核验须有对应视觉证据，可用代表帧或与场景任务兼容的视频；纯音频不携带人宠参考图，不产生视觉身份确认。MiLoCo 的 fused 输入、身份状态与样本组织是实现参考；其[人体身份核验与重审](../references/miloco-perception.md#人体身份核验与重审)区分下一窗派发、名义重审间隔与未生效的五秒配置，不能把模型自评分、确认次数或这些参数直接当成本项目可靠性保证和调用周期。首期使用用户登记资料；自动样本积累另行定义资格、保留和纠错，不作为成员位置前置条件。

各来源默认独立分析，按成员身份汇总出现记录，不要求先拼接多路视频。后续联合核验按问题选择有限的多源代表帧或短片，每份保留来源、原时间与时间质量；分屏表示不能把各路最新帧伪装成同时拍摄。跨房间关联的候选等待与媒体保留须另设有界预算，不能隐式延长 P4 的媒体期限。Frigate 接入属于后续来源适配，须验证媒体、时间、去重与授权契约；不替换家庭领域的身份和位置状态所有者。

### P7 联合测量

测量只覆盖实际启用的能力：Agent 暂缓时核对 P1–P4 的本地效果、CPU/RSS、候选率、媒体字节及无人消费时的回收；启用 P5/P6 后再加入 Agent 任务时延、请求数、token 用量、判断接纳及模型故障影响。P7 不把未启用能力或长期记忆变成本地前置链路的完成条件。

MiLoCo 的帧率、窗口、阈值及源码中的性能注释是参考配置，不能证明本项目达到相同性能。使用相同素材核对检测、跟踪、音频和语义效果，并在实际摄像头上验证联合运行；分别记录缺帧、身份纠正、语义失败以及当前感知说明中的逐路延迟和资源指标。线程、采样和编码参数按实测调整，保持基础链路独立、结果有效性与资源清理约束；缺少最终部署门槛不阻塞已具备条件的能力实现及探索测量。

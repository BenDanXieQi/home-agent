# 视频详情与感知调试实施计划

视频画面分析已具备实时展示、JSON 默认展开、前端定格与返回实时。本文维护尚未交付的功能：独立图片分析、结果复制与图片下载，以及随后接入的音频和窗口展示。当前行为和验证限制归[感知说明](../perception.md#单路帧关联与定格)及 [Web README](../../apps/web/README.md)维护。

## 1. 目标与功能范围

用户从视频卡片进入对应设备与镜头的“画面分析”，查看连续视频、检测／跟踪标记和 JSON，定格后检查当前画面与结果。视频仍为一级导航入口，详情复用现有播放器和帧关联实现，不另建摄像头列表或独立采集管理页面。

完整调试功能包含：

| 能力 | 用户能做什么 | 当前基础与待实现部分 |
| --- | --- | --- |
| P0 图片分析 | 上传图片，查看检测框及 JSON，复制结果并下载带框图片 | 已有后端图片检测；网页上传、HTTP 字节输入和结果面板待接入 |
| P1 视频检测 | 查看当前摄像头的检测框和 JSON，定格及返回实时 | 已有后端检测与视频详情；结果复制和定格下载待接入 |
| P2 人宠跟踪 | 查看轨迹编号、实测／预测结果及 JSON | 复用已有后端跟踪、叠加和 JSON，不新增详情视图 |
| P3 声音 | 查看音轨状态、人声与声音区间 | 后端能力尚未落地，之后再接入页面 |
| P4 窗口筛选 | 查看通过／跳过摘要，选择仍可读取的窗口与媒体 | 随媒体能力接入，不用当前画面冒充历史内容 |

P0–P2 为首期功能范围；P3–P4 随真实后端能力接入，不预建不可用的按钮和空视图。调试不调用 Agent 或语义模型，不把调试结果保存到数据库，不长期保存录像。用户主动下载由浏览器完成。

音频、窗口、筛选、裁切和媒体生命周期由[媒体感知计划](media-perception.md)维护；本文只定义其页面接入。后台分析配置与内部结果校验见[后台分析与结果校验](../perception.md#后台分析与结果校验)。

## 2. 视频页面行为

后台按配置持续分析，与前端是否打开、正在查看哪个页面、是否定格无关。进入画面分析后自动接收后台已有结果，不创建页面采集任务。视频列表和详情删除采集管理区，不提供采集启停、时长、能力选择或刷新状态按钮。

| 用户操作 | 页面行为 |
| --- | --- |
| 进入画面分析 | 打开所选设备与镜头，自动接收并展示已有结果；JSON 默认展开并实时更新 |
| 定格 | 固定当前实际画面、同帧标记和同一次取样的完整 JSON；后台分析和页面订阅继续运行 |
| 返回实时 | 恢复显示最新画面与 JSON，不重启后台分析 |
| 离开页面 | 释放相应前端资源，后台仍按配置分析 |
| 来源没有分析结果 | 显示暂无结果，不替换成配置首路，不触发额外图片分析 |
| 来源访问失效 | 自动清理对应画面与结果，拒绝旧来源或旧运行的迟到消息 |

定格后画面、标记和 JSON 均不追加迟到结果，也不提供“分析此帧”。返回实时后使用最新结果。底层观看连接与缓冲的释放沿用已有播放器生命周期，不能影响后台分析。

结果详情明确区分后台最新结果与当前画面的匹配结果。复用已有帧身份和关联规则；实时画面沿用较早标记时保留已有提示，定格只保留同帧标记。没有匹配结果不推断未采样或未检出。

设备清单、家庭版本和来源访问校验自动执行，属于内部结果有效性约束，不做成用户选项。暂时媒体断流不等于访问撤销，已有有效定格仍可查看。

## 3. 下一阶段功能

### 独立图片分析入口

在视频模块提供独立“图片分析”入口，打开图片面板。入口与视频播放条件分开：未选择家庭、没有摄像头或媒体服务不可用时，只要本机访问有效，仍能使用图片分析。

用户选择图片后，页面显示实际提交图片的预览；点击分析，后台返回该图片的检测结果，页面展示检测框和默认展开的 JSON。提供选择其他图片、清除输入及明确的等待、忙碌、失败反馈。替换输入或离页后，旧请求结果不得覆盖当前输入。

此入口消费现有图片检测能力，不改变后台摄像头配置，不产生视频轨迹，不把上传图片声明为可信摄像头证据。

### 复制 JSON 与下载图片

视频详情与图片结果面板都提供“复制 JSON”，使用浏览器剪贴板能力复制点击时的完整快照。实时模式复制一次当前快照，显示仍继续更新；定格模式复制固定快照。

视频定格提供“下载图片”，使用已经固定的像素及同帧标记生成 PNG；没有同帧结果时下载无框图片。图片分析面板使用该次实际提交图片及返回结果生成带框 PNG。下载不再次分析、不创建后台导出任务。

## 4. 图片分析与后续媒体的接入逻辑


### P0 独立图片分析

网页上传调用已有图片检测链路，返回该次输入的检测框和 JSON。前端预览、结果叠加及下载必须对应同一份实际输入；确需缩放或处理图片方向时显示实际提交尺寸，复用原生图片 API 与已有 sharp，不自行实现图片解析。

图片字节通过 HTTP 交给现有解码和计算池，复用现有输入大小、像素和计算容量限制。文件选择使用原生 `File`／`Blob`；具体上传编码按已有 HTTP 与解码接口选择，不预设额外压缩流程、指纹体系或新的任务协议。

图片分析可与后台视频分析同时使用，不能要求用户停止摄像头。复用现有共享计算机制；如果视频持续占用造成图片无法执行，只补齐该问题需要的调度，不预设轮流派发算法、固定等待位置或另一套计算池。

请求等待时间应覆盖实际上传、模型准备与推理过程，沿用现有超时和错误表达。替换图片、离页或访问失效时不再接纳旧响应；取消前端等待不等于原生计算已结束，计算资源仍由现有任务完成与进程退出机制释放，不能因单个请求取消关闭健康共享池。

输入无效、容量忙碌、计算失败分别使用已有反馈。图片分析不创建可恢复后台任务，不保存上传图片到数据库，不提供新的任务状态查询页面。

### 按需下载图片

网页导出统一在浏览器执行，使用页面仍持有的图片和结果，通过 Canvas 原生 `toBlob()` 合成 PNG，无需新增图像生成依赖、后台图片保留期限、导出任务或媒体申请接口。现有本地命令继续使用自己的 PNG 输出功能，不为网页导出强行改造文件命令。

- P0 导出只使用该次提交的图片及其返回结果，不重新检测；按检测输入尺寸合成带框 PNG。
- 连续视频定格导出固定点击时的确切像素和同帧结果层；沿用框、无法确认的层及其他帧轨迹历史不得混入。无同帧结果时只下载无框图片。
- 点击后晚到结果不改变本次导出；导出标为调试图片，不作为后台认证证据。限制像素、并发和临时副本，完成后释放对象 URL；离页或作用域失效取消未完成工作。

### P3 声音

后台提供音频结果后，在现有分析面板中展示实际返回的音轨状态、能量、人声结果和时间区间，沿用 JSON 查看方式。声音属于时间区间，不冒充某张视频帧的检测结果；无音轨、输入不足与失败使用后台已有含义。

不另行要求声音曲线、专用仪表盘或新的能力切换界面。音轨处理与双摄共享音轨归媒体计划维护。

### P4 窗口

后台提供窗口筛选结果后，展示实际返回的窗口时间、通过／跳过原因及可用媒体。用户选择仍有效的窗口时，只查看该窗口已有摘要和媒体，不叠加当前实时结果，不为查看过去内容重新打开摄像头。

媒体不存在时显示实际不可用原因，不能用当前画面替代。页面读取和申请媒体沿用媒体计划定义的期限、访问校验与共享编码机制，不在这里另外设计媒体管理器、表示状态体系、轨迹历史或“综合视图”。

## 5. 接口与实现边界

已有视频继续走 WebRTC（浏览器实时音视频），结果继续使用现有 SSE（服务端持续事件连接）和快照，不为新增图片入口重做播放器、订阅协议或跨标签页连接管理。复用现有 HTTPS／HTTP/2 入口。

| 接口 | 归属与用途 |
| --- | --- |
| `GET /api/perception` | 已有：读取后台状态和当前结果 |
| `GET /api/perception/stream` | 已有：持续接收后台状态和结果 |
| `POST /api/perception/images/detect` | 待实现：接收图片字节，返回该输入的检测结果 |
| 窗口查询、媒体申请与读取 | 随 P4 接入确定，遵守媒体计划的访问和期限约束 |

不增加页面采集开始／停止接口。结果复制与 PNG 下载由浏览器完成，无需新增后台接口。只有实际功能要求现有快照无法提供的数据时，才补充订阅字段或结果批次，不把逐帧历史、完整日志或新状态协议作为图片与导出的前置条件。

实现复用以下职责：

- 根目录 `packages/api/`：图片输入限额、返回结果及必要的共享边界，类型从 schema 和实现推导。
- `apps/backend/src/perception/`：现有图片解码、检测和计算池；HTTP 仅适配字节输入与请求生命周期。
- `apps/web/src/modules/perception/` 与 `pages/cameras/`：已有结果展示、图片输入、JSON 复制和原生 Canvas 导出。
- 现有播放模块：观看连接、帧读取和缓冲；不增加另一套解码链路。

图片、位图、对象 URL、在途请求和 P4 媒体均有数量、字节与生命周期边界。复用已有计算完成、进程退出和资源释放机制；实际缺失的处理随相应功能补齐，不另建通用任务或采集命令框架。优先使用原生平台能力和现有成熟依赖，按真实职责拆分代码。

## 6. 功能实施顺序

1. **独立图片分析**：接通图片字节输入与现有检测能力，完成上传预览、分析请求、框及 JSON 结果展示；图片与后台视频共享计算资源。
2. **结果输出**：接入 JSON 复制、视频定格下载和图片分析结果下载，全部复用已持有的画面及结果。
3. **声音与窗口展示**：对应后台能力落地后接入声音区间、筛选摘要及窗口媒体，不提前制造替代数据。

实时展示与定格的当前行为继续按第 2 节保持；代码精简伴随功能实现，不单独替代功能交付。项目主交付顺序由[家庭情景与自动化计划](household-automation.md#9-实施顺序与改动位置)维护。

已完成功能的用法与限制更新到所属当前功能文档，计划只保留剩余职责。检查仅覆盖受改动影响的最小范围；未经用户明确许可不新增测试或故障注入脚本。设备侧断流、时间重置和联合负载的未覆盖范围仍按当前感知说明维护，不作为尚未实现功能的替代工作。

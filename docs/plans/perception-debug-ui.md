# 看家详情与感知调试实施计划

本文只维护尚未交付的声音和窗口展示。独立图片上传分析、视频实时展示、JSON 默认展开、定格与返回实时的当前行为和限制归[感知说明](../perception.md)及 [Web README](../../apps/web/README.md)维护。

## 1. 剩余功能范围

看家仍为一级导航入口，详情复用现有播放器、帧关联及 JSON；独立图片结果面板复用已提交的图片与检测结果，不重建摄像头列表或采集管理页面。

| 能力        | 待实现功能                                   | 现有基础与边界                           |
| ----------- | -------------------------------------------- | ---------------------------------------- |
| P3 声音     | 查看音轨状态、人声与声音区间                 | 后端已提供分块结果，待接入现有分析面板   |
| P4 窗口筛选 | 查看通过／跳过摘要，选择仍可读取的窗口与媒体 | 随媒体能力接入，不用当前画面冒充历史内容 |

P3–P4 随真实后端能力接入，不预建不可用的按钮和空视图。调试不调用 Agent 或语义模型，不把调试结果保存到数据库，不长期保存录像。

后台按配置持续分析，与前端打开、离开及定格无关。保持当前来源、访问有效性与帧关联规则，不增加采集启停、时长、能力选择、“分析此帧”、额外详情或新任务体系。媒体断流不等于访问撤销，已有有效定格仍可查看。

已实现音频、窗口、筛选、裁切和媒体生命周期由[当前感知说明](../perception.md)维护，未交付判断接纳由[媒体感知计划](media-perception.md)维护；本文只定义其页面接入。后台分析配置与内部结果校验见[后台分析与结果校验](../perception.md#后台分析与结果校验)。

## 2. 声音与窗口展示

### P3 声音

后台已通过现有快照与 SSE 提供音频分块结果；页面在现有分析面板中展示实际返回的音轨状态、能量、人声结果和分块时间区间，沿用 JSON 查看方式。声音属于时间区间，不冒充某张视频帧的检测结果；无音轨、输入不足与失败使用后台已有含义。

当前分块视图不能重建历史或生成 4 秒窗口人声结论，窗口汇总随媒体 P4 接入。不另行要求声音曲线、专用仪表盘或新的能力切换界面。音轨处理与双摄共享音轨归媒体计划维护。

### P4 窗口

后台已提供[窗口查询、媒体申请与读取](../perception.md#本机接口)；页面接入时展示实际返回的窗口时间、通过／跳过原因及可用媒体。用户选择仍有效的窗口时，只查看该窗口已有摘要和媒体，不叠加当前实时结果，不为查看过去内容重新打开摄像头。

媒体不存在时显示实际不可用原因，不能用当前画面替代。页面读取和申请媒体沿用媒体计划定义的期限、访问校验与共享编码机制，不另行设计媒体管理器、轨迹历史或“综合视图”。

## 3. 接口与实现边界

视频继续走 WebRTC（浏览器实时音视频），结果继续使用现有 SSE（服务端持续事件连接）和快照，图片继续调用现有上传检测接口。窗口查询、媒体申请与读取复用已交付的 P4 接口。复用现有 HTTPS／HTTP/2 入口。

只有实际功能要求现有快照无法提供的数据时，才补充订阅字段或结果批次，不重做播放器、订阅协议或跨标签页连接管理。

实现复用以下职责：

- 根目录 `packages/api/`：必要的共享边界，类型从 schema 和实现推导，不重复定义结果字段。
- `apps/web/src/modules/perception/` 与 `pages/cameras/`：已有结果展示、图片输入、定格快照及后续声音和窗口展示。
- 现有播放模块：观看连接、帧读取和缓冲，不增加另一套解码链路。
- `apps/backend/src/perception/`：已有解码、检测与共享计算，仅随真实媒体能力补齐必要接口。

## 4. 实施顺序

1. **声音与窗口展示**：对应后台能力落地后接入声音区间、筛选摘要及窗口媒体，不提前制造替代数据。

代码精简伴随功能实现，不单独替代功能交付。项目主交付顺序由[家庭情景与自动化计划](household-automation.md#9-实施顺序与改动位置)维护。

已完成功能的用法与限制更新到所属当前功能文档，计划只保留剩余职责。检查仅覆盖受改动影响的最小范围；未经用户明确许可不新增测试或故障注入脚本。设备侧断流、时间重置和联合负载的未覆盖范围仍按当前感知说明维护，不作为尚未实现功能的替代工作。

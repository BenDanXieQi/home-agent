# 视频详情与感知调试实施计划

> 状态：完整页面待实施，视频卡片详情入口、单路视频帧关联与定格已实现。P0 图片检测、P1 摄像头检测和 P2 人宠跟踪已有后端实现；P2 仍有家庭实景及联合负载验收未完成，P3 音频与 P4 窗口筛选尚未落地。单路帧关联的协议与当前验证范围见[感知说明](../perception.md#单路帧关联与定格)；设备侧断流与时间重置等关口尚未通过，不表示完整页面已经交付。

## 1. 目标与边界

感知属于视频的详情能力：用户从 `/cameras` 视频页的某个视频卡片进入该视频的详情子页，在同一来源上下文中观看连续视频、查看检测／跟踪框、定格分析及 P0–P4 结果。工作台通过“视频”一级入口进入已有视频详情，复用已迁入的帧关联与查看组件。调试不依赖 Agent，不调用语义模型，不把调试结果保存到数据库，不长期保存录像。

backend、Web 和本地入口作为同一产品同步修改、构建与交付，使用同一套共享契约和确定的运行环境。实现直接修正现有链路，不保留新旧协议并行、旧行为回退或面向未知部署的兼容分支。HTTPS／HTTP/2、目标浏览器和媒体依赖由项目统一配置并验收；不满足要求时修正运行环境，不为此扩展前端架构。

本文拥有页面行为、采集控制、播放与结果关联及调试接口。音频、窗口、筛选、裁切和媒体生命周期由[媒体感知计划](media-perception.md)维护；当前功能与限制见[感知说明](../perception.md)和[Web README](../../apps/web/README.md)。既有设备清单、授权及配置的存储不变。

首期交付 P0–P2 的完整调试闭环。P3–P4 随真实后端能力接入，未实现能力明确标注、不可启用。暂停是保留一张当前画面，不承诺任意倒带；短片回放限于 P4 仍可读取的窗口。用户主动下载不属于后台长期存储。

### 复用已有帧关联与展示

沿用当前已实现的链路：go2rtc 提供来源媒体代次与 RTP（实时传输协议）时间戳；分析端使用 FFmpeg NUT 容器与 NodeAV 交付同包像素、PTS（画面展示时间戳）和时间基准；浏览器通过 `MediaStreamTrackProcessor` 读取 `VideoFrame`，使用 `VideoFrame.metadata().rtpTimestamp` 关联结果，由同一 Canvas（画布）展示和定格。来源媒体代次与 RTP 时间共同标识帧，不能只依赖设备 ID 或 `revision`。

复用当前展示控制器、缓冲和资源释放逻辑，不重新选择解码格式、帧读取方式或播放器。现有尺寸、缓冲时长、帧数与字节上限，以及 Chrome 154／studio 摄像头的验证范围，以[单路帧关联与定格](../perception.md#单路帧关联与定格)为准。完整页面接入时只验证受改动影响的路径；设备侧断流、时间重置及联合负载仍需专项验收，更换目标浏览器或媒体链路后重新核对对应边界。

持续视频叠加与同帧定格是交付要求。关联失效时清理实时结果并按已有生命周期重建，不把尚未通过的故障场景写成已验证能力。媒体时间用于关联，不自动成为可信拍摄时间；保留接收时间和时间质量，不直接比较浏览器、后台墙上时钟及不同进程的单调时钟。

## 3. 页面与用户操作

视频卡片提供“画面分析”入口，进入对应设备及镜头通道的详情子页；顶部显示“视频 / 设备名称 / 镜头”，返回时恢复视频列表的筛选与滚动位置。侧栏及窄屏底部导航始终选中“视频”，感知能力不占一级导航。详情子页承载画面、定格和 JSON 分析，能力标签只用于当前视频内部切换。

复用 React Hook Form、Zod、Radix 及现有表单、标签、按钮和反馈组件，按操作分别判断准入。详情入口不要求该来源已配置检测；无检测时显示当前状态并提供合法的采集操作，不自动改看配置中的第一路来源。视频页工具区承载采集管理与“检测图片”，后者打开独立图片面板；工具区位于家庭及播放门控之外，未选家庭、没有摄像头或媒体不可用时，仍可检测图片和取消待接纳配置意图。

| 操作               | 页面准入与可见性                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 选择来源／开始采集 | 当前账号、家庭和设备清单资格已确认；开始校验所选能力。媒体暂未就绪作为启动进度或失败呈现，不直接复用观看条件                   |
| 停止活动采集       | 已知目标及所属作用域即可按停止协议提交，后台最终校验；不要求媒体就绪或 SSE 已连接                                              |
| 取消配置意图       | 已取得待接纳意图及控制版本即可提交；控制位于家庭选择门控之外，等待家庭时也可见                                                 |
| 建立直播连接       | 当前来源访问有效，媒体绑定及观看条件满足；此处使用播放资格                                                                     |
| 查看／导出已有定格 | 已持有有效图片且其来源未被明确撤权；媒体断流或重新绑定不隐藏定格。访问同步暂不可确认时标为历史并暂停新数据接纳，确认撤权后清理 |
| 独立图片检测       | 账号访问有效，未选择家庭或媒体服务不可用不阻止入口；计算错误按 P0 自身状态呈现                                                 |

停止和取消控制始终位于播放门控外；无法确认目标时保留控制及恢复状态的提示。媒体不可用不等于访问撤销。独立图片也不依赖摄像头是否存在。

```text
视频
[采集管理] [检测图片]
视频卡片 → [画面分析]

视频 / 工作室摄像头 / 镜头 1                 [返回视频列表]
当前来源采集状态与操作

连续视频＋叠加层                      当前视频结果详情
[暂停画面] [返回实时]                 检测｜跟踪｜声音｜筛选
[检测框] [轨迹] [标签]                [展开 JSON] [刷新] [复制]

当前视频近期记录：运行变化、观测缺口、声音区间、筛选窗口
```

当前观看来源由打开的视频卡片及镜头通道确定，详情内不再维护另一套家庭摄像头列表。双摄设备可以切换本设备镜头；打开其他视频从视频列表进入。首期以单视频详情为主，不要求双路对照布局；多个详情标签页仍共用同一后台采集状态。

后台采集范围与正在查看的视频分开管理：视频页采集管理显示完整来源集合，详情操作默认针对当前来源。已有多路采集时明确展示共享范围，停止按钮注明将停止整次采集及受影响的来源，不能伪装成只停止当前视频；查看详情不扩大或替换采集范围。标签与叠加开关只改变展示，不启停后台能力。综合展示复用当前视频的结果，不维护另一份状态。

| 视图 | 展示重点                                                       |
| ---- | -------------------------------------------------------------- |
| 检测 | 框、类别、置信度、帧龄、跳帧与失败指标；图片检测入口           |
| 跟踪 | 轨迹编号、实测／预测框、特征状态及断点；编号不等于成员身份     |
| 声音 | 音轨状态、能量、人声概率和时间区间                             |
| 筛选 | 窗口、通过／跳过原因、候选类型、全景／裁切及媒体可用性         |
| 综合 | 实时能力按来源和时间关联；选中历史窗口后只显示该窗口片段与摘要 |

窄屏把结果详情放在视频下方；控制、标签及选框操作支持键盘和可访问名称。沿用当前卡片 `object-contain` 的完整画幅显示，叠加层的坐标变换需包含实际缩放和留黑边，不能按容器尺寸直接画框。

### 播放、定格与停止

| 操作           | 行为                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------ |
| 暂停画面       | 固定当前实际展示帧；后台继续采集，观看端不继续积压待展示帧                                 |
| 返回实时       | 释放定格和过时积压，恢复当前视频                                                           |
| 停止采集       | 后台停止本次分析；清除实时框，已取得定格可作为历史查看，观看连接可继续播放原视频           |
| 离开页面       | 释放观看、页面订阅、图片和读取资源；后台按其采集策略继续，直至显式停止或有限期限到达       |
| 隐藏标签页     | 释放观看和播放积压，页面查看会话保留定格；恢复后仍处于定格模式，只有返回实时才恢复直播展示 |
| 切换家庭／退出 | 结束旧作用域运行及 UI 调试采集，清空相关媒体及结果；配置采集按第 4 节协调                  |

### 框与定格的一致性

展示对象分别持有画面身份和各结果层的来源帧身份，匹配类型为同帧、沿用或无法确认。连续视频帧率高于检测采样率时，可短暂沿用已关联的较早结果，必须标记“沿用”及年龄，并在有限间隔后隐藏；不采用未来帧结果，不把沿用称作预测。跟踪的 `measured`／`predicted` 只使用后台原有含义，前端不新增跟踪算法。

暂停立即切换到同帧核对：保存画面 B 的确切像素，只保留 B 的同帧层，移除来自 A 的沿用框及无法确认的层，并提示已隐藏非同帧框。B 的迟到结果只能在原运行仍有资格时更新 B 的对应层；已停止或失同步后不再追加连续结果。轨迹历史可以单独查看，不当成 B 的检测结果。

没有同帧结果时显示“暂无结果”；只有后端明确提供处理依据时，才显示等待、跳过或失败等原因。结果缺失、计数变化、超时或序号空缺都不能证明“未采样”。页面不维护全量逐帧日志，已有处理信息不足时如实显示未知。

任何有效定格都可点击“检测此帧”，走独立图片检测；结果在单独区域展示，不覆盖连续结果，不制造轨迹或可信摄像头证据。正常停止采集不主动取消此图片请求；共享计算故障仍可能使请求失败。

### JSON 分析入口

当前结果详情必须提供可展开、手动刷新和复制的 JSON，复用现有查看数据与浏览器剪贴板接口。快照包含采样时间 `sampledAt`、家庭作用域与订阅同步状态、来源和运行资格、最新观测及跟踪结果，以及当前展示帧、关联类型和各叠加层的身份。最新观测即使尚未匹配到画面也可检查，不能把它冒充当前帧结果。

展开或手动刷新时生成快照，不按视频帧率刷新 JSON。定格时保留对应分析快照；迟到的同帧结果可通过显式刷新查看。来源撤权时同步清除相关快照，复制内容与当前可见快照一致。

## 4. 后台采集控制

backend 独占采集意图、适用的截止时间及当前运行状态，一个 backend 同时管理一次活动采集，可包含多路来源。UI 与配置启动经过同一个接纳入口，所有标签页显示同一份状态；页面订阅消失不停止采集。新增可重复的采集开始／停止操作，`close()` 仍表示服务最终关闭。

### 启动与来源选择

一个服务持有采集控制状态，UI 调试与配置采集共用资格校验、逐路运行和计算容量，但保留各自的来源及期限策略。

| 项目     | UI 调试采集                                                            | 配置采集                                                                                        |
| -------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 期限     | 默认 10 分钟，可显式指定经校验的有限时长                               | 保留配置驱动的持续采集，不隐式增加 10 分钟期限                                                  |
| 来源     | 接纳时校验并固定所选通道；家庭全选也只展开一次，无来源或超过容量则拒绝 | 保留显式来源与 `household` 选择语义；`household` 持续跟随当前有资格的摄像头通道，受共享容量约束 |
| 家庭绑定 | 绑定接纳时已就绪的家庭及作用域，切换家庭或退出即结束，不迁移请求       | 沿用已有家庭资格协调；撤销旧作用域运行后，按配置和新作用域资格重新协调                          |
| 来源变化 | 新增设备不扩大集合，移除／撤权后不自动重新加入                         | 根据当前配置与资格协调；资格恢复后可以建立新运行                                                |
| 媒体故障 | 在原资格和剩余期限内恢复，不因首帧或重试续期                           | 在配置意图仍有效时继续恢复，不添加隐式截止时间                                                  |

接纳 UI 请求时产生采集编号并记录开始／截止时间，随后准备计算与媒体，启动等待也消耗本次时长。页面明确显示意图来源、实际通道和有限期限或持续采集状态。任何通道撤销后重新接纳都取得新运行身份，旧结果不得继续使用。

配置保留来源及计算／采样参数；能力选择共用共享 schema（结构校验规则），默认检测与跟踪，不随新能力上线自动启用 P3／P4。空来源不自动启动，也不阻止 P0 准备计算。非空配置在 backend 启动时建立配置意图；家庭或来源资格暂未就绪时等待，明确配置错误则显示失败，不把暂时无来源当作永久拒绝。

待接纳配置意图与活动采集由同一所有者串行控制。已有配置意图或采集时，页面显示当前状态；用户须显式取消／停止后再开始 UI 调试，不静默覆盖、不创建并行采集。并发动作以控制版本拒绝过期操作。用户显式取消或停止配置采集后，本次进程不再自动重建配置意图，重新启动 backend 才重新读取配置；UI 调试结束也不自动恢复配置采集。正常资格协调与暂时断流恢复不等于用户停止。

能力在开始前选择，运行中修改需要停止再开始：跟踪依赖检测，纯视频筛选不强制依赖跟踪，声音及音频筛选校验实际输入能力，不可用能力明确拒绝。只关闭显示不算关闭计算。控制请求带家庭作用域、请求标识与预期控制版本，停止指定采集编号；重复请求不重复启动，旧停止不结束新采集。允许启动中停止，先撤销实时资格再清理资源，未释放资源继续计入容量。HTTP 接纳与资源真正启动／停止完成分别表示，逐路健康与总体状态分开。

复用现有 XState 生命周期、`AbortController` 和并发初始化共用的 Promise；只补充实际缺失的控制状态，不另建通用任务或命令框架。

### 控制错误与故障影响

内部控制协议返回有类型的错误及其影响范围，不按错误文本分类，也不把所有 `videoControl()` 异常交给共享池的 `fail()`。

| 类别           | 示例与成立条件                                                                     | 处理范围                                                                                       |
| -------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 可预期控制拒绝 | 容量不足、过期运行、重复或冲突请求；在分配前拒绝，或已确认本次分配完整回滚         | 只结算本次控制，不终止原计算代；完全相同且仍活动的重复启动返回原确认，已停止运行的重复停止成功 |
| 单路媒体失败   | 一路读取、解码或访问失败，能确认该路停止并释放所属资源                             | 撤销该路资格，发布其健康状态，按采集意图与期限决定恢复；不重启其他来源或中断图片               |
| 共享计算故障   | 进程退出、通信损坏、异常协议响应、硬超时、内部不变量破坏，或无法确认安全回滚／释放 | 撤销受影响计算代并按池级策略回收恢复，所有依赖它的摄像头和图片均可能受影响                     |

副作用已经发生但清理状态不明时，不能为了保持“局部失败”把异常包装成普通拒绝；先进入安全回收。旧计算代的迟到失败不得触发新计算代恢复。用户正常停止某路或一次采集不关闭健康共享池，也不主动取消在途图片；若停止过程升级为共享故障，则不保证图片完成，页面显示实际失败和恢复状态。

### 计算资源生命周期

跟踪停用需停止接纳输入并收尾在途工作，最后一个使用者释放后关闭外观模型、归还预留计算名额；单路 `tracking.stop()` 不等于模型已退出。不能提前归还名额或中断其他任务仍使用的资源。

共享计算池的准备／恢复与摄像头初始化分开，仍由同一服务持有并合并并发初始化。图片请求只准备公共预算、图片解码及检测模型；默认空来源、从未启动采集、FFmpeg 或摄像头媒体依赖不可用，不应阻止 P0。视频启动负责 FFmpeg 探测、来源和视频参数检查；公共计算预算或模型错误仍明确失败。

图片请求不得通过 `start()`／`retry()` 隐式创建采集。池恢复后只协调仍有效且未超过适用期限的采集意图；计算池状态、配置等待状态与视频采集健康分别公开。停止摄像头不关闭图片能力，视频初始化失败不把健康的 P0 标成不可用。

## 5. 状态、结果与资源的所有权

| 数据                   | 唯一所有者与接纳条件                                                               | 停止采集后                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 实时观测               | 现有观测存储；校验家庭、采集、来源运行、媒体代次及帧身份                           | 拒绝新的实时结果；已取得的同帧副本只作历史查看                               |
| 独立图片结果           | backend 完成当前 HTTP 请求，页面持有确切输入和返回结果；按请求身份及访问作用域接纳 | 不依赖摄像头运行，可以完成和展示                                             |
| 历史窗口／媒体         | 媒体管理器；按历史访问资格、记录身份及期限校验                                     | 正常停止不自动删除仍可读取的历史，也不恢复实时资格                           |
| 实时观看连接与播放缓冲 | 视频父路由的播放会话所有者及实时展示控制器                                         | 可随可见性、连接故障或 `revision` 变化释放／重建                             |
| 定格、图片输入及导出   | 页面内查看会话，独立于播放组件挂载                                                 | 连接重建不删除；返回实时释放定格，替换输入释放旧图片，离页或访问失效全部清理 |

不把图片请求或历史窗口塞入只接受当前运行的 observation store，不给它们虚构摄像头运行身份。HTTP 及 SSE 对同一记录使用一致的版本规则，旧消息不能覆盖新状态。后台重启后旧内存引用失效，页面不得把它们关联到新实例。

### 家庭与感知状态的组合接纳

`modules/perception/` 统一组合家庭公共状态和感知状态，再交给展示控制器及查看会话。家庭设备清单约束来源访问，感知消息不授予设备访问。家庭版本为 `scope_epoch + sequence`，感知快照携带其已核对的家庭版本，两条流各自的 sequence 不能直接比较。

单设备移除可能不改变 epoch。家庭更新确认设备／通道移除时，先使该来源运行失效，再清理观看、叠加、定格及在途读取；记录当前查看范围内的移除版本，使迟到感知消息和绘制回调不能复活原运行。设备重新加入需满足新的家庭状态及新运行授权，按 UI 固定集合或配置动态协调的来源策略重新接纳。无需另建权限存储，复用家庭版本和来源运行身份完成判断。

任一流断开或引用了尚未应用的家庭版本时暂停相关实时接纳，重连先应用家庭快照，再应用基于该版本的感知快照。恢复历史窗口只恢复其历史读取资格。无关设备变化不清空有效画面；媒体故障不等于家庭撤权。上述接纳规则同样用于 HTTP 返回和异步展示，不依赖消息恰好按顺序到达。

独立图片入口遵守本机访问校验。页面以已确认的账号和页面访问上下文隔离旧响应，未选择家庭是允许的已知状态，不要求摄像头或媒体连接就绪。切换输入、离页、退出或已绑定作用域失效时停止等待并拒绝旧响应；后台按第 7 节收尾，取消 HTTP 不等于终止原生计算。普通采集停止或播放重连不会撤销图片请求。浏览器上传的来源说明不提升为服务端认可的摄像头事实。

### Web 查看会话与展示控制

页面查看会话挂在能力标签、可见性控制及带 `revision` 的播放组件之外，拥有定格像素、各层结果身份、独立图片输入和在途图片请求；不把像素存入全局 Jotai。切换能力标签、隐藏浏览器标签或替换观看连接不销毁查看会话。显式切换镜头时释放旧镜头定格，但独立图片输入仍保留；离页、退出或关联访问失效清理对应会话资源。

暂停先把当前实际展示对象转交查看会话，再停止该观看连接和实时缓冲，后台采集继续。不在仍运行的 `PlaybackSession` 上仅调用 `video.pause()`，否则其出帧看门狗会把正常定格判成卡流。返回实时时重新建立观看连接及帧关联；媒体 `revision` 变化可以使原定格成为历史，但不自动切回直播，也不向它追加新运行结果。

同一个展示控制器选择视频帧、匹配结果层、提交屏幕画面并固定定格／导出对象；React/Jotai 管理命令、模式和详情，不依靠 atom 更新顺序保证逐帧同步。沿用第 2 节已有帧关联实现，改动展示链路时核对像素与身份，不只检查时间戳。

### Web 命令状态

复用现有请求层和反馈组件，不另建通用命令框架。前端分别保存命令发送／回执状态、服务端采集状态、同步可信度，不复用日志采集命令的全局互斥条件。可以复用按钮反馈组件，但停止不因开始请求未结算、正在等确认或 SSE 断开而一律禁用。

已从有效快照、事件或回执取得目标采集编号和所属作用域时，停止有独立请求标识和准入规则，可在该采集启动中发送；只合并同一目标的重复停止，不抢占或覆盖其他命令的回调。断线时可携最后已知目标及版本提交，由 backend 校验；若冲突则读取当前状态，只在仍为同一目标且访问有效时继续停止，不能改为停止新采集。晚到的开始响应不能覆盖已确认的停止状态。

尚不知道采集编号时，保留停止意向并查询当前状态；采集快照和回执保留其开始请求标识，确认属于本次请求后再停止，不能靠来源列表猜测。原请求仍可能接纳时，一次空快照不能证明后台未启动。无法确认时显示状态未知并允许恢复读取，不自动重发开始，也不把取消 HTTP 当作停止。配置待接纳意图没有活动采集编号，应按其控制版本取消该意图；该动作与停止活动采集在协议中明确区分，均由同一控制所有者处理。

## 6. 接口与有界订阅

连续视频继续走 WebRTC；精确关联观看读取同一 WebRTC 轨道的原生解码帧及 RTP 元数据，控制与一次性图片检测走 HTTP；SSE（服务端持续事件连接）推送状态及轻量结果；P4 媒体经受控 HTTP 读取。不广播媒体字节，不为少量控制操作引入 WebSocket。

### Web 入口与 HTTP/2

开发和生产的浏览器入口统一使用 Caddy 提供受信任的 HTTPS＋HTTP/2，页面和 `/api` 同源；开发转发到 Vite 与 backend，生产提供构建页面并转发 API，内部链路使用 HTTP/1.1。采用 Caddy 自动 HTTPS 和本地证书管理，证书信任安装属于部署步骤，不自建证书工具或代理。SSE 使用正确的 `text/event-stream` 响应类型，沿用 Caddy 默认即时刷新行为，不额外设置会改变客户端断开取消语义的 `flush_interval -1`；超时与心跳及图片处理预算一致。参见 [Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)和[流式代理说明](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming)。WebRTC 信令和媒体连通性独立核对。

入口保留真实 Host／Origin，把明确的入口地址纳入本机访问校验，并核对容器转发后的实际 TCP 对端。部署配置、证书和启动命令归运行说明维护。浏览器网络面板中的页面、SSE 和 API 实际显示 `h2` 才通过验收；协商不符就修正入口。

每标签页保留既有家庭订阅，视频详情或采集管理按需建立一条页面级感知订阅，日志页继续自己的订阅；离页释放对应连接。多标签页控制通过配置好的 HTTP/2 入口和有界服务端处理实现，不引入跨标签页共享或全局连接调度。验收至少覆盖三个视频详情标签页同时订阅、停止、上传及读取。

入口部署作为独立工作项推进，最终多标签页验收必须使用该入口，不把部署工作作为每次页面修改的前置关口。前端 SSE 读取复用现有 `consumeEventStream`，不重复实现流解码与事件解析。

以下路径为完整页面的接口边界，复用已有查询和订阅入口并补齐控制、图片与媒体接口；共享 schema放在根目录 `packages/api/`，类型从 schema 和实现推导。

| 接口                                      | 行为                                                             |
| ----------------------------------------- | ---------------------------------------------------------------- |
| `GET /api/perception`                     | 当前采集、运行资格、逐路健康、能力及限额                         |
| `POST /api/perception/capture/start`      | 开始指定来源、能力及期限的采集                                   |
| `POST /api/perception/capture/stop`       | 以明确的目标类型停止指定采集，或按控制版本取消尚未接纳的配置意图 |
| `GET /api/perception/stream`              | 初始快照、状态变化、帧结果批次、近期摘要、缺口和心跳             |
| `POST /api/perception/images/detect`      | 一次性图片上传与检测，返回该输入的结果，不创建可恢复后台任务     |
| `GET /api/perception/windows`             | 查询仍有访问资格的近期窗口摘要及媒体表示状态；不返回逐帧历史结果 |
| `POST /api/perception/windows/:id/media`  | 按需申请全景、裁切或音频表示；已就绪返回引用，编码中返回表示标识 |
| `GET /api/perception/representations/:id` | 查询已申请的 P4 表示状态，不触发编码                             |
| `GET /api/perception/media/:id`           | 读取已生成媒体，重新校验访问与期限                               |

### 订阅与重新同步

当前 SSE 最新快照可以用于状态，但不足以匹配所有展示帧。增加有界结果批次和近期摘要，按身份去重、按版本更新；允许明确的传输缺口，不承诺无损记录或无限回放。初始快照与后续事件有明确衔接位置，重连恢复当前状态和仍保留的历史范围。

当前运行资格独立于可丢结果合并保存，发送时优先处理状态变化，再发送小批结果。停止或替换时清除已失效的实时队列项，不清除仍有效的历史状态。已在途字节不能被抢占，因此需要有限的写入期限，超时结束连接并要求重新同步，不能让状态一直排在积压结果后面。写入、心跳和失同步时间预算按目标环境实测确定并统一配置，不预设尚未验证的毫秒指标。

帧结果携带所依赖的来源运行及媒体代次，不能仅比较命令控制版本。连接重建、未知代次、运行资格缺口或状态新鲜度超限时，立即暂停实时接纳及向定格追加连续结果，清除实时框，取得完整快照后恢复。普通结果与视频仍在到达不代表资格恢复。

历史记录按历史读取资格单独恢复，不因实时运行列表省略旧运行而删除。独立图片响应也不以 SSE 连通为前提；若账号／家庭访问本身失效或无法确认，暂停相关接纳，重新确认访问后再处理。服务端撤权立即约束读取，不能依赖前端已收到通知；不承诺客户端瞬时知道远端停止。

## 7. 图片检测、导出与 P3–P4 接入

### P0 与“检测此帧”

网页图片和摄像头定格共用一次性上传入口与现有计算池。浏览器用原生 `File`／`Blob`、`createImageBitmap` 的图片方向处理及 Canvas `toBlob()`／`OffscreenCanvas.convertToBlob()` 生成方向已归一化的有界压缩图片；预览和提交使用同一 Blob，后端不再根据原始 EXIF（图片方向等元数据）重复旋转，不手写 EXIF 解析器。请求和响应以输入指纹及请求身份关联，公开实际提交尺寸，不把缩小后的输入称作原图。

图片请求适配函数单独设置公共 HTTP 客户端的 `timeoutMs` 并保留主动取消，不使用其默认 12 秒，也不提高其他接口默认值或开启自动重试。端到端预算覆盖有界上传、共享池冷启动／准备、排队与推理、响应传输和解析；按共享接口限额推导，而不是只取计算任务期限。当前模型初始化允许 30 秒、单次检测允许 10 秒，浏览器等待必须覆盖合法冷启动的组合路径并包含上传及响应余量。

后台为各阶段及整次图片请求设置可执行的预算，并在公共契约中提供与前端一致的等待配置；计算恢复中的等待也计入准备预算，无法在预算内准备则明确返回不可用，不无限等待恢复。部署中的 HTTP／代理响应期限不得短于该接口预算。超时仅表示页面未取得结果，不说明计算已终止，清理仍遵循下述生命周期。

上传直接使用有界压缩图片字节作为 HTTP 请求体，不创建应用临时文件。后端按现有 32 MiB 输入上限及 `frameLimits` 解码像素限制准入，在现有图片检测入口增加字节输入，经计算进程传给 sharp，复用输入哈希、解码与检测流程；本地 CLI 的文件读取保留为同一检测流程的文件适配入口。无需手写 multipart 解析、另建计算池或文件清理登记表。

请求与计算任务分别持有其实际使用的字节和解码资源；限制并发、等待队列和总在途字节，计算进程通信产生的副本也计入预算。上传完成后不保留后台导出输入，不提供结果恢复查询；响应丢失或请求失败时显示实际状态，由用户决定是否再次检测。

浏览器取消可终止上传、撤出尚未执行的排队工作或停止响应等待。已进入原生计算的工作仍按既有硬期限收尾，不因单个请求取消关闭共享池。请求持有的字节可在不再使用时释放；计算名额及任务资源必须等实际任务完成或所属进程确认退出后释放，不能以 HTTP 结束、结果 Promise 拒绝或 IPC 断开作为计算已结束的依据。复用现有任务完成及进程退出监督，只补充缺失的完成信号；收尾期间继续计入容量，无法确认退出时按共享故障处理，不引入图片文件删除、重启扫描或可恢复任务机制。

“检测此帧”必须在持续采集中可用。共享计算池统一调度视频与交互图片，图片保持一个有界等待位置；有图片等待时，新的空闲计算名额不能持续被视频抢占。两类任务同时等待时交替授予新名额，视频内部继续按来源轮转；不抢占已执行的原生任务，也不新增第二个计算池。这样单计算名额时也不会饿死任一类任务，多名额时仍使用同一并发上限。

图片准入时检查队列容量和完成预算，排队与执行分别有界并计入端到端期限；队列已满返回忙碌，取消尚未执行的图片立即释放等待位置。忙碌是实际容量反馈，不以自动重试或要求停止采集替代调度实现。验收持续视频负载下已接纳图片能在约定预算内被派发，视频也继续获得计算机会；原生任务硬故障仍按共享恢复处理。

共享计算进程不提供图片硬故障隔离：图片推理硬超时或进程级故障可能回收整个计算进程，暂时中断其他摄像头的检测／跟踪并触发恢复。公平调度不改变这一故障边界；页面应展示共享计算恢复及来源缺口。普通无效图片、容量忙碌与浏览器停止等待不应被升级为关闭共享池。

### 按需下载图片

网页导出统一在浏览器执行，使用页面仍持有的图片和结果，通过 Canvas 原生 `toBlob()` 合成 PNG，无需新增图像生成依赖、后台图片保留期限、导出任务或媒体申请接口。现有本地命令继续使用自己的 PNG 输出功能，不为网页导出强行改造文件命令。

- P0 导出只使用该次提交的图片及其返回结果，不重新检测；按检测输入尺寸合成带框 PNG。
- 连续视频定格导出固定点击时的确切像素和同帧结果层；沿用框、无法确认的层及其他帧轨迹历史不得混入。无同帧结果时只下载无框图片。
- “检测此帧”的 P0 结果在其独立结果区域导出，不与原连续跟踪混合。
- 点击后晚到结果不改变本次导出；导出标为调试图片，不作为后台认证证据。限制像素、并发和临时副本，完成后释放对象 URL；离页或作用域失效取消未完成工作。

### P3 声音

后台完成音轨接入、解码及观测发布后再接视图，双摄共享音轨只处理一次。区分安静、未检出人声、无音轨、输入不足和失败；按时间区间关联，不能把声音伪装成某张检测帧的事实。连续调试视频默认静音，音视频同步播放按实际交付的 P4 片段验证。

### P4 窗口

复用媒体计划的窗口、筛选和候选，显示有界保留的通过与跳过摘要。历史查看范围是窗口片段与窗口级摘要，逐帧检测、轨迹和声音曲线属于实时视图。点击窗口时退出综合实时展示，清除实时框、轨迹和声音明细，显示窗口时间、覆盖缺口、筛选原因、实际保存的声音汇总及媒体表示；没有保存的项目明确显示“无历史明细”。返回实时后重新使用当前结果，不改变采集。

窗口摘要由 P4 媒体管理器在窗口形成时维护有界投影，使用窗口身份及版本，通过窗口查询和快照恢复；不从当前 observation store 或浏览器恰好收到的 SSE 倒推。刚进入页面和重连都取得同一份仍保留的摘要，缺失或过期不填入最新观测。内部为裁切保存的框不自动成为页面可查询的历史结果；裁切表示仅展示实际参数和坐标映射，不叠加未经交付的历史框。

选择媒体表示后才请求编码。后台按窗口、处理版本和规范化参数共用任务及产物；就绪返回媒体引用，接纳编码返回表示标识，容量不足返回忙碌。SSE 或状态查询只反映生成状态，媒体 GET 只读取，均不触发重复编码。页面区分未生成、生成中、就绪、失败、过期、淘汰和撤销；失败只由显式重试重新申请，期限不续期。

媒体生命周期以[媒体计划](media-perception.md#运行结束与历史媒体读取)为准。正常停止后，仍保留的窗口输入和产物在原期限内继续支持摘要查看、按需编码和媒体读取；撤权终止相关读取并清空页面。媒体不存在时只展示摘要，不能用最新画面代替。查看或暂停不会延长期限，也不会触发 Agent。

## 8. 资源预算与实施落点

控制、结果和图片请求使用有界内存；P4 媒体按媒体计划使用应用临时目录，重启不恢复，临时目录不进入长期录像数据卷。摘要、P4 媒体、编码任务及读取分别限制数量、字节、并发和期限，沿用媒体计划的限制；不因慢消费者阻塞基础检测。

浏览器资源按第 5 节分层释放：观看连接替换只释放实时资源，查看会话继续持有有界定格及图片；查看会话结束再释放其位图、对象 URL 和请求。轻量状态进入 Jotai，后台分析范围与浏览器正在观看的来源数量分别限额，无查看需求不生成调试画面副本。

展示缓冲直接复用当前实现及[已确定预算](../perception.md#单路帧关联与定格)，把尺寸、延迟、帧数和字节上限视为同一组配置，不重新立项选型。完整页面增加多个详情标签页、图片或导出副本时核算总内存并验收联合负载；只有实际改变展示策略或预算时，才重新测量相应的匹配率、晚到比例、展示延迟与峰值内存。

## 9. 交付与验收

| 工作项         | 交付与验收重点                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| 帧关联剩余边界 | 复用已有单路实现，补齐设备侧断流、时间重置及联合负载验收；改动相关链路时核对同帧像素与结果                 |
| 控制与状态组合 | 保留配置持续采集与 `household` 动态协调，增加 UI 有限采集；启动中或订阅断开可停止，未选家庭可取消配置意图  |
| P0 与共享计算  | 默认空来源、未选家庭、视频依赖不可用时可检测图片；有界字节输入，等待覆盖冷启动，图片与视频公平获得计算机会 |
| 页面与分析     | 连续视频、定格、同帧导出及 JSON 展开／刷新／复制；隐藏、标签切换和连接重建保留定格，返回实时才恢复直播     |
| 入口部署       | Caddy HTTPS／HTTP/2、本机访问校验及多标签页联合验收                                                        |
| P3／P4 展示    | 后端能力落地后接入共享音轨与窗口摘要；停止后仍在原期限内查看已有窗口，历史层不采用当前结果                 |

控制、P0、页面和入口部署可独立推进，完整交付时组合验收。已有帧关联不作为重复选型关口，但尚未验证的设备故障和联合负载不能省略。P3–P4 是后续交付，不为暂未实现的能力建立替代实现。项目主交付顺序仍由[协作计划](household-automation.md#9-实施顺序与改动位置)维护。

验收覆盖以下行为：

- **运行控制**：重复请求不重复采集，旧停止不影响新运行；配置等待可取消，持续配置按资格协调，UI 接纳后来源固定；显式停止后配置不自动复活；容量拒绝和单路失败不重启健康池，无法确认资源释放时按共享故障处理。
- **状态组合**：家庭先移除设备、感知后到旧结果时不能复活画面；同 epoch 内移除再加入需要新运行，HTTP 和绘制回调同样遵守；历史读取与实时资格分别恢复。
- **Web 交互**：一级导航只有视频入口，卡片详情对应所选设备与镜头，不默认选择配置首路；返回列表恢复原位置；停止与取消在播放门控之外；开始回执晚到不覆盖已停止状态；未选家庭不隐藏 P0，媒体断流不隐藏已有定格；JSON 区分最新观测与展示帧，复制快照可核对，撤权后清空。
- **计算清理**：图片不落临时文件，字节及解码副本有总量预算；任务完成或原进程确认退出后才归还计算容量；取消已执行图片不关闭健康共享池，硬故障影响按真实计算代呈现；关闭跟踪实际释放模型及名额。
- **容量与时延**：图片等待位置、解码像素、视频展示缓冲、媒体编码及读取都有预算；持续采集下验证公平派发、端到端图片响应、视频缺帧率及单个／多个详情标签页峰值内存。
- **媒体**：同窗同表示只编码一次，停止不重启摄像头取旧窗口，期限不因查看或重试延长；撤权取消相关编码／读取，过期显示真实不可用状态。
- **部署**：开发、生产分别验收证书、本机访问校验、SSE 无缓冲和 `h2`；三个以上视频详情标签页加日志、上传及读取时，控制请求仍在预算内完成，离页释放订阅。

已有同步链路直接复用；新增计算调度、控制接口、完整页面及入口部署仍需实现，不能把“有改造入口”视为已验证。真实摄像头、浏览器和联合负载验收结果归所属当前功能文档维护。未经明确许可不新增测试或故障注入脚本，只运行与改动直接相关的最小检查。

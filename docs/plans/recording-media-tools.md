# 原始录像与媒体读取：部署验收

Backend 的原片存储、参数化读取、共享 SD 原片与直接媒体生成已接入。配置、接口、容量及生命周期见 [Backend 媒体说明](../../apps/backend/README.md#原始录像与媒体读取)，请求规则由[录像服务 schema](../../apps/backend/src/recordings/service.ts)定义。本文只保留尚未完成的部署验收，不把源码审查或合成输入的结果视为真实设备结论。

## 待完成验收

- 核对检测模型加载失败或计算进程退出后的录像连续性，以及真实来源断流重连、媒体代次及编码参数变化。确认码流是否使用开放 GOP（部分画面依赖前一组画面），核对最旧段淘汰后紧接的段能否从实际可解码帧读取。
- 用真实 SD 素材核对跨文件区间、断流和已淘汰前段的解码依赖，确认素材不足不会被相邻帧的显示保持掩盖。文件时间戳不能证明传感器完整采集。
- 在长关键帧间隔分段、并行转换及共享 SD 下载负载下，核对实际增长、预留抵扣和删除成功后的容量归还。核对在用原片受到保护，空间不足只淘汰未使用原片，仍不足明确返回容量错误；同时核对落盘前的容量约束及部分写入、关闭失败时的占用保留。
- 核对家庭撤销或替换、单设备撤销、普通媒体重连、服务关闭及重启的边界：所属请求与重试及时取消，普通重连保留仍有资格的已封段文件，旧实例缓存清理完成后再开始新实例。
- 在真实摄像头部署中核对不同物理连接同时下载、同连接串行读卡，以及批量等待请求取消后 `gate` 仍能释放并接纳后续请求。联合核对现有窗口媒体、身份、声音与 SD 回放在真实负载下的可用性。

验收材料保存在 Git 忽略的数据位置；共享文档只更新已确认的适用范围及仍未验证的限制，不保留一次性运行记录。

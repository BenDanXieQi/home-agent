# 设备状态与历史页面

**状态：采集与历史展示待实现。** 登录、绑定、设备清单、播放和状态订阅已实现，使用方式见[家庭运行时](../household-runtime.md)和 [Web README](../../apps/web/README.md)。本计划只定义接入真实采集与历史后的页面增量，不重建订阅或登录流程。

[实施入口](README.md)

## 数据边界

复用现有共享 schema、状态 SSE、版本检查与批次应用。页面只消费后台已提交状态，命令响应不直接覆盖状态。采集与历史能力交付时才增加对应实体，不提前注册空接口或空字段。

| 数据                                             | 所属契约与显示                                                                   |
| ------------------------------------------------ | -------------------------------------------------------------------------------- |
| `latest`                                         | [设备采集](device-collection.md)定义当前值、来源、观测质量与当前质量；未知不补零 |
| `source_health`                                  | 连接、订阅覆盖、暂停与恢复状态，不能与设备离线混用                               |
| `device.availability`、`read_enabled_properties` | 按采集契约提供在线状态及允许读取的能力，不从云端设备清单推导实时可用性           |
| `history_health`                                 | [设备历史](device-history.md)定义当前写入健康；详细缺口按需查询，不进入公共快照  |

当前传输上限、重连、慢连接处理和登录材料读取全部沿用[家庭运行时](../household-runtime.md#公共接口与-sse)。采集新增状态在提交前检查自己的条数和字节上限，完整编码仍受现有 SSE 上限约束。任何超限都不阻挡退出、停止或已确认的访问撤销。

设备规则状态仅在具体事件场景需要时增加，由[第一方协作计划](household-automation.md#设备事件输入)的规则模块拥有；不是即时动作策略状态。人员、活动与要求由家庭领域查询提供，不复制进设备属性 `latest`，也不为了界面另存一份家庭情景。

## 页面增量

1. 设备详情展示最近值、最后上报和变化时间、来源、当前质量和不可用原因。浏览器断线显示未同步，设备离线、属性过期、订阅失败与数据超限分别表达。
2. 采集过载按 `source_health` 显示缺口、继续接收或暂停；仅有实际恢复任务时显示进度和下次重试。人工重试使用现有 `connection/retry`，不新增页面轮询。
3. 依据 `read_enabled_properties` 提供一次性读取，沿用采集计划的 35 秒 HTTP 期限；不自动重发，返回后最多等待 5 秒让订阅追上回执版本。部分失败按项显示；超时表示结果未确认，未追上表示状态未同步，运行失效丢弃旧响应。
4. 历史仅在用户打开对应能力时查询。缓存键包含绑定身份、能力和时间范围，取消传到请求；关闭周期、聚焦和重连自动刷新。原观测、质量、保留口径及缺口可见，不插值冒充持续状态；历史响应不写回当前值。
5. 页面继续使用每标签页一条状态订阅和同一份 Jotai 状态；按需历史用已有 TanStack Query 分页，不建立第二份当前值缓存。历史写入异常通过订阅显示，不要求先打开历史查询。

## 完成条件

- [ ] 真实属性更新可见，未知、过期、设备离线与浏览器未同步可区分。
- [ ] 多页面不增加云端读取；复用已有断线重连、作用域隔离和资源释放。
- [ ] 一次性读取的部分失败、超时及回执未同步不会误报整批成功。
- [ ] 历史写入故障不影响当前值；已知缺口、未保存区间和未知覆盖不被画成完整经过。
- [ ] 人物与活动判断不会被当作原始设备值；界面只展示实际已交付能力。

本页面不阻塞没有界面依赖的情景维护或 Agent 任务。物理动作、主动通知和情景展示按各自具体场景验收，不以设备页面完成代替它们。

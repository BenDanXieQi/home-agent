# 成员短期外观归因实施计划

状态：证据出口、家庭短期参照规则、统一关联与活动纠正、现有页面已接入；校准和专项运行验收未完成，正式装配仍不输出外观成员归属。当前实现、参数候选、使用方式和限制见[家庭短期人体外观参照](../perception.md#家庭短期人体外观参照)。本文只维护剩余校准、验收及属性模型的后续条件；主交付顺序仍由[家庭情景与自动化](household-automation.md#9-实施顺序与改动位置)维护。

## 目标与范围

近期任意一路摄像头通过现有人脸规则确认成员后，以该目标对应的人体外观建立短期参照。任意一路后续出现的人物，包括同一路的原轨迹或新轨迹，都可以匹配这些参照，形成“推测是某成员”的关联。摄像头只标记证据来源，不规定起点、接力顺序或必须经过的房间。

交付闭环为：人脸确认 → 短期外观参照 → 人体外观推测 → 后续人脸确认或纠正 → 现有成员活动记录。首期仅覆盖人物，不扩展猫狗识别。

复用已有 ReID（把人体外观转换成可比较向量的模型），不增加模型或推理次数，不新增数据库表。范围不含 Agent、性别推断、家庭在场前提、房间路线、位置汇总、人工纠错页面或自动人脸样本积累。采样修复单独验收，不在本文重做；输入缺失时明确保持未知。

## 5. 校准与验收

证据出口、归因规则、活动保存和页面已经接入，仍须完成下列校准与专项运行验收。公开 Real28 身份标注素材与离线分数校准入口已接入，使用固定身份独立调参／留出划分，报告同镜头、排除目标镜头及换衣的成员选择和未登记身份结果；当前跨镜头覆盖不足，分数仅为候选。Real28 入口没有原帧时间、人脸确认、真实家庭场景或活动事务及页面联动；MEVA 原视频输入分析已统计两个镜头的合格新特征间隔及同帧有脸检测交集，但没有全局身份映射或直接确认，不能替代下表专项运行验收。ChokePoint 联合入口已用真实人脸质量、隔离参照、现有三次确认规则和短期外观领域分析；冻结协议排除后已登记目标的合格新样本仅两份，未产生确认或短期外观参照，不能替代确认后归因验收。AMI 单参照近景入口进一步产生了真实确认和两份同帧短期外观参照，仅证明单场景链路可运行，没有逐帧身份真值、多人误归属或独立成员校准证据。完整 AMI 长段已做同输入 1／5／10 分钟参照及 1／3／5 秒支持窗口诊断对照，九组均无推测增量；Real28 tune 失败代表索引已固定，不能据公开单场景选择家庭策略。正式装配不输出外观推测，因此不产生外观推测活动；不选择上线分数或时间参数，已有直接身份活动保存不受影响。采样链路的独立修复须核对输入可用性，不把未采到或未提取当成匹配失败。

收集同人同镜头、同人不同镜头、不同人相似衣着、换衣及长时间间隔片段，比较正确与错误成员的分数分布，确定绝对门槛和领先差值，再用另一组片段验收。不能在同一片段调参后把该片段当独立验证；无法区分的场景保持未知。只有单人素材时只验收单人覆盖，不能宣称已验证多人误归属。额外统计同帧人脸／新外观共同可用比例、每路新特征间隔和推测闪断次数；若当前“复用特征不计数、不续期”约束导致覆盖不足，记录限制再决定是否调整，不暗中延长有效期或增加推理频率。比较参照期限及支持窗口时固定素材和其他参数，最终选定数值、策略版本和覆盖范围后才启用活动写入。

记录可归属片段增量、错误归属、推测形成延迟及缓存峰值；覆盖率提升不能掩盖错认。未知原因至少区分无参照、无新特征、分数不足、候选接近及冲突。

实施时只运行直接相关的最小已有测试范围；新增测试或故障注入脚本须先取得用户明确许可。类型检查和必要的页面核对随实际改动执行。实现后把用法和未覆盖限制更新到当前功能文档，已完成施工步骤从本计划移除，不保存一次性验证日志。

## 6. 属性模型的后续条件

轻量 PP-LCNet 人体属性原权重的固定 Real28 离线评估已完成，保守候选未增加正确接纳或减少错误，不接入。能力、冻结协议、结果与本机资源边界见[人体可见属性参考](../references/person-attributes.md)；复现入口见[离线评估说明](../../apps/backend/scripts/perception-evaluation/README.md#人体可见属性对照)。

现有公开静态裁剪没有姿态、遮挡、低光、属性与完整度独立真值，不能替代这些专项或第5节真实家庭／数据库验收。只有后续具备独立标注和明确基础归因问题，且新的离线候选实测有收益时，才考虑另定原帧裁剪保留、触发时机与计算预算；属性一致仍不能让未达ReID门槛的身份通过。该条件下属于新增模型调用，不沿用首期“不增加推理次数”的承诺。本计划不提前创建在线模块或配置。

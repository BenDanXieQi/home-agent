## 交付方向

Home Agent 面向持续负责家庭事务的 personal agent：Agent 维护关注、承诺、调查、问询与等待，家庭变化和可靠工作输入驱动后续处理；backend 与第一方 Agent 协作维护家庭情景，backend 拥有已启用自动化、证据接纳和动作结果。情景不完整时可按授权继续调查，工作与家庭事实分别维护。主实施顺序、场景依赖和分阶段验收统一见[家庭情景与自动化](household-automation.md#9-实施顺序与改动位置)，不在索引复制批次与进度。

本地感知可独立交付，Agent、历史和页面按具体用途接入。领域语义以家庭模型为准，来源质量以各来源契约为准；尚未实现的能力不得写入当前功能说明作为可用行为。全部文档的层次与维护边界见[文档导航](../README.md)。

## 每项交付的检查

### 原生能力与成熟库优先

通用实现遵守仓库原生能力／成熟库优先规则。当前 SSE 流处理见 [Web 说明](../../apps/web/README.md#状态订阅与播放)，跟踪求解与原生性能统计见[感知说明](../perception.md)。backend 自动化已使用 [Graphile Worker](../automations.md#保存恢复与接口)，Agent 持续工作的等待与恢复随[运行框架选型](household-automation.md#输入分类与可靠交接)核验；历史清理采用 [TimescaleDB 保留策略](device-history.md#查询与清理)，音视频处理采用 [FFmpeg、sharp 与 Silero VAD](media-perception.md#后续能力契约)；当前能力与后续设计分别在所属功能文档和计划维护，不提前安装无使用方依赖或创建空模块。

静态文件服务已使用 Hono，状态更新使用 Mutative，生命周期使用 XState，图片处理使用 sharp，模型线程使用 Piscina。替换须减少总体维护成本并保留行为，不能仅为减少本地行数引入第二套媒体栈或运行时。

### 交付边界

- 明确实际输入来源、要解决的问题、输出用途和不确定性；不以 checkpoint 保存代替可用判断或用户可见结果。
- 校验作用域、迟到输入、真实取消、资源上限与故障隔离；临时断流不抹掉已经取得的历史证据。
- 验收只覆盖本次启用能力；真实设备、源码审查与模拟输入的证据分开，不把局部通过写成全链路保证。
- 按仓库规则运行最小相关检查；纯文档只检查文档，未经用户许可不新增测试或故障注入脚本。
- 实现后把使用方法与验证限制更新到功能文档，计划只保留待交付职责，不保留逐次执行日志。

原始材料保留在 Git 忽略的 `data/verification/` 或 `data/perception/`；共享文档不保存账号、凭据和一次性运行报告。设备接入仍未验证的范围集中见[家庭运行时验证范围](../household-runtime.md#验证范围)与[米家来源契约](../contracts/mijia.md#实机证据与使用限制)。

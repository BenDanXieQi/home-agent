# 米家与摄像头

完成[快速开始](../README.md#快速开始)后，在 Web 使用米家 App 扫码登录，按提示完成安全验证。授权会加密保存，重启后自动恢复；无需在 go2rtc 再次登录或复制 token。

米家接入以已有扫码登录流程为唯一用户登录入口，共用账号保存、恢复、续期和退出机制，扫码成功后，backend 复用该登录身份完成 Xiaomi Miloco OAuth 授权，获取 access token 与 refresh token；不需要再次扫码或打开额外授权页面。登录页说明授予昵称、头像和智能家庭服务权限。MiCloud 与 OAuth 凭据合并存入同一个 AES-256-GCM 加密的 `mijia` 记录，完整授权和保存成功后才报告登录成功。OAuth 授权失败时本次登录失败，不覆盖当前账号。属性读取直接复用当前 MiCloud 扫码会话。backend 提供正式内部一次性读取入口；已在灯、空气检测仪、温湿度计和人在传感器的 13 项代表属性上实读成功，适用范围与限制见[米家来源契约](mijia-source-contract.md)。

账号登录、恢复和续期后，backend 异步读取当前账号昵称与头像，通过 `/state.account.profile` 返回。侧栏账号入口和账号弹窗共用这些资料；读取失败不影响授权或设备接入，资料缺失或头像加载失败时显示默认名称或图标。资料只保存在当前账号内存状态中，退出或切换账号后清除。

## 摄像头预览

摄像头页按设备支持的镜头通道显示画面，各画面可独立关闭和重试。只有浏览器持续收到并解码新帧才显示播放正常；连接检查成功不代表摄像头已出流。

米家授权可用、已选择家庭并完成 go2rtc 绑定后，backend 根据该家庭的设备列表为在线摄像头的受支持通道创建共享流；go2rtc 持续连接摄像头并接收视频，无需先打开摄像头页。关闭预览或离开页面只释放网页观看连接，go2rtc 的取流继续运行。官方能力元数据声明为双摄的设备，其两个镜头共用一个 MISS 物理连接，按视频包 `flags` 的高字节分流，各镜头保留独立播放资源；同一运行时会话内的并发首次连接与重连均串行建立一次物理连接。最后一个镜头源释放或账号运行时会话撤销时关闭该连接。多个开发实例各自仍会占用连接，摄像头连接上限不会因本机共享而消失。短暂离线期间可能保留已有画面，页面显示“离线状态确认中”。

## 组件与资源

backend 管理账号授权、设备列表、取流生命周期和播放信令；go2rtc 接收摄像头视频并通过 WebRTC 分发给浏览器；浏览器解码并显示画面。摄像头共享流和观看连接的管理请求及 SDP 由 backend 发送给 go2rtc，实际视频包沿“摄像头 → go2rtc → 浏览器”传输，不经过 backend。本项目的 Go 扩展编译在 go2rtc 内，原生与 Docker 模式运行的是同一套媒体实现。

| 名称                | 含义与归属                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------- |
| 保存的米家授权      | PostgreSQL 中同一记录保存的 MiCloud 与 OAuth 加密材料，由 backend 统一保存、恢复和删除                         |
| 米家账号会话        | backend 内 MiCloud 实例持有的小米云凭据、Cookie 和设备请求状态                                                 |
| 属性读取采集实例    | 当前 MiCloud 会话的读取范围及 `collection_generation`，会话替换或撤销时使旧读取失效                            |
| go2rtc 运行时会话   | backend 通过内部 `session` 接口建立，以 `sessionId` 标识，持有内存凭据及本项目的媒体资源，通过心跳续租         |
| 摄像头共享流        | go2rtc 中每个设备通道的私有流，以 `sourceId` 标识；backend 管理其注册、重试与释放                              |
| 常驻消费者          | go2rtc 内附着于共享流的内部消费者，维持取流并监测收包活跃度，不解码、保存视频或执行模型推理                    |
| 网页观看连接        | 附着于同一共享流的独立 WebRTC 消费者，以 `playbackId` 标识；backend 同时维护其预留与协商记录                   |
| 媒体代次 `revision` | backend 当前媒体生命周期的标识，媒体失效或重新绑定时更换，用于拒绝旧播放请求；不是配置版本号或 go2rtc 构建版本 |

“共享”指同一通道的常驻消费者与网页观看者复用媒体流；“常驻”指取流独立于网页观看连接，仍受 go2rtc 运行时会话和摄像头资源生命周期约束。共享流只存在于 go2rtc 内存，不写入 YAML 或全局流注册表。

服务接口可达、米家账号可用、go2rtc 绑定就绪、共享流注册成功和网页出帧是不同状态。`binding.status = ready` 表示运行时凭据安装成功；`PUT camera` 返回 204 表示私有流已创建并启动异步取流，不保证已经收到视频包。播放资源的 `active` 表示 SDP 协商完成，只有浏览器持续收到并显示新帧才算画面正常。

## 资源释放

| 操作或事件                               | 保存的授权 | 摄像头共享流与观看连接                                                           |
| ---------------------------------------- | ---------- | -------------------------------------------------------------------------------- |
| 关闭一路预览或离开摄像头页               | 保留       | 释放对应网页观看连接，共享流和常驻消费者继续运行                                 |
| 正常停止 backend                         | 保留       | 请求删除 go2rtc 运行时会话，释放其共享流和观看连接                               |
| 成功退出米家登录                         | 删除       | 先删除保存的授权，再撤销当前媒体并请求清理运行时会话；授权删除失败不报告退出成功 |
| backend 意外退出或无法续租               | 保留       | go2rtc 在运行时会话租约过期后清理其凭据、共享流和观看连接                        |
| 通道移除、地址／型号变化或离线保留期结束 | 保留       | 释放对应共享流及其观看连接；需要时为新通道规格重新注册                           |

backend 每 15 秒发送心跳，go2rtc 每次成功续租后保留 60 秒租约，并每 5 秒检查过期会话。正常关闭或退出时若清理请求失败，也由停止续租后的过期清理兜底；清理不是在断线瞬间完成。go2rtc 的租约过期不删除数据库授权，也不代表小米账号凭据已经失效。

云端首次报告设备离线时，backend 为已注册且没有注册错误的通道设置 60 秒离线确认窗口，以等待后续设备发现确认；这不保证摄像头实际仍在出流。go2rtc 独立监测视频包并处理取流恢复，浏览器独立检测可见画面的首帧和停滞。

## 家庭、房间与设备能力

家庭选择是后端统一工作范围，覆盖状态快照中的设备、家庭聚合、规格查询、属性读取和摄像头共享流。默认不选择任何家庭，只有一个家庭时也需显式选择。未归属家庭的设备不进入工作范围。

`GET /api/mijia/homes` 返回 `{ selectedHomeId, status, items }`；`items` 包括账号可访问的家庭（含共享和空家庭），每项为 `{ id, name, shared }`。同样的信息位于 `/state` 的 `homes` 中。`status` 为 `unselected`、`selected` 或 `unavailable`；家庭目录的读取进度和错误沿用 `/state.devices.status`。

`PUT /api/mijia/home-selection` 接收 `{ accountId, homeId }`，`accountId` 使用最新 `/state.account.id`，`homeId` 使用家庭目录 ID；传 `null` 清除选择。账号会话不匹配时拒绝操作，避免旧页面修改新账号。成功返回完整状态快照，媒体重新绑定的进度由 `binding` 表示。Web 在“设置 → 米家家庭”提供选择和清除入口，选择后立即保存；目录读取失败或没有可选家庭时提供重新获取入口，请求期间禁止重复操作，失败时显示错误并补查后端状态。

选择以区域和米家用户 ID 关联保存在 `mijia_home_selections` 表中，续期、重启和同账号重新登录后保留，退出登录不删除偏好。目录仍由米家云提供，不持久化副本。选择写入失败时保留原范围；选择保存后立即撤销旧读取和媒体代次，媒体通过串行清理与重新绑定接入新范围。清理失败时保持不可播放并暴露媒体错误，不恢复旧范围。所选家庭从目录消失时保留其 ID、标记 `unavailable` 并清空工作设备，不能自动切到其他家庭；该家庭重新可访问后恢复其范围。

设备发现先读取米家家庭／房间目录，再按自有及共享家庭的设备 ID 分批、分页读取详情并合并归属。详情接口未返回的设备不进入设备列表，因此归属记录数量可能大于可显示设备数量。`GET /api/mijia/state` 的设备项包含 `home_id`、`home_name`、`room_id`、`room_name`；无归属信息的字段为 `null`。家庭中未分配房间的设备保留家庭信息，不把家庭名称当成房间。目录读取失败会报告设备读取失败，不发布不完整的新设备快照。归属分页会校验游标和响应，不写入数据库。

`GET /api/mijia/home` 与 `GET /api/mijia/devices/:did/spec` 的成功响应采用 MiLoCo 的 `{ code: 0, message, data }` 结构；错误继续使用本项目公共错误协议。

`/home` 聚合所选家庭的设备及其规格，返回 `home_name`、`devices`、`areas`、`scenes`、`persons`。`areas` 为所选家庭房间目录的 `{ name }` 数组（包括空房间）；设备项包含 `did`、`name`、`home`、`room`、`model`、`online`、`category`、`spec`、`sub_devices`。返回所选家庭的 `home_name`；未选择或所选家庭不可访问时拒绝查询。场景和人员尚未接入，对应数组为空；子设备名称尚未接入，`sub_devices` 为 `null`。这些是当前聚合数据的功能范围限制。目录仍由后台发现及 `POST /devices/refresh` 更新，读取 `/home` 不刷新云端设备目录。

`/devices/:did/spec` 的 `data` 返回 `did`、`name`、`home`、`model`、`room`、`online`、`category`、`spec`。`home`、`room` 为名称，未知时为空字符串。无可用规格时保留设备资料并返回 `category: null`、`spec: {}`；能力定义请求失败或规格格式无效仍报告错误，展示翻译失败不影响已经取得的能力定义。

`spec` 对齐 MiLoCo 的精简规格，以 `prop.<siid>.<piid>`、`action.<siid>.<aiid>` 为键：

- 所有条目包含 `description`、`format`、`writeable`、`readable`、`notify`，以及适用的 `type_name`、`service_type_name`、`service_description`、`prop_description`。
- 属性按规格提供 `unit`、`value_range`、`value_list`，缺失的可选字段省略。枚举项包含 `name`、`value`、`description`。
- 动作的 `format` 为输入参数说明数组的 JSON 字符串；有输入时提供 `in_params: [{ name, format }]`；无输入时省略。动作 `writeable: true`、`readable: false`、`notify: false`。
- `description` 组合服务和属性／动作的中文说明，`prop_description` 保留原始说明。不输出事件、动作输出、类型 URN 或另行设计的 `kind`、实例 ID 字段。与 MiLoCo lite 解析一致，忽略 device-information 服务和非 MIoT 标准命名空间的私有条目。

规格优先使用设备的 `spec_type`，未提供时按型号查询公开 MIoT URN。能力定义与展示翻译分别读取和缓存：翻译请求失败、超时或响应格式无效时，保留已验证的 readable 等能力及规格原文描述；翻译失败不写成功缓存，后续查询可重新获取翻译。一次查询的元数据网络请求共用 30 秒预算，翻译只使用剩余时间；预算在能力取得后耗尽时，停止翻译并返回原文规格，不另起请求。能力尚未取得时的预算超时仍报错；调用方取消、账号撤销或调用方自身期限到达，始终终止整个查询。型号映射、能力定义与成功翻译各缓存 24 小时、最多 128 项，归属当前 MiCloud 实例。账号替换或续期创建新实例后重新获取。未知设备返回 `mijia_device_not_found`，规格网络和解析失败使用独立错误码。公开规格请求不携带账号凭据；设备变化会使在途结果失效。

能力定义不含当前属性值。`notify`、`writeable` 表示规格声明，不表示已接入属性订阅或设备控制。当前未实现 MiLoCo 的本地标准库翻译补充和子设备服务名称覆盖。

## 一次性属性读取

backend 提供 `MijiaService.readProperties(properties, signal)`，由调用方显式指定 `{ did, siid, piid }`。service 取得当前已接纳的 MiCloud 会话，校验设备仍属于所选家庭且属性规格为 readable；请求和返回均重验账号、设备及采集实例。未选择家庭时拒绝读取；切换家庭会取消旧采集实例，不自动选择第一个家庭或所有设备。

规格预检按设备分组，每次最多并发查询 3 台设备。属性读取全部调用共用串行批次，应用预算为每批最多 150 项、单次 HTTP 最长 30 秒，支持取消。逐项只接受本批地址，保留 `-702000000`、`-702010000` 的接受语义，缺失 value 不补 null，普通部分失败保留其他成功项。返回值标记为 `baseline`／`cloud_cache`，`observed_at=null`；`read_started_at` 和 `received_at` 为 UTC RFC3339 毫秒字符串，不能代替设备观测时间。某批认证被拒绝后停止本次后续批次，已取得的成功项与失败观测仍按项返回；后台触发现有会话续期，不重发本次属性请求。若会话替换或退出已使旧采集范围失效，则拒绝旧结果。

属性读取按稳定来源遵守 `Retry-After`：期限内后续批次和新读取均不发请求，返回 `unavailable` 且 `read_started_at=null`，接收时间沿用原失败观测。到期后等待下一次显式读取，不自动重试。账号自动及手动恢复续期同样遵守该期限，超长等待分段调度。

请求复用 MiCloud RC4 传输，`datasource=1` 为缓存优先，缓存缺失可能触发设备 RPC，不保证最新值；统一按 `cloud_cache/baseline` 保守处理。该入口不写家庭状态，不提供属性读取 HTTP 路由或周期属性轮询。`observeDevices(deviceIds, onObservation, signal)` 提供正式内部 MQTT 属性与在线观察，使用同一账号保存的 OAuth 凭据，按所选家庭的明确设备集合订阅，返回取消、状态快照和临时失败重试入口；消息与逐 topic 的订阅确认分别交付。观察不写家庭状态，也未接前端实时展示。自动重连恢复与独立设备事件尚未接入；缓存读取成功不能直接推导属性边沿。字段、失败原因及来源能力矩阵见[读取契约](mijia-source-contract.md#正式读取入口)。

## 支持范围

- 目前支持中国大陆区及局域网 IPv4 摄像头，不支持远程中继或云端部署。
- 使用 WebRTC 接收视频，不提供对讲、设备控制、录制或转码。编码需同时受 go2rtc 与浏览器支持。
- 维护一个米家账号，可并行播放多个摄像头；观看连接与待建立连接合计上限为 32；go2rtc 运行时会话中的摄像头共享流另有 32 路上限，多镜头按通道计数。
- 多镜头展示取决于已实现的设备通道映射，不保证所有型号兼容。
- Docker 网络要求及平台限制见[本地运行](running.md#docker-摄像头网络)。macOS 还需允许运行服务的终端／开发应用访问“本地网络”。

长期运行、云端授权自然轮换及设备离线恢复仍需更多实际环境验证。当前已验证 C700 持续输出 1920×1080 画面，C500 双镜头通过一个物理连接同时输出 848×480 画面；一路观看关闭和重开不影响另一镜头，观看资源及后台会话关闭后的物理连接释放均通过。其他开发实例或米家客户端仍会占用设备连接，不能保证超过设备连接上限时仍可播放。目录离线且未播放的摄像头保持未验证。

## 授权与配置

授权加密存放在 PostgreSQL，密钥默认为 `config/credentials.key`，由 `bun run setup` 创建。可用 `CREDENTIAL_KEY_FILE` 指定其他密钥文件。数据库与密钥应分别备份；恢复授权需要二者匹配。密钥不得提交 Git。

授权恢复失败时，按页面提示重试或清除授权后重新扫码。“退出米家登录”会删除已保存授权并清理连接；正常停止 backend 会保留授权。网络错误不会直接视为授权失效，但授权被拒绝时需重新扫码。

账号授权（`account`）与扫码尝试（`loginAttempt`）独立。已登录账号弹窗只显示账号状态、设备数量和退出操作；更换账号先退出再扫码。没有可用账号时显示登录页，自动获取二维码，并在轮询获知后端报告过期后自动刷新。恢复保存会话期间不创建扫码尝试；请求失败或主动取消后由用户重试，安全验证期间不自动替换二维码。退出后的媒体清理失败会显示错误和重试清理入口，清理成功后再自动获取二维码。

账号会话由唯一所有者恢复和续期。OAuth 保存实例 UUID、access token、refresh token 与过期时间；实例 UUID 为 32 位无连字符十六进制字符串，续期保持不变。账号维护按 MiCloud 与 OAuth 较早的到期时间调度，OAuth 距到期不足 5 分钟时使用 refresh token 续期，和 MiCloud 候选一起保存后接纳。OAuth 被拒绝时要求重新扫码，网络失败沿用账号维护的重试机制。目录与属性读取复用同一 MiCloud 实例，媒体从该账号取得所需凭据；“退出米家登录”删除两类本地凭据并清理目录、读取及媒体，不调用小米云端撤销应用授权接口。当前没有独立属性读取授权、uid 映射或 OAuth 解绑命令。属性传输故障与 go2rtc 故障按各自通路报告，不自动换协议。会话接纳或撤销会更换读取采集代次，并拒绝旧结果。

go2rtc 地址通过 `config/config.yaml` 的 `services.go2rtc.url` 配置。保存地址即表示使用该服务。backend 独立于浏览器每 3 秒检查配置，变更后自动清理旧连接并连接新服务；原实例不可达时，需恢复它以完成旧 go2rtc 运行时会话清理。扫码凭据在运行时生效，不写入 go2rtc YAML，不需要重启。

当前仅供可信本机使用。浏览器通过 backend 访问米家控制接口，通过 WebRTC 从 go2rtc 接收视频；凭据、二维码、设备源地址及 SDP 不进入日志或追踪。不要向公网或不可信局域网暴露管理端口。

## HTTP 与追踪

| 接口                                    | 用途                                                   |
| --------------------------------------- | ------------------------------------------------------ |
| `GET /api/mijia/state`                  | 当前流程、绑定、设备状态                               |
| `GET /api/mijia/homes`                  | 可选家庭及当前选择                                     |
| `PUT /api/mijia/home-selection`         | 保存或清除当前账号的家庭选择                           |
| `GET /api/mijia/home`                   | 家庭设备、房间名称与规格聚合                           |
| `GET /api/mijia/devices/:did/spec`      | 设备属性与动作的 MIoT 精简规格                         |
| `POST /api/mijia/login`                 | 开始独立扫码流程                                       |
| `DELETE /api/mijia/login/:id`           | 取消对应流程                                           |
| `POST /api/mijia/login/:id/verify`      | 提交本次短信或邮件验证码                               |
| `POST /api/mijia/connection/retry`      | 返回 202，按当前状态恢复授权、媒体连接或设备列表       |
| `DELETE /api/mijia/session`             | 删除保存的授权并退出登录                               |
| `POST /api/mijia/devices/refresh`       | 重读设备列表                                           |
| `POST /api/mijia/playback/reservations` | 带当前 `revision` + `deviceId` + `channel` 预留播放 ID |
| `GET /api/mijia/playback/:id`           | 读取预留、协商或已建立状态；已建立时返回原 SDP answer  |
| `PUT /api/mijia/playback/:id`           | 带当前 `revision` 和 SDP offer 激活对应播放            |
| `DELETE /api/mijia/playback/:id`        | 释放对应播放                                           |

`GET /api/mijia/state` 只读取快照，不触发配置协调或媒体维护。`connectionOperation` 表示最近一次显式连接重试：包含 `id`、`createdAt`、`updatedAt`，状态为 `running`、`succeeded`、`failed` 或 `cancelled`，失败时附带公共 `ApiError`。重复提交复用正在进行的操作 ID；完成判定检查账号、媒体连接和设备快照，业务失败不会被标记为成功。开始新的扫码、退出或停止服务会取消当前重试编排，旧任务不能覆盖新操作结果。后台自动维护仍有自己的生命周期。

操作记录只保存在进程内，不提供历史任务列表；新重试替换旧结果，账号替换、成功退出或进程重启清除记录。后台自动恢复后，失败操作的记录保留；账号已登录、媒体绑定与设备快照均就绪时，页面不再将该操作错误显示为当前故障。状态快照响应统一携带 `Retry-After`；202 还携带指向状态查询的 `Location`。前端复用请求模块解析秒数或 HTTP 日期，并按服务端提示轮询（限制为 1–60 秒）。重试连接保留健康连接；刷新设备保持独立。

HTTP 输入复用共享 JSON 读取与 Zod 校验，登录、设备与连接状态使用判别联合，使各状态所需字段明确。错误沿用公共 `AppError` 响应结构，包含静态错误码／文案、安全字段问题及可用的 `traceId`。米家错误使用 `mijia_` 前缀；前端米家、健康状态和连接设置通过同一个 Hono RPC 请求模块调用；路径和输入由后端路由推导，运行时仍使用共享 schema 校验响应。

复用[共享追踪](observability.md)，记录 `mijia.*` 阶段、区域和静态 `error.type`，授权恢复和凭据保存的失败在转换成页面状态前记录。下游调用记录 CLIENT 类型和 HTTP 响应状态；后台心跳与退避使用独立上下文，主动取消不计为故障。无论是否开启内容追踪，米家 Cookie、验证码、token、二维码、原始云响应、源地址及 SDP 都不进入日志或 span；go2rtc 补丁也移除了 Xiaomi 路径的原始 debug/trace 内容。

观看连接采用服务端预留 ID 后提交 SDP 的两阶段创建。预留响应为 201，`Location` 指向可 GET、PUT 和 DELETE 的观看资源。预留不启动媒体，30 秒自动过期，并计入 32 个连接上限；浏览器并行收集 ICE，取得 ID 后即使协商响应丢失也可释放。未知或已释放 ID 的激活被拒绝，因此取消后的迟到激活不能重新创建连接。释放观看连接不停止 go2rtc 中的摄像头共享流和常驻消费者。

同一观看 ID 和媒体代次 `revision` 下，重复 PUT 相同 SDP 会等待同一次协商或返回已保存的 answer，不建立第二个观看者；不同 SDP 返回 `mijia_playback_conflict`（409）。GET 可恢复丢失的协商结果。前端只对该 PUT 的网络错误或超时自动重试一次，复用原参数，并受播放器总协商期限约束。

backend 已接收的播放协商不随浏览器至 backend 的单个 HTTP 连接断开而取消。释放由 DELETE、账号／源失效和服务端 70 秒协商期限控制；成功后由观看连接生命周期及媒体心跳回收。释放、失败或过期后 GET 返回 404，旧 PUT 不会重新创建资源。SDP 结果仅保留在活动观看资源内存中，不写入日志或持久化。

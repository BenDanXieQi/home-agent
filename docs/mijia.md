# 米家与摄像头

完成[快速开始](../README.md#快速开始)后，在 Web 使用米家 App 扫码登录，按提示完成安全验证。授权会加密保存，重启后自动恢复；无需在 go2rtc 再次登录或复制 token。

米家接入以扫码为唯一用户登录入口。backend 复用扫码身份静默完成 Xiaomi Miloco OAuth 授权，不需要再次扫码或打开额外授权页面；登录页说明授予昵称、头像和智能家庭服务权限。MiCloud 与 OAuth 共同构成一个完整接入会话，凭据合并存入同一个 AES-256-GCM 加密的 `mijia` 记录，由同一个账号服务保存、恢复、续期和退出。完整授权和保存成功后才采用新账号；新账号的 OAuth 授权失败只使本次登录失败，不覆盖当前账号。

属性读取直接复用当前 MiCloud 会话，MQTT 消息推送使用同一账号保存的 OAuth 凭据。backend 提供内部接口，分别用于读取属性和订阅设备上报的消息（观察）；适用范围、实机证据和限制见[米家来源契约](contracts/mijia.md)。

账号登录、恢复和续期后，backend 异步读取当前账号昵称与头像，通过公共状态的 `projection.account.account.profile` 返回；公共状态是后台已确认、供页面和内部功能读取的数据。侧栏账号入口和账号弹窗共用这些资料；读取失败不影响授权或设备接入，资料缺失或头像加载失败时显示默认名称或图标。资料只保存在当前账号内存状态中，退出或授权失效后清除。

## 摄像头预览

摄像头页按设备支持的镜头通道显示画面，各画面可独立关闭和重试。标签页可见时，画面进入可视区域及其上下 240 像素范围后建立观看连接；离开该范围或隐藏标签页后释放浏览器连接与解码资源，再次显示时自动连接。手动暂停的画面保持暂停。只有浏览器持续收到并解码新帧才显示播放正常；连接检查成功不代表摄像头已出流。

米家授权可用、已选择家庭并完成 go2rtc 绑定后，backend 根据该家庭的设备列表为摄像头的受支持通道创建共享流；go2rtc 持续连接摄像头并接收视频，无需先打开摄像头页。关闭预览或离开页面只释放网页观看连接，go2rtc 的取流继续运行。官方能力元数据声明为双摄的设备，其两个镜头共用一个 MISS 物理连接，按视频包 `flags` 的高字节分流，各镜头保留独立播放资源；同一运行时会话内的并发首次连接与重连均串行建立一次物理连接。最后一个镜头源释放或账号运行时会话撤销时关闭该连接。多个开发实例各自仍会占用连接，摄像头连接上限不会因本机共享而消失。设备清单在线标记只用于诊断；是否可播放由实际媒体连接和出帧决定。

## 组件与资源

backend 管理账号授权、设备列表、取流生命周期和播放信令；go2rtc 接收摄像头视频并通过 WebRTC 分发给浏览器；浏览器解码并显示画面。摄像头共享流和观看连接的管理请求，以及协商音视频连接所需的 SDP 数据，由 backend 发送给 go2rtc，预览视频包沿“摄像头 → go2rtc → 浏览器”传输，不经过 backend；[本地感知](perception.md)另使用私有分析分支，由 backend 计算子进程读取并解码。本项目的 Go 扩展编译在 go2rtc 内，原生与 Docker 模式运行的是同一套媒体实现。

| 名称                    | 含义与归属                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| 保存的米家授权          | PostgreSQL 中同一记录保存的 MiCloud 与 OAuth 加密材料，由 backend 统一保存、恢复和删除                         |
| 米家账号会话            | backend 接纳的完整 MiCloud 与 OAuth 会话；MiCloud 实例持有扫码云凭据、Cookie 和设备请求状态                    |
| 属性读取采集实例        | 当前 MiCloud 会话的读取范围及 `collection_generation`，会话替换或撤销时使旧读取失效                            |
| go2rtc 运行时会话       | backend 通过内部 `session` 接口建立，以 `sessionId` 标识，持有内存凭据及本项目的媒体资源，通过心跳续租         |
| 摄像头共享流            | go2rtc 中每个设备通道的私有流，以 `sourceId` 标识；backend 管理其注册、重试与释放                              |
| 常驻消费者              | go2rtc 内附着于共享流的内部消费者，维持取流并监测收包活跃度，不解码、保存视频或执行模型推理                    |
| 网页观看连接            | 附着于同一共享流的独立 WebRTC 消费者，以 `playbackId` 标识；backend 同时维护其预留与协商记录                   |
| 媒体运行标识 `revision` | backend 当前媒体生命周期的标识，媒体失效或重新绑定时更换，用于拒绝旧播放请求；不是配置版本号或 go2rtc 构建版本 |

“共享”指同一通道的常驻消费者与网页观看者复用媒体流；“常驻”指取流独立于网页观看连接，仍受 go2rtc 运行时会话和摄像头资源生命周期约束。共享流只存在于 go2rtc 内存，不写入 YAML 或全局流注册表。

服务接口可达、米家账号可用、go2rtc 绑定就绪、共享流注册成功和网页出帧是不同状态。`binding.status = ready` 表示运行时凭据安装成功；`PUT camera` 返回 204 表示私有流已创建并启动异步取流，不保证已经收到视频包。播放资源的 `active` 表示 SDP 协商完成，只有浏览器持续收到并显示新帧才算画面正常。

## 资源释放

| 操作或事件                   | 保存的授权 | 摄像头共享流与观看连接                                                           |
| ---------------------------- | ---------- | -------------------------------------------------------------------------------- |
| 关闭一路预览或离开摄像头页   | 保留       | 释放对应网页观看连接，共享流和常驻消费者继续运行                                 |
| 画面远离可视区域或隐藏标签页 | 保留       | 释放对应网页观看连接；再次显示时按原播放选择重新连接，共享流和常驻消费者继续运行 |
| 正常停止 backend             | 保留       | 请求删除 go2rtc 运行时会话，释放其共享流和观看连接                               |
| 成功退出米家登录             | 删除       | 先删除保存的授权，再撤销当前媒体并请求清理运行时会话；授权删除失败不报告退出成功 |
| backend 意外退出或无法续租   | 保留       | go2rtc 在运行时会话租约过期后清理其凭据、共享流和观看连接                        |
| 通道移除或地址／型号变化     | 保留       | 释放对应共享流及其观看连接；需要时为新通道规格重新注册                           |

backend 每 15 秒发送心跳，go2rtc 每次成功续租后保留 60 秒租约，并每 5 秒检查过期会话。正常关闭或退出时若清理请求失败，也由停止续租后的过期清理兜底；清理不是在断线瞬间完成。go2rtc 的租约过期不删除数据库授权，也不代表小米账号凭据已经失效。

go2rtc 独立监测视频包并处理取流恢复，浏览器独立检测可见画面的首帧和停滞。设备清单的在线字段不会单独阻止播放或撤销已有观看。

## 家庭、房间与设备能力

家庭选择是后端统一工作范围，覆盖设备清单、规格、属性读取／订阅和摄像头。设备清单包含家庭、房间、设备及其归属，代码字段名为 `directory`；设备规格描述支持的属性、动作和事件，不包含当前属性值。`household/` 的 XState 运行时随 backend 启动；无浏览器打开时也维护账号、设备清单和媒体。业务状态为 `unbound`、`waiting_for_home`、`initializing`、`running`、`stopping`，详情见[家庭运行时](household-runtime.md)。

一个部署绑定一个账号，同时只服务一个家庭。设置页通过 `GET /api/mijia/setup/homes` 读取候选，通过 `PUT /api/mijia/scope/homes` 保存非空家庭 ID；首次只有一个家庭时自动保存后采用。已有绑定时可在设置中确认重新绑定同一账号下的其他家庭；异账号登录被拒绝，退出保留绑定。重新绑定先可靠保存，再撤销旧运行并初始化新家庭，详见[重新绑定家庭](household-runtime.md#重新绑定家庭)。

`scope_epoch` 隔离重启、授权失效和新登录会话的旧任务。同账号续期保留家庭运行身份。启动可以显示缓存，但完整云端清单确认并提交后才允许设备访问。缓存读取或保存失败显示 `storage_degraded`，不阻挡首次运行和新设备生效。

`DeviceDiscovery` 每五分钟及结构变化通知后同步设备清单。完整清单确认的移除、转出或定义变化撤销对应旧读取、订阅与播放；普通云端刷新失败保留当前已确认设备。缓存事务最多五秒，后续后台或手动刷新重试保存当前完整清单，不累积已移除条目。

`POST /api/mijia/devices/refresh` 接收 `{ scope_epoch, target }`，`target` 为 `directory`、`specs` 或 `all`。请求被接受时返回 202 和当前 `state_version`；完成情况通过状态订阅通知，过期的 `scope_epoch` 返回 409。页面筛选不改变后台家庭范围。家庭、房间、设备及规格摘要统一通过 SSE（服务端持续推送事件的 HTTP 连接）接收公共状态，普通查询不触发云端请求。

后台按含版本的规格唯一标识 URN 共享能力资料；未提供 URN 时先按型号解析。规格并发上限 3，短暂故障额外按 2 秒、10 秒重试两次，单台失败不阻塞家庭。相同设备清单和同账号续期复用规格；设备移除或授权失效释放不再引用的资料。显式规格刷新按最终 URN 合并正在执行的任务，不被其他规格组阻止；失败保留已有能力并显示错误；规格不按时间过期。规格来源不支持的型号显示未就绪，不伪造空能力成功。

`spec` 对齐 MiLoCo 的精简规格，以 `prop.<siid>.<piid>`、`action.<siid>.<aiid>`、`event.<siid>.<eiid>` 为键：

- 所有条目包含 `description`、`format`、`writeable`、`readable`、`notify`，以及适用的 `type_name`、`service_type_name`、`service_description`、`prop_description`。
- 属性按规格提供 `unit`、`value_range`、`value_list`，缺失的可选字段省略。枚举项包含 `name`、`value`、`description`。
- 动作的 `format` 为输入参数说明数组的 JSON 字符串；有输入时提供 `in_params: [{ name, format }]`；无输入时省略。动作 `writeable: true`、`readable: false`、`notify: false`。
- `description` 组合服务和属性／动作的中文说明，`prop_description` 保留原始说明。事件保留事件 ID 和参数描述；这不表示已接入事件推送。规格实体另保留 URN 和版本，不输出动作输出。与 MiLoCo lite 解析一致，忽略 device-information 服务和非 MIoT 标准命名空间的私有条目。

规格优先使用设备的 `spec_type`，缺失时按型号查询公开 MIoT URN。协议适配只获取和解析资料，缓存归家庭模块；翻译失败不丢弃已取得的能力定义。单次响应、设备清单和后端规格分别有独立大小上限，完整规格不进入公共快照。设备保留 `category` 并派生 readable、writeable、notify、action、event 能力标签。

能力定义不含当前属性值。`notify`、`writeable` 表示规格声明，不表示已接入属性订阅或设备控制。当前未实现 MiLoCo 的本地标准库翻译补充和子设备服务名称覆盖。

## 一次性属性读取

backend 提供内部 `MijiaService.readProperties(properties, signal)` 读取指定属性，以及 `observeDevices(deviceIds, onObservation, signal)` 观察属性和在线消息。它们共用已接纳账号与家庭范围，独立设备事件尚未接入。

读取返回云缓存性质的观测，不保证最新值；观察已用于[限时上报日志](household-runtime.md#设备上报日志)，尚未提交家庭当前属性值或持续采集状态。当前没有属性读取 HTTP 路由或周期属性轮询，设备规格声明不等于已启用采集。

字段、批次、取消、限流和恢复语义统一见[正式读取入口](contracts/mijia.md#正式读取入口)及[正式推送入口](contracts/mijia.md#正式推送入口)，不在使用说明重复定义来源契约。

## 支持范围

- 目前支持中国大陆区及局域网 IPv4 摄像头，不支持远程中继或云端部署。
- 使用 WebRTC 接收视频，不提供对讲、设备控制、录制或转码。编码需同时受 go2rtc 与浏览器支持。
- 维护一个米家账号，可并行播放多个摄像头；观看连接、待建立连接与尚未确认清理的观看资源合计上限为 32；go2rtc 运行时会话中的摄像头共享流另有 32 路上限，多镜头按通道计数。
- 多镜头展示取决于已实现的设备通道映射，不保证所有型号兼容。
- Docker 网络要求及平台限制见[本地运行](running.md#docker-摄像头网络)。macOS 还需允许运行服务的终端／开发应用访问“本地网络”。

长期运行、云端授权自然轮换及设备离线恢复仍需更多实际环境验证。当前已验证 C700 持续输出 1920×1080 画面，C500 双镜头通过一个物理连接同时输出 848×480 画面；一路观看关闭和重开不影响另一镜头，观看资源及后台会话关闭后的物理连接释放均通过。其他开发实例或米家客户端仍会占用设备连接，不能保证超过设备连接上限时仍可播放。设备清单标记离线的摄像头不预先禁止连接，具体型号仍以实际出帧为准。

## 授权与配置

授权加密存放在 PostgreSQL，密钥默认为 `config/credentials.key`，由 `bun run setup` 创建。可用 `CREDENTIAL_KEY_FILE` 指定其他密钥文件。数据库与密钥应分别备份；恢复授权需要二者匹配。密钥不得提交 Git。

恢复保存授权时，backend 先准备并验证完整会话，再统一保存和接纳。认证失败进入 `reauth_required`，需重新扫码；网络或限流失败进入可重试的恢复错误状态，不直接认定授权失效。“退出米家登录”会删除已保存授权并清理连接；正常停止 backend 会保留授权。

账号或家庭的媒体资格撤销时，立即停止旧会话心跳并撤销本地观看；远端清理失败独立退避重试，不依赖新家庭就绪或新账号接纳。

账号授权（`account`）与扫码尝试（`login`）独立。已登录账号弹窗只显示账号状态、设备数量和退出操作；更换账号先退出再扫码。没有可用账号时显示登录页，自动获取二维码，并在订阅获知后端报告过期后自动刷新。恢复保存会话期间不创建扫码尝试；请求失败或主动取消后由用户重试，安全验证期间不自动替换二维码。退出后的媒体清理失败会显示错误和重试清理入口，清理成功后再自动获取二维码。

账号维护按 MiCloud 与 OAuth 较早的到期时间调度。OAuth 距到期不足 5 分钟时使用 refresh token 续期，与准备好的新 MiCloud 会话一起保存成功后采用；OAuth 保存实例 UUID、access token、refresh token 与过期时间；实例 UUID 为 32 位无连字符十六进制字符串，在续期时保持不变。MQTT 连接认证拒绝先交给账号维护强制刷新被拒绝的 token，刷新成功后恢复观察连接。普通网络、限流或单 topic 权限拒绝不直接撤销整个账号；已应用到家庭状态、且未被撤销的设备清单仍允许属性读取和新建消息订阅。恢复和续期重试遵守 `Retry-After`，topic 拒绝按订阅状态单独报告。

已接纳会话的续期最终返回认证失败时，整个账号进入 `reauth_required`，撤销设备清单、在途读取、MQTT 观察及媒体访问，并请求清理 go2rtc 资源；即使 MiCloud 单独仍可用，也不保留部分接入会话。该失效处理保留数据库授权记录，重新登录可替换它，退出登录才删除它。设备清单与属性读取使用同一 MiCloud 实例，媒体从该账号取得所需凭据；当前没有独立属性授权、uid 映射或 OAuth 解绑命令，也不调用小米云端撤销应用授权接口。属性传输和 go2rtc 故障按各自通路报告，不自动换协议；会话接纳或撤销使旧读取结果失效。

go2rtc 地址通过 `config/config.yaml` 的 `services.go2rtc.url` 配置。保存地址即表示使用该服务。backend 独立于浏览器每 3 秒检查配置，变更后自动清理旧连接并连接新服务；原实例不可达时，需恢复它以完成旧 go2rtc 运行时会话清理。扫码凭据在运行时生效，不写入 go2rtc YAML，不需要重启。

当前仅供可信本机使用。浏览器通过 backend 访问米家控制接口，通过 WebRTC 从 go2rtc 接收视频；凭据、二维码、设备源地址及 SDP 不进入日志或追踪。不要向公网或不可信局域网暴露管理端口。

## HTTP 与追踪

| 接口                                    | 用途                                                                   |
| --------------------------------------- | ---------------------------------------------------------------------- |
| `GET /api/mijia/state`                  | 已提交公共快照，仅供诊断                                               |
| `GET /api/mijia/events`                 | 家庭公共状态 SSE                                                       |
| `PUT /api/mijia/scope/homes`            | 带 `scope_epoch` 保存家庭选择                                          |
| `GET /api/mijia/login/:id/material`     | 按需读取本次有效登录材料                                               |
| `POST /api/mijia/login`                 | 开始独立扫码流程                                                       |
| `DELETE /api/mijia/login/:id`           | 取消对应流程                                                           |
| `POST /api/mijia/login/:id/verify`      | 提交本次短信或邮件验证码                                               |
| `POST /api/mijia/connection/retry`      | 返回 202，按当前状态恢复授权、媒体连接或设备列表                       |
| `DELETE /api/mijia/session`             | 删除保存的授权并退出登录                                               |
| `POST /api/mijia/devices/refresh`       | 重读设备列表                                                           |
| `POST /api/mijia/playback/reservations` | 带当前 `scope_epoch` + `revision` + `deviceId` + `channel` 预留播放 ID |
| `GET /api/mijia/playback/:id`           | 读取预留、协商或已建立状态；已建立时返回原 SDP answer                  |
| `PUT /api/mijia/playback/:id`           | 带当前 `revision` 和 SDP offer 激活对应播放                            |
| `DELETE /api/mijia/playback/:id`        | 释放对应播放                                                           |

`GET /api/mijia/state` 只读取快照，不触发配置协调或媒体维护。`connectionOperation` 表示最近一次显式连接重试：包含 `id`、`createdAt`、`updatedAt`，状态为 `running`、`succeeded`、`failed` 或 `cancelled`，失败时附带公共 `ApiError`。重复提交复用正在进行的操作 ID；完成判定检查账号、媒体连接和设备快照，业务失败不会被标记为成功。开始新的扫码、退出或停止服务会取消当前重试编排，旧任务不能覆盖新操作结果。后台自动维护仍有自己的生命周期。

操作记录只保存在进程内，不提供历史任务列表；新重试替换旧结果，账号替换、成功退出或进程重启清除记录。后台自动恢复后，失败操作的记录保留；账号已登录、媒体绑定与设备快照均就绪时，页面不再将该操作错误显示为当前故障。账号命令响应只返回 `state_version`，页面不把命令响应写入状态。页面通过同一 SSE 订阅接收快照和连续版本变化；登录公共状态不包含二维码或验证地址，材料由独立接口按 `id/material_version` 读取。重试连接保留健康连接；刷新设备保持独立。

HTTP 输入复用共享 JSON 读取与 Zod 校验，登录、设备与连接状态使用判别联合，使各状态所需字段明确。错误沿用公共 `AppError` 响应结构，包含静态错误码／文案、安全字段问题及可用的 `traceId`。米家错误使用 `mijia_` 前缀；前端米家、健康状态和连接设置通过同一个 Hono RPC 请求模块调用；路径和输入由后端路由推导，运行时仍使用共享 schema 校验响应。

复用[共享追踪](../packages/observability/README.md)，记录 `mijia.*` 阶段、区域和静态 `error.type`，授权恢复和凭据保存的失败在转换成页面状态前记录。下游调用记录 CLIENT 类型和 HTTP 响应状态；后台心跳与退避使用独立上下文，主动取消不计为故障。无论是否开启内容追踪，米家 Cookie、验证码、token、二维码、原始云响应、源地址及 SDP 都不进入日志或 span；go2rtc 补丁也移除了 Xiaomi 路径的原始 debug/trace 内容。

观看连接采用服务端预留 ID 后提交 SDP 的两阶段创建。预留响应为 201，`Location` 指向可 GET、PUT 和 DELETE 的观看资源。预留不启动媒体，30 秒自动过期，并计入 32 个连接上限；浏览器并行收集 ICE，取得 ID 后即使协商响应丢失也可释放。未知或已释放 ID 的激活被拒绝，因此取消后的迟到激活不能重新创建连接。释放观看连接不停止 go2rtc 中的摄像头共享流和常驻消费者。

同一观看 ID 和媒体运行标识 `revision` 下，重复 PUT 相同 SDP 会等待同一次协商或返回已保存的 answer，不建立第二个观看者；不同 SDP 返回 `mijia_playback_conflict`（409）。GET 可恢复丢失的协商结果。前端对该 PUT 的网络错误或超时自动重试一次，复用原参数，并受播放器总协商期限约束。

backend 已接收的播放协商不随浏览器至 backend 的单个 HTTP 连接断开而取消。释放由 DELETE、账号／源失效和服务端 70 秒协商期限控制；成功后由观看连接生命周期及媒体心跳回收。释放、失败或过期后 GET 返回 404，旧 PUT 不会重新创建资源。远端删除未确认时保留待清理记录，并发 DELETE 合并；失败后可再次 DELETE，成功媒体心跳也会重试，整段媒体会话删除确认后清除对应记录。SDP 结果仅保留在活动观看资源内存中，不写入日志、文件或数据库。

播放连接响应一次返回 `id`、SDP `sdp` 和 `connection`。`connection.sourceRecentlyActive` 表示观看开始时常驻视频源最近 30 秒内收到过视频包；它不是设备清单的在线状态，也不保证浏览器可以解码。`connection.timings` 包含后端 `prepareMs`、`negotiationMs`，以及可取得的 go2rtc `queueMs`、`sourceMs`、`answerMs`，单位为毫秒。续租和视频源准备并行执行，两者成功且会话仍有效后才建立观看连接。遥测缺失或异常不使有效媒体答案失败，此时源活动状态为 `null`。

浏览器从开始连接计时，用 `requestVideoFrameCallback` 确认首次显示画面。应用 answer 前显示“连接中”，应用后显示“等待画面”；这些状态来自当前播放会话，不请求额外的进度接口。首帧耗时与历史样本直接在浏览器记录，不上报后端。后端记录协商及释放诊断，go2rtc 记录排队、源连接和 answer 生成耗时。连接诊断共享播放 ID 的 SHA-256 摘要前 16 位 `attempt_id`；后端同时记录 `trace_id`，这些诊断不输出原始播放 ID、设备名称、画面、凭据或 SDP。

预估历史保存在当前浏览器、当前站点的 `localStorage`，刷新或关闭后重新打开仍可复用。每组最多 30 次成功记录，页面缓存最多 128 组，有效期 24 小时。按摄像头、通道和源活动状态分组，后端重启产生的新运行标识不会使同一摄像头的历史失去用途。每次成功只保存受影响的一组，页面只在首次使用时读取历史，不订阅其他标签页的变化。同组并发写入以最后一次保存为准；预估样本允许少量遗漏，不作为需要强一致性的业务状态。

收到连接响应后，浏览器使用其中的源状态选择本地历史。至少 5 个可比样本仍未到达首帧时，显示这些样本剩余等待时间的第 25 至第 90 百分位范围；样本不足或源状态未知时只显示已经等待的时间。范围会随当前等待时间更新，超时阈值不作为预估。首帧可能先于应用 answer 的 Promise 完成，此时首帧等待记为零。不可见期间完成的连接不参与学习。

样本保存浏览器可提供的连接类型与速度等级，重新打开页面时仅载入与当前提示一致的记录。当前页面的在线／离线事件以及这些提示的变化会使该页面已载入的历史失效；变化前启动的连接不写入新样本。普通带宽、往返延迟波动不清空历史。浏览器不提供网络提示时仍按未知环境复用历史；网络提示相同也不能证明实际网络相同，因此无法识别所有局域网、移动网络或 VPN 路径变化，预估可能超出范围。

可见播放在首帧前失败或超时，会清除该摄像头、通道和源活动状态的历史；源状态尚未知时清除该通道两种源状态的历史。之后重新积累至少 5 个可比成功样本才显示预估。主动停止、浏览器能力不足、自动播放受限、可见性中断及首帧后的故障不触发这项清理。失败不作为成功耗时样本，预估范围也不表示播放成功率。

记录只包含标识、粗略网络提示与耗时，不保存画面、SDP 或凭据；存储失败时保留本页内存记录，不影响播放，后续成功播放会再次尝试保存。状态栏仅在可见且等待首帧时逐秒更新，已播放画面不受预估计时驱动。

## 设备清单主动更新

设备清单通过 MQTT 变更通知和每 5 分钟的后台发现保持更新。绑定／解绑、改名和换房通知合并后触发完整同步，不直接修改设备清单字段。订阅范围、生命周期及诊断入口见[家庭运行时](household-runtime.md#设备清单与规格)。

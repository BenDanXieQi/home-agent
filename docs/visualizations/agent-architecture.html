src/main.ts

打开文件 ↗

管理进程资源、启动 HTTP，并等待退出信号。

何时使用
Bun 进程入口。
谁持有状态
createProcessLifecycle 拥有退出信号、计时器与 processResources。
依赖 / 调用
loadConfig → createProcessLifecycle → createApp → serve → waitForShutdown。
  • AsyncDisposableStack 是原生异步资源清理栈，按登记逆序等待释放；main 用 await using 接管生命周期对象。
  • 退出依次释放 HTTP → app → Pi 提供方会话资源 → telemetry；应用内部依次释放 receiver → workflows → assistant。
  • 首次信号启动默认 10 秒退出预算；装配返回失败后的进程清理也受预算约束。没有退出信号时，工厂内部初始化失败回收发生在装配返回前，不受此计时约束。
  • HTTP stop() 等待在途请求；预算耗尽记录错误并 process.exit(1)。重复信号不延长预算，同步阻塞会延迟计时器。

判断一段语音转写是否需要助手回应、是否表达完整。

何时使用
由 Backend 语音收件箱通过 /api/workflows 调用
谁持有状态
模型调用由 Agent 执行；片段期限、限流与状态由 Backend 管理。
依赖 / 调用
validSpeechDialogueRequest → completeStructuredOutput → speechDecisionSchema。
  • 不使用聊天主会话，不执行设备操作。
  • 输入和输出复用共享 speech-dialogue 契约；只把文字、切段边界和相对时间发给模型。

函数、方法与关键回调

createWorkflow({ modelCatalog, modelRef, budget })

根据注入的模型引用创建语音判断实例。

输入

共享模型清单、注入的 modelRef 与执行预算。

输出 / 结果

{run}；缺少可用模型时返回 {run: undefined}。

通过 modelCatalog.resolve(modelRef) 取得可用模型并创建 run；提示词要求通过 interpret_speech 提交一次结构化结果，区分助手请求、普通聊天、媒体内容和不确定情况。

run(input, signal)

检查片段期限与前文关系，组合信号并以 withEvaluation 调用 interpretSpeech。

输入

speechDialogueRequestSchema 与取消信号。

输出 / 结果

{id, observationId, decision}。

调用同时受应用执行预算和材料 expiresAt 约束；输出预算取应用配置与模型容量的较小值。结果必须只有一个 interpret_speech 工具调用，needsResponse / isComplete / requestText 必须一致。

segmentContext(observation)

将转写片段转换成模型需要的文字与时间关系。

输入

当前片段或同源前文。

输出 / 结果

text、boundary、相对当前片段开始的 startOffsetMs/endOffsetMs。

不向模型发送设备身份或音频模型指纹；相对时间不证明前后文字来自同一说话人。

interpretSpeech(input, requestSignal)

执行结构化判断并校验返回决策。

输入

转写证据与包含材料期限的取消信号。

输出 / 结果

{id, observationId, decision}。

segmentContext 组织相对时间；只接受一个 interpret_speech 调用，经共享 schema 校验后记录评测输出。

为每个规划会话创建独立 Harness，根据文字、图片及现有草稿持续规划空间和通道。

何时使用
workflow 装配后，通过 start/message/read/close 使用。
谁持有状态
sessions 保存每个 session_id 的 scope、Harness、Conversation 与关闭函数；SpatialPlanningDoc 属于该会话。
依赖 / 调用
defineDoc / section / defineTool → startSession → Harness.open / createConversation → submit / wait；retainScope 释放失效家庭会话。
  • start/read 不请求模型；图片必须是合法 JPEG/PNG/WebP base64，所选模型需支持 image。
  • 每个会话独立运行；同一会话忙碌时拒绝第二次 message，不创建跨会话单执行名额。
  • 只产生可审阅草稿，保存业务空间资料由 Backend 负责。会话、对话和草稿使用 MemoryStorage，重启后丢失。
  • 请求 scope 必须与会话及已保留家庭范围一致；家庭切换、关闭单会话或退出都会关闭对应 Harness 和会话资源。
  • 关闭后从 sessions 移除会话，管理器不保留该 Harness 和 MemoryStorage 引用。正常页面退出会请求 close；整页强制关闭、网络中断或创建回执丢失时仍可能留下会话，直到显式关闭、家庭范围变化或进程退出。

几个容易混淆的技术词

Harness
pi-durable 的运行器实例，组织会话、模型调用和工具任务。
root
这个 Harness 的主会话句柄。每条聊天消息提交到同一个 root。
Submission
一次已接纳输入的记录与操作句柄，可以等待结果或撤回尚在队列中的输入。
inbox
框架保存待处理输入的队列；follow-up 表示当前工作回答后再接着处理。
Context
Chord 的调用上下文，携带取消信号。它不是家庭资料快照，也不是模型消息列表。
scope
当前账号、家庭及运行标识，用来检查资料是否仍属于本次允许读取的范围。
schema
数据结构与约束定义。Zod 在运行时按它校验输入和响应，TypeScript 可从中推导类型。
span
一段操作的追踪记录，保存开始/结束、耗时和错误，便于关联一次请求中的各步骤。

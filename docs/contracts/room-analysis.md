# 房间 AI 上下文

设备页 `/devices` 选中具体房间后的 AI 近况只展示最近采纳的观测描述和无法确认的事项。例如将开关报告表达为“照明关闭、净化器开启”，不展示设备读数、百分比、型号、标识符、布尔字面量或内部字段，也不把行为原因和场景猜测混入观测。报告是否可能滞后、当前是否有人等不确定性仍用自然语言保留。

脱敏作用于 AI 卡片的展示文字。Agent 和 backend 校验输出文字及证据引用；数字、英文／代码形式的内容和中文数量／单位表达未通过检查时，结果不采纳。页面展示前也做同样校验，不直接显示未通过检查的文字。证据 ID 和当次上下文保留在后台分析状态中供校验，卡片不展开原始证据值。分析时间、模型、耗时、token 用量和触发状态收在“分析信息”中。

设备原始状态仍可在页面下方查看；模型输入、后台上下文和本机接口仍包含原始观测，此展示规则不改变采集和模型分析所用的数据。只有数值、没有明确定义的语义等级时，描述省略该读数，不擅自改写成“舒适”“空气良好”或“安全”。设备详情的“仅显示开启的设备”只影响列表，分析输入保留相关属性的 false、0 和关闭状态。

## 启用

在根目录 `.env` 配置 `AGENT_MODEL`、`OPENAI_API_KEY`，使用 OpenAI 兼容服务时配置 `OPENAI_BASE_URL`，然后重启 Agent。模型须支持 `strict` 工具调用形式的结构化输出；不支持时显示失败，不自动换用其他输出方式或模型。

使用支持 `thinking.type` 的服务（如 MiMo）时，可设置 `AGENT_THINKING=disabled`，避免简单房间总结消耗额外推理时间和输出预算；也可设为 `enabled`。未设置时不发送该参数，采用服务自身默认值。此配置同时作用于房间总结和普通对话。

点击“分析当前房间”提交一次任务。初始化读值和待确认报告可以参与手动分析，模型必须保留缓存、采样时间未知及有效期未确认等限制。没有可用的相关属性时由代码返回证据不足，不调用模型。缺配置、连接失败、输出校验失败也会在卡片中显示，后台保留本次准备的上下文。

自动分析另有事实前提：原生属性必须匹配触发策略，且已通过 `config/collection.json` 的来源、有效期与 `rule_eligible` 配置，连续两次有效实时报告形成可信变化。配置含义见[设备事实](device-facts.md#本机策略)。没有已验证策略时仍持续采集，但不会自动把待确认值当作行为事件；首次读到“有人”也不会触发“刚进入”。

## 确定性筛选

`room-analysis/context.ts` 集中定义原生属性选择和版本。开关、工作状态、模式、占用、门、窗帘位置及喂食状态等离散属性按变化筛选；无关遥测、同值、初始化缓存、重放、断线、过期及不符合规格的值不能生成触发事件。独立设备事件和视觉到访尚未接通。

数值按原生类型和单位匹配，与上次触发基线累计比较；同值和低于阈值的报告不进入触发变化，达到阈值（含等于）才进入。尚未触发时保留基线，例如温度从 26℃ 逐次上升到 26.2℃、26.6℃ 不触发，到 27℃ 时触发，避免漏掉缓慢升温。断线、有效性中断或来源／规格／策略改变时清除基线。

| 属性           | 变化阈值 | 单位       |
| -------------- | -------- | ---------- |
| 温度、目标温度 | 1        | celsius    |
| 相对湿度       | 5        | percentage |
| 照度           | 30       | lux        |
| 亮度           | 10       | percentage |
| 色温           | 300      | kelvin     |
| PM2.5          | 15       | μg/m3      |
| CO₂            | 100      | ppm        |

这套阈值同时用于筛选分析触发、校验运行中结果和判断总结是否过期。开关、门、占用、模式等离散状态变化不使用数值容差；未知单位或值类型不匹配也不按噪声忽略。这些是当前初始筛选阈值，不代表每个型号已经完成来源验证，也没有隐含灯光、睡眠或投喂规则。

候选变化合并 1.5 秒，合并等待最长 5 秒；同房间任务开始至少间隔 30 秒，冷却期间保留待处理变化。一个房间同时最多一个任务，全局并发 2 个。变化保留顺序和实际前后值；超过 20 条会裁减并标明不完整，不能据此计算完整到访次数。排队时只保留变化，开始执行才重新读取房间；超过 60 秒或依据已失效的变化不再作为触发。属性失效、来源或规格变化时撤销其排队变化，连接恢复后的新基线不会重新激活旧变化。

## 上下文与接纳

事实仍由 `HouseholdRuntime` 单独维护，`RoomAnalysisService` 负责分析任务和当前总结，不反向修改设备值。同值和小幅波动仍更新原始设备快照，过滤只决定是否值得重新分析。上下文从同一提交快照选取相关原生属性，每个设备属性只保留一个最新值，附设备名、枚举说明、单位、观测与收到时间、有效性和证据 ID；变化列表仅包含筛选后的可信变化，不发送完整规格或全量 MQTT 日志。稳定的灯开关、门状态仍作为背景保留一次，不因没有变化而删除。缺值和裁减以覆盖信息说明。

每次最多取房间前 2,000 项属性，送入模型最多 64 项观测、20 条变化、24 KiB；输出最多 12 KiB、模型输出上限 1,800 tokens。最多维护 50 个房间的分析状态，待处理变化总计不超过 512 KiB。单次执行最多 90 秒，不自动重试失败模型请求。任务不阻塞事实提交和现有自动化。

Agent 使用独立的一次性 LangGraph 图，将设备资料作为数据，输出带证据引用的观测描述和未知项，不提供设备操作工具。Agent 和 backend 都校验结构、展示文字与引用；backend 还检查家庭范围、房间相关事实和证据有效期。结果接纳和总结有效性均以开始分析时的相关属性值为固定基线，不随同值或小幅报告移动基线。相对基线的累计差值达到阈值、离散状态改变或证据条件改变时，返回结果不覆盖当前总结；其他房间变化不影响本次分析。同值续报和低于阈值的波动不会让运行中的结果作废，也不会让已采纳总结反复过期。

已采纳总结在相关重要变化、设备资料或证据有效性变化后标为过期，最迟在上下文形成 10 分钟后失效；这是有效性上限，不是定时总结。质量变差、来源切换、规格变化、设备离线及证据到期不受数值阈值保护。属性是否到期由家庭运行时按持续收到的报告维护，不使用输入快照中的旧截止时间重复判定；同值续报不延长总结自身的十分钟上限。运行中曾发生依据失效或重要变化，即使返回前恢复原值，也不采纳该次结果。到期只标记失效，不唤醒模型。总结仍引用生成时的观测值和时间，不把小幅变化后的最新值冒充模型当时的依据。校验通过也不等于推测客观正确；人物身份、睡眠、宠物位置等没有证据时保持未知。

当前总结、上下文与任务只保存在后台内存；后台重启、退出家庭或访问撤销后清空并取消任务，不写入设备历史或 Agent 对话检查点。没有长期人物画像、活动记录、历史问答、持久任务恢复或真实设备控制。

## 接口与展示同步

以下 backend 接口接受 `{ scope_epoch, room_id }`，`room_id=null` 表示未分配房间，沿用本机访问限制和家庭范围检查。

| 接口                              | 行为                                                       |
| --------------------------------- | ---------------------------------------------------------- |
| `POST /api/rooms/analysis/query`  | 只读获取房间分析状态，不触发模型                           |
| `POST /api/rooms/analysis/run`    | 接受一次分析请求，返回 202；运行中的重复请求合并           |
| `POST /api/rooms/analysis/events` | SSE 发送所选房间的当前分析状态；重连补当前值，不补历史事件 |

分析 SSE 最多 8 个连接，慢客户端只保留最新状态，写出超过 15 秒断开；心跳 15 秒，浏览器超过 45 秒无消息后重新同步。切换房间和退出页面关闭该订阅，不取消独立运行的后台分析。设备事实继续使用现有家庭 SSE。断开期间保留旧总结并显示等待同步。

backend 向 Agent 的 `POST /api/room-analysis` 发送 `{ run_id, context }`。该接口不要求对话数据库，单进程并发上限 2；模型内容是否进入追踪由已有 `OTEL_INCLUDE_CONTENT` 控制。普通聊天通过四个只读工具查询家庭概览、设备清单、状态和成员资料，见 [Agent 家庭查询工具](../../apps/agent/README.md#家庭查询工具)；房间分析仍使用独立的一次性图。

真实模型推断质量、可信属性触发和运行期间断线／撤销等分支需要在相应模型与实机来源环境下验收；静态检查或缺配置提示不能代替这些验证。

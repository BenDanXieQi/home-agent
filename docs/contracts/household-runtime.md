# 家庭运行时：功能与业务行为

本文按业务规则、运行资格、故障范围和组合场景说明家庭运行时的功能约束，供核对需求、设计验证和评审行为使用。规则描述系统对外提供的结果，不以某个类、函数、状态机库或数据库实现作为成立依据。

家庭运行时负责三件事：可靠保存本实例唯一的家庭绑定；后台维护该家庭的设备清单和规格；向页面提供已确认的运行状态。操作说明与实现边界见[家庭运行时](../household-runtime.md)，接入通路的失败范围见[米家来源契约](mijia.md#失败范围)。实机证据与未验证范围统一见[验证范围](../household-runtime.md#验证范围)，本文列出的规则和场景本身不代表已经验证通过。

导航：[业务边界](#业务边界) · [功能规则](#功能规则) · [组合场景](#组合场景与结果判定) · [证据边界](#证据与适用边界)。

## 业务边界

本契约保留实现和已有测试使用的规则编号与组合场景，不复述代码调用顺序。操作、状态含义和术语见[家庭运行时](../household-runtime.md)。一个部署只服务一个绑定家庭；账号授权、家庭运行资格、设备能力和页面同步是不同状态，不能互相替代。

## 功能规则

规则编号用于后续需求追踪。表中的结果是业务断言，不规定内部函数调用顺序、对象结构或固定数量的中间状态。

### 首次设置与唯一绑定

| 编号   | 前提与触发                                           | 应有结果                                                                                                                                                                   |
| ------ | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BND-01 | 启动时数据库已有绑定。                               | 恢复原账号身份与原家庭；云端出现其他家庭或候选顺序变化不触发重新选择。设置候选接口按需返回同账号已取得的家庭列表。                                                         |
| BND-02 | 没有绑定，已授权账号只有一个候选家庭。               | 先可靠保存绑定，再自动采用该家庭；保存未确认前不能宣告家庭已绑定或允许设备任务。                                                                                           |
| BND-03 | 没有绑定，已授权账号有多个候选家庭。                 | 等待用户选择，不默认选择第一个；仅接受有效、非空的候选家庭 ID。查询候选只读已取得资料，不触发云请求。                                                                      |
| BND-04 | 首次选择的保存明确失败。                             | 向调用方报告失败，仍可重新提交选择；不能只在内存中采用家庭并继续运行。保存结果不确定时按 BND-07 处理。                                                                     |
| BND-05 | 绑定已保存，后续设备清单初始化失败。                 | 保留绑定并显示初始化失败；重试的是设备清单同步，不要求重新选择，也不再次创建绑定。                                                                                         |
| BND-06 | 已有绑定时重新绑定家庭，或尝试异账号登录。           | 允许同账号其他有效家庭；先可靠保存，再更换运行标识、清空旧显示与规格、取消旧设备访问及媒体，异步初始化新家庭。同一家庭、过期运行标识或并发冲突被拒绝；异账号不能替换绑定。 |
| BND-07 | 保存超时、响应丢失或事务提交结果无法立即确定。       | 先核对数据库中的实际结果，未确认前不继续盲目插入。业务成功依据可靠保存的事实，不能仅按客户端是否收到成功响应判断。                                                         |
| BND-08 | 用户退出、授权失效、原账号重新登录，或重新绑定家庭。 | 退出和失效保留绑定；重新登录恢复最近保存的家庭。设置中的重新绑定遵守[重新绑定家庭](../household-runtime.md#重新绑定家庭)流程。                                             |

### 启动、运行与授权变化

| 编号   | 前提与触发                                                                   | 应有结果                                                                                                                                                                         |
| ------ | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RUN-01 | 应用启动，无页面连接，Agent 未启动。                                         | 后台自行恢复授权与绑定、获取设备清单并准备规格；家庭是否运行只取决于业务资格。                                                                                                   |
| RUN-02 | 启动时有同账号、同家庭的缓存。                                               | 可以展示缓存，但仍等待本轮完整云端清单确认；不能据此启动读取、观察或新播放。其他账号或家庭的缓存不能充当本家庭资料。                                                             |
| RUN-03 | 首次云端请求失败、响应非法、分页未完成或超限。                               | 保持不可运行的初始化状态并报告对应问题；允许在条件满足后刷新重试。失败不产生一份部分可用的首轮清单。                                                                             |
| RUN-04 | 本轮完整云端清单确认并接纳。                                                 | 家庭可以进入 `running`；缓存故障、尚未准备的规格和媒体故障分别显示，不能成为全家庭启动门槛。                                                                                     |
| RUN-05 | 已运行家庭的普通云请求发生网络失败、超时或限流。                             | 保留已确认且未撤销的设备范围与已有任务，报告同步问题并遵守来源退避；不能把一次请求失败解释成设备全部移除或账号明确失效。                                                         |
| RUN-06 | 同账号正常续期成功。                                                         | 保留稳定绑定和家庭运行标识；受凭据更新影响的连接或请求按自身生命周期更新，旧通路结果不能绕过各自的有效性检查。                                                                   |
| RUN-07 | 当前完整会话被明确判定认证失效。                                             | 撤销本轮设备访问、取消读取和观察及媒体资格，进入无可用授权的状态，保留家庭绑定。不能因另一类凭据仍有效而继续以部分会话运行。                                                     |
| RUN-08 | 用户退出，凭据删除成功或失败。                                               | 退出开始即暂停新工作并撤销旧任务。删除成功后保持无授权，绑定仍在；删除失败且授权仍有效时，报告退出失败并立即重新同步完整云端清单，正常校验后才能恢复运行，不能凭旧缓存直接恢复。 |
| RUN-09 | 正常停止及随后重启。                                                         | 停止接收新工作，取消请求、订阅、计时器和观看资源，等待关闭所需的清理收尾；保留授权和绑定供下次启动恢复。重启产生新运行标识，重新满足本轮清单条件。                               |
| RUN-10 | 旧请求、旧规格任务、旧保存回调或旧连接消息在停止、退出、失效或新登录后返回。 | 不能写入新一轮状态、重新授予资格或创建新一轮资源。判断依据是结果仍属于有效运行，而非它返回了成功。                                                                               |

### 设备清单与保存

| 编号   | 前提与触发                                                             | 应有结果                                                                                                                                                                                                       |
| ------ | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DIR-01 | 云端全部请求和分页成功完成，但部分家庭／房间成员没有详情。             | 只接纳实际返回详情的设备。缺详情的成员不阻挡家庭初始化，也不能使用展示缓存取得访问资格；原已接纳设备本次不再返回详情时撤销其访问，随后重新返回时重新接纳。                                                     |
| DIR-02 | 账号其他家庭的资料缺少设备详情。                                       | 不阻断账号恢复或已绑定家庭运行；业务范围始终过滤为绑定家庭。                                                                                                                                                   |
| DIR-03 | 完整且可接纳的设备清单到达。                                           | 家庭、房间、设备与归属按实际变化更新；改名保留身份，换房更新归属，移除条目不累积。用家庭级 cloud_synced_at 记录本次整份清单确认时间，不为每条记录重复更新时间；saved_at 只表示当前清单最近一次确认保存的时间。 |
| DIR-04 | 完整资料确认设备移除、转出或局部访问撤销。                             | 先从允许读取、观察和播放的范围撤销对应设备，再取消资源；其他设备继续运行。缓存保存或远端清理失败不恢复被撤销设备。                                                                                             |
| DIR-05 | 完整资料确认某设备型号或规格定义变化。                                 | 该设备按新定义判定资格，撤销其旧读取、观察与播放任务；旧规格摘要不能自动授权新定义下的读取。其他设备不受牵连，缓存保存失败不延迟这一边界。                                                                     |
| DIR-06 | 确认整个绑定家庭失去访问。                                             | 保留绑定，撤销全家庭设备任务，进入 `initializing` 并报告 `home_unavailable`；等待原账号权限恢复，不能转成选择其他家庭。恢复后重新确认完整清单。                                                                |
| DIR-07 | 读取或保存设备清单缓存失败。                                           | 报告 `storage_degraded`。已确认云端清单仍能接纳，新设备、新归属和撤销仍生效。分别记录 `cloud_synced_at` 与最近成功的 `saved_at`，失败不能伪造保存成功时间。                                                    |
| DIR-08 | 缓存故障后发生后台或显式清单刷新，数据库已恢复。                       | 再次尝试保存当前完整清单；可靠保存后更新保存时间并清除对应存储降级。无需退出、重新扫码或重新绑定。                                                                                                             |
| DIR-09 | 完整资料超过设备清单容量限制。                                         | 不截断实体来拼出可运行的部分清单；拒收超限资料并报告 `capacity_degraded`。其中已确认的撤销仍生效，不能为保留旧展示而保留已失去的访问资格。                                                                     |
| DIR-10 | 获取过程中发生取消、运行失效，或提交时身份、范围、数据大小不满足要求。 | 不能把该结果作为当前有效清单；在途中发起成功不代表返回时仍可接纳。                                                                                                                                             |
| DIR-11 | 刷新后的设备清单与已接纳内容一致，包括云端仅改变返回顺序。             | 复用未变化记录，不发布家庭／房间／设备条目更新，不重建规格任务或正常摄像头源。仍确认本轮同步和错误恢复；规格刷新及媒体失败重试按各自命令和条件执行。                                                           |
| DIR-12 | 当前设备清单已确认保存，本次内容未变；或仅少量条目变化。               | 未变化时不启动新的缓存数据库事务，保存时间保持不变。变化时只提交新增／修改条目与删除键；首次保存传入完整清单。任何失败或未确认结果都不能命中先前的保存确认，下一次仍须重试或先核对。                           |
| DIR-13 | 新设备或重新出现的设备使用已接纳、仍适用的共享规格。                   | 直接复用已有规格；不让共享该规格的其他设备重新进入准备状态，不重复解析或下载。型号或规格定义变化仍检查新的适用性。                                                                                             |

请求失败、响应结构错误或分页未完成时，不能把局部结果当成完整清单推断移除。全部请求成功但个别成员没有详情属于 DIR-01；这些已确认的访问变化不能被后续容量或缓存问题否定。可继续展示的旧资料不自动等于仍可访问的设备集合。

### 增量处理的边界

增量指已确认记录的变化，不代表云端提供增量游标或数据库按设备独立落盘。完整查询与分页完成后才能确认移除；保存等待期间已取得的规格结果不能被旧清单覆盖。名称／房间变化不重建正常媒体连接，定义或权限变化仍独立判定。具体存储与发布方式见[设备清单与规格](../household-runtime.md#设备清单与规格)。

### 后台发现与显式刷新

| 编号   | 前提与触发                                   | 应有结果                                                                                                                                          |
| ------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| REF-01 | 家庭后台处于可维护状态，没有用户刷新。       | 按五分钟周期发现设备清单变化；关闭全部页面不停止维护。账号恢复已取得的完整资料可直接用于本轮确认，无需浏览器额外触发。                            |
| REF-02 | 收到绑定、解绑、改名或换房等结构变化通知。   | 合并短时间通知后重新读取完整设备清单，以校验后的资料确认变化；不能仅凭通知载荷直接改名、改归属或判定移除。周期发现继续承担补漏。                  |
| REF-03 | 提交 `directory`、`specs` 或 `all` 刷新。    | 分别请求清单同步、规格重新准备或两者；刷新不修改家庭绑定。清单同步引入的新设备或新定义仍自然触发所需规格准备。                                    |
| REF-04 | 发现、通知或用户请求在刷新期间重复到达。     | 合并同类在途工作，清单刷新最多保留一次后续刷新；不能堆积无限任务，也不能丢掉后续仍需执行的目标。合并和显式操作都不绕过供应商退避期限。            |
| REF-05 | 有效刷新被接纳。                             | 返回 202 和 `state_version`，最终完成或失败由订阅显示；202 不承诺云同步、缓存保存或规格准备已经成功。没有立即产生公共字段变化也不能吞掉有效刷新。 |
| REF-06 | 用户读取状态、诊断、设置候选或建立状态订阅。 | 只观察已有状态，不因此请求云端同步或启动后台；慢连接和重复读取也不能增加云请求。                                                                  |

### 规格准备与设备摘要

| 编号   | 前提与触发                                                           | 应有结果                                                                                                                                                          |
| ------ | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SPC-01 | 接纳设备清单，设备需要规格。                                         | 后台准备完整能力定义；优先使用设备提供的 `spec_type`，缺少时按型号解析。家庭不等待全部规格完成才运行；需要规格的读取须等待该设备适用规格就绪。                    |
| SPC-02 | 多台设备引用同一规格定义，或同一型号需要解析。                       | 共享相同资料与准备工作；同一最终 URN 在显式刷新批次内获取一次。只要仍有设备引用，共享资料不能因另一台设备移除或失败而消失；最后一个引用消失后释放无用资料和任务。 |
| SPC-03 | 某个规格准备发生瞬时失败。                                           | 在规定次数与间隔内重试并显示实际状态；重复设备清单不重置失败次数，不形成永久重试循环。单个任务失败不阻塞其他设备的成功规格。                                      |
| SPC-04 | 同一定义已有适用规格，重新准备失败。                                 | 可保留此前已确认能力和旧展示摘要，失败不得删除仍适用的共享能力；同一失败任务影响的设备如实显示错误，未受该任务影响的设备保持原结果。                              |
| SPC-05 | 型号或 URN 已改变，新规格未成功。                                    | 旧摘要可以继续用于展示，但不能据此允许新定义的读取；必须重新确认适用规格，不能把“以前读过”当作当前资格。                                                          |
| SPC-06 | 新规格资料超过大小限制。                                             | 拒收新增资料并报告容量问题，保留已接纳资料及真实任务错误；任务开始、完成、失败仍可被反映，不能一直伪装成加载中。                                                  |
| SPC-07 | 规格成功、失败或引用关系变化。                                       | 只改变受影响设备的规格摘要与适用能力；未受影响设备的业务资料保持一致。完整能力表保留在后端，公共状态只公开摘要。                                                  |
| SPC-08 | 页面显示 `readable`、`writeable`、`notify`、`action`、`event` 标签。 | 表示规格声明了对应能力，不能推导已启用控制、已订阅推送、已收到事件或已经取得当前属性值。                                                                          |

### 公共状态与页面订阅

| 编号   | 前提与触发                                         | 应有结果                                                                                                                                                     |
| ------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PUB-01 | 公共状态发生变化。                                 | 一整批已校验、身份一致的数据原子生效，此后再通知消费者和启动依赖该结果的操作。不能发布互相矛盾的生命周期、家庭和设备关系。                                   |
| PUB-02 | 数据被接纳后，其外部来源对象继续变化。             | 已确认状态不能被静默改写；可观察变化仍须经过有效更新与版本发布。无需通过检查特定对象引用或某个冻结 API 来定义这一业务保证。                                  |
| PUB-03 | 同一轮公共状态变化、没有变化，或运行资格换代。     | 同轮变化推进 `sequence`；没有公共变化不为命令数量虚增版本。重启、重新绑定家庭、失效和新登录会话使旧运行标识失效，同账号正常续期不更换家庭标识。              |
| PUB-04 | 页面或诊断读取公共状态。                           | 只取得允许公开的字段；不含凭据、登录材料、完整规格、供应商接入秘密、内部任务及连接对象。首次设置与重新绑定的候选从专用接口读取，不进入公共快照。             |
| PUB-05 | 仅同步时间、同步状态或健康信息变化。               | 只发布对应控制记录，不重复发送设备清单。页面保留未变化设备集合和条目引用，不重新计算设备筛选结果。变化条目使用整条记录替换；不是逐字段补丁。                 |
| WEB-01 | 标签页首次连接或重新建立订阅。                     | 先取得完整当前快照，再接收连续版本的整批增量；初始化订阅期间的变化不能造成页面永久漏状态。同一标签页的页面区域共用状态订阅。                                 |
| WEB-02 | 增量缺版本、运行标识变化或消息非法。               | 不继续猜测或拼接状态，重新同步完整快照；非法或不连续的整批变化不能部分应用。                                                                                 |
| WEB-03 | 页面普通断流，随后恢复。                           | 可以保留旧显示，但标记未同步；重新连接取得当前状态，不补发断线期间的设备事件历史。后台运行和其他页面不受该连接影响。                                         |
| WEB-04 | HTTP 命令完成，SSE 确认尚未到达。                  | 命令响应不直接回填公共状态；刷新完成、退出结果等由已确认状态展示。退出期间暂停新播放，直到订阅达到回执版本，或取得 HTTP 结束后重新订阅的完整快照再判定资格。 |
| WEB-05 | SSE 未同步时用户提交控制命令。                     | 不把断流作为所有命令的统一禁令；按具体命令所需身份与运行标识由后台校验。旧标识不能绕过校验，新播放仍遵守退出期间的额外确认条件。                             |
| WEB-06 | 自动重连、手动重试或标签页恢复同时触发。           | 共用重连等待期限并遵守服务器 `Retry-After`；不能通过反复点击或切换标签页提前重试。                                                                           |
| WEB-07 | 页面筛选房间、分类、能力、在线状态或搜索设备。     | 只改变可见内容，不修改绑定、不删除后台设备、不取消其他设备任务，也不因此重新同步云端。                                                                       |
| WEB-08 | 单个连接写入缓慢、队列超限、消息超大或连接被取消。 | 关闭或回收该连接，其他消费者继续接收，后台继续维护；不能阻塞全局状态发布。HEAD 只返回响应头，不创建订阅。                                                    |

## 故障影响范围

按以上规则分别判断绑定、云清单、缓存、规格、来源和页面故障；不能将局部故障扩大为全家庭失权。供应商认证、限流和通路恢复见[来源契约](mijia.md#失败范围)，媒体释放见[米家资源释放](../mijia.md#资源释放)。不在此重复各来源的处理表。

## 组合场景与结果判定

下列场景用于说明规则相遇时应如何判定，不是执行记录。A 表示本部署绑定的账号和家庭，B 表示另一账号或家庭；设备甲、乙为不同的稳定设备身份。

| 场景                         | 前提与事件顺序                                                                 | 可观察结果与对应规则                                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| SC-01 单候选保存失败         | 无绑定；账号仅有家庭 A；保存明确失败，随后恢复保存条件。                       | 失败期间没有运行资格；重新确认可靠保存后采用 A，再完成完整清单初始化。BND-02、BND-04、RUN-04。                                                     |
| SC-02 并发首次选择           | 无绑定；两个请求分别选择 A、B，保存过程交错。                                  | 最多一个可靠绑定，不能覆盖已经保存的绑定；不约定并发请求谁先成功。页面和运行范围最终与实际保存的绑定一致。BND-06、BND-07。                         |
| SC-03 绑定回执丢失           | 数据库已提交 A，但保存响应丢失；调用方重试。                                   | 核对后仍只有 A；不能重复插入或误进入选择 B。已有绑定的设置请求仍遵守冲突规则，不要求重复请求返回相同 HTTP 成功码。BND-06、BND-07。                 |
| SC-04 绑定成功、首轮同步失败 | 绑定 A 保存成功；云清单失败；用户刷新。                                        | 刷新恢复清单，绑定保持 A，不重复保存选择；成功回执不提前显示为已运行。BND-05、RUN-03、REF-05。                                                     |
| SC-05 启动有旧缓存           | 缓存显示设备甲；本轮云清单尚未完成；发起读取或播放。                           | 可以看见缓存，但任务不被授权；完整云清单确认后才按当前设备与能力判定。RUN-02、RUN-04。                                                             |
| SC-06 首轮缓存失败           | 绑定与授权有效；完整清单确认设备甲；缓存写入失败。                             | 家庭可运行，规格适用且属性可读时可读取，媒体条件满足时可播放；显示存储降级，保存时间不伪造。DIR-07、RUN-04。                                       |
| SC-07 运行中缺详情           | 甲、乙原本有效；本次所有请求和分页成功，成员仍引用甲但未返回甲详情。           | 撤销甲的访问及在途任务，乙继续运行；家庭可运行，稍后甲的详情重新出现则重新接纳。若是请求、结构或分页失败，则不据此撤销甲。DIR-01、DIR-04、RUN-05。 |
| SC-08 移除叠加保存失败       | 完整清单确认甲移除、乙仍有效；数据库保存失败；甲旧请求晚到。                   | 甲立即失去资格，旧结果不能恢复甲；乙继续可用，报告缓存错误。DIR-04、DIR-07、RUN-10。                                                               |
| SC-09 撤销叠加容量超限       | 完整资料确认甲已转出，同时新增设备使清单超限。                                 | 不接纳截断后的新增清单；甲仍被撤销，旧显示不能授权甲。DIR-09。                                                                                     |
| SC-10 改定义叠加规格失败     | 甲型号或 URN 改变；旧摘要仍显示；新规格加载失败；乙未变化。                    | 甲旧任务失效，旧摘要不授权新读取；乙继续使用其已确认能力。DIR-05、SPC-05、SPC-07。                                                                 |
| SC-11 共享规格减少引用       | 甲、乙共用规格；甲移除；随后乙也移除。                                         | 甲移除不损害乙能力；没有剩余引用后释放无用资料和任务。SPC-02。                                                                                     |
| SC-12 家庭失权与普通断网     | 分别发生“请求网络失败”和“确认 A 已不可访问”；账号还能看到 B。                  | 普通失败保留已确认范围；明确失权撤销 A 的全家庭资格，保留绑定且不选择 B。RUN-05、DIR-06。                                                          |
| SC-13 刷新交错且无人看页面   | 没有浏览器；周期发现进行中；结构通知与显式刷新交错到达。                       | 后台继续维护，合并重复工作并保留必要后续目标，遵守退避；最终状态可供稍后连接的页面读取。REF-01 至 REF-05。                                         |
| SC-14 退出失败后重获资格     | 退出使甲旧任务失效；凭据删除失败且授权仍有效；重新云同步先失败后成功。         | 失败期间不运行；完整合法清单成功后才恢复新任务，旧任务不能复活；绑定始终保留。RUN-08、RUN-10。                                                     |
| SC-15 旧运行结果晚到         | A 的旧运行发起清单、规格或播放工作；授权失效后原账号重新登录；旧结果返回成功。 | 只允许当前轮结果改变当前状态；绑定可以相同，但旧运行资格不因身份相同而复用。RUN-07、RUN-10、PUB-03。                                               |
| SC-16 订阅初始化遇更新       | 页面取得首快照的边界上发生整批换房更新，随后连续更新或消息断档。               | 消费者不会长期漏掉换房；连续版本得到完整结果，断档则重新同步；不呈现半批归属。PUB-01、WEB-01、WEB-02。                                             |
| SC-17 退出回执先于订阅       | 退出 HTTP 已结束，页面仍显示退出前 `running`；用户尝试新播放。                 | 不以旧显示授权播放；等待符合 WEB-04 的订阅确认，再依据真实当前状态判断。WEB-04、WEB-05。                                                           |
| SC-18 慢页面与正常页面并存   | 一个连接停止消费直到队列超限，另一个正常；后台仍有设备变化。                   | 回收慢连接，正常页面继续收取变化，后台不停止且不增加云请求；慢页面重连取得当前快照。WEB-03、WEB-08。                                               |
| SC-19 停止叠加在途保存       | 已发起数据库保存；随后停止；数据库操作完成或结果暂不确定。                     | 保存事实须按数据库结果核对，不能要求取消撤回已经发生的提交；无论结果如何，旧回调不能把停止后的运行恢复为有效。BND-07、RUN-09、RUN-10。             |
| SC-20 缓存恢复但另有故障     | 已显示存储降级，同时甲规格失败；下一次清单保存成功。                           | 清除对应存储降级并更新保存时间，甲规格故障仍按实际结果显示；一次恢复不能掩盖另一类故障。DIR-08、SPC-03。                                           |

## 行为验证依据

已有测试与规则的映射、运行方式及证据限制见[家庭功能测试](../../apps/backend/tests/household/README.md)。业务断言不依赖私有方法、类布局或精确内部调用次数；规则列出不表示全部实机场景已经通过。

### 证据与适用边界

实机覆盖与限制以[家庭运行时的验证范围](../household-runtime.md#验证范围)为准。文档审阅、确定性场景和故障模拟不能替代实机证据，也不能泛化到所有设备、固件及操作系统异常退出方式。

以下边界需区分已确认规则与产品尚未约定的细节：

- **首次授权后没有任何候选家庭：** 唯一绑定与运行资格规则仍成立，但具体提示文案、候选重新获取入口及其交互流程没有独立业务约定。
- **家庭存在但可访问设备为零：** 所有请求和分页成功、家庭仍存在时，可运行空清单；不据此判定家庭失权。设备成员缺少详情同样不授予该设备访问资格。请求或分页失败不构成空清单确认。
- **设备在本家庭内换房：** 更新当前归属；仅名称或房间变化不重建正常媒体连接，不能套用跨家庭转出的全设备撤销结论。设备定义或访问范围同时变化时，分别按对应规则判断。
- **异常数据库存量：** 多条绑定、损坏绑定、人工把缓存归属改错等不是正常首次设置。文档要求维护后只保留一条合法绑定，未规定对所有损坏形态自动修复或选择哪条记录。
- **超限资料中的旧展示细节：** 已确认撤销必须生效、超限新增资料不得截断接纳；错误期间页面保留哪些旧展示条目，不应替代访问资格断言。
- **精确的收敛时长与逐项错误码：** 本文列出的公开期限以外，不承诺设备通知到页面的固定延迟、停机清理的统一完成秒数，或尚未约定的错误码映射。

这些边界不影响已经明确的唯一绑定、缓存不授权、范围撤销、原子状态和后台独立运行规则。需要把它们写成更细的行为断言时，应先补齐对应业务约定。

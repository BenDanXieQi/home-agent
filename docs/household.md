# 家庭运行时

一个本地部署固定服务一个家庭。后台随应用启动，维护该家庭的设备清单、规格和媒体状态，不依赖页面访问。云端账号有多个家庭时只在首次设置中选择；正常运行没有切换器或在线改绑流程。

## 绑定与运行资格

`mijia_home_selections` 保存本实例唯一的账号键和家庭 ID。账号键由区域和用户 ID 编码；绑定读写共用部署级事务锁，拒绝另一账号或另一家庭覆盖绑定。首次只有一个候选家庭时自动可靠保存后采用，多个候选时由设置页选择。退出或凭据失效保留家庭绑定；重新登录必须使用原账号。

绑定和凭据必须可靠保存。当前账号有授权、完整云端清单通过校验并提交后才进入 `running`，允许设备任务和新播放。启动缓存只用于展示，不能授权设备读取。目录缓存可重新获取：读取或保存失败标记 `storage_degraded`，但已确认的云端清单、新设备及新归属仍可使用。`cloud_synced_at` 与最近成功的 `saved_at` 分别记录；下一次后台或手动刷新再次保存完整清单。

初始化云端请求失败时保持 `initializing` 并允许刷新重试。已运行家庭普通刷新失败保留已确认资料和任务。完整清单确认设备移除或转出时立即撤销该设备访问；型号或规格变化使该设备的旧读取、观察和播放失效。整个家庭失去访问时保留绑定并报告 `home_unavailable`，等待原账号权限恢复，不转为选择另一家庭。

### 绑定纠错

选错家庭时先停止 backend（本地统一启动的服务可用 `bun run stop`），确认旧进程与观看资源结束，再修改数据库中的绑定并重新启动。数据库需保持运行。使用当前部署的数据库连接执行；本地 Compose 可用 `docker compose exec db psql -U home_agent -d home_agent` 进入 SQL 控制台。

```sql
SELECT account_key, home_id FROM mijia_home_selections;
-- 用上一步核实的账号键和目标家庭 ID 替换下面的占位值。
UPDATE mijia_home_selections
SET home_id = '<正确家庭ID>', updated_at = now()
WHERE account_key = '<原账号键>';
```

修改后应只有一条绑定记录。目标家庭 ID 必须属于原账号；错误或失去权限的家庭会报告不可访问。若需要重新执行首次选择，可在停机时删除这一条绑定，再启动并在设置页选择；单候选会自动采用。需要更换账号时同时通过现有授权清除流程移除凭据，停机清除绑定，再启动登录。不要修改旧目录缓存的账号或家庭归属。

绑定家庭和房间引用的设备必须取得详情，完整性检查先于设备撤销与缓存保存。其他家庭缺少详情不影响本家庭运行；本家庭清单不完整时保留已确认设备，首次初始化则等待清单恢复。

## 领域职责与状态

`household/machine.ts` 用 XState 管理生命周期，`runtime.ts` 协调首次绑定、清单与规格准备。`HouseholdSource` 是接入边界，`mijia/household.ts` 连接米家服务；`MijiaService` 管理账号和凭据，`DeviceDiscovery` 获取云端目录，媒体模块管理 go2rtc，`HouseholdSpecifications` 管理后端完整规格与设备引用。

| 状态               | 含义                                                   |
| ------------------ | ------------------------------------------------------ |
| `unbound`          | 无可用账号授权，持久家庭绑定可能仍存在                 |
| `waiting_for_home` | 等待首次家庭选择                                       |
| `initializing`     | 等待当前完整清单，或绑定家庭不可访问                   |
| `running`          | 账号与当前完整清单已确认，缓存／规格／媒体故障分别显示 |
| `stopping`         | 正在关闭任务与资源                                     |

状态节点决定公共 `status`；普通数据发布不能改变生命周期。候选状态通过一次内部 `commit` 原子生效，guard 只判断。提交后再通知订阅者、分发操作；内部 `input_sequence` 防止同一次操作重复执行，没有公共变化的有效命令仍可分发。异步网络、数据库、连接和取消控制器由资源所有者管理。

`scope_epoch` 标识一轮有效运行，隔离重启、授权失效和新登录会话的旧结果；同账号凭据续期保留家庭运行标识。`sequence` 只在公共状态变化时递增。播放同时检查家庭标识与媒体 `revision`，它们分别管理自己的生命周期。

## 设备清单与规格

后台每五分钟同步目录，结构变化通知经防抖触发同步；重复请求合并。完整清单中的设备引用必须有详情，不完整返回整批拒收。账号恢复取得的完整清单直接复用，普通 GET 不触发云请求。缓存事务最多五秒，包含锁等待；结果未确认时先核对持久结果再执行后续写入。

完整规格只保存在后端，按含版本的 URN 共享。最多三个准备任务，瞬时失败额外在两秒、十秒重试。重复清单不重置失败次数；显式刷新合并同一批次，同一 URN 在批次内获取一次。没有设备引用的资料和解析任务被释放。

页面收到规格标识、准备状态、错误、分类和能力标签。旧摘要可继续显示；读取前检查规格是否适用于当前型号及定义。型号或 URN 改变后，旧显示缓存不能授权新读取。同定义刷新失败可保留已确认能力；一个解析任务失败不影响其他已成功任务。

## 公共接口与 SSE

| 接口                                | 内容                                                                                                     |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `GET /api/mijia/state`              | `{ scope_epoch, sequence, projection }`，只读诊断快照                                                    |
| `GET /api/mijia/diagnostics`        | 按需 JSON 字节大小和最近进程内存采样                                                                     |
| `GET /api/mijia/events`             | 完整快照与增量 SSE                                                                                       |
| `GET /api/mijia/setup/homes`        | 首次设置候选 `{ items }`，已有绑定时为空；不触发云请求                                                   |
| `PUT /api/mijia/scope/homes`        | 首次保存 `{ scope_epoch, home_id }`，非空家庭 ID；保存完成返回 202 `{ state_version }`；已有绑定返回 409 |
| `POST /api/mijia/devices/refresh`   | `{ scope_epoch, target: directory / specs / all }`，接纳后返回 202 `{ state_version }`                   |
| `GET /api/mijia/login/:id/material` | 当前尝试的二维码和验证材料，`no-store`                                                                   |

公共 `projection` 只包含账号、登录、连接操作、媒体、家庭、健康，以及 `home/room/device` 记录。实体键按稳定身份数组编码。候选家庭、完整规格、凭据、登录材料和内部操作不进入 SSE。`latest/source_health/rule_status` 尚未进入当前协议。`availability=unknown`、空的 `read_enabled_properties` 不表示持续采集已启用。

Mutative `produce` 构造候选，不冻结调用方数据；变化条目经共享 Zod schema 白名单和身份校验后成为独立不可变对象。未变化条目保留引用；浅冻结对象不能绕过后续校验。状态机不维护一份重复的序列化字节账本。

每个浏览器标签页共用一条 SSE。先订阅再取得完整快照，此后整批发送连续变化；同版本编码可被多连接复用。运行标识变化或停止时要求重新同步；断线恢复当前状态，不补发事件历史。缺失版本或消息非法时重连，普通断流保留旧显示并标记未同步。

心跳十五秒；浏览器等待响应头十秒、首快照三十秒，之后四十五秒无有效消息重连。退避从一秒增长到三十秒并加随机延迟，稳定同步六十秒后重置，遵守服务器 Retry-After。自动重连、手动重试和标签页恢复共用等待期限。

HTTP 命令与 SSE 确认分开。命令按自身所需标识发起，不以 SSE 连通为通用前提；命令响应不回填公共状态。退出期间暂停新播放，等订阅达到回执或取得 HTTP 结束后重新订阅的完整快照才恢复资格。首次设置不会终止另一个家庭运行。房间、分类、能力与在线状态筛选仅改变页面显示。

## 资源限制与关闭

- 目录接纳和缓存最多 4 MiB、1024 台设备；完整规格独立最多 4 MiB，单次规格响应也最多 4 MiB。
- 设置候选和账号资料各最多 2 MiB。规格摘要标识最多 256 个 ASCII 字符、分类最多 64 字符；规格错误最多 1 KiB，其他公共控制错误最多 4 KiB。
- SSE 快照上限 8 MiB，每连接变化队列最多 256 条或 2 MiB，最多 16 条连接。写入十五秒未完成、队列满或消息过大时关闭该连接。

资料超限时报告 `capacity_degraded` 并保留上次接纳资料，不截断实体。退出、停止、访问撤销和规格任务开始／结束不经过统一容量准入。数据与传输分别在自己的边界限制大小，没有控制空间或每设备字节预留。

诊断 `bytes` 分别报告当前目录、元数据、公共状态及后端规格的实际 UTF-8 JSON 字节数。进程内存每六十秒采样，峰值只表示采样观察到的值，不代表家庭独占内存或瞬时峰值。

停止和失效取消请求、订阅、计时器及观看，关闭等待媒体队列收尾。迟到结果不能更新新运行。慢 SSE 不阻塞其他连接，不触发额外云请求；HEAD 仅返回响应头，不建立订阅。

持续属性采集、历史和规则在[后续步骤](plans/household-steps/02-household-runtime.md)实施，当前静态目录与规格摘要不能作为实时感知结果。

## 设备上报日志

`/device-logs` 展示当前家庭最近一次诊断采集，页面可开始 10 分钟采集、提前停止、搜索设备／房间／属性／值、筛选上报类型和变化类型、暂停显示及下载完整 JSONL（每行一个 JSON 对象）。页面显示最近 500 条记录，新记录位于顶部；暂停只停止列表更新，统计与后台记录继续。切换页面、刷新和浏览器断线不影响后台采集。页面日志通过独立 SSE 每秒更新，重连取得最近记录，不补发已移出窗口的行；完整内容以下载文件为准。

`DevicePushLogs` 负责诊断采集，通过 `MijiaService.observeDevices` 复用账号 MQTT 连接，订阅采集开始时当前家庭中全部活动设备的属性和在线状态；设备标识须能用于消息主题。它不主动读值，不把收到的消息写入家庭 `latest`，也不执行设备动作。订阅确认、失败和连接中断分别记录；未收到推送不表示设备离线或状态未变。供应商未推送、无法解析的消息以及独立 MIoT 事件不在统计范围内。

上报频率按本机接收时间统计：一个已解析消息包可产生多条属性记录，消息包数与状态条数分开计数。首次看到某设备属性时标为首次上报，之后与本次采集最近一次值比较，区分值变化和同值上报。重复值和 MQTT 保留消息均记录；这些标记只帮助阅读日志，不用于确定家庭的当前属性值，也不保证识别出所有重复事件。订阅和连接记录不计入设备上报频率。

采集由后端定时停止。家庭作用域失效或不再允许观察设备时，采集会中断；后端重启后恢复最近的展示数据并标记采集中断，不自动补采。每次采集的完整记录、开始时的设备清单快照和汇总，分别保存在仓库 `data/mqtt-logs/<id>.jsonl`、`<id>.snapshot.json`、`<id>.summary.json`；`latest.json` 每 5 秒保存最近的展示数据。文件目录权限为 0700，文件为 0600，均被 Git 忽略。历史文件不会被新采集覆盖，页面只展示同账号、同家庭的最近一次采集。单次日志达到 256 MiB 或等待写入的数据超过 8 MiB 时停止并报告错误；没有自动清理旧文件。

| 接口                             | 内容                                                                    |
| -------------------------------- | ----------------------------------------------------------------------- |
| `GET /api/mijia/logs`            | 最近采集的汇总和最近 500 行                                             |
| `POST /api/mijia/logs/capture`   | `{ duration_seconds }`，60–3600 秒，默认 600 秒；同一时刻只允许一次采集 |
| `DELETE /api/mijia/logs/capture` | 停止当前采集                                                            |
| `GET /api/mijia/logs/events`     | `snapshot` / `update` SSE；最多 8 条页面连接                            |
| `GET /api/mijia/logs/download`   | 下载当前展示会话的完整 JSONL；采集中下载只包含已写入部分                |

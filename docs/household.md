# 家庭运行时

backend 启动 `household/runtime.ts` 的 XState 实例，不依赖页面访问。`MijiaService` 负责唯一账号、凭据和供应商接入，`DeviceDiscovery` 获取云端目录，媒体模块管理 go2rtc 资源；家庭状态机持有已提交的公共业务状态。规格由家庭模块按活动设备共享、准备和释放。配置、凭据、媒体连接和 Promise 不进入公共状态。

## 生命周期与目录

状态为 `unbound`、`waiting_for_home`、`initializing`、`running`、`stopping`。初始化分别报告账号、家庭选择、目录阶段及安全错误。`running` 表示账号和完整已保存目录就绪，规格可以继续准备，不能理解为设备属性采集已启动。

家庭选择按米家账号的区域／用户身份持久化。目录保存在 `household_directories`，按账号和家庭隔离，包含家庭、房间、设备归属、最后发现时间和归档标记。数据库只保存目录字段；恢复时规格引用、在线可用性和采集状态重新初始化。未分配房间保持空值。

重启先展示同账号同家庭的持久目录并标为尚未同步；授权和本次完整目录保存、提交前不能主动读取、订阅或新播放。普通目录刷新失败保留已运行家庭及当前目录，保存失败标为 `storage_degraded`。完整云端清单确认撤销时先移除任务资格，随后保存归档；旧结果不能恢复资格。

目录和选择的写入复用账号服务串行入口。事务的锁等待、语句和总事务期限均为 5 秒；提交响应不确定时读取持久结果核对。设备发现保留一份最新完整候选，保存重试不建立另一份状态权威；显式刷新与后台发现可以替换候选。确认成功后才接纳新增设备和归属。

切家生成新 `scope_epoch`，清空旧目录、规格和运行状态，再撤销旧任务、保存选择并初始化目标家庭。保存或初始化失败保持目标家庭错误状态；选择保存失败时，目录刷新重新保存该目标，规格单独刷新不接纳。不恢复旧家庭继续运行。同账号凭据续期保留家庭身份和规格，只替换受影响连接。退出、账号替换或家庭访问撤销会使旧作用域失效。

## 目录主动更新

后台登录后复用同一账号的 MQTT 连接，订阅 `user/{uid}/g_op/bind`、`unbind`，以及账号下设备的 `device/{did}/g_op/rename`、`hr_change` 精确主题。账号级目录订阅包含非受管家庭的设备，以发现设备移入；设备属性观察与业务目录仍受当前家庭限制。无法作为单层 topic 的设备 ID 不订阅，周期目录同步仍覆盖它们。

通知只表示目录可能发生变化，不直接采用其载荷修改归属。连续通知按 5 秒尾沿防抖合并，然后调用现有目录刷新流程；MQTT 连接恢复后也安排一次同步。提交仍经过完整目录校验、持久化和家庭作用域检查。原有 5 分钟后台发现用于补漏，通知触发的成功刷新会重新计时。

目录与属性订阅共享 MQTT 连接、订阅确认上限和重连退避。退出、切换作用域和停止时取消通知监听及计时器；新目录提交后重新协调订阅。同账号凭据续期沿用观察所有者并使用更新的凭据重连。

`GET /api/mijia/directory/push` 是只读诊断接口，返回连接状态、期望／已确认／失败主题数量、通知计数及最近接收时间；不返回 topic、账号 ID、设备 ID、凭据或消息载荷。连接成功与订阅确认分别报告，订阅失败不会被静默标为成功。

## 状态提交与接口

`machine.ts` 同步提交状态和安全操作描述。运行时在 actor 启动前注册唯一应用级订阅出口；先按 `input_sequence` 标记已处理，再分发通知和异步操作。被拒绝的输入不执行操作，已接纳但没有公共变化的命令仍执行操作。公共版本独立为 `{ scope_epoch, sequence }`，只有公共变化递增 `sequence`。

| 接口                                | 内容                                                                        |
| ----------------------------------- | --------------------------------------------------------------------------- |
| `GET /api/mijia/state`              | 诊断快照 `{ scope_epoch, sequence, projection }`；不刷新云端                |
| `GET /api/mijia/events`             | 同一已提交状态的 SSE                                                        |
| `PUT /api/mijia/scope/homes`        | `{ scope_epoch, home_id }`，202 `{ state_version }`                         |
| `POST /api/mijia/devices/refresh`   | `{ scope_epoch, target: directory / specs / all }`，202 `{ state_version }` |
| `GET /api/mijia/login/:id/material` | 当前尝试的二维码／验证材料，`no-store`                                      |

其他账号命令返回 `{ state_version }`，页面通过订阅确认状态，不把命令响应写回缓存。播放预约同时携带家庭 `scope_epoch` 和媒体 `revision`，作用域不匹配时返回 409；SDP 只经过播放专用接口。

`projection` 的账号、登录、连接操作、媒体、家庭和健康使用同名固定 key；home、room、device 使用 JSON 编码的身份元组 key。规格准备时使用已知 URN 或型号分组标识，完整规格接纳成功后按含版本的 URN 共享。型号解析到新 URN 但能力读取失败时，原型号组保留旧 URN、版本和能力，不把旧能力标为新版本。属性 `latest`、`source_health`、`rule_status` 均为空，设备 `availability` 为 `unknown`，`read_enabled_properties` 为空。

云目录 `online` 保留作诊断，`last_seen_at` 表示目录发现时间。它们不代表实时在线证明，也不单独阻止播放。设备保留原始名称、房间、型号，规格保留类别及属性、动作、事件地址；能力标签从规格派生。事件元数据存在不代表事件推送可用。

## SSE 与浏览器

共享 Zod 协议位于 `packages/api/src/contracts/household.ts`。服务端同步注册通知后取得快照，后续变化按顺序发送。每次提交只计算一次差异，验证后的快照按公共版本复用，SSE 编码也由同版本客户端共享；每条连接仍独立管理发送队列与取消。同次提交的所有 upsert/remove 位于一条 `state_change`；连接切家时发送 `resync_required` 并关闭，新连接从完整快照开始，不补发历史。

浏览器每个标签页一条应用级连接，使用 Hono RPC fetch、eventsource-parser 及共享协议校验，Jotai 派生页面显示。只接纳同一作用域的连续版本；缺口、非法消息或切家时停止应用增量并重连。每次连接先取得快照；重试从 1 秒增加至最多 30 秒并错开，稳定同步 60 秒后重置。短暂断流保留旧显示并标为未同步；切家和退出清空旧家庭。

快照大小、心跳与失联期限使用共享协议的 `householdStreamPolicy`。服务端心跳间隔 15 秒；客户端等待响应头最多 10 秒、首快照 30 秒，之后 45 秒没有有效消息即重连。SSE 不使用普通 JSON 请求总超时。米家页面没有状态轮询；服务连接配置等无关查询保持独立。

登录公共状态仅含 `id/status/error/material_version`。页面按尝试和材料版本合并请求，显示前再次比对；二维码、验证码、验证地址、Cookie、token、SDP 和内部连接均不进入 SSE。

## 容量与清理

`household/config.ts` 集中定义后端预算：目录与规格 4 MiB、公共元数据与协议预算 2 MiB、快照 8 MiB；每连接待发送最多 256 条或 2 MiB，另容纳一份快照；最多 16 条状态连接。新状态提交前检查容量，超限保留已提交状态并标记 `capacity_degraded`。

SSE 的快照、变化、心跳共用发送队列，正在发送的消息仍占预算；写入超过 15 秒、队列满或消息超限时关闭连接。断开、异常和停止共用退订、清计时器、清缓冲逻辑。单个慢客户端不阻塞其他客户端，也不触发云端读取。

规格并发 3，瞬时失败额外在 2 秒、10 秒重试。只有活动设备引用的规格组保留；重复目录同步不重置失败次数。显式刷新按最终 URN 合并正在进行的请求，其他组加载中不阻止已失败组重试；成功才替换能力，失败保留已有能力并显示错误。内部属性预检只读已准备规格。

## 当前范围

本模块提供家庭运行、目录持久化、后台规格、公共状态订阅和限时设备推送诊断。业务属性持续采集、最新值仲裁、历史和规则的规划见 [家庭步骤计划](plans/household-steps/02-household-runtime.md)；不将静态目录或空采集字段显示成实时感知。

## 设备上报日志

`/device-logs` 展示当前家庭最近一次诊断采集，页面可开始 10 分钟采集、提前停止、搜索设备／房间／属性／值、筛选上报类型和变化类型、暂停显示及下载完整 JSONL。页面显示最近 500 条记录，新记录位于顶部；暂停只冻结列表，统计与后台记录继续。切换页面、刷新和浏览器断线不影响后台采集。页面日志通过独立 SSE 每秒更新，重连取得最近记录，不补发已移出窗口的行；完整内容以下载文件为准。

`DevicePushLogs` 独立拥有诊断会话，通过 `MijiaService.observeDevices` 复用账号 MQTT 连接，订阅开始时当前家庭全部活动且标识可订阅的设备，包含属性和在线状态。它不主动读值，不将观察提交为家庭 `latest`，也不执行设备动作。订阅确认、失败和连接中断分别记录；未收到推送不表示设备离线或状态未变。供应商未推送、无法解析的消息以及独立 MIoT 事件不在统计范围内。

密度按本机接收时间统计：一个已解析消息包可产生多条属性记录，消息包数与状态条数分开计数。首次看到某设备属性只标为首次上报，之后按本次会话最近值判断值变化或同值上报，重复值和 MQTT 保留消息均保留；这不是业务状态仲裁或精确事件去重。订阅和连接记录不计入设备上报密度。

采集由后端定时停止。家庭作用域或观察资格失效会中断；后端重启恢复最近展示并标记中断，不自动补采。每次采集的完整行、起始目录快照和汇总分别保存在仓库 `data/mqtt-logs/<id>.jsonl`、`<id>.snapshot.json`、`<id>.summary.json`；`latest.json` 每 5 秒保存最近展示。目录权限为 0700，文件为 0600，位于 Git 忽略目录。历史文件不会被新采集覆盖，页面只展示同账号同家庭的最近一次会话。单次日志达到 256 MiB 或写入积压超过 8 MiB 时停止并报告错误；没有自动清理旧文件。

| 接口                             | 内容                                                                    |
| -------------------------------- | ----------------------------------------------------------------------- |
| `GET /api/mijia/logs`            | 最近采集的汇总和最近 500 行                                             |
| `POST /api/mijia/logs/capture`   | `{ duration_seconds }`，60–3600 秒，默认 600 秒；同一时刻只允许一次采集 |
| `DELETE /api/mijia/logs/capture` | 停止当前采集                                                            |
| `GET /api/mijia/logs/events`     | `snapshot` / `update` SSE；最多 8 条页面连接                            |
| `GET /api/mijia/logs/download`   | 下载当前展示会话的完整 JSONL；采集中下载只包含已写入部分                |

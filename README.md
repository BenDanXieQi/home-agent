# Home Agent

Home Agent 是一个本地运行的家庭助手项目。backend 提供有来源的设备报告、成员出现记录和感知材料；第一方 Agent 围绕用户的问题与职责按需查询、解释和请求动作。系统逐项建立可用能力，不以维护完整的家庭世界模型为目标。

## 项目动机

家庭设备提供的线索通常不完整：没有检测到人不等于无人，喂食器报告出粮不等于宠物已经吃过，摄像头所在房间也不一定是目标的位置。助手需要说明依据和未知，在必要时继续查询或询问，而不是先把所有生活情况裁定成确定状态。

可靠性主要落在系统自己的责任上：记住用户确认的信息、按时推进已经答应的事情、执行前核对授权、保存真实动作结果。比如从用户确认的遛狗时间计算提醒，可以先于自动识别每次遛狗交付。

项目独立实现，参考 MiLoCo 的媒体筛选、身份核验与上下文组织；固定源码及采用边界见[MiLoCo 参考](docs/references/miloco-perception.md)。

## 核心设计

1. **提供可核查的记录。** backend 保存实际来源、观察时间、归因和修订；默认查询返回精简摘要，需要时再取详情和仍可用的媒体。来源故障、截断、过期和未知分别说明。
2. **围绕职责进行调查。** Agent 应用层保存目标、进度、等待和暂时解释。记录变化与定时期限按职责唤醒工作，不把所有上报直接送给模型，也不要求每个解释成为共享家庭状态。
3. **明确管理执行。** 时间锚点、暂停、取消、授权、重复接纳和动作结果由程序管理；解释材料与实际执行各有责任。需要恢复的工作不能只依赖提示词或聊天历史。

这些是目标设计。主路线见[家庭观察与 Agent 工作协作设计](docs/plans/household-automation.md#实施顺序与改动位置)：先接通已有材料查询，再交付用户报告与一次到期提醒；变化驱动调查、媒体理解和设备动作按各自真实依赖接入。首个查询或持续职责不等待全部模型入口迁移，本地感知仍可独立交付。信息含义见[信息边界与状态归属](docs/plans/household-model.md)，具体拟新增存储见[家庭记录与 Agent 工作存储设计](docs/plans/household-storage.md)。

## 当前能力

- 米家登录与授权恢复、家庭选择、设备清单保存、设备规格准备、后台属性采集和带质量的当前值查询已实现。Web 可在 `/devices` 查看房间设备与 [AI 观测描述](docs/contracts/room-analysis.md)，后者需要模型配置。
- Web 已提供 Agent 聊天、会话历史、成员资料与识别参考管理、家庭数据库浏览。聊天具有概览、设备清单、设备状态和成员资料四个只读工具，尚不能通过这些工具读取成员出现记录或感知窗口。
- 本地检测、人宠跟踪、参考身份关联及可修订的成员出现记录已接入；人体短期外观归因仍有校准与专项验收限制，正式装配不输出外观成员归属。摄像头预览、筛选窗口、短期媒体、音频分析与本地语音转写已提供，具体使用与验证范围见[感知说明](docs/perception.md)。
- 房间分析仅描述设备证据；语音判断只识别转写是否构成完整助手请求。持续职责、到期通知、Agent 多模态调查、长期记忆及设备控制闭环尚未接入，不能从已有接口或计划推定可用。

当前仅供可信本机使用，每实例运行一个家庭。切换米家家庭仍会清理相关业务数据和 Agent 会话；范围见[家庭运行时](docs/household-runtime.md#切换家庭与清理数据)。计划中的稳定本地家庭与来源绑定分离尚未实施。

## 当前服务分工

技术栈：Bun、TypeScript、React、Hono、LangGraph、PostgreSQL 和 go2rtc。

| 模块           | 已实现职责                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------- |
| `apps/backend` | 来源接入、设备事实、成员与身份接纳、感知和媒体、房间分析编排、语音交付、聊天转发与 Web 静态托管 |
| `apps/agent`   | 流式聊天与四个只读家庭工具、会话检查点、房间观测描述、语音请求判断及追踪                        |
| `apps/web`     | 登录、设备与房间、成员、摄像头与分析、设备日志、数据库浏览、聊天和设置                          |
| go2rtc         | 摄像头取流与浏览器媒体连接                                                                      |

backend 与 Agent 在独立进程中通过 HTTP 通信，由项目启动命令统一管理。本地感知不依赖 Agent 模型凭据；单独启动方式见[运行说明](docs/running.md#单独启动与检查)。

## 快速开始

需要 Bun ≥ 1.4.2、Caddy 和已运行的 Docker。macOS 可运行 `brew install caddy` 安装入口服务；其他平台见[运行说明](docs/running.md#https-与-http2-入口)。摄像头预览需要本机能访问摄像头所在局域网；Docker 模式请先完成[网络设置](docs/running.md#docker-摄像头网络)。

```sh
bun install --frozen-lockfile
bun run setup
```

编辑生成的 `.env`，使 `POSTGRES_PASSWORD` 与 `DATABASE_URL` 中的密码一致。`POSTGRES_PORT` 设置 Docker 数据库的宿主机端口，须与 `DATABASE_URL` 中的端口一致；若本机 5432 已被占用，可将两处端口设为 5433。使用对话 API 时还需配置 `AGENT_MODEL`、`OPENAI_API_KEY`，按需填写 `OPENAI_BASE_URL`。

```sh
bun run dev
```

首次启动后运行 `bun run web:trust`，按系统提示完成本地证书信任。打开 <https://localhost:8443/>，使用米家 App 扫码登录。设备与摄像头仅接入已选择的家庭；首次使用请在“设置 → 米家家庭”选择要接入的家庭。日常运行 `bun run dev`，停止应用与依赖使用 `bun run stop`，查看状态使用 `bun run status`。`dev` 自动启动并等待数据库就绪、执行 backend 迁移与 Agent 存储初始化，再检查数据库；新增迁移后重新运行 `dev` 即可。只准备数据库时运行 `bun run db:migrate`，无需先启动其他服务。

本机配置与凭据不提交 Git。恢复已有数据库授权时，还需恢复对应的凭据加密密钥；详见[米家与摄像头](docs/mijia.md)。

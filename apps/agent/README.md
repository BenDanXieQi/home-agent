# Agent

## 模型配置

在根目录 `.env` 中为各入口设置 `provider/modelId`，并配置该提供商的认证；示例见 [`.env.example`](../../.env.example)。内置供应商的模型必须存在于 Pi 的清单并通过凭据可用性检查。模型注册与认证由 [models.ts](src/models.ts) 调用 Pi 提供商实现。提示词还需要 [Langfuse 配置](../../docs/agent/prompt-management.md#配置与使用)。

llama.cpp 使用 `llamacpp/<模型 ID>`，模型 ID 取自服务的 `/v1/models`，`LLAMA_CPP_BASE_URL` 填写包含 `/v1` 的服务地址。启用服务器鉴权时设置 `LLAMA_CPP_API_KEY`；未设置时使用 OpenAI 客户端要求的占位 key。上下文容量在 Agent 初始化时从服务 `/v1/models` 的 `meta.n_ctx` 自动读取；服务必须返回该字段。本地模型不记录供应商费用。模型须已在 llama.cpp 中可用，实际能力及请求字段支持以服务为准。

主助手和媒体主会话使用 `AGENT_MODEL`；Workflow 的模型选项见[各自配置](src/workflows/registry.generated.ts)，媒体子分析使用 `AGENT_MEDIA_ANALYSIS_MODEL`。启用音视频分析 Agent 须同时配置两个模型。未配置主模型不影响本地检测与家庭数据接收。启动方式与进程配置见 [Host](../agent-host/README.md)。

## 媒体分析

[独立子分析](src/media-analysis/extension.ts)使用 `media-analysis-agent` 提示词，把中文背景资料和实际视频或音频交给模型，返回中文描述；每次使用全新会话，不继承媒体主会话或其他子分析的历史。媒体协议转换由[供应商适配器](src/media-analysis/providers/)负责。支持 MiMo、百炼 Omni 的 OpenAI 兼容媒体接口和 Gemini 原生接口；llama.cpp 复用 Qwen 媒体请求格式，端点必须支持实际发送的媒体模态与字段。提示词准备与版本发布见[提示词管理](../../docs/agent/prompt-management.md)。

纯音频采用 MP3，减少传输体积。[OpenAI 音频输入](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[MiMo](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/multimodal-understanding/audio-understanding)、[Gemini](https://ai.google.dev/gemini-api/docs/audio) 和[百炼 Omni](https://www.alibabacloud.com/help/en/model-studio/qwen-omni) 均支持 MP3 与 WAV；格式支持不表示任意模型都支持音频理解。

## 音视频分析 Agent

[分析服务](src/media-analysis/service.ts)由 Host 装配，同时设置 `AGENT_MODEL` 和 `AGENT_MEDIA_ANALYSIS_MODEL` 启用，未设置子分析模型时不启动。还需在 Langfuse 中准备 `media-agent` 和 `media-analysis-agent` 提示词，可运行 `bun run --cwd apps/agent prompts:init` 初始化缺失项。Backend 把画面变化、语音或宠物声音选出的同镜头相邻片段合成连续媒体区间，不以本地检测窗口作为模型任务。Agent 当前仅接纳视频区间，纯音频区间不创建分析任务。采集运行或音轨改变、媒体缺口会分开区间；区间末端经过下一次本地检测接纳期，且输入媒体完整可读后进入队列。持续延长的区间在待分析池显示收集中，媒体仍受原有保留期限限制。成员、空间或设备清单尚未就绪时保留队列，恢复后继续处理仍可读取的区间。

每次子分析输入完整的成员与空间中文描述，并注明摄像头、房间、观测区域、该时刻有效的镜头描述和时间。背景、视频与音频的时间均按 Agent 运行环境的本地时区格式化并附带 GMT 偏移，正文沿用该时区；部署时应使 Agent 的系统时区与家庭所在地一致。检测框、身份归因及其证据不进入子分析；摄像头来源标识供媒体主会话补看使用。Host 按整个分析区间读取 MP4 采样视频，有可用声音时合入音轨，不补造缺失媒体。模型任务、结果保存和原片回看均使用该区间，不依赖单个检测窗口 ID。

输入明确标注实际提供的画面与声音。成员、空间和镜头说明仅作背景，不作为事件证据；仅有音频时只描述声音，不能据此确认画面、人物身份或移动路线。看不清、听不清或没有可确认活动时允许直接说明，不强行补齐叙事要素。这些要求通过提示词约束模型，不保证消除无依据的描述；结果仍须与原始媒体核对。

初次区间由 [Pacer 异步队列](https://tanstack.com/pacer/latest/docs/framework/vanilla/guides/async-queuing)调度，按媒体结束时间从新到旧启动，最多同时分析 5 个区间；全局等待容量为当前家庭设备清单中的总镜头数 × 10，双镜头计为 2 个，离线镜头计入，已归档设备不计入。容量随设备清单更新，超额时优先保留最新区间，较旧区间显示已跳过，不会重新入队，已启动的分析继续执行。迟到的旧媒体不会挤掉较新的待分析区间；过期区间不再启动，失败不自动重试。每次读取与分析总截止 120 秒。概述按完成顺序提交给持续复用的[媒体主会话](src/media-analysis/session.ts)，并注明原始媒体时间；它使用 `media-agent` 提示词结合历史判断，历史由框架自动压缩。需要核实时，`read_camera_media` 读取指定摄像头、镜头和时间范围的本地录像，由独立子分析回答问题后继续判断；同轮补看依次执行，不占初次区间的队列名额，也不额外提交概述或保存动态。需要整体主助手处理时，`emit_event` 交接事情说明、时间、位置、理由和不确定性。事件成功表示主助手已接纳输入，不表示判断或设备动作已经完成。

子分析概述与动态保存分别执行，互不阻断；详情保留概述并显示具体提交或保存错误，不因交付失败重新分析。结果保存仍核验当前家庭绑定，不要求分析输入仍在临时待分析池中。完成状态表示子分析已产出结果，不表示媒体主会话已结束判断。中文描述记录在追踪中，成功保存的结果进入 Backend 动态历史，同一区间按来源、时间与媒体类型去重。

调度状态只在内存中，重启后重新接纳当前推送中仍可读取的区间；迟到的新片段只提交尚未分析的部分，已接纳片段不会因旧窗口移出保留范围而重复入队。已启动的分析使用读取时取得的背景资料。运行标识变化不取消分析或清空临时媒体状态；同一家庭保留主会话模型上下文，上下文接收端确认切换绑定家庭时取消分析、清空临时状态并重置模型上下文，历史条目保留。服务关闭取消在途任务并释放资源，主会话保存在 MySQL。媒体读取和结果保存受 Backend 当前访问资格与可用性限制，读取或模型错误显示失败。子分析与调度队列不恢复；当前不提供独立长期记忆库、最新观察写回、延迟补读或自动重试。真实模型端点的连续判断、补看与事件交接效果仍需部署验证。

Web「动态」上方独立展示正在／等待分析任务，观测房间筛选仅作用于该区域；下方按最新在前展示媒体主会话的思考与最终回复，每批 30 条，可继续读取更早记录，并显示每轮开始和结论完成时间。每轮可展开对应的初次分析与补看详情，包括媒体时间、子分析起止时间、实际返回的思考和结论；补看同时注明核实问题。历史从持久条目读取，模型上下文压缩、重置和服务重启不删除这些记录。页面通过 SSE（服务端事件流）接收更新，分析详情按需读取实际送给模型的视频／音频；离开页面不取消分析。仅显示模型实际返回的内容，供应商未返回思考时不补造。子分析完成结果另行保存在数据库，不作为媒体主会话的判断展示。

## 会话存储

家庭主助手与媒体主 Agent 共用一个 Pi Durable Harness，通过 `AGENT_DATABASE_URL` 把主会话保存到 MySQL。工作流（Workflow）和子 Agent 共用内存 Harness，重启后不恢复；返回给主 Agent 的子分析和委派结果随主会话保存。主会话在打开时读取，聊天和未完成任务须在收到带有当前家庭绑定的完整快照后接纳或恢复；运行标识变化不触发任务取消或会话重置，确认绑定家庭改变才取消旧任务并重置所有已保存主会话的模型上下文，包括当前未启用的 Agent。正常会话达到容量阈值时由框架自动压缩。

[MySQL 存储](src/storage/mysql.ts)复用 Pi 的读取与文档重放，把提交追加到数据库；启动时重放全部提交到内存，存储量与启动成本随历史增长。共享存储仅允许一个进程持有数据库连接锁；连接或持久写入失败会停止该存储的后续写入，需要恢复数据库连接并重启 Agent。临时工作区文件不保存，历史文字和结果不延长原始媒体的可读期限。

## Workflow 扩展

空间规划保留持续会话；自动化生成和语音判断为每次请求创建独立 Conversation，请求结束后关闭会话，只返回现有结构化结果。Workflow 使用当前家庭上下文；上下文断线或撤销会取消依赖它的在途读取，确认切换绑定家庭时清理会话。提交、等待和取消使用同一通路；提交工具请求结束执行，错误工具调用由 Pi Durable 原生工具回合处理，一次请求可能调用模型多次。

每个 `src/workflows/<name>/workflow.ts` 必须导出 `extensions`，声明所需的运行时扩展；没有扩展时导出 `[] as const`。运行 `bun run --cwd apps/agent generate` 自动汇总声明，无需修改宿主。具体对话显式选择所需扩展。

扩展和文档定义可以在模块内复用，会话状态由对应的对话持有。浏览器通过 `backend-client` 构建边界使用 Workflow 契约；扩展定义的初始化应能在未使用时被构建工具移除。

会话的流式文本与完整回答由通用进度通路交付，完整回答先于成功结果发送。空间规划结果只包含规划状态与会话信息，不另行返回回答正文。

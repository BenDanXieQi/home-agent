# Web

基于 React、Vite、Tailwind CSS 4、TanStack Router / Query、Jotai、React Hook Form、Radix 与 Motion 的本机家庭工作台。

当前提供账号登录、房间设备列表、房间观测描述、家庭成员资料维护、摄像头预览与分析、短期筛选片段、SD 录像回看、保留帧的人物历史判断、设备日志、家庭数据库浏览、Agent 聊天和设置，尚无行为总结界面。人物判断来自本地参考资料，不代表已核实的家庭成员身份。项目的家庭语义目标见[领域模型规划](../../docs/plans/household-model.md)，不属于当前页面已实现能力。

## 运行

在仓库根目录执行 `bun run dev`，首次运行 `bun run web:trust` 完成本地证书信任，访问 <https://localhost:8443/>。Caddy 把页面与热更新连接转发到 Vite，把 `/api` 转发到 `.env` 中配置的 backend；生产环境执行 `bun run start`，使用同一 HTTPS 入口提供构建页面和 API。Vite 的 `5173` 为内部开发端口，静态预览不提供 API 代理。独立启动 Web 时另运行 `bun run web:dev`；入口配置、证书与停止方式见[运行说明](../../docs/running.md#https-与-http2-入口)。

构建时，`build/precompress.ts` 为 HTML、JavaScript、CSS 和 SVG 生成更小的 Brotli（`.br`）与 gzip（`.gz`）副本，原文件继续保留；字体本身已压缩，不重复处理。压缩副本随 Web 构建产物一起复制到 backend。生产静态响应与缓存策略见 [Backend 静态文件服务](../backend/README.md#静态文件服务)。开发服务器不使用这些预压缩文件。

## 使用流程

移动端底部导航固定显示“房间、成员、看家”和“更多”，其余页面及后续新增入口通过“更多”菜单访问，不提供横向滑动；当前页面属于菜单时高亮“更多”。移动端账号入口位于设置页，机器人显示在顶部标题旁。

设备和摄像头仅展示 backend 所选家庭的范围。在“设置 → 米家家庭”选择要管理的家庭后，页面通过状态订阅显示保存和初始化进展；已绑定时可通过“重新绑定家庭”选择其他家庭。未选择或所选家庭不可访问时设备列表为空。这里的设备清单包括家庭、房间、设备及其归属信息；公共状态是 backend 提供给页面读取的账号、家庭、清单、规格和媒体等信息。

未登录时显示米家登录页，自动获取二维码并在后端报告过期后自动刷新；用户可手动刷新或取消，请求失败后显示重试入口。恢复保存会话和安全验证期间不自动创建新扫码尝试。已保存的授权由 backend 恢复，浏览器不保存账号凭据；恢复失败时可以重试或清除授权。已登录账号窗口只显示账号信息和退出操作，更换账号先退出再扫码。账号授权与扫码尝试分别从公共状态派生为 `account`、`loginAttempt`，摄像头暂停选择随新登录会话或家庭访问失效清空。退出清理失败时保留错误和重试清理入口，清理完成后自动获取二维码。

自动取码的启动条件由 `mijiaCanStartLoginAutomaticallyAtom` 从账号、扫码尝试、命令和读取状态派生。`LoginFlow` 的 effect 仅在启动条件变化时调用 `startMijiaLoginAutomaticallyAtom`；该命令执行前再次读取共享状态，并复用 `performMijiaAtom` 同步设置的 pending 标志防止重复派发。组件不使用 `useRef` 记忆“已经请求过”，因此 StrictMode 重跑和组件重新挂载共用同一启动规则。取码请求失败后停止自动尝试，保留显式重试；按钮操作仍由事件处理器直接执行。扫码任务由 backend 持有，effect 不创建独立计时器，也不在组件卸载时取消服务端尝试。

从根路径开始扫码并登录成功后，先打开设置检查连接状态。已有授权恢复时进入房间页；直接打开或刷新设备、看家、设备日志及设置的深链时保留目标页面。读取首个账号快照期间显示加载状态。导航包含 Agent、房间、成员、看家、日志、数据和设置，并提供账号入口。窄屏使用底部导航，各入口均有可访问名称。工作台标题栏最小高度为 64 像素，进入看家详情等子页时，右侧操作按钮的增减不会改变单行标题的位置。

| 路径                               | 内容                                                       |
| ---------------------------------- | ---------------------------------------------------------- |
| `/`                                | 等待账号快照；恢复授权进入房间页，新扫码完成进入设置       |
| `/agent`                           | 流式聊天、历史会话恢复、连续追问及工具调用详情             |
| `/members`                         | 按成员名称切换标签页、查看及编辑成员资料                   |
| `/members/new`                     | 独立添加人物或宠物，保存后进入新成员标签页                 |
| `/devices`                         | 按房间浏览设备、AI 近况、属性详情、搜索与筛选              |
| `/cameras`                         | 看家：平铺显示全部镜头，为可见及邻近区域的镜头建立播放连接 |
| `/cameras/$deviceId/$channel`      | 查看实时检测、筛选片段及其关联的 SD 录像                   |
| `/cameras/$deviceId/$channel/view` | 放大观看单个镜头，返回看家或进入画面分析                   |
| `/device-logs`                     | 采集设备上报、筛选信号、查看连接记录及比较设备变化         |
| `/data`                            | 家庭成员、上下文及对象关联的记录浏览                       |
| `/settings`                        | 连接检查、服务地址配置，以及摄像头接入重试                 |

摄像头按名称自然排序，同名时按设备 ID 排序，刷新不沿用云端返回顺序。多镜头设备按支持的通道显示，镜头按 1、2 排列。每个镜头各占一格，进入可见区域及其上下 240 像素范围时独立管理播放预约、浏览器实时音视频（WebRTC）连接、重试和出帧状态。滚动离开该范围立即解除显示和解码，未被接管的连接在 1 秒交接期后释放；标签页短暂隐藏时保留播放器和连接，连续隐藏 15 秒后释放连接；缓冲期间返回沿用原连接，释放后返回重新连接。关闭一路不会停止其他画面；用户暂停选择在自动释放资源、媒体运行标识 `revision` 的变化和短暂离线期间保留，切换账号或家庭运行范围后清空，页面切换不清空。`revision` 在媒体失效或重新绑定时更换，用于拒绝旧播放请求。由 backend 管理的 go2rtc 摄像头共享流继续取流；浏览器预览视频不经过 backend，本地感知使用独立分析分支。设备清单中的在线字段只作提示，不单独阻止播放，能否出帧由实际媒体连接决定。使用限制见[米家与摄像头](../../docs/mijia.md)。

房间页（`/devices`）统一展示设备清单和房间观测。顶部以房间切换范围，默认“全部房间”；房间按家庭与房间 ID 区分，包含尚未分配设备的房间，未分配设备单独列为“未分配房间”。选中具体房间时展示该房间的 AI 近况、更新时间和分析入口；全部与未分配范围不展示 AI 近况。搜索、分类、能力和在线状态筛选只影响设备列表，不改变房间分析范围。

设备行展示名称、所属房间、最多两项最近属性与有效性、在线情况，尚未上报的设备仍保留。展开详情查看型号、订阅状态、全部属性（含缺值项）、来源质量、报告／读取／变化时间，以及一次性读取入口；每次最多读取前 100 项可读属性。摄像头画面和日志入口位于设备详情。页面底部的家庭采集诊断提供缺口、丢弃、拒收信息和采集重试，不受列表筛选影响。

设备列表延续浅灰容器与白色设备行，复用虚拟列表、房间选中线和展开动效。设备行独立订阅本设备属性与订阅状态，未变化的属性分组保留引用；设备上报只更新对应内容，不重算房间和分类选项，也不重新播放整行入场；房间、家庭变化后清除展开选择，详情关闭或卸载时取消未完成的页面读取请求。支持系统减少动态效果设置。

设备日志每次采集持续 10 分钟，也可手动停止。页面保留最近 500 条上报，支持按设备、房间、分类和内容筛选，并可比较多台设备的变化。日志页通过路由的 `staticData.contentLayout` 声明使用视口布局：固定在工作台可用视口内，设备列表与日志内容分别滚动，页头保持固定。列表高度随筛选、提示和窗口尺寸调整；筛选区空间不足时可单独滚动，给设备列表和日志内容保留最小阅读空间。宽窄屏共用同一组设备选择器与日志阅读器，只切换面板排列方向，保留搜索、视图、重复上报设置和阅读状态。窄屏展开设备选择时，上下两区均分可用空间，收起后日志区使用剩余空间，并预留底部导航位置。暂停阅读仅冻结当前展示；切换页面也不会停止后台采集。

连接问题由机器人提示，桌面端位于侧栏，移动端位于顶部标题旁。正常或等待连接期间，机器人仅展示活动状态，不提供连接弹窗。异常时机器人旁显示提示点，点击可展开连接说明和“打开设置”入口；连接恢复后关闭弹窗。弹层支持 Escape 关闭与焦点返回。机器人和详情共用 `connectionNoticeAtom`，结合服务可达性和米家摄像头绑定状态。主动检查连接在设置页操作。Agent 未连接不影响已经就绪的摄像头预览。

## 独立图片分析

看家页和登录页的“图片分析”打开 `/cameras/images`，通过独立公开路由使用工作台布局，不经过米家账号门禁，可在未登录、未选择家庭、没有摄像头或媒体不可用时使用。选择、分析与重新选择共用一个 `Button`，各状态保持稳定宽度，图标和文案直接切换。首次选图在准备完成前保持“选择图片”，准备成功后显示“重新选择图片”；重新选图、重试和继续分析在等待期间保留各自的操作来源，分别保持“重新选择图片”“重试分析”和“分析图片”。等待反馈复用 `Button.pendingAction`：前 150 毫秒禁用，持续等待后显示进度图标与可点击的“取消等待”；快速完成时不插入取消文案。准备与分析阶段还由下方状态提示展示。选择文件后显示实际提交 PNG 的预览和尺寸并自动分析，随后展示检测框、类别、置信度、目标数量及默认展开的完整 JSON。重新选择时只在确认新文件后替换输入与结果，取消文件选择保留原内容；准备失败回到“选择图片”，请求失败保留当前图片并显示“重试分析”；本机访问失效后释放图片并回到“选择图片”。取消等待保留已准备图片并显示“分析图片”；尚未准备完成时回到“选择图片”。图片名称旁的 × 直接清除图片与结果并取消在途等待，焦点回到显示“选择图片”的主按钮。页面提供准备、上传等待、忙碌与失败反馈。此入口不管理视频采集，不生成轨迹。

`image-size` 在完整解码前读取并校验图片尺寸，无法确定尺寸的输入直接拒绝；浏览器原生处理图片方向与透明背景，解码后再次校验实际尺寸，预览和上传共用一份 PNG。输入字节、像素及等待限制与 HTTP 行为见[独立图片上传分析](../../docs/perception.md#独立图片上传分析)。页面取消等待并释放对象 URL；替换、清除、离页和本机访问失效后拒绝旧响应，原生准备仍在完成时只继续最新选择。图片页不挂接摄像头播放或感知订阅，后台配置分析继续运行。浏览器上传、取消和持续视频联合负载尚未完成运行验收。

## 看家详情与感知帧查看

实时详情侧栏的“当前成员关联”与画面调试数据并列，显示后台核验的成员名称、完整成员 ID、轨迹、判断状态和观察时间。识别依据不足时显示“疑似”，多次画面识别结果一致时显示“已识别”，同名按 ID 区分。面板复用当前来源的既有感知订阅；定格时继续实时更新并明确说明不属于定格画面。面板分别提示身份分析未启用、状态同步中、来源未配置或不可用、等待首个结果、结果过期及身份分析暂不可用；失同步、来源撤权、运行变化及结果失效后清空当前关联，成员改名更新展示、停用或删除撤销关联。筛选片段继续展示冻结的窗口身份。

画面分析与独立图片分析沿用工作台的内容边距，不额外居中限宽。实时检测与筛选片段共用顶部返回与模式切换区域，镜头标题、房间信息和画面起点保持一致；宽屏均采用左侧画面、右侧信息的两栏布局，窄屏按画面在前、信息在后排列。画面区域固定为 16:9，最高为视口高度的 65%，实际图像完整等比显示；暂无片段、仅文字与加载状态也保留同样尺寸。片段播放器位于左侧顶部，媒体选项和说明在画面下方，右侧展示片段列表、语音与其他详情。实时画面的定格／返回实时操作与播放状态放在同一工具栏，视频 JSON 默认展开，声音原始 JSON 默认折叠。独立图片分析保持自己的画面与结果布局。

看家页每个镜头卡片的“画面分析”进入 `/cameras/$deviceId/$channel`，工作台导航保持选中“看家”。详情按该设备与镜头匹配感知来源，用原生 WebRTC 解码帧、来源媒体代次及 RTP 时间关联检测／跟踪，并支持定格、返回实时与 JSON 查看。未配置感知的来源仍可观看和定格，并明确显示暂无检测／跟踪结果；不自动改看其他来源。后台按配置独立持续分析，看家列表和详情不提供采集管理；进入、离开、定格及返回实时均不启停后台。视频与声音分析使用独立面板；视频 JSON 默认展开并实时更新。实时模式下两个面板全部折叠时停止取样，重新展开恢复更新；定格模式重新展开仍读取原定格快照。视频内容仅在其面板展开时挂载和生成 JSON。定格同时固定画面、框与 JSON，隐藏标签页不重新取样已定格内容，返回实时恢复更新；当前规则见[后台分析与结果校验](../../docs/perception.md#后台分析与结果校验)。独立图片分析使用 `/cameras/images`；详情的“筛选片段”入口查看短期窗口筛选与媒体，并可从片段详情查找对应的 SD 录像。协议、预算和实机验证范围统一见[感知说明](../../docs/perception.md#单路帧关联与定格)。

声音分析位于独立声音面板内，展示音轨状态、声音能量、人声概率、后台阈值判定和分块时间区间；原始 JSON 默认折叠，仅展开时挂载并生成，折叠后停止序列化。折叠整个声音面板会卸载其内容，重新展开时原始 JSON 恢复默认折叠。视频与声音共用一次 250 ms 取样和定格快照，声音区间独立于视频帧；页面按 `sources[].audioTrackRunId` 关联音轨，核对家庭范围、设备与镜头资格，不依赖视频计算是否就绪。声音分析只提供能量与人声活动检测，不转写内容、识别说话人或描述环境声音；最新分块持续替换，不保留完整说话记录。无音轨、输入不足、过期与失败不推导成“无人声”。时间基准、共享音轨语义及已验证和未验证范围统一见[声音分块查看](../../docs/perception.md#声音分块查看)。

`PlaybackSession.attach()` 为已有连接挂接原生视频或 Canvas 展示；Canvas 回调按需读取接收轨道的克隆，切换展示时取消读取并停止克隆，不终止原接收轨道。回调借用 `VideoFrame` 及该观看的媒体代次，回调同时提供同一帧元数据中的 `rtpTimestamp`（90 kHz 来源时间），不把 `VideoFrame.timestamp` 当作 RTP 时间。观看会话在回调结束后释放原生帧，读取者不能保留它；页面展示控制器持有自己的有界位图。帧身份契约来自根目录 `packages/api`。普通观看以 `<video>` 为显示面，关联观看以 Canvas 为显示面，共享观看会话；后者要求 `MediaStreamTrackProcessor` 和 `VideoFrame.metadata().rtpTimestamp`。感知订阅使用类型化 RPC 读取一条页面级 SSE，断开暂停实时结果接纳，离页取消读取并释放 reader（流读取器）。

### 窗口筛选与媒体

画面分析页提供“实时检测”（当前画面与检测结果）和“筛选片段”（后台筛选的历史短片段，`?mode=windows`）。筛选片段按当前家庭、设备和镜头展示，直接进入不会创建实时观看连接；切换模式不影响后台持续分析，也不把当前检测框叠加到过去片段。首次打开筛选片段后，在同一镜头详情内切换到实时检测会保留片段页、选中项、已加载媒体及播放位置；隐藏时暂停播放并停止窗口请求，返回后可从原位置继续播放，无需重新下载已加载媒体。首次只看实时检测不加载片段页；离开镜头详情、切换镜头或家庭运行范围时释放这份页面缓存。

通过筛选的窗口自动生成默认媒体：视觉候选保存全景采样视频，有完整音轨时携带声音；纯音频候选保存声音。片段关闭后最多保留 30 分钟，全部摄像头的磁盘缓存及在途编码预留合计最多 1 GiB；容量满时优先清理最旧且未在读取的产物。时间、容量、摘要预算和访问资格均可能提前结束可读性，不保证任何负载下留满半小时。此功能不调用 LLM，也不建设语义任务队列。

列表在前台读取来源过滤后的轻量摘要，有排队或生成中的片段时每秒更新，其余时候每四秒更新，与窗口关闭周期一致。后台只接纳画面变化达到阈值或已有非空语音转写的窗口，页面直接展示后台记录，不提供筛选开关；一次显示 50 条，可继续显示更早片段。仅建立比较基准的首帧、静止画面、单纯声音能量过阈或只有人物判断不保留为历史，也不生成媒体。来源为连续比较独立保留一张有界前置帧，触发跨窗变化时会连同该帧一起回放。等待转写期间只保留有界的关联元信息，不为未通过窗口保留回放画面和声音；迟到文字到达后形成文字记录，不恢复已丢弃的媒体。未开启转写时只有画面变化能形成记录。画面变化不表示已确认有人走动，转写不确认说话人或排除电视声。列表区分排队、生成中、可播放、失败和已清理，并给出语音段数、人物轨迹数及当时已确认的本地标签。尚未选择片段且列表中只有一个未过期、可播放的片段时自动选中；选中后保留当前内容，新片段到来不切换。选择片段后读取详细事实并直接加载已生成的默认媒体，无需再点击申请。显示的“最晚保留至”属于压缩媒体期限，原始像素的短期保留期限独立存在。

详情的“语音文字”按音轨运行、媒体代次和实际音频区间关联本地转写，跨窗口语音保留完整文字并标注延续关系，不推断说话人。窗口关闭后仍可补充在期限内完成的转写，列表版本变化会刷新详情且不卸载已打开的媒体；无文字、未启用和条数截断分别提示。

详情的“当时人物判断”只读取每张保留帧的 `identity` 历史快照，按帧时间展示当时的分析状态、人物轨迹、本地参考标签、支持证据数与最近证据时间，不读取来源的最新身份状态。未收到准确帧结果、当时未启用、缺少人物判断和当时识别尚未完成分别显示；未收到结果不推导成无人，历史中的未完成状态不显示为当前加载。后续识别不会回填或改写这些判断，本地标签也不代表已核实的家庭成员身份。SD 回看中的“保留帧”定位按钮使用相同帧编号；判断仍只属于这些采样帧，不随播放器进度更新，也不扩展到整段录像。

原始输入仍可读时，可以显式生成其他全景／裁切图片、视频或声音表示；原始输入释放后，仍可切换类型和声音选项，读取已保存的媒体，但不能生成新的媒体。每种媒体按自己的状态判断是否可读取，默认片段被清理不影响其他仍保留的媒体。没有合适裁切区时显示实际使用全景。排队或生成中每 500 毫秒只读查询；申请响应丢失后只读核对结果。临时网络或服务器错误最多重试三次，重试间隔逐渐延长；明确不存在或已失效的窗口停止自动查询，显示不可用。编码失败仅在原始输入仍可用时允许手动重试，不自动重复编码。

当前选择不被新片段、列表过滤、摘要移除或列表读取失败替换。家庭状态连接暂时失联时，暂停新请求、生成和重试，保留当前选择及已经加载的媒体；同步恢复后重新核对后台生成状态。已经完整加载到浏览器的一份媒体（最多 4 MiB，不含解码资源）可以继续播放和拖动；切换片段、媒体类型、镜头、家庭或离页时释放。后台清理后，已释放的浏览器副本不能再次下载；确认访问撤销时清理当前查看。到期使用一次性通知，JSON 仅在展开且数据改变时生成。HTTP 错误结构化保留状态码，可解析的 JSON 错误附带服务端原因。

媒体文件属于单个 backend 运行期间的临时回看缓存，不写入家庭数据库；正常停止删除产物，重启清理上次中断遗留的自有文件，不恢复旧引用或播放列表。浏览器刷新不重启 backend，仍可重新读取保留范围内的片段。资源预算和未完成验收见[感知说明](../../docs/perception.md#媒体窗口筛选与按需读取)。

### SD 录像回看与事件定位

SD 录像在准备、可播放、过期、撤权及不可用状态下保留相同的画面区域尺寸，原生播放器在区域内完整等比显示。窗口详情的“查找 SD 录像”使用仍保留的事件摘要，不要求原始像素或本地采样媒体仍可读取。有画面变化或转写的窗口摘要最长保留 30 分钟，未接纳的窗口只保留转写等待期间的关联元信息且不开放查询；此入口不延长摘要期限、不把事件写入数据库。有对应 SD 录像时可在片段详情内播放；摘要过期后无法再申请查找。

准备完成后，原生视频播放器直接读取有访问校验的媒体 URL，按播放和拖动需要读取文件范围，不先下载整个文件到浏览器内存。回看从所选录像开头开始；窗口事件只有在后端把多张保留帧与录像中的画面唯一对应并核对时间间隔后，才自动定位事件，显示误差范围及按保留帧编号定位的按钮。缺少这种证据时只展示附近时段的候选录像，不把本机接收时间换算成准确播放位置。录像时段和缺口可在播放器下方展开查看。浏览器事件定位按钮跳转到非零位置的端到端验收仍未完成。

每次回看由独立资源持有。准备期间可取消；创建响应丢失时沿同一标识恢复状态，不重复建立新资源。切换录像、关闭、离页或来源访问失效后取消请求并释放资源。回看缓存仅属于当前 backend 运行，申请后最多保留 30 分钟，也可能因容量或访问资格提前失效；媒体读取仍须通过当前家庭和来源校验。SD 回看不重新生成人物判断或转写，也不读取最新结果补到历史画面。窗口附近候选下载或校验失败不会使其他可用候选一起失效；候选证据不完整时取消精确定位，只播放附近的有效录像。协议、媒体预算和来源限制见[米家与摄像头](../../docs/mijia.md)。

## 代码组织

- `src/app/`：创建应用共用的 Jotai Store 和 QueryClient；`StateProvider` 通过 `AppStateEffects` 装配家庭订阅及配置保存生命周期，将 Store 显式传给订阅。
- `src/api/`：公共 HTTP 客户端、响应校验、取消、超时、重试和结构化错误。传输层不读取 Store，也不依赖界面文案；错误展示由 `messages/zh-CN.ts` 负责。
- `src/modules/household/`：家庭公共快照、状态订阅、纯版本确认规则、同步状态与提示、家庭选择查询，以及共享的 `HouseholdAccess` 访问提示。
- `src/modules/devices/`：从公共快照派生设备清单、同步状态、数量和能力异常；提供设备分类文案与清单错误提示。搜索和筛选属于设备页面。
- `src/modules/mijia/`：`account.ts` 读取账号与扫码尝试，`login.ts` 派生登录展示和自动启动条件，`commands.ts` 统一协调命令互斥、取消和回执确认，`connection.ts` 派生连接重试资格，`api.ts` 转换米家控制协议。账号头像与连接重试入口在该领域内复用。
- `src/modules/perception/`：看家父路由持有一条页面级感知订阅及访问校验，列表和详情复用；每个详情持有自己的来源状态；`source-state.ts` 派生访问资格、当前来源及播放目标，`state.ts` 接纳只读结果，`use-perception-subscription.ts` 装配共享订阅，`source-access.ts` 保存跨列表／详情的设备移除版本，`use-frame-viewer.ts` 装配连续位图展示、帧身份匹配、定格及资源释放。结果通过 Store 订阅直接交给展示控制器；`CameraInspection.tsx` 独立负责声音摘要与 JSON 展示，仅在至少一个分析面板展开且实时观看时定时取样，`CameraAudioAnalysis.tsx` 展示实际音轨状态及能量／人声分块；取样不重渲染播放器区域。定格快照由查看会话持有，折叠不丢失；画面不依赖 React 更新逐帧绘制。独立图片由 `image-analysis.ts` 准备实际提交 PNG 并通过类型化 RPC 上传，`use-image-analysis.ts` 持有输入、响应与取消边界，`ImageAnalysis.tsx` 展示选择器、预览、框和 JSON。窗口请求及查询配置由 `windows.ts` 适配媒体契约，`use-window-media.ts` 协调申请、结果核对与取消，`use-window-input-state.ts` 管理到期通知。`CameraAnalysisLayout.tsx` 统一实时检测与片段的左右分栏；`CameraWindows.tsx` 持有稳定的布局、窗口选择与轻量列表，通过 `use-window-detail.ts` 按需读取完整事实，`WindowDetail.tsx` 展示详情。切换片段只重置媒体与详情，列表滚动位置和按钮焦点保留；媒体加载、不可读取及解码失败均保留画面区域尺寸。`WindowIdentity.tsx` 只展示保留帧的历史人物判断，`WindowSpeech.tsx` 展示窗口关联的完整语音段及接纳期限，`WindowMedia.tsx` 展示媒体选择和申请状态，`WindowMediaPreview.tsx` 持有原生预览与媒体引用清理；窗口展示文案集中在 `window-presentation.ts`。
- `src/modules/recordings/`：`api.ts` 适配 SD 回放资源契约，`use-recording-playback.ts` 持有申请、状态恢复、到期和释放，`RecordingPlayer.tsx` 管理原生播放器及已证实的事件定位。`WindowRecording.tsx` 把保留窗口接到 SD 回看。
- `src/modules/playback/`：`access.ts` 派生播放资格，`state.ts` 提供媒体状态及观看阶段汇总；`page-activity.ts` 用 Jotai atom 管理播放活动状态，首次订阅时监听标签页可见性，最后一个订阅解除时清理监听与隐藏缓冲计时器；`session.ts` 持有浏览器媒体资源，`api.ts` 接收完整播放目标并发送请求，`history.ts` 处理本地存储，`environment.ts` 观察浏览器环境，`estimates.ts` 保存纯样本规则。`use-playback-session.ts` 为原生视频和 Canvas 共用会话接管、`useSyncExternalStore` 快照读取及 Jotai 阶段注册；`use-mijia-playback.ts` 负责原生视频元素适配。`PlaybackProvider` 随看家父路由存续，按家庭作用域、媒体版本、设备和镜头复用会话；子页卸载只解除显示并释放使用权，1 秒内同一路接管会沿用 WebRTC 连接，超时无人使用才关闭。进入分析时另外保留列表当时正在使用的连接，隐藏画面立即解除显示和帧处理，返回列表再接管；只保留这一组来源，不累积滚动浏览过的连接。返回列表时首次渲染读取保留会话的当前快照，已经收到首帧的会话恢复显示时不再展示首次加载遮罩；尚未收到首帧和真正重新建立连接时仍显示加载，播放错误保留错误提示。离开看家模块、来源撤权或媒体版本失效时立即关闭，标签页连续隐藏 15 秒后关闭，显式重新播放会重建连接。画面和媒体资源由会话持有，不放入 Jotai；工作台只汇总正在展示的轻量播放阶段。
- `src/modules/connections/`：服务配置、连接检查、健康查询及派生提示。
- `src/modules/members/`：成员资料查询、保存和删除请求；筛选和编辑状态由成员页面持有。
- `src/modules/device-logs/`：日志快照与采集命令确认、HTTP 请求和状态订阅；`use-device-logs.ts` 将页面生命周期连接到订阅。
- `src/pages/<页面>/index.tsx`：路由入口及页面组合。设备筛选、日志设备选择、对比选择、筛选与分组纯函数均就近放置；`workspace/` 负责账号路由门控、弹窗状态和跨领域活动提示。`WorkspaceFrame`、`SidebarFrame`、`WorkspaceNavigation`、`WorkspaceHeader` 供加载态和正式工作台共用。
- `src/components/`：不依赖业务状态和请求的通用界面组件，通过 props 接收内容和交互。`Notice` 与 `StatusNotice` 统一提示布局及错误／状态语义。`BackLink` 统一页面返回入口的尺寸、箭头、悬停、按下和键盘焦点样式，使用带目的地文案的路由链接返回所属页面；页面只指定目的地和布局间距。
- `src/utils/`：通用纯函数、动效配置及不依赖业务状态的交互 Hooks。
- `src/pages/cameras/camera-transitions.css`：看家列表、放大观看和画面分析之间的原生画面过渡，由看家父路由加载；视频图像与黑色背景分别缩放。
- `src/index.css`：字体、主题、全局基础规则和共用动画；组件布局和交互样式跟随对应组件。

每份状态只有一个所有者：家庭订阅写公共快照，命令只写请求元数据和确认条件，播放器持有自己的媒体资源。页面读取所需领域状态，不经一个聚合全部业务的 Hook；领域模块不依赖页面，通用组件不依赖领域模块。应用装配负责注入 Store，HTTP 适配函数通过参数取得调用上下文。

同步状态由 `householdSyncStatusAtom` 表达为 `connecting`、`confirming` 或 `synced`；界面另用 `householdSyncMessageAtom` 派生提示文字。业务判断读取状态，未同步和等待回执以普通提示展示，不冒充请求失败。

开关的键盘操作与无障碍语义由 Radix Switch 提供，按压与拖动由 Motion 手势处理。日志页在宽屏使用 `react-resizable-panels` 管理面板宽度、指针调整和键盘操作，设备列表宽度限制为 200–380 像素；窄屏使用上下排列。

基础组件的属性从实际渲染目标推导：原生元素使用 `ComponentProps<"span">` 等类型，Motion 与 Radix 封装使用 `ComponentProps<typeof 目标组件>`。只额外定义组件自己的语义属性，内部管理的属性通过 `Omit` 排除；其余属性（包括 `ref`）透传到对应元素，`className`、样式和事件按组件职责合并。内部测量与调用方共用元素时，通过 `useComposedRef` 合并引用并保留 React 19 回调 ref 的清理。业务组件从协议、Store Hooks 或子组件推导已有输入类型；路由页面不为了统一形式添加无用途的 DOM 属性。

工作台页面挂在无路径的 `account` 父路由下。`AccountGate` 统一处理首个账号快照、未登录界面、根路径登录后导航和账号失效，保留设备／摄像头／设备日志／设置的目标 URL；`pages/workspace/index.tsx` 的 `WorkspaceLayout` 负责工作台布局。`AccountGate` 读取已有的家庭公共状态，不额外发鉴权请求；同账号恢复期间可展示已保存的设备清单，但不能据此开始读取或播放。界面的登录检查不阻止路由模块预加载，也不替代 API 的访问校验。

`RetryConnectionButton` 复用派生 atom 的重试条件与运行状态，登录、看家和设置页不各自判断。`RequestFeedback` 分别展示可重连的状态同步提示与操作错误；字段级校验继续由表单处理。活跃扫码状态判定由共享协议模块提供，供登录材料读取和界面共同使用。

登录界面和工作台共用 `loginViewAtom` 组合公共登录状态、当前版本的登录材料与命令结果。日志页以服务端持续推送事件的连接（SSE）为展示数据源，开始／停止采集由状态层统一记录请求、确认和错误，按钮与机器人共用 `deviceLogCaptureAtom`，不保存另一份展示快照；冻结历史用于阅读，属于独立的界面状态。 同一家庭返回日志页保留已知数据并重新连接，切换家庭才清空显示。采集回执由对应任务状态或请求结束后重新订阅的完整快照确认，确认后即消费回执，后续断线不会重新激活旧操作；网络超时只有在推送已显示对应启动或停止效果时才消除提示。控制状态立即渲染，仅日志内容延后渲染。手动服务检查等待配置和服务状态两个请求都结束后才结算，单个请求提前失败不会提前解除忙态。

家庭公共状态由应用级 SSE 订阅写入 `householdSnapshotAtom`，每个标签页共用一条连接，页面切换不会重复建立订阅。派生 atom 从这份状态计算界面所需字段。服务配置、服务检查和 backend 健康检查继续使用 `serviceConfigQueryOptions`、`serviceStatusQueryOptions` 和 `backendHealthQueryOptions` 的 Query 缓存；二维码与安全验证材料按登录尝试 ID 和材料版本单独读取，不进入公共状态。

`performMijiaAtom` 是可写的异步 atom，接受 `MijiaCommand` 判别联合类型，支持 `startLogin`、`verifyLogin`、`cancelLogin`、`retryConnection`、`logout`、`refreshDevices` 和 `selectHome`。React 组件通过 `useSetAtom` 调用，组件外通过同一应用 Store 的 `appStore.set` 调用。命令默认互斥并取消过时的请求；验证码提交期间继续接收 SSE，取消登录和重新扫码可以中止当前验证等待并发起新命令。每次命令持有独立请求序号及取消控制器，旧响应、错误和结束回调不能覆盖新命令。

命令按自身所需信息发起，不以 SSE 已连接为通用前提。首次选择家庭和刷新设备清单必须有已取得的 `scope_epoch`，断流时可携带最后已知值，由 backend 拒绝过期作用域；没有标识就不发送请求，也不补空值。取消和验证登录必须指定尝试 ID。退出、手动开始登录和重试连接使用对应账号命令，不要求先取得快照；首次状态仍不可用时，登录页提供手动登录和清除授权入口。自动取码继续要求公共状态已同步。

命令响应只返回操作结果和 `state_version`，不写入公共快照。HTTP 请求结算后立即释放请求锁；`mijiaCommandSyncPendingAtom` 独立表示页面是否已看到接纳版本，未追上时提示“操作已接收，正在等待状态同步…”，不把已接受的操作改报失败，也不占用命令锁。确认条件是同一 epoch 的 sequence 已达到回执，或 HTTP 结算后重新订阅取得完整当前快照；后者允许后台已经进入比回执更新的作用域。界面反馈由 `commandFeedback` 统一区分请求中、等待确认、成功和失败；家庭绑定与重新连接控件在等待确认期间保持忙态，状态连接失败时允许手动恢复。这份确认不表示后台设备清单刷新已经完成。浏览器至 backend 的网络及超时提示可在新状态消息到达后消除，验证码拒绝等业务失败不会因此清除。

退出期间暂停新播放；HTTP 成功后，旧快照和旧心跳不能越过回执恢复播放，须满足上述版本或完整快照确认。HTTP 结果不确定时，须重新订阅取得完整快照。`householdSnapshotReceivedAtom` 只记录完整快照的接收次数，普通增量和心跳不递增它。单纯 SSE 短断不额外限制播放，也不拆除已有画面；账号替换和媒体重建仍由 `revision` 使旧播放失效。验证码只存在于表单和当前请求执行过程中，提交后清空表单，不进入 MutationCache 或界面 atom。

恢复登录与重新绑定是后台操作：HTTP 202 表示请求已接收，`restoring`／`installing` 等进展通过 SSE 更新。相关按钮结合当前 HTTP 请求与已同步的服务端忙态防止重复触发；断流后的陈旧忙态不阻止手动重试。

服务配置使用 Query mutation，其 observer 在切换页面时保持存活。所有本机 API 查询与 mutation 均使用 `networkMode: "always"`，浏览器的 offline 事件不会阻止请求本机 backend；实际请求仍受超时限制。

## 状态订阅与播放

家庭、设备日志、感知和房间分析订阅共用 `src/api/event-stream.ts`：原生 `TextDecoderStream` 与 `eventsource-parser` 的 `EventSourceParserStream` 负责解码和事件解析，`pipeTo` 传递取消并释放流锁；适配器统一处理响应检查、缓冲／消息大小限制和接收期限。各领域只维护快照接纳、版本、业务通知及自己的重连策略，不再各自拼装字节读取循环。

登录、授权恢复、设备加载和摄像头绑定进展通过同一 SSE 订阅更新，不轮询米家状态。新连接先接收完整快照，再按连续版本应用变化；断流时可保留旧显示并标为未同步，切换账号或家庭时清除旧快照。自动重连、手动重连和页面恢复可见都遵守同一最早重连时间及服务器 `Retry-After`。服务连接仍每 10 秒检查一次，backend 健康状态仍每 30 秒检查一次；这些 Query 检查在后台标签页暂停，恢复焦点或网络连接后刷新。

看家页使用应用已有的公共状态；尚未收到状态时显示确认提示，页面挂载不触发设备清单刷新。开始播放要求账号、所选家庭和媒体连接均已就绪，镜头位于可见区域或其邻近范围，且用户未暂停；退出操作还须按命令回执或之后重新取得的完整快照确认作用域。普通设备清单刷新及短暂错误保留观看连接；新登录会话或家庭访问失效、设备访问撤销、媒体运行标识 `revision` 变化时清理对应旧观看资源。播放器的 key 包含 `revision`、设备和通道，无关状态更新不会重建连接；暂停选择由 `modules/playback/preferences.ts` 的共享 atom（界面状态单元）统一持有，按家庭运行范围隔离；列表和放大观看页共同读取与更新，切换页面、短暂离线及媒体重连不丢失选择。

播放预留和描述媒体连接参数的 SDP 信令通过 backend 完成，视频经 go2rtc 的 WebRTC 连接直接到达浏览器；协商成功不等于已经出帧。`CameraWall` 共用一次标签页可见性订阅，每个镜头观察自身与视口的距离。标签页短暂隐藏时保留播放会话，连续隐藏 15 秒或滚出邻近范围后卸载并释放观看预约、浏览器连接及媒体轨道；释放后重新可见时建立新的观看预约，保留用户的暂停选择。后台共享流继续取流。资源术语见[组件与资源](../../docs/mijia.md#组件与资源)。

`PlaybackSession` 在 `modules/playback/session.ts` 中管理观看连接、可见性、帧回调、超时和释放。`use-mijia-playback.ts` 负责 React 订阅和播放状态 atom 注册。家庭作用域 `scope_epoch` 从看家页面显式传入播放会话与预约请求；没有已知作用域时不创建播放组件，预约适配函数不读取全局 Store 或补空标识。预留请求与浏览器准备并行；原有连接响应同时提供源活动状态和后端实测耗时，没有额外的播放进度请求或首帧上报。

视频卡片的“放大查看”进入独立观看路由 `/cameras/$deviceId/$channel/view`，保留工作台导航与标题，画面占满剩余内容空间并保持完整比例。`CameraView.tsx` 提供“返回”、Esc 返回和“画面分析”入口；浏览器返回、前进和刷新均使用实际路由。观看页复用 `MijiaPlayer` 与看家父路由持有的播放会话，列表与观看页之间接管同一路连接，不重新建立观看预约；独立打开或刷新时按当前家庭的设备访问资格建立连接。暂停、重新播放和错误提示沿用播放器行为。

`MijiaPlayer.tsx` 的视频区域在等待、暂停、恢复播放之间保持同一个节点，播放资格变化只接管或释放会话，不替换参与缩放的视频区域。`modules/playback/media-aspect.ts` 按家庭运行范围保留各镜头实测宽高比，原生视频读取媒体元数据和尺寸变化，分析画布读取当前展示帧尺寸，路由接管时复用该比例。视频图像尺寸由 CSS 容器查询单位计算，不逐帧测量布局。`MijiaPlayer.tsx` 负责视频容器和操作，`PlaybackStatus.tsx` 负责状态栏，`playback-presentation.ts` 集中派生文案。只有可见且等待首帧时才挂载本地计时器，恢复可见立即读取当前时钟。首帧由 `requestVideoFrameCallback` 确认，实际连接用时和历史记录直接在浏览器完成。中央加载动效在首帧后淡出，不映射耗时百分比；减少动态效果偏好下保持静态。

实时检测只对网络、连接中断和出帧超时等可恢复错误自动重试，每次观看连续失败最多重试三次，等待间隔为 2、4、8 秒；收到画面后重置预算。浏览器能力缺失和响应校验失败保留错误，不自动重新协商，页面提供“重新播放”入口。

`modules/playback/estimates.ts` 提供纯样本规则和剩余等待估算，`history.ts` 在 `localStorage` 中按组保存有界记录，每次只写本次连接所属的一组。刷新或重新打开可复用历史，多个标签页不实时同步，同组并发保存允许最后写入覆盖。`environment.ts` 监听当前页面可识别的网络变化，排除跨环境连接样本。存储失败不影响播放。范围只在收到连接响应且有足够本地样本时显示；详细规则见[播放资源](../../docs/mijia.md#http-与追踪)。

普通选择控件使用 Radix Select 管理键盘导航、焦点与输入定位；日志设备类型搜索选择使用 cmdk 管理搜索和选项导航，Radix Popover 管理弹层与焦点返回。界面只适配业务值和样式。

React Hook Form 在刷新时保留已修改的服务地址，保存成功后重置表单基线；离开确认弹窗保护未保存的编辑，取消离开后恢复原焦点。账号窗口关闭后，桌面端焦点回到侧栏账号按钮，移动端回到设置页账号入口。

侧栏顶部的主题机器人统一显示当前页活动。`createWorkspaceActivityAtom` 接收当前路由，在 Jotai 中直接组合服务查询、操作 mutation、家庭公共状态、账号授权、播放状态和日志状态；`WorkspaceBrand` 只订阅派生结果并渲染。页面不注册或回写机器人展示信号。每路播放的状态 atom 由播放 Hook 持有并在挂载期间加入播放器集合，媒体对象不进入共享 Store；日志订阅在收到上报时直接更新日志 atom，列表通过 `useDeferredValue` 延后渲染，机器人读取同一数据源。本机服务离线优先于当前页活动，其后依次是处理中、需要注意和持续监听；自动服务轮询不触发忙态。多路摄像头只驱动同一个侧栏机器人，卡片保留各自的状态文字及等待圆点。空闲偶尔眨眼，处理时轻微歪头，结束后从当前姿态平滑回正，连续状态切换从正在显示的姿态接续；监听时侧头，异常提示一次后保持静态，离线时垂眼；悬停机器人可查看具体状态，减少动态效果偏好会停用动画。

登录页和工作台各路由按需加载；账号窗口随工作台外壳加载，首次打开不等待额外代码。侧栏导航仅在悬停或聚焦时预加载目标路由。设备与摄像头路由分别静态引入自己的列表或播放器，共用 `HouseholdAccess` 的家庭访问与同步提示，数量、能力错误和恢复入口由各页面组合；共享组件不引入设备列表或播放器。因此加载设备路由不加载摄像头播放实现，页面内部也无需新增代码加载等待。整页淡入只在一级导航切换时播放；看家列表、放大观看与画面分析详情之间切换不重新淡入整个内容区。看家列表、放大观看与画面分析详情通过浏览器原生 View Transition（页面画面过渡）按设备与镜头分别关联视频图像和黑色背景，以 320 毫秒动画放大或缩回；图像边界始终按实际宽高比计算，黑边随背景与图像的边界一起连续变化；动画期间只显示原画面的单层快照，结束后交回实时画面，标题、按钮和其他镜头不参与缩放或新旧画面混合；进入时更新观看或分析 URL，两种页面均提供“返回”按钮并支持按 Esc 返回看家列表；返回按钮、Esc 和浏览器返回完成后，焦点恢复到同一镜头对应的放大或分析入口，镜头已移除时放到主内容区，浏览器前进和返回也使用相同过渡。直接打开观看或分析页面不播放卡片放大；系统启用减少动态效果时直接切换。动画需要浏览器支持带类型的 View Transition。Motion 动画功能异步加载，过渡遵循减少动态效果的系统偏好。组件布局、尺寸、颜色、响应式和交互状态直接使用 Tailwind 类名；公共组件通过 `tailwind-merge` 合并调用方样式。类名必须以完整字符串出现在源码中，条件样式使用完整类名映射或 `data-*`、ARIA 状态变体，不能拼接类名前缀和变量。`src/index.css` 只维护字体、主题、全局基础规则和共用动画，不放页面或组件样式类。

## Agent 聊天

侧栏“Agent”（`/agent`）提供聊天页，可发送消息、连续追问、停止回答、开启新对话，通过历史侧栏选择已保存的会话；侧栏可展开或收起。欢迎页示例问题只填入输入框，不自动请求模型。Enter 发送，Shift + Enter 换行，中文输入法确认不发送。回答使用 `react-markdown` 与 `remark-gfm`，支持标题、强调、列表、引用、表格、任务列表和代码块；宽表格和代码块可横向滚动。原始 HTML 不执行，图片仅展示替代文字，链接在新标签页打开。用户消息和工具详情按纯文本展示。

页面按消息轮次、输入区和历史侧栏组织。流式文本按浏览器动画帧合并更新，历史轮次与侧栏保持独立渲染，Markdown 使用延迟值解析；结束或失败时立即提交剩余文本，不依赖下一帧。

通过类型化客户端调用 `POST /api/chat`，消费回答文字、工具开始／结束和执行终止事件。每个工具可展开名称、参数和返回内容；返回预览最多 16,000 字符，截短时标注，模型获得的工具结果不受此预览限制。“已返回”表示工具返回了结果，结果中仍可能包含查询失败或信息不可用。执行信息显示 `runId`。

历史侧栏按最近更新时间列出会话，以首条用户消息作标题，每页 10 条，可刷新和加载更多。聊天结束或人工刷新时收回已加载页，只重新请求第一页，后续仍可加载更多会话。点击会话读取已保存的用户消息、Markdown 回答和工具结果，默认展示最近 10 轮，可加载更早消息。正常完成的会话可以继续追问；仍在运行或执行中断的会话显示提示，可重新加载或新建对话。刷新页面后可以从列表重新选择会话，不自动选择旧会话。历史列表使用 TanStack Query 分页，按家庭运行范围隔离缓存，退出页面后丢弃缓存。

页面离开、切换家庭运行范围、选择其他会话或点击“新对话”会取消进行中的请求；只清空当前界面，不删除数据库中的旧对话。家庭重新绑定按原有规则清空 Agent 检查点及历史。流未收到明确完成事件时显示未完成，不自动重发；停止或失败时后台可能已经保存输入与部分执行。等待模型期间可停止，客户端静默期限为 135 秒。

聊天需要 Agent 模型和会话数据库可用，家庭查询还需要当前家庭就绪。设备和成员工具的能力与时效约束见 [Agent 家庭查询工具](../agent/README.md#家庭查询工具)。当前不提供设备控制和人宠位置查询。真实模型调用与浏览器完整交互仍需在本机运行环境验收。

## 家庭成员

侧栏“成员”（`/members`）与“房间”同级。每个人、每只宠物各占一个以名称标识的标签页，使用房间页的下划线切换样式；成员较多时可横向滚动。下方展示当前成员的基本资料、AI 成员画像区域和最近活动，顶部显示人数与宠物数量。标签页按稳定成员 ID 区分，重名不会合并；选中项保存到 `member` 查询参数，刷新后保留，无有效选中项时展示第一位成员。

“添加成员”打开独立页面 `/members/new`，保存后返回并选中新成员；取消或返回不保存。当前成员的“编辑资料”在其标签页内打开表单，编辑期间暂停成员切换；后台刷新失败只显示错误，不卸载已有表单或清除未保存字段。添加成员保存期间保留顶部返回栏并禁用返回，避免表单位置变化。人物填写名称及外观描述／备注，宠物额外填写物种。保存后把资料写入数据库；已登记成员的类型不可修改。删除须在确认弹窗中确认，只移除成员资料，保留历史上下文。这里管理手动登记的资料和人物识别参考，不显示当前身份关联、当前位置或行为总结。

人物详情的“成员识别参考”提供“从摄像头录制”和“上传照片”两个按钮；猫狗只提供“上传照片”。上传按钮打开文件选择器，人物照片要求单人，猫狗照片要求单只对应物种的宠物。上传后提取裁剪和识别特征，挑选候选并保存，自动启用个体识别。标题旁显示已保存数量与容量，没有照片时显示添加引导。进入录制或候选挑选时隐藏添加入口，录制区域内可取消返回，录制或提取期间使用对应的取消操作。录制区域打开期间暂停删除已保存照片。模型未就绪时，录制与上传入口均禁用。录制按“选择摄像头 → 录制（最长 15 秒，可提前结束）→ 提取人脸照片 → 挑选并保存”推进。选择器来自当前家庭的完整设备清单，显示名称、房间及镜头，不要求来源加入后台检测，也不要求选择人物轨迹。实时预览就绪后才可开始；浏览器通过原生 `MediaRecorder` 录制当前摄像头的视频轨道，不录音。录制显示秒数和进度，可点击“结束录制，挑选照片”提前进入提取，最长 15 秒自动结束。默认通过当前电脑或手机的浏览器语音在开始、第 5 秒和第 10 秒提示拍摄：提示正对镜头和左右转头；录制结束时提示正在提取、随后挑选保存。语音可在录制前关闭，语音不可用时仍展示文字引导；不调用摄像头扬声器，也不自动判定角度是否采齐。结束录制保留已有录像，取消录制才丢弃；取消、离开页面、隐藏标签页和视频中断均终止当前登记等待，不保存参考照片。录制要求浏览器支持 WebM/VP8 或 MP4，暂不支持时可上传照片。

提取完成后显示至多 12 张识别参考候选；候选默认不勾选，用户需核对归属，可按剩余参考容量勾选多张，一次确认保存。页面区分录制中、提取中、候选待确认和登记完成，完成提示明确显示保存数量；空候选、模型不可用、提取失败、确认过期均显示原因或下一步。确认期限从提取完成开始为 2 分钟，取消与过期不新增参考；保存是否成功以接口确认及已保存照片列表为准。上传沿用文件与解码像素限制、EXIF 方向处理；人物上传检查单人脸，猫狗上传检查单只同类宠物；未检出或质量不足显示拒绝原因。候选包含人脸或动物裁剪，不提供用户视频文件上传。

参考区显示已保存照片数量、缩略图及删除操作，页面可见时每 5 秒刷新参考及模型状态。人物及猫狗保存参考后自动启用识别，参考区显示识别状态及启停按钮；模型或参考版本不适用时显示具体原因。识别按固定阈值工作，实时面板以“疑似”和“已识别”区分识别依据是否充分。重名人物仍按 UUID 归属，参考操作不写入文字资料 `/save`。实时摄像头页面提供当前人宠成员关联，成员参考区不修改历史判断。页面离开会取消未保存登记，过期会话仍可取消后重新开始。完整输入、容量和接口限制见 [Backend 参考登记](../backend/README.md#人物识别参考存储)。

成员详情使用与房间页相同的内容宽度：宽屏上方左侧为基本资料，右侧为 AI 成员画像，下方的最近活动占满内容区；小屏幕改为上下排列。AI 成员画像生成尚未接入，页面明确展示未接入状态，生成按钮不可用，不生成或保存总结。

最近活动读取当前成员关联的 `context_records`，复用家庭上下文只读接口，每页 25 条，按发生时间倒序展示。首页在页面可见时每 5 秒刷新，翻页后停止自动刷新，点击刷新返回首页。后台把有效人宠关联及支持证据保存为成员观察，同一来源运行、轨迹、人物和参考版本合并为一条，观察时间随新证据更新；识别依据不足时显示“疑似”，达到多次采样支持条件后显示“已识别”，状态说明解释自动识别依据；状态来自采样证据，不是用户确认。记录中的房间描述摄像头归属，不证明成员位置，也不推断正在做什么。参考登记本身不是活动记录，行为理解尚未接入。展示观察／判断类型、描述、发生时间和确定程度；其他生产者的过期状态按最近一次取得记录的时间判断。成员观察只有存在已生成且未过期的采样视频，或已查询到覆盖最后一次观察时间的 SD 录像时，整条才可点击并显示箭头。不可回看的观察仅展示文本；查询失败或尚未完成不提供入口。回看优先查询 backend 已生成且未过期的采样视频，按来源运行和首次至最后一次观察的时间范围定位最近可播放片段；本轮缓存查询成功结束且未命中后，才查询 SD 录像；缓存正在刷新、因离线暂停或查询失败时，不提供 SD 入口。SD 录像通过 `/api/mijia/recordings/availability` 查询索引，同页同来源的观察合并查询，每 30 秒重新核对。采样片段查询同样按摄像头／镜头合并，查询结果按视频运行建立共享索引，活动行只消费对应回放目标；片段到期后统一更新入口。SD 回看进入独立录像页，先再次核对 backend 缓存；命中时跳转对应筛选片段，确认未命中后才从 SD 卡准备录像、按设备报告时间定位并静音播放，可手动打开声音；设备时间与本机观察时间没有逐帧对齐保证。返回按钮和 Escape 回到原成员，切换分析内容后仍保留成员来源；不可回看的记录不跳转，不以当前画面替代历史证据。片段最多保留 30 分钟，活动记录独立保存。当前不提供活动时间筛选。

成员读取和提交要求家庭连接就绪；同一家庭短暂失去同步时保留已加载资料和草稿，并禁用表单与提交，恢复同步后可继续编辑。切换家庭运行范围、退出账号或家庭访问失效时卸载编辑区并清除草稿。成员 mutation 在业务模块统一处理缓存协调，页面离开后的迟到响应不能触发导航，旧家庭结果不能写回当前缓存。名称最多 100 字符，物种最多 50 字符，描述最多 2,000 字符，每个绑定家庭最多登记 500 位成员。重新绑定家庭时随家庭上下文一起清空。

## 家庭数据库浏览

侧栏“数据”（`/data`）只读展示 `household_subjects`、`context_records` 和 `context_entities`。使用顶部下划线标签切换数据表，查看记录总数、搜索结果和分页，每页 25 条，空表不显示分页，但仍可展开“字段结构”查看列名、类型、允许空值和主键信息。点击记录的“查看”展开完整 JSON，关闭详情后焦点回到该记录的查看按钮；记录已不在页面时回到搜索框。后台刷新失败保留已加载表格和详情，并显示具体错误。成员详情可跳到相关上下文，上下文详情可跳到关联对象，关联详情可返回正文。搜索范围分别为成员名称、上下文描述或主题、关联对象 ID；成员计数为全表准确数量，上下文和关联计数为数据库维护的全表估计，标签与页脚以“约”标识；它们不是搜索匹配数。翻页使用后台返回的游标，页面保存已访问页的位置以支持返回上一页。

切换数据表、搜索或翻页时保留上一份结果，待新结果到达后一起替换内容；等待新结果时明确标识目标表和当前展示的表，关联筛选说明随已展示结果更新；此时旧记录的详情入口不可操作，请求期间分页不可操作。加载状态与完成结果通过独立状态区域播报。加载与空状态保持相同的最小高度。清除搜索和清除关联筛选分别只移除对应条件，并把焦点送回搜索框。

页面读取真实数据库，不自动创建示例数据。尚未接入业务写入时空表属正常状态。家庭运行就绪后才查询；断连、运行标识变化或切换家庭时卸载旧浏览器并丢弃查询缓存，恢复后重新读取。只读接口及访问边界见 [Backend 数据库说明](../backend/README.md#家庭上下文表)。

## 检查

```sh
bunx turbo run lint check-types --filter=@home-agent/web
bunx turbo run build --filter=@home-agent/web
```

通过上述 Turbo 命令构建时会先检查 TypeScript；直接运行 Web 包的 `build` 只执行 Vite 打包，需另运行 `check-types`。Oxfmt 负责格式化。API 契约来自 `@home-agent/api/contracts` 和 `@home-agent/api/mijia`。`VITE_*` 变量会暴露给浏览器，不得存放凭据。

## 类型化 HTTP 客户端

所有浏览器到 backend 的请求使用 `@home-agent/backend/client` 导出的 `createBackendClient`，由 Hono `hc` 从链式路由推导路径、方法、路径参数、JSON 输入和响应。功能模块不拼接 API 路径，不手写 JSON 序列化，也不直接调用 fetch。`packages/api` 继续定义运行时 Zod 协议、错误和 HTTP 语义；客户端请求辅助函数同时检查 RPC 响应类型与校验器输出类型。

`createApiClient(baseUrl, fetchImpl)` 注入传输，默认使用同源路径和浏览器 fetch。功能调用通过回调取得该客户端及请求选项，统一执行超时、取消和错误处理。例如：

```ts
requestJson(
  (client, options) => client.api.config.$get({}, options),
  configResponseSchema,
  { signal },
);
```

`requestJsonResponse` 额外返回解析后的 `Retry-After`，`requestEmpty` 验证 204 响应。播放释放沿用 keepalive。重试默认关闭；播放 offer 显式选择 `retryOnceOnTransportFailure`，最多重发一次相同参数。每次请求沿用调用方的 `timeoutMs`，播放器的取消信号统一约束首次请求和重试，总协商期限为 85 秒，不因重试重新计时。HTTP 业务错误和响应校验失败不自动重试，后台生命周期恢复继续由 backend 管理。

RPC 声明由 backend 的 `build:rpc` 生成到 `dist/rpc`，不提交 Git。Turborepo 在 Web 检查和构建前生成声明；根目录 `bun run dev` 或 `bun run dev:web` 同时运行声明 watcher。单独调用 Web 包脚本前需先执行 `bun run --cwd apps/backend build:rpc`。声明和客户端运行时代码都不引入服务端实现到浏览器包；SSE 接口通过类型化客户端返回原始流，不使用 JSON 响应辅助函数。

家庭设置在首次未绑定或展开“重新绑定家庭”时通过 `GET /api/mijia/setup/homes` 读取候选。设置页显示已绑定家庭；重新绑定需选择其他家庭并确认对设备任务和视频连接的影响，保存期间禁用重复提交。保存后的初始化失败可刷新设备清单重试。设备、看家页标题仅显示对应数量；设置页标题不显示摄像头接入状态，连接问题在具体设置项提示。完整规格与候选家庭不进入公共快照。

设备清单与能力信息由后台自动获取。设备页和看家页不提供常驻刷新按钮；设备页仅在清单同步、初始化或能力信息获取失败时显示“重试”，能力失败同时在侧栏设备入口显示黄色提示点。清单失败重试同步清单与能力信息，仅能力失败时重新获取能力信息。看家页清单失败引导前往设备页处理，单路画面重试保留在播放器内。设置页不提供设备规格维护操作。

设置导航在本机服务正常或首次检查期间不显示状态点；连接失败期间保留静态红点，图标每隔 6 秒轻摆一次，其余时间静止，不添加可见文字或呼吸闪烁；系统开启减少动态效果时只显示静态红点，恢复后停止动画并隐藏红点。

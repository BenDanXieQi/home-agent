# Web

基于 React、Vite、Tailwind CSS 4、TanStack Router / Query、Jotai、React Hook Form、Radix 与 Motion 的本机家庭工作台。

当前提供账号登录、设备列表、摄像头预览、设备日志和设置，尚无聊天、家庭语义展示或建模界面。视频预览只展示摄像头画面，不包含人物识别或活动判断。项目的家庭语义目标见[领域模型规划](../../docs/plans/household-model.md)，不属于当前页面已实现能力。

## 运行

在仓库根目录执行 `bun run dev`，访问 <http://127.0.0.1:5173/>。Vite 将 `/api` 代理到根目录 `.env` 中配置的 backend 地址。生产环境执行 `bun run start`，通过 backend 的 HTTP 端口访问。Vite 静态预览不提供 API 代理。

## 使用流程

设备和摄像头仅展示 backend 所选家庭的范围。在“设置 → 米家家庭”选择要管理的家庭后，页面通过状态订阅显示保存和初始化进展；已绑定时可通过“重新绑定家庭”选择其他家庭。未选择或所选家庭不可访问时设备列表为空。这里的设备清单包括家庭、房间、设备及其归属信息；公共状态是 backend 提供给页面读取的账号、家庭、清单、规格和媒体等信息。

未登录时显示米家登录页，自动获取二维码并在后端报告过期后自动刷新；用户可手动刷新或取消，请求失败后显示重试入口。恢复保存会话和安全验证期间不自动创建新扫码尝试。已保存的授权由 backend 恢复，浏览器不保存账号凭据；恢复失败时可以重试或清除授权。已登录账号窗口只显示账号信息和退出操作，更换账号先退出再扫码。账号授权与扫码尝试分别从公共状态派生为 `account`、`loginAttempt`，摄像头暂停选择随新登录会话或家庭访问失效清空。退出清理失败时保留错误和重试清理入口，清理完成后自动获取二维码。

自动取码的启动条件由 `mijiaCanStartLoginAutomaticallyAtom` 从账号、扫码尝试、命令和读取状态派生。`LoginFlow` 的 effect 仅在启动条件变化时调用 `startMijiaLoginAutomaticallyAtom`；该命令执行前再次读取共享状态，并复用 `performMijiaAtom` 同步设置的 pending 标志防止重复派发。组件不使用 `useRef` 记忆“已经请求过”，因此 StrictMode 重跑和组件重新挂载共用同一启动规则。取码请求失败后停止自动尝试，保留显式重试；按钮操作仍由事件处理器直接执行。扫码任务由 backend 持有，effect 不创建独立计时器，也不在组件卸载时取消服务端尝试。

从根路径开始扫码并登录成功后，先打开设置检查连接状态。已有授权恢复时进入设备页；直接打开或刷新设备、摄像头、设备日志及设置的深链时保留目标页面。读取首个账号快照期间显示加载状态。导航包含设备、摄像头、设备日志和设置，并提供账号入口。窄屏使用底部导航，各入口均有可访问名称。

| 路径           | 内容                                                 |
| -------------- | ---------------------------------------------------- |
| `/`            | 等待账号快照；恢复授权进入设备页，新扫码完成进入设置 |
| `/devices`     | 设备列表、搜索，以及房间、分类、能力和在线状态筛选   |
| `/cameras`     | 平铺显示全部镜头，为可见及邻近区域的镜头建立播放连接 |
| `/device-logs` | 采集设备上报、筛选信号、查看连接记录及比较设备变化   |
| `/settings`    | 连接检查、服务地址配置，以及摄像头接入重试           |

摄像头按名称自然排序，同名时按设备 ID 排序，刷新不沿用云端返回顺序。多镜头设备按支持的通道显示，镜头按 1、2 排列。每个镜头各占一格，进入可见区域及其上下 240 像素范围时独立管理播放预约、浏览器实时音视频（WebRTC）连接、重试和出帧状态。滚动离开该范围或隐藏标签页会释放浏览器观看资源，返回可见区域时自动重新连接。关闭一路不会停止其他画面；用户暂停选择在自动释放资源、媒体运行标识 `revision` 的变化和短暂离线期间保留，切换账号、家庭或离开页面后清空。`revision` 在媒体失效或重新绑定时更换，用于拒绝旧播放请求。由 backend 管理的 go2rtc 摄像头共享流继续取流；视频不经过 backend。设备清单中的在线字段只作提示，不单独阻止播放，能否出帧由实际媒体连接决定。使用限制见[米家与摄像头](../../docs/mijia.md)。

设备日志每次采集持续 10 分钟，也可手动停止。页面保留最近 500 条上报，支持按设备、房间、分类和内容筛选，并可比较多台设备的变化。暂停阅读仅冻结当前展示；切换页面也不会停止后台采集。

连接问题由导航栏的机器人提示。异常时机器人旁显示提示点，点击可展开连接说明和“检查连接”入口；弹层支持 Escape 关闭与焦点返回，窄屏底部导航保留机器人入口。机器人和详情共用 `connectionNoticeAtom`，结合服务可达性和米家摄像头绑定状态。Agent 未连接不影响已经就绪的摄像头预览。

## 代码组织

- `src/app/`：创建应用共用的 Jotai Store 和 QueryClient；`StateProvider` 通过 `AppStateEffects` 装配家庭订阅及配置保存生命周期，将 Store 显式传给订阅。
- `src/api/`：公共 HTTP 客户端、响应校验、取消、超时、重试和结构化错误。传输层不读取 Store，也不依赖界面文案；错误展示由 `messages/zh-CN.ts` 负责。
- `src/modules/household/`：家庭公共快照、状态订阅、纯版本确认规则、同步状态与提示、家庭选择查询，以及共享的 `HouseholdAccess` 访问提示。
- `src/modules/devices/`：从公共快照派生设备清单、同步状态、数量和能力异常；提供设备分类文案与清单错误提示。搜索和筛选属于设备页面。
- `src/modules/mijia/`：`account.ts` 读取账号与扫码尝试，`login.ts` 派生登录展示和自动启动条件，`commands.ts` 统一协调命令互斥、取消和回执确认，`connection.ts` 派生连接重试资格，`api.ts` 转换米家控制协议。账号头像与连接重试入口在该领域内复用。
- `src/modules/playback/`：`access.ts` 派生播放资格，`state.ts` 提供媒体状态及观看阶段汇总；`session.ts` 持有浏览器媒体资源，`api.ts` 接收完整播放目标并发送请求，`history.ts` 处理本地存储，`environment.ts` 观察浏览器环境，`estimates.ts` 保存纯样本规则。React Hook 只装配播放会话、订阅和阶段注册。
- `src/modules/connections/`：服务配置、连接检查、健康查询及派生提示。
- `src/modules/device-logs/`：日志快照与采集命令确认、HTTP 请求和状态订阅；`use-device-logs.ts` 将页面生命周期连接到订阅。
- `src/pages/<页面>/index.tsx`：路由入口及页面组合。设备筛选、日志设备选择、对比选择、筛选与分组纯函数均就近放置；`workspace/` 负责账号路由门控、弹窗状态和跨领域活动提示。`WorkspaceFrame`、`SidebarFrame`、`WorkspaceNavigation`、`WorkspaceHeader` 供加载态和正式工作台共用。
- `src/components/`：不依赖业务状态和请求的通用界面组件，通过 props 接收内容和交互。`Notice` 与 `StatusNotice` 统一提示布局及错误／状态语义。
- `src/utils/`：通用纯函数、动效配置及不依赖业务状态的交互 Hooks。
- `src/index.css`：字体、主题、全局基础规则和共用动画；组件布局和交互样式跟随对应组件。

每份状态只有一个所有者：家庭订阅写公共快照，命令只写请求元数据和确认条件，播放器持有自己的媒体资源。页面读取所需领域状态，不经一个聚合全部业务的 Hook；领域模块不依赖页面，通用组件不依赖领域模块。应用装配负责注入 Store，HTTP 适配函数通过参数取得调用上下文。

同步状态由 `householdSyncStatusAtom` 表达为 `connecting`、`confirming` 或 `synced`；界面另用 `householdSyncMessageAtom` 派生提示文字。业务判断读取状态，未同步和等待回执以普通提示展示，不冒充请求失败。

开关的键盘操作与无障碍语义由 Radix Switch 提供，按压与拖动由 Motion 手势处理。日志页在宽屏使用 `react-resizable-panels` 管理面板宽度、指针调整和键盘操作，设备列表宽度限制为 200–380 像素；窄屏使用上下排列。

基础组件的属性从实际渲染目标推导：原生元素使用 `ComponentProps<"span">` 等类型，Motion 与 Radix 封装使用 `ComponentProps<typeof 目标组件>`。只额外定义组件自己的语义属性，内部管理的属性通过 `Omit` 排除；其余属性（包括 `ref`）透传到对应元素，`className`、样式和事件按组件职责合并。内部测量与调用方共用元素时，通过 `useComposedRef` 合并引用并保留 React 19 回调 ref 的清理。业务组件从协议、Store Hooks 或子组件推导已有输入类型；路由页面不为了统一形式添加无用途的 DOM 属性。

工作台页面挂在无路径的 `account` 父路由下。`AccountGate` 统一处理首个账号快照、未登录界面、根路径登录后导航和账号失效，保留设备／摄像头／设备日志／设置的目标 URL；`pages/workspace/index.tsx` 的 `WorkspaceLayout` 负责工作台布局。`AccountGate` 读取已有的家庭公共状态，不额外发鉴权请求；同账号恢复期间可展示已保存的设备清单，但不能据此开始读取或播放。界面的登录检查不阻止路由模块预加载，也不替代 API 的访问校验。

`RetryConnectionButton` 复用派生 atom 的重试条件与运行状态，登录、摄像头和设置页不各自判断。`RequestFeedback` 分别展示可重连的状态同步提示与操作错误；字段级校验继续由表单处理。活跃扫码状态判定由共享协议模块提供，供登录材料读取和界面共同使用。

登录界面和工作台共用 `loginViewAtom` 组合公共登录状态、当前版本的登录材料与命令结果。日志页以服务端持续推送事件的连接（SSE）为展示数据源，开始／停止采集由状态层统一记录请求、确认和错误，按钮与机器人共用 `deviceLogCaptureAtom`，不保存另一份展示快照；冻结历史用于阅读，属于独立的界面状态。 同一家庭返回日志页保留已知数据并重新连接，切换家庭才清空显示。采集回执由对应任务状态或请求结束后重新订阅的完整快照确认，确认后即消费回执，后续断线不会重新激活旧操作；网络超时只有在推送已显示对应启动或停止效果时才消除提示。控制状态立即渲染，仅日志内容延后渲染。手动服务检查等待配置和服务状态两个请求都结束后才结算，单个请求提前失败不会提前解除忙态。

家庭公共状态由应用级 SSE 订阅写入 `householdSnapshotAtom`，每个标签页共用一条连接，页面切换不会重复建立订阅。派生 atom 从这份状态计算界面所需字段。服务配置、服务检查和 backend 健康检查继续使用 `serviceConfigQueryOptions`、`serviceStatusQueryOptions` 和 `backendHealthQueryOptions` 的 Query 缓存；二维码与安全验证材料按登录尝试 ID 和材料版本单独读取，不进入公共状态。

`performMijiaAtom` 是可写的异步 atom，接受 `MijiaCommand` 判别联合类型，支持 `startLogin`、`verifyLogin`、`cancelLogin`、`retryConnection`、`logout`、`refreshDevices` 和 `selectHome`。React 组件通过 `useSetAtom` 调用，组件外通过同一应用 Store 的 `appStore.set` 调用。命令默认互斥并取消过时的请求；验证码提交期间继续接收 SSE，取消登录和重新扫码可以中止当前验证等待并发起新命令。每次命令持有独立请求序号及取消控制器，旧响应、错误和结束回调不能覆盖新命令。

命令按自身所需信息发起，不以 SSE 已连接为通用前提。首次选择家庭和刷新设备清单必须有已取得的 `scope_epoch`，断流时可携带最后已知值，由 backend 拒绝过期作用域；没有标识就不发送请求，也不补空值。取消和验证登录必须指定尝试 ID。退出、手动开始登录和重试连接使用对应账号命令，不要求先取得快照；首次状态仍不可用时，登录页提供手动登录和清除授权入口。自动取码继续要求公共状态已同步。

命令响应只返回操作结果和 `state_version`，不写入公共快照。HTTP 请求结算后立即释放请求锁；`mijiaCommandSyncPendingAtom` 独立表示页面是否已看到接纳版本，未追上时提示“操作已接收，正在等待状态同步…”，不把已接受的操作改报失败，也不占用命令锁。确认条件是同一 epoch 的 sequence 已达到回执，或 HTTP 结算后重新订阅取得完整当前快照；后者允许后台已经进入比回执更新的作用域。界面反馈由 `commandFeedback` 统一区分请求中、等待确认、成功和失败；家庭绑定与重新连接控件在等待确认期间保持忙态，状态连接失败时允许手动恢复。这份确认不表示后台设备清单刷新已经完成。浏览器至 backend 的网络及超时提示可在新状态消息到达后消除，验证码拒绝等业务失败不会因此清除。

退出期间暂停新播放；HTTP 成功后，旧快照和旧心跳不能越过回执恢复播放，须满足上述版本或完整快照确认。HTTP 结果不确定时，须重新订阅取得完整快照。`householdSnapshotReceivedAtom` 只记录完整快照的接收次数，普通增量和心跳不递增它。单纯 SSE 短断不额外限制播放，也不拆除已有画面；账号替换和媒体重建仍由 `revision` 使旧播放失效。验证码只存在于表单和当前请求执行过程中，提交后清空表单，不进入 MutationCache 或界面 atom。

恢复登录与重新绑定是后台操作：HTTP 202 表示请求已接收，`restoring`／`installing` 等进展通过 SSE 更新。相关按钮结合当前 HTTP 请求与已同步的服务端忙态防止重复触发；断流后的陈旧忙态不阻止手动重试。

服务配置使用 Query mutation，其 observer 在切换页面时保持存活。所有本机 API 查询与 mutation 均使用 `networkMode: "always"`，浏览器的 offline 事件不会阻止请求本机 backend；实际请求仍受超时限制。

## 状态订阅与播放

登录、授权恢复、设备加载和摄像头绑定进展通过同一 SSE 订阅更新，不轮询米家状态。新连接先接收完整快照，再按连续版本应用变化；断流时可保留旧显示并标为未同步，切换账号或家庭时清除旧快照。自动重连、手动重连和页面恢复可见都遵守同一最早重连时间及服务器 `Retry-After`。服务连接仍每 10 秒检查一次，backend 健康状态仍每 30 秒检查一次；这些 Query 检查在后台标签页暂停，恢复焦点或网络连接后刷新。

摄像头页使用应用已有的公共状态；尚未收到状态时显示确认提示，页面挂载不触发设备清单刷新。开始播放要求账号、所选家庭和媒体连接均已就绪，镜头位于可见区域或其邻近范围，且用户未暂停；退出操作还须按命令回执或之后重新取得的完整快照确认作用域。普通设备清单刷新及短暂错误保留观看连接；新登录会话或家庭访问失效、设备访问撤销、媒体运行标识 `revision` 变化时清理对应旧观看资源。播放器的 key 包含 `revision`、设备和通道，无关状态更新不会重建连接；暂停选择由当前家庭的摄像头网格单独保存。

播放预留和描述媒体连接参数的 SDP 信令通过 backend 完成，视频经 go2rtc 的 WebRTC 连接直接到达浏览器；协商成功不等于已经出帧。`CameraWall` 共用一次标签页可见性订阅，每个镜头观察自身与视口的距离。隐藏标签页或滚出邻近范围时卸载播放会话，释放观看预约、浏览器连接及媒体轨道；重新可见时建立新的观看预约，保留用户的暂停选择。后台共享流继续取流。资源术语见[组件与资源](../../docs/mijia.md#组件与资源)。

`PlaybackSession` 在 `modules/playback/session.ts` 中管理观看连接、可见性、帧回调、超时和释放。`use-mijia-playback.ts` 负责 React 订阅和播放状态 atom 注册。家庭作用域 `scope_epoch` 从摄像头页面显式传入播放会话与预约请求；没有已知作用域时不创建播放组件，预约适配函数不读取全局 Store 或补空标识。预留请求与浏览器准备并行；原有连接响应同时提供源活动状态和后端实测耗时，没有额外的播放进度请求或首帧上报。

`MijiaPlayer.tsx` 负责视频容器和操作，`PlaybackStatus.tsx` 负责状态栏，`playback-presentation.ts` 集中派生文案。只有可见且等待首帧时才挂载本地计时器，恢复可见立即读取当前时钟。首帧由 `requestVideoFrameCallback` 确认，实际连接用时和历史记录直接在浏览器完成。中央加载动效在首帧后淡出，不映射耗时百分比；减少动态效果偏好下保持静态。

`modules/playback/estimates.ts` 提供纯样本规则和剩余等待估算，`history.ts` 在 `localStorage` 中按组保存有界记录，每次只写本次连接所属的一组。刷新或重新打开可复用历史，多个标签页不实时同步，同组并发保存允许最后写入覆盖。`environment.ts` 监听当前页面可识别的网络变化，排除跨环境连接样本。存储失败不影响播放。范围只在收到连接响应且有足够本地样本时显示；详细规则见[播放资源](../../docs/mijia.md#http-与追踪)。

React Hook Form 在刷新时保留已修改的服务地址，保存成功后重置表单基线；离开确认弹窗保护未保存的编辑，取消离开后恢复原焦点。账号窗口关闭后，焦点回到侧栏账号按钮。

侧栏顶部的主题机器人统一显示当前页活动。`createWorkspaceActivityAtom` 接收当前路由，在 Jotai 中直接组合服务查询、操作 mutation、家庭公共状态、账号授权、播放状态和日志状态；`WorkspaceBrand` 只订阅派生结果并渲染。页面不注册或回写机器人展示信号。每路播放的状态 atom 由播放 Hook 持有并在挂载期间加入播放器集合，媒体对象不进入共享 Store；日志订阅在收到上报时直接更新日志 atom，列表通过 `useDeferredValue` 延后渲染，机器人读取同一数据源。本机服务离线优先于当前页活动，其后依次是处理中、需要注意和持续监听；自动服务轮询不触发忙态。多路摄像头只驱动同一个侧栏机器人，卡片保留各自的状态文字及等待圆点。空闲偶尔眨眼，处理时轻微歪头，结束后从当前姿态平滑回正，连续状态切换从正在显示的姿态接续；监听时侧头，异常提示一次后保持静态，离线时垂眼；悬停机器人可查看具体状态，减少动态效果偏好会停用动画。

登录页和工作台各路由按需加载；账号窗口随工作台外壳加载，首次打开不等待额外代码。侧栏导航仅在悬停或聚焦时预加载目标路由。设备与摄像头路由分别静态引入自己的列表或播放器，共用 `HouseholdAccess` 的家庭访问与同步提示，数量、能力错误和恢复入口由各页面组合；共享组件不引入设备列表或播放器。因此加载设备路由不加载摄像头播放实现，页面内部也无需新增代码加载等待。Motion 动画功能异步加载，过渡遵循减少动态效果的系统偏好。组件布局、尺寸、颜色、响应式和交互状态直接使用 Tailwind 类名；公共组件通过 `tailwind-merge` 合并调用方样式。类名必须以完整字符串出现在源码中，条件样式使用完整类名映射或 `data-*`、ARIA 状态变体，不能拼接类名前缀和变量。`src/index.css` 只维护字体、主题、全局基础规则和共用动画，不放页面或组件样式类。

## 检查

```sh
bunx turbo run lint check-types --filter=@home-agent/web
bunx turbo run build --filter=@home-agent/web
```

通过上述 Turbo 命令构建时会先检查 TypeScript；直接运行 Web 包的 `build` 只执行 Vite 打包，需另运行 `check-types`。Oxfmt 负责格式化。API 契约来自 `@home-agent/api/contracts` 和 `@home-agent/api/mijia`。`VITE_*` 变量会暴露给浏览器，不得存放凭据。

## 类型化 HTTP 客户端

所有浏览器到 backend 的请求使用 `@home-agent/backend/client` 导出的 `createBackendClient`，由 Hono `hc` 从链式路由推导路径、方法、路径参数、JSON 输入和响应。功能模块不拼接 API 路径，不手写 JSON 序列化，也不直接调用 fetch。`packages/api` 继续定义运行时 Zod 协议、错误和 HTTP 语义；客户端请求辅助函数同时检查 RPC 响应类型与校验器输出类型。

`createApiClient(baseUrl, fetchImpl)` 注入传输，默认使用同源路径和浏览器 fetch。功能调用通过回调取得该客户端及请求选项，统一执行超时、取消和错误处理。例如：

```ts
requestJson(
  (client, options) => client.api.config.$get({}, options),
  configResponseSchema,
  { signal },
);
```

`requestJsonResponse` 额外返回解析后的 `Retry-After`，`requestEmpty` 验证 204 响应。播放释放沿用 keepalive。重试默认关闭；播放 offer 显式选择 `retryOnceOnTransportFailure`，最多重发一次相同参数。每次请求沿用调用方的 `timeoutMs`，播放器的取消信号统一约束首次请求和重试，总协商期限为 85 秒，不因重试重新计时。HTTP 业务错误和响应校验失败不自动重试，后台生命周期恢复继续由 backend 管理。

RPC 声明由 backend 的 `build:rpc` 生成到 `dist/rpc`，不提交 Git。Turborepo 在 Web 检查和构建前生成声明；根目录 `bun run dev` 或 `bun run dev:web` 同时运行声明 watcher。单独调用 Web 包脚本前需先执行 `bun run --cwd apps/backend build:rpc`。声明和客户端运行时代码都不引入服务端实现到浏览器包；SSE 接口通过类型化客户端返回原始流，不使用 JSON 响应辅助函数。

家庭设置在首次未绑定或展开“重新绑定家庭”时通过 `GET /api/mijia/setup/homes` 读取候选。设置页显示已绑定家庭；重新绑定需选择其他家庭并确认对设备任务和视频连接的影响，保存期间禁用重复提交。保存后的初始化失败可刷新设备清单重试。设备、视频页标题仅显示对应数量；设置页标题不显示摄像头接入状态，连接问题在具体设置项提示。完整规格与候选家庭不进入公共快照。

设备清单与能力信息由后台自动获取。设备页和视频页不提供常驻刷新按钮；设备页仅在清单同步、初始化或能力信息获取失败时显示“重试”，能力失败同时在侧栏设备入口显示黄色提示点。清单失败重试同步清单与能力信息，仅能力失败时重新获取能力信息。视频页清单失败引导前往设备页处理，单路画面重试保留在播放器内。设置页不提供设备规格维护操作。

设置导航在本机服务正常或首次检查期间不显示状态点；连接失败期间保留静态红点，图标每隔 6 秒轻摆一次，其余时间静止，不添加可见文字或呼吸闪烁；系统开启减少动态效果时只显示静态红点，恢复后停止动画并隐藏红点。

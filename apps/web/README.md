# Web

基于 React、Vite、Tailwind CSS 4、TanStack Router / Query、Jotai、React Hook Form、Radix 与 Motion 的本机家庭工作台。

当前提供账号登录、房间设备列表、空间关系资料维护、家庭成员资料维护、摄像头预览与分析、短期筛选片段、SD 录像回看、保留帧的人物历史判断、设备日志、家庭数据库浏览、Agent 聊天和设置，尚无行为总结界面。成员归因按本地参考与接纳规则展示，保留推定依据和未知，不能当作当前位置。Backend 到 Agent 的专用数据交付和只读诊断见[当前数据与材料历史](../../docs/household-runtime.md#agent-当前数据与材料历史)。

## 运行

在仓库根目录执行 `bun run dev`，首次运行 `bun run web:trust` 完成本地证书信任，访问 <https://localhost:8443/>。Caddy 把页面与热更新连接转发到 Vite，把 `/api` 转发到 `.env` 中配置的 backend；生产环境执行 `bun run start`，使用同一 HTTPS 入口提供构建页面和 API。Vite 的 `5173` 为内部开发端口，静态预览不提供 API 代理。独立启动 Web 时另运行 `bun --env-file=.env scripts/web-entry.ts development`；入口配置、证书与停止方式见[运行说明](../../docs/running.md#https-与-http2-入口)。

## 使用流程

移动端底部导航固定显示“房间、成员、看家”和“更多”，其余页面及后续新增入口通过“更多”菜单访问，不提供横向滑动；当前页面属于菜单时高亮“更多”。移动端账号入口位于设置页，机器人显示在顶部标题旁。

设备和摄像头仅展示 backend 所选家庭的范围。在“设置 → 米家家庭”选择要管理的家庭后，页面通过状态订阅显示保存和初始化进展。未选择或所选家庭不可访问时设备列表为空。这里的设备清单包括家庭、房间、设备及其归属信息；公共状态是 backend 提供给页面读取的账号、家庭、清单、规格和媒体等信息。

未登录时显示米家登录页，自动获取二维码并在后端报告过期后自动刷新；有效二维码期间仅提示扫码，不提供刷新或取消登录按钮；取码或登录失败后显示重试入口。二维码或安全验证材料读取失败时，只重试读取当前尝试的材料，不创建新扫码尝试。恢复保存会话和安全验证期间不自动创建新扫码尝试。已保存的授权由 backend 恢复，浏览器不保存账号凭据；恢复失败时可以重试或清除授权。已登录账号窗口只显示账号信息和退出操作，更换账号先退出再扫码。账号授权与扫码尝试分别从公共状态派生为 `account`、`loginAttempt`，摄像头暂停选择随新登录会话或家庭访问失效清空。退出清理失败时保留错误和重试清理入口，清理完成后自动获取二维码。

自动取码的启动条件由 `mijiaCanStartLoginAutomaticallyAtom` 从账号、扫码尝试、命令和读取状态派生。`LoginFlow` 的 effect 仅在启动条件变化时调用 `startMijiaLoginAutomaticallyAtom`；该命令执行前再次读取共享状态，并复用 `performMijiaAtom` 同步设置的 pending 标志防止重复派发。组件不使用 `useRef` 记忆“已经请求过”，因此 StrictMode 重跑和组件重新挂载共用同一启动规则。取码请求失败后停止自动尝试，保留显式重试；按钮操作仍由事件处理器直接执行。扫码任务由 backend 持有，effect 不创建独立计时器，也不在组件卸载时取消服务端尝试。

从根路径开始扫码并登录成功后，先打开设置检查连接状态。已有授权恢复时进入房间页；直接打开或刷新设备、看家、设备日志及设置的深链时保留目标页面。读取首个账号快照期间显示加载状态。导航包含 Agent、房间、成员、看家、日志、数据和设置，并提供账号入口。窄屏使用底部导航，各入口均有可访问名称。工作台标题栏最小高度为 64 像素，进入看家详情等子页时，右侧操作按钮的增减不会改变单行标题的位置。

| 路径                               | 内容                                                       |
| ---------------------------------- | ---------------------------------------------------------- |
| `/`                                | 等待账号快照；恢复授权进入房间页，新扫码完成进入设置       |
| `/agent`                           | 向常驻主会话提交消息并显示本次回答                         |
| `/members`                         | 按成员名称切换标签页、查看及编辑成员资料                   |
| `/members/new`                     | 独立添加人物或宠物，保存后进入新成员标签页                 |
| `/devices`                         | 按房间浏览设备、属性详情、搜索与筛选                       |
| `/cameras`                         | 看家：平铺显示全部镜头，为可见及邻近区域的镜头建立播放连接 |
| `/cameras/$deviceId/$channel`      | 查看实时检测、筛选片段及其关联的 SD 录像                   |
| `/cameras/$deviceId/$channel/view` | 放大观看单个镜头，返回看家或进入画面分析                   |
| `/device-logs`                     | 按时间查看设备属性与在线历史、比较设备报告及导出记录       |
| `/data`                            | 家庭成员、上下文及对象关联的记录浏览                       |
| `/settings`                        | 连接检查、服务地址配置，以及摄像头接入重试                 |

摄像头按名称自然排序，同名时按设备 ID 排序，刷新不沿用云端返回顺序。多镜头设备按支持的通道显示，镜头按 1、2 排列。每个镜头各占一格，进入可见区域及其上下 240 像素范围时独立管理播放预约、浏览器实时音视频（WebRTC）连接、重试和出帧状态。滚动离开该范围立即解除显示和解码，未被接管的连接在 1 秒交接期后释放；标签页短暂隐藏时保留播放器和连接，连续隐藏 15 秒后释放连接；缓冲期间返回沿用原连接，释放后返回重新连接。关闭一路不会停止其他画面；用户暂停选择在自动释放资源、媒体运行标识 `revision` 的变化和短暂离线期间保留，切换账号后清空，页面切换不清空。`revision` 在媒体失效时更换，用于拒绝旧播放请求。由 backend 管理的 go2rtc 摄像头共享流继续取流；浏览器预览视频不经过 backend，本地感知使用独立分析分支。设备清单中的在线字段只作提示，不单独阻止播放，能否出帧由实际媒体连接决定。使用限制见[米家与摄像头](../../docs/mijia.md)。

房间、日志和 Agent 接收页共用搜索输入控件及属性值格式化入口：枚举说明优先，其次识别开关布尔值，其他值按 JSON 保留字符串、数值、布尔和 null 的类型；单位统一显示，缺少有效值标为“无值”。格式化使用各页实际提供的元数据，房间当前属性没有携带枚举列表时显示原始值；日志继续使用报告保存时的规格，接收页使用接收记录附带的规格。房间与日志的房间筛选按家庭、房间 ID 区分，搜索范围分别为当前设备清单、已加载日志和保留的接收记录。

房间页（`/devices`）展示设备清单和最近属性报告。顶部以房间切换范围，默认“全部房间”；房间按家庭与房间 ID 区分，包含尚未分配设备的房间，未分配设备单独列为“未分配房间”。支持按房间名、设备名、标识、别名和型号搜索，并按分类、能力和在线状态筛选设备。

设备行展示名称、所属房间、最多两项最近报告和米家报告的在线／离线情况。在线状态由设备清单初始化并随实时上下线通知或清单刷新更新，浏览器尚未同步时显示待同步；来源连接健康在采集诊断中展示。尚未上报属性的设备仍保留。列表保留属性名、值及单位，过期报告标为已过期；完整属性及来源说明可悬停查看，长内容省略显示。展开详情查看型号、订阅状态、全部属性（含缺值项）、来源与具体原因、报告／读取／变化时间，以及一次性读取入口；每次最多读取前 100 项可读属性。摄像头画面和日志入口位于设备详情。页面底部的家庭采集诊断提供缺口、丢弃、拒收信息和采集重试，不受列表筛选影响。

设备列表延续浅灰容器与白色设备行，复用虚拟列表、房间选中线和展开动效。设备行独立订阅本设备属性与订阅状态，未变化的属性分组保留引用；设备上报只更新对应内容，不重算房间和分类选项，也不重新播放整行入场；房间变化后清除展开选择，详情关闭或卸载时取消未完成的页面读取请求。支持系统减少动态效果设置。

设备日志读取数据库中已保存的属性与在线报告，默认查询最近一小时，最新记录在前。页头的时间范围入口显示开始时间与“至今”或固定结束时间，提供近 15 分钟、1 小时、6 小时和 24 小时的快捷起点；自定义时间展开后按本地时间选择固定区间。按设备与报告类型在服务端筛选；设备选择区从当前设备清单提供房间、分类和设备搜索，最多比较四台设备。重置会清空设备搜索、房间、分类、单选设备与对比选择，并保留当前浏览或对比模式。已移出清单设备的历史仍可在全部历史中读取，名称缺失时显示设备 ID，原始数据保留完整标识。阅读、设备对比与导出统一使用变化记录：后端只保存首次值及值或属性说明变化，连续同值不会新增记录；页面显示每条记录的接收时间，不提供表达方式切换或报告次数。每批按接口上限读取至多 1,000 条；单页仍受接口字节预算约束，滚动接近底部时按游标自动读取更早记录并追加到同一列表，批大小不是整个时间范围的记录上限。事件列表保留动态高度虚拟化、展开项与键盘焦点；对比表按时间分组动态测量和虚拟化，只挂载可见分组、预加载分组及当前焦点分组，详情展开状态不随离屏卸载丢失；阅读冻结时保持位置，页面记录退出后通过虚拟列表公开测量接口释放旧测量。整行进入使用淡入和位移，不把行高度从零展开，以免批量到达时和虚拟测量相互触发。记录计数仅表示当前已加载记录，属性／描述／值搜索也只检查已加载记录；空页不表示设备离线或区间完整。连接与订阅诊断仍在设备页底部查看。

第一页通过独立历史 SSE 接收已入库记录：先取得当前页，后续只接收变化记录、移出项和完整页顺序，查询结束时间随成功保存后的更新推进。普通列表与设备对比共用阅读状态：向下滚动时保留正在阅读的记录，实时流继续接收最新页；回到顶部或点击“回到最新”后显示最新结果。断流会保留已有显示并重连，重新取得当前有界首屏，不完整重放断线期间的逐条报告；读取失败时提供“重试”。滚动接近底部时，自动按冻结的结束时间读取更早记录，关闭实时首屏流并把结果追加到原列表，不显示页码或翻页按钮。继续读取保留滚动位置及阅读冻结；切换设备或记录类型保留冻结的时间范围，并重新读取筛选结果。显式修改时间范围时重新建立查询，筛选或范围变化都会清空追加的历史。固定范围的阅读按钮为“回到顶部”；页头的“回到最新”重新取得实时首屏并释放追加的历史。

初始读取、实时更新、分页和导出统一使用 `POST /api/device-history/events`。导出始终读取当前时间、设备和类型条件下的全部已保存报告；服务端在一个 SQL 查询快照和原生游标中生成有界临时页文件，结束事务后连续交付数据批次，浏览器保存接口记录的 JSONL（每行一个 JSON 对象），可取消等待；已加载记录的文本搜索不影响导出。服务端临时页文件与浏览器 JSONL 内容分别限制为 64 MiB，超限不生成下载文件，需缩小时间区间或设备范围；导出不以页面已加载记录替代完整查询；读取期间的晚提交报告不进入这次查询快照。导出沿用 Backend 配置的读取期限，超时或流失败时不生成部分文件，需缩小范围后重试。

日志页通过路由的 `staticData.contentLayout` 声明使用视口布局：固定在工作台可用视口内，设备列表与日志内容分别滚动，页头保持固定。首次读取使用阅读器加载状态，读取更早记录时在列表底部提示；切换设备或筛选条件时不在面板上方插入加载文案。单选设备的背景与勾选图标在各自设备行内同步淡入淡出，不跨行滑动；设备行预留图标空间，选中时不改变文字宽度。列表高度随筛选、异常提示和窗口尺寸调整；筛选区空间不足时可单独滚动，给设备列表和日志内容保留最小阅读空间。宽窄屏共用同一组设备选择器与日志阅读器，只切换面板排列方向，保留搜索、视图和阅读状态。窄屏展开设备选择时，上下两区均分可用空间，收起后日志区使用剩余空间，并预留底部导航位置。

连接问题由机器人提示，桌面端位于侧栏，移动端位于顶部标题旁。正常或等待连接期间，机器人仅展示活动状态，不提供连接弹窗。异常时机器人旁显示提示点，点击可展开连接说明和“打开设置”入口；连接恢复后关闭弹窗。弹层支持 Escape 关闭与焦点返回。机器人和详情共用 `connectionNoticeAtom`，结合服务可达性和米家摄像头绑定状态。主动检查连接在设置页操作。Agent 未连接不影响已经就绪的摄像头预览。

## Agent 接收数据观察

接收索引首次读取全部保留摘要，之后每两秒按接收会话和序号查询新增摘要，并按服务端最早保留序号清理已淘汰记录。搜索仍覆盖全部保留记录的完整变化，展开详情仍固定为当时接收版本。

导航“数据”打开 `/agent-context`，通过 Backend 的本机只读代理 `GET /api/agent/receipts` 读取独立 Agent 进程的接收记录索引，每 2 秒更新。此页依赖 Agent 服务，不独立订阅 Backend 发布流，不用发送端状态替代接收端证据。Agent 不可用时隐藏旧结果并显示错误。

“接收记录”按 Agent 接收顺序倒序展示时间、初始接收／状态更新、涉及的数据部分、接收消息大小和合并后上下文大小；常规状态更新不重复显示协议与成功提示，只标记初始接收和同步未完成。接收消息按 SSE 数据正文计算；上下文按完整 `{ scope, parts }` 的紧凑 JSON 计算，均为 UTF-8 字节数，使用 KiB／MiB 显示，精确字节数通过悬停查看，仅大小变化时显示相对上一条接收记录的增减，不等于进程内存占用。大小不变不表示内容未变。可按序号、时间、部分名称及全部变化中的房间、设备、属性和变化值筛选。展开直接展示索引中该条记录的完整变化，不读取消息正文或合并快照，不提供记录 JSON 导出；省略的部分沿用旧值；设备增量只更新或删除指定条目，其他提供部分整体替换。列表预览前三项变化，设备属性按“房间 / 设备 / 属性：旧值 → 新值”展示；首次接收与删除单独标记；同值更新显示“当前值：…（未变化）”，并列出实际变化的可用性、报告、上报／读取时间、有效期和候选值。属性名称缺失时明确显示属性编号与“名称未知”。统一观察展示新增、更新和移除的线索与引用，并描述成员出现归因修订、窗口内容修订、语音与叫声数量、原始音视频保留状态及片段生成状态等材料摘要变化，不另行读取材料来补充列表。仅采集接收计数等未进入业务摘要的更新时显示“无属性或观察变化”；统一观察仅读取时间或查询范围变化时不重复推送。展开默认展示完整变化列表，每次显示 20 项。设备属性浏览的描述和单位从接收到的设备清单规格读取；规格尚未收到或属性未定义时显示属性地址。展开后固定列表，收起或选择“返回最新记录”恢复索引更新；接收本身一直运行。已被服务端淘汰的记录无法重新读取。

接收器完整保留当前连接与家庭资格下的接收记录，页面显示接收与保留数量。记录只在 Agent 内存中，断线、重连、家庭资格变化、停止或重启会清空。页面观察到接收会话变化时清除旧选择和阅读内容。不是持久历史，也不补录上线前的数据。

“近期操作”分区通过 RecordBrowser 展示来源、完整 target 与三个时间字段；名称及能力描述仅按当前快照解析，不表示历史名称，缺设备或规格时显示原始 target。压缩上下文保留同一 operations 部分的状态、截断、来源文本与完整目标参数；发送开始不等于生效，移出近期窗口不表示撤销，范围不构成完整审计。

原始上下文和压缩后上下文通过“获取最新上下文”更新当前阅读快照；页头“刷新接收记录”仅在接收记录标签显示。JSON 阅读区统一提供“下载 JSON 文件”和“复制 JSON 内容”，页面不重复放置下载入口。下载直接使用当前数据，不依赖阅读区排版成功；压缩转换与阅读器加载期间沿用说明、工具栏和阅读区的布局。来源的截断标记保留。JSON 使用 Web Worker（浏览器后台线程）格式化，通过 Pretext 排版和 TanStack Virtual 按可见行挂载，自动换行并可连续滚动。列表轮询只传递索引，不重复拉取大消息正文；离页取消请求并释放缓存。接收规则、生命周期与连接详情集中在折叠说明中；接收时间和心跳时间单独显示，心跳不增加记录数量、不更新最近数据时间。

“原始上下文”中，可在“统一观察”分类展开单条观察和关联成员记录。画面变化、声音和转写属于窗口，不推断关联成员是说话人。点击“查看画面”复用成员页的播放查找：优先按窗口 ID 定位可播放本地片段，否则查询摄像头录像；窗口观察使用时间区间中点查询和定位录像，独立成员记录使用最近观察时间；跳转分别保留录像片段起点、实际定位时刻和原观察区间。没有成员关联也能查看画面，等待连接、查询中、查询失败、来源暂不可用和成功无结果分别显示；查询失败或来源暂不可用时可重新查找。查找、窗口匹配与跳转由 `modules/playback/` 和共用播放链接维护，数据页不自行编码媒体。

数据页的家庭情景提供“空间关系”分类，展示接收的空间、通道和观测绑定，通道两端、观测目标与设备来源按名称关联；可搜索、筛选绑定启停状态并查看原始 JSON。接收记录列出空间、通道和观测绑定的新增、更新与删除；观测绑定保存接收时的来源和目标名称，并展示来源、目标、启停状态与说明的变化，支持按名称搜索，删除后仍保留当时的名称。

## 独立图片分析

看家页和登录页的“图片分析”打开 `/cameras/images`，通过独立公开路由使用工作台布局，不经过米家账号门禁，可在未登录、未选择家庭、没有摄像头或媒体不可用时使用。选择、分析与重新选择共用一个 `Button`，各状态保持稳定宽度，图标和文案直接切换。首次选图在准备完成前保持“选择图片”，准备成功后显示“重新选择图片”；重新选图、重试和继续分析在等待期间保留各自的操作来源，分别保持“重新选择图片”“重试分析”和“分析图片”。等待反馈复用 `Button.pendingAction`：前 150 毫秒禁用，持续等待后显示进度图标与可点击的“取消等待”；快速完成时不插入取消文案。准备与分析阶段还由下方状态提示展示。选择文件后显示实际提交 PNG 的预览和尺寸并自动分析，随后展示检测框、类别、置信度、目标数量及默认展开的完整 JSON。重新选择时只在确认新文件后替换输入与结果，取消文件选择保留原内容；准备失败回到“选择图片”，请求失败保留当前图片并显示“重试分析”；本机访问失效后释放图片并回到“选择图片”。取消等待保留已准备图片并显示“分析图片”；尚未准备完成时回到“选择图片”。图片名称旁的 × 直接清除图片与结果并取消在途等待，焦点回到显示“选择图片”的主按钮。页面提供准备、上传等待、忙碌与失败反馈。此入口不管理视频采集，不生成轨迹。

`image-size` 在完整解码前读取并校验图片尺寸，无法确定尺寸的输入直接拒绝；浏览器原生处理图片方向与透明背景，解码后再次校验实际尺寸，预览和上传共用一份 PNG。输入字节、像素及等待限制与 HTTP 行为见[独立图片上传分析](../../docs/perception.md#独立图片上传分析)。页面取消等待并释放对象 URL；替换、清除、离页和本机访问失效后拒绝旧响应，原生准备仍在完成时只继续最新选择。图片页不挂接摄像头播放或感知订阅，后台配置分析继续运行。浏览器上传、取消和持续视频联合负载尚未完成运行验收。

## 看家详情与感知帧查看

实时详情侧栏的“当前成员关联”与画面调试数据并列，显示后台核验的成员名称、完整成员 ID、轨迹、判断状态和观察时间。已有成员关联的未确认状态显示“可能是某成员”，多次采样支持的确认状态显示“系统识别为某成员”，同名按 ID 区分。归因依据展开后先用一句话说明人脸、宠物、家庭登记资料或人体外观判断的原因；技术详情展开后显示成员 ID、目标来源、支持帧、实际参考来源、人脸确认时间、媒体代次、证据标识及模型／处理／参考版本；目标证据最多展示前 8 份并注明省略数量，保存的摘要不变。余弦相似度和领先差值是匹配分数，不是身份概率。当前成员关联及其完整支持依据统一从来源级 `associations` 读取，外观关联不要求该来源有人脸结果；来源失效、撤权或期限结束时撤下实时关联。面板复用当前来源的既有感知订阅；定格时继续实时更新并明确说明不属于定格画面。面板分别提示身份分析未启用、状态同步中、来源未配置或不可用、等待首个结果、结果过期及身份分析暂不可用；失同步、来源撤权、运行变化及结果失效后清空当前关联，成员改名更新实时展示，不清空支持；名称、描述及同分类物种写法修改不触发重采样。参考停用撤销对应特征关联，唯一物种归因仍按全部家庭资料判断；删除成员或改变物种资格重新计算关联。筛选片段继续展示冻结的窗口身份。实时视频分析 JSON 中的 `source.identity` 是当前判断摘要，不含内部结束轨迹 `recent` 或逐轨迹完整 `evidence`；窗口历史判断仍从窗口详情读取。

画面分析与独立图片分析沿用工作台的内容边距，不额外居中限宽。实时检测与筛选片段共用顶部返回与模式切换区域，镜头标题、房间信息和画面起点保持一致；宽屏均采用左侧画面、右侧信息的两栏布局，窄屏按画面在前、信息在后排列。画面区域固定为 16:9，最高为视口高度的 65%，实际图像完整等比显示；暂无片段、仅文字与加载状态也保留同样尺寸。片段播放器位于左侧顶部，媒体选项和说明在画面下方，右侧展示片段列表、语音与其他详情。实时画面的定格／返回实时操作与播放状态放在同一工具栏，视频 JSON 默认展开，声音原始 JSON 默认折叠。独立图片分析保持自己的画面与结果布局。

看家页每个镜头卡片的“画面分析”进入 `/cameras/$deviceId/$channel`，工作台导航保持选中“看家”。详情按该设备与镜头匹配感知来源，用原生 WebRTC 解码帧、来源媒体代次及 RTP 时间关联检测／跟踪，并支持定格、返回实时与 JSON 查看。未配置感知的来源仍可观看和定格，并明确显示暂无检测／跟踪结果；不自动改看其他来源。后台按配置独立持续分析，看家列表和详情不提供采集管理；进入、离开、定格及返回实时均不启停后台。视频与声音分析使用独立面板；视频 JSON 默认展开并实时更新。实时模式下两个面板全部折叠时停止取样，重新展开恢复更新；定格模式重新展开仍读取原定格快照。视频内容仅在其面板展开时挂载和生成 JSON。定格同时固定画面、框与 JSON，隐藏标签页不重新取样已定格内容，返回实时恢复更新；当前规则见[后台分析与结果校验](../../docs/perception.md#后台分析与结果校验)。独立图片分析使用 `/cameras/images`；详情的“筛选片段”入口查看短期窗口筛选与媒体，并可从片段详情查找对应的 SD 录像。协议、预算和实机验证范围统一见[感知说明](../../docs/perception.md#单路帧关联与定格)。

声音分析位于独立声音面板内，展示音轨状态、声音能量、人声概率、后台阈值判定和分块时间区间；原始 JSON 默认折叠，仅展开时挂载并生成，折叠后停止序列化。折叠整个声音面板会卸载其内容，重新展开时原始 JSON 恢复默认折叠。视频与声音共用一次 250 ms 取样和定格快照，声音区间独立于视频帧；页面按 `sources[].audioTrackRunId` 关联音轨，核对家庭范围、设备与镜头资格，不依赖视频计算是否就绪。声音分析只提供能量与人声活动检测，不转写内容、识别说话人或描述环境声音；最新分块持续替换，不保留完整说话记录。无音轨、输入不足、过期与失败不推导成“无人声”。时间基准、共享音轨语义及已验证和未验证范围统一见[声音分块查看](../../docs/perception.md#声音分块查看)。

### 窗口筛选与媒体

画面分析页提供“实时检测”（当前画面与检测结果）和“筛选片段”（后台筛选的历史短片段，`?mode=windows`）。筛选片段按当前家庭、设备和镜头展示，直接进入不会创建实时观看连接；切换模式不影响后台持续分析，也不把当前检测框叠加到过去片段。首次打开筛选片段后，在同一镜头详情内切换到实时检测会保留片段页、选中项、已加载媒体及播放位置；隐藏时暂停播放并停止窗口请求，返回后可从原位置继续播放，无需重新下载已加载媒体。首次只看实时检测不加载片段页；离开镜头详情、切换镜头时释放这份页面缓存。

通过筛选的窗口自动生成默认媒体：视觉候选保存全景采样视频，有完整音轨时携带声音；纯音频候选保存声音。视频缓存从片段关闭后最多保留 30 分钟；文字、人物判断、声音分类、观察时间与 SD 定位信息保存到数据库，保留 365 天。全部摄像头的磁盘缓存及在途编码预留合计最多 1 GiB；容量满时优先清理最旧且未在读取的产物。时间、容量、摘要预算和访问资格均可能提前结束可读性，不保证任何负载下留满半小时。此功能不调用 LLM，也不建设语义任务队列。

列表在前台读取来源过滤后的轻量摘要，有排队或生成中的片段时每秒更新，其余时候每四秒更新，与窗口关闭周期一致。后台只接纳画面变化达到阈值、已有非空语音转写或在完整音频中检出猫狗声音的窗口，页面直接展示后台记录，不提供筛选开关；服务端每页最多 50 条，可按日期筛选、翻到更早记录或返回最新记录；成员活动入口保留完整短期缓存用于定位，列表先显示 50 条，按需继续展开，已定位且位于首批之外的选中片段单独显示；列表区分缓存可播放和仅保留文字、可查找 SD 录像的状态。未启用数据库、保存失败、待保存队列满或因资格变化丢弃待写记录时明确提示。数据库读取暂时失败时仍可查看当前有权限的缓存，并提示历史查询受限，不把缓存列表当作全部历史。仅建立比较基准的首帧、静止画面、单纯声音能量过阈或只有人物判断不保留为历史，也不生成媒体。来源为连续比较独立保留一张有界前置帧，触发跨窗变化时会连同该帧一起回放。等待转写期间只保留有界的关联元信息，不为未通过窗口保留回放画面和声音；迟到文字到达后形成文字记录，不恢复已丢弃的媒体。未开启转写时，画面变化和已启用的猫狗声音分类均可形成记录。画面变化不表示已确认有人走动，转写不确认说话人或排除电视声。列表区分排队、生成中、可播放、失败和已清理，并给出语音段数、猫声／狗声标签、人物轨迹数及当时已确认的本地标签。猫狗声音详情包含分数与整段分析区间，不推断具体宠物；纯声音片段可直接回听。尚未选择片段且列表中只有一个未过期、可播放的片段时自动选中；选中后保留当前内容，新片段到来不切换。选择片段后读取详细事实并直接加载已生成的默认媒体，无需再点击申请。显示的“最晚保留至”属于压缩媒体期限，原始像素的短期保留期限独立存在。

详情的“语音文字”按音轨运行、媒体代次和实际音频区间关联本地转写，跨窗口语音保留完整文字并标注延续关系，不推断说话人。窗口关闭后仍可补充在期限内完成的转写，列表版本变化会刷新详情且不卸载已打开的媒体；无文字、未启用和条数截断分别提示。

详情的“当时人物判断”只读取每张保留帧的 `identity` 历史快照，按帧时间展示当时的分析状态、人物轨迹、本地参考标签、支持证据数与最近证据时间，不读取来源的最新身份状态。未收到准确帧结果、当时未启用、缺少人物判断和当时识别尚未完成分别显示；未收到结果不推导成无人，历史中的未完成状态不显示为当前加载。后续识别不会回填或改写这些判断，本地标签也不代表已核实的家庭成员身份。SD 回看中的“保留帧”定位按钮使用相同帧编号；判断仍只属于这些采样帧，不随播放器进度更新，也不扩展到整段录像。

原始输入仍可读时，可以显式生成其他全景／裁切图片、视频或声音表示；原始输入释放后，仍可切换类型和声音选项，读取已保存的媒体，但不能生成新的媒体。每种媒体按自己的状态判断是否可读取，默认片段被清理不影响其他仍保留的媒体。没有合适裁切区时显示实际使用全景。排队或生成中每 500 毫秒只读查询；申请响应丢失后只读核对结果。临时网络或服务器错误最多重试三次，重试间隔逐渐延长；明确不存在或已失效的窗口停止自动查询，显示不可用。编码失败仅在原始输入仍可用时允许手动重试，不自动重复编码。

当前选择不被新片段或列表读取失败替换；主动切换日期或翻页时清空选择。家庭状态连接暂时失联时，暂停新请求、生成和重试，保留当前选择及已经加载的媒体；同步恢复后重新核对后台生成状态。已经完整加载到浏览器的一份媒体（最多 4 MiB，不含解码资源）可以继续播放和拖动；切换片段、媒体类型、镜头或离页时释放。后台清理后，已释放的浏览器副本不能再次下载；确认访问撤销时清理当前查看。到期使用一次性通知，JSON 仅在展开且数据改变时生成。HTTP 错误结构化保留状态码，可解析的 JSON 错误附带服务端原因。

媒体文件属于单个 backend 运行期间的临时回看缓存，不写入家庭数据库；正常停止删除产物，重启清理上次中断遗留的自有文件，不恢复旧媒体引用；已提交的文字与时间记录仍通过数据库恢复列表和详情，可查找原摄像头的 SD 录像。浏览器刷新不重启 backend，仍可重新读取保留范围内的片段。资源预算和未完成验收见[感知说明](../../docs/perception.md#媒体窗口筛选与按需读取)。

### SD 录像回看与事件定位

SD 录像在准备、可播放、过期、撤权及不可用状态下保留相同的画面区域尺寸，原生播放器在区域内完整等比显示。窗口详情的“查找 SD 录像”使用仍保留的事件摘要，不要求原始像素或本地采样媒体仍可读取。已接纳观察的文字与时间引用在数据库中保留 365 天，未接纳窗口只保留分析等待期间的关联元信息且不开放查询。此入口读取原摄像头与镜头的 SD 录像，不延长记录期限；后端重启后仍可查找。SD 录像被覆盖或不可用时，文字记录继续保留；记录到期后无法再按该窗口查找。

准备完成后，原生视频播放器直接读取有访问校验的媒体 URL，按播放和拖动需要读取文件范围，不先下载整个文件到浏览器内存。回看从所选录像开头开始；窗口事件只有在后端把多张保留帧与录像中的画面唯一对应并核对时间间隔后，才自动定位事件，显示误差范围及按保留帧编号定位的按钮。缺少这种证据时只展示附近时段的候选录像，不把本机接收时间换算成准确播放位置。录像时段和缺口可在播放器下方展开查看。浏览器事件定位按钮跳转到非零位置的端到端验收仍未完成。

每次回看由独立资源持有。准备期间可取消；创建响应丢失时沿同一标识恢复状态，不重复建立新资源。切换录像、关闭、离页或来源访问失效后取消请求并释放资源。回看缓存仅属于当前 backend 运行，申请后最多保留 30 分钟，也可能因容量或访问资格提前失效；媒体读取仍须通过当前家庭和来源校验。SD 回看不重新生成人物判断或转写，也不读取最新结果补到历史画面。窗口附近候选下载或校验失败不会使其他可用候选一起失效；候选证据不完整时取消精确定位，只播放附近的有效录像。协议、媒体预算和来源限制见[米家与摄像头](../../docs/mijia.md)。

## 状态订阅与播放

登录、授权恢复、设备加载和摄像头绑定进展通过同一 SSE 订阅更新，不轮询米家状态。新连接先接收完整快照，再按连续版本应用变化；断流时可保留旧显示并标为未同步，切换账号时清除旧快照。自动重连、手动重连和页面恢复可见都遵守同一最早重连时间及服务器 `Retry-After`。服务连接仍每 10 秒检查一次，backend 健康状态仍每 30 秒检查一次；这些 Query 检查在后台标签页暂停，恢复焦点或网络连接后刷新。

播放预留和描述媒体连接参数的 SDP 信令通过 backend 完成，视频经 go2rtc 的 WebRTC 连接直接到达浏览器；协商成功不等于已经出帧。`CameraWall` 共用一次标签页可见性订阅，每个镜头观察自身与视口的距离。标签页短暂隐藏时保留播放会话，连续隐藏 15 秒或滚出邻近范围后卸载并释放观看预约、浏览器连接及媒体轨道；释放后重新可见时建立新的观看预约，保留用户的暂停选择。后台共享流继续取流。资源术语见[组件与资源](../../docs/mijia.md#组件与资源)。

实时检测只对网络、连接中断和出帧超时等可恢复错误自动重试，每次观看连续失败最多重试三次，等待间隔为 2、4、8 秒；收到画面后重置预算。浏览器能力缺失和响应校验失败保留错误，不自动重新协商，页面提供“重新播放”入口。

普通选择控件使用 Radix Select 管理键盘导航、焦点与输入定位；日志设备类型搜索选择使用 cmdk 管理搜索和选项导航，Radix Popover 管理弹层与焦点返回。界面只适配业务值和样式。

React Hook Form 在刷新时保留已修改的服务地址，保存成功后重置表单基线；离开确认弹窗保护未保存的编辑，取消离开后恢复原焦点。账号窗口关闭后，桌面端焦点回到侧栏账号按钮，移动端回到设置页账号入口。

侧栏顶部的主题机器人统一显示当前页活动。本机服务离线优先于当前页活动，其后依次是处理中、需要注意和持续监听；自动服务轮询不触发忙态。多路摄像头只驱动同一个侧栏机器人，卡片保留各自的状态文字及等待圆点。空闲偶尔眨眼，处理时轻微歪头，结束后从当前姿态平滑回正，连续状态切换从正在显示的姿态接续；监听时侧头，异常提示一次后保持静态，离线时垂眼；悬停机器人可查看具体状态，减少动态效果偏好会停用动画。

## Agent

`/agent` 通过 backend `POST /api/chat` 向同一个进程内主会话提交消息，可以结合之前的对话继续处理；页面只展示本次回答，没有历史列表。刷新页面不清空服务端会话，服务重启后清空。并发消息由 pi-durable 收件箱排队。离开页面或点击“停止等待”结束本次等待并尝试撤回排队消息；已经开始的工作继续运行。失败不自动重发。当前没有家庭资料注入、家庭业务工具或定期巡检，模型配置与运行方式见 [Agent](../agent/README.md)。

## 空间关系资料

`/spaces/manual` 是手动维护次级页面，提供空间、通道和观测绑定三个页签，可新增、编辑、删除，绑定可直接启停。空间资料可在设备连接尚未就绪时维护；新建或更换绑定来源从当前设备清单选择设备与镜头。删除有引用的空间或通道时，页面列出阻止删除的记录，并可打开对应编辑表单；停用绑定仍保留引用。保存后重新读取整体资料。

`/spaces` 默认展示 AI 分析：首页点击加号上传单张户型图，再点击“开始 AI 分析”。上传支持 JPEG、PNG、WebP，选择新图片替换原图。第一次发送以当前空间、通道资料创建会话；会话建立后即可补充说明、回答问题或再上传一张图片继续调整，首轮只返回问题也可以继续。每轮展示最新回答、待澄清问题和完整草稿，可读取草稿或结束会话。右上角“手动维护”进入次级页面，该页可返回 AI 分析。家庭连接就绪后才可调用，模型须支持图片输入。草稿不会保存到数据库，也不采集摄像头画面，不接受视频；离页关闭已创建的会话，创建期间离页会等到 ID 返回后关闭。整页强关或网络故障导致创建回执丢失时，可能保留到家庭撤销或服务关闭。服务重启后需重新开始。失败不自动重发，有会话 ID 时可先读取草稿核对。规划与自动化生成请求由服务执行期限控制等待，浏览器不叠加固定请求超时。

桌面从侧栏“空间”进入，移动端从“更多”进入。先登记空间，再选择两端空间登记通道，最后选择设备／镜头及观察目标填写说明。来源暂时不可用时，已有绑定仍可维护；设备移动或镜头转动后，应人工检查覆盖范围和方向。完整 ID 保留在名称提示中。重新进入页面或回到窗口时按查询缓存策略更新，读取失败可重试。

## 家庭成员

侧栏“成员”（`/members`）与“房间”同级。每个人、每只宠物各占一个以名称标识的标签页，使用房间页的下划线切换样式；成员较多时可横向滚动。下方展示当前成员的基本资料、AI 成员画像区域和最近活动，顶部显示人数与宠物数量。标签页按稳定成员 ID 区分，重名不会合并；选中项保存到 `member` 查询参数，刷新后保留，无有效选中项时展示第一位成员。

“添加成员”打开独立页面 `/members/new`，保存后返回并选中新成员；取消或返回不保存。当前成员的“编辑资料”在其标签页内打开表单，编辑期间暂停成员切换；后台刷新失败只显示错误，不卸载已有表单或清除未保存字段。添加成员保存期间保留顶部返回栏并禁用返回，避免表单位置变化。人物填写名称及外观描述／备注，宠物额外填写物种。保存后把资料写入数据库；已登记成员的类型不可修改。删除须在确认弹窗中确认，只移除成员资料，保留历史上下文。这里管理手动登记的资料和人物识别参考，不显示当前身份关联、当前位置或行为总结。

人物详情的“成员识别参考”提供“从摄像头录制”和“上传照片”两个按钮；猫狗只提供“上传照片”。上传按钮打开文件选择器，人物照片要求单人，猫狗照片要求单只对应物种的宠物。上传后提取裁剪和识别特征，挑选候选并保存，自动启用个体识别。标题旁显示已保存数量与容量，没有照片时显示添加引导。进入录制或候选挑选时隐藏添加入口，录制区域内可取消返回，录制或提取期间使用对应的取消操作。录制区域打开期间暂停删除已保存照片。模型未就绪时，录制与上传入口均禁用。录制按“选择摄像头 → 录制（最长 15 秒，可提前结束）→ 提取人脸照片 → 挑选并保存”推进。选择器来自当前家庭的完整设备清单，显示名称、房间及镜头，不要求来源加入后台检测，也不要求选择人物轨迹。实时预览就绪后才可开始；浏览器通过原生 `MediaRecorder` 录制当前摄像头的视频轨道，不录音。录制显示秒数和进度，可点击“结束录制，挑选照片”提前进入提取，最长 15 秒自动结束。默认通过当前电脑或手机的浏览器语音在开始、第 5 秒和第 10 秒提示拍摄：提示正对镜头和左右转头；录制结束时提示正在提取、随后挑选保存。语音可在录制前关闭，语音不可用时仍展示文字引导；不调用摄像头扬声器，也不自动判定角度是否采齐。结束录制保留已有录像，取消录制才丢弃；取消、离开页面、隐藏标签页和视频中断均终止当前登记等待，不保存参考照片。录制要求浏览器支持 WebM/VP8 或 MP4，暂不支持时可上传照片。

提取完成后显示至多 12 张识别参考候选；候选默认不勾选，用户需核对归属，可按剩余参考容量勾选多张，一次确认保存。页面区分录制中、提取中、候选待确认和登记完成，完成提示明确显示保存数量；空候选、模型不可用、提取失败、确认过期均显示原因或下一步。确认期限从提取完成开始为 2 分钟，取消与过期不新增参考；保存是否成功以接口确认及已保存照片列表为准。上传沿用文件与解码像素限制、EXIF 方向处理；人物上传检查单人脸，猫狗上传检查单只同类宠物；未检出或质量不足显示拒绝原因。候选包含人脸或动物裁剪，不提供用户视频文件上传。

参考区显示已保存照片数量、缩略图及删除操作，页面可见时每 5 秒刷新参考及模型状态。人物及猫狗保存参考后自动启用识别，参考区显示识别状态及启停按钮；模型或参考版本不适用时显示具体原因。识别按固定阈值工作，实时面板以“可能是某成员”和“系统识别为某成员”区分依据是否达到确认条件。重名人物仍按 UUID 归属，参考操作不写入文字资料 `/save`。实时摄像头页面提供当前人宠成员关联，成员参考区不修改历史判断。页面离开会取消未保存登记，过期会话仍可取消后重新开始。完整输入、容量和接口限制见 [Backend 参考登记](../backend/README.md#人物识别参考存储)。

成员详情使用与房间页相同的内容宽度：宽屏上方左侧为基本资料，右侧为 AI 成员画像，下方的最近活动占满内容区；小屏幕改为上下排列。AI 成员画像生成尚未接入，页面明确展示未接入状态，生成按钮不可用，不生成或保存总结。

最近活动读取当前成员关联的 `context_records`，复用家庭上下文只读接口，每页最多 25 条，按发生时间倒序展示；后台完整响应受 2 MiB 限额约束，较大的记录会减少当页条数，分页沿用实际返回的游标，不截断归因依据。首页在页面可见时每 5 秒刷新，翻页后停止自动刷新，点击刷新返回首页。后台把有效人宠关联及支持证据保存为成员观察，同一家庭作用域、来源运行、媒体代次及轨迹合并为一条，后续归因纠正沿用活动 ID 并替换成员主体，观察时间随新证据更新；卡片按摄像头来源与时间、观察结果、判断依据、回看状态展示。主句和状态读取 `attribution.current`；推测记录只在主句写“可能是某成员”，不重复显示“未确认”或固定依据说明；确认时写“系统识别为某成员”并显示“系统已确认”。具体依据在详情中解释人脸照片匹配、全部有效猫狗参考照片一起进行的宠物特征比较、近期已确认画面的外观比较，或家庭资料中仅登记一只同物种宠物的推测；最高匹配分数和唯一登记宠物均不表示确认身份。判断撤回后显示无法确定身份及“判断已撤回”，并说明实际撤回原因，不沿用旧摘要中的成员结论。特征与外观状态来自采样证据，物种归因来自实测框与家庭成员资料；这些状态不是用户确认。记录中的房间描述摄像头归属，不证明成员位置，也不推断正在做什么。参考登记本身不是活动记录，行为理解尚未接入。展示观察／判断类型、描述、发生时间和确定程度；其他生产者的过期状态按最近一次取得记录的时间判断。成员观察只有存在已生成且未过期的采样视频，或已查询到覆盖当前归因证据时间的 SD 录像时，卡片底部才提供“查看画面”链接。查询进行中显示“正在查找可回看的画面…”，没有可用入口时显示“暂无可回看的画面”；查询提示、无画面提示与回看按钮保持相同的最小高度，后台核对时不因状态切换压缩卡片。不把查询失败或尚未取得录像说成过期或未录制。回看优先查询 backend 已生成且未过期的采样视频，按来源运行及当前归因的实际观察时间定位可播放片段；判断撤回时使用最近变更前的归因证据时间，避免跳到另一摄像头的撤回触发时间；本轮缓存查询成功结束且未命中后，才查询 SD 录像；后台核对采样片段和 SD 录像期间保留已查到的 SD 回看按钮与已确认的无画面提示，刷新或因离线暂停时禁用点击；核对完成后更新入口，查询失败时不提供 SD 入口。SD 录像通过 `/api/mijia/recordings/availability` 查询索引，同页同来源的观察合并查询，每 30 秒重新核对。采样片段查询同样按摄像头／镜头合并，查询结果按视频运行建立共享索引，活动行只消费对应回放目标；片段到期后统一更新入口。SD 回看进入独立录像页，先再次核对 backend 缓存；命中时跳转对应筛选片段，确认未命中后才从 SD 卡准备录像、按设备报告时间定位并静音播放，可手动打开声音；设备时间与本机观察时间没有逐帧对齐保证。返回按钮和 Escape 回到原成员，切换分析内容后仍保留成员来源；不可回看的记录不跳转，不以当前画面替代历史证据。片段最多保留 30 分钟，活动记录独立保存。后台轮询不触发“刷新记录”按钮的加载动画，刷新失败保留已有活动。当前不提供活动时间筛选。“查看详情”在白底卡片内展开当前判断依据，以细分隔线和折叠行组织信息，不重复展示当前结论。有身份变更时，一行说明变更前后的结论及处理时间；“判断记录”展开首次判断、最近变更前后的快照与变更说明，并注明不含完整历史，没有变更时不显示。“来源与时间”展示摄像头、登记房间、首次及最近拍到时间、判断更新时间。成员 ID、跟踪编号、分数和模型版本收进“技术详情”。列表不显示判断更新次数。详情读取 `attribution.original/current/lastCorrection`，分别展示最新依据与最近身份判断变更。同一成员从未确认转为直接识别确认也登记变更，普通采样刷新不计入变更。活动中的名称刷新沿用普通保存节流，不累计身份纠正，首次及最近纠正快照保留当时名称；已完成历史不批量改名。撤销区分人脸冲突、身份替换与无法核对结束身份的保守失效，不能据此声称所有未知均已证实错认。归属按当前成员主体查询；撤销后设备来源和摘要仍保存在数据库，不恢复旧成员关联。无可回看画面时仍可查看文字及判断依据，不延长媒体期限。回看定位使用原来源运行及所选归因证据时间，活动起止时间仍独立展示。采样视频打开后定位至最近保留帧，并说明该时刻的帧是否实际保留；附近采样帧没有目标不证明原观察时刻没有目标。采样帧可能经过缩放或裁切，SD 录像仍只有设备时间定位保证。默认未校准时不产生外观活动；全部身份状态的浏览器展示及隔离数据库纠正联动仍需专项运行验收。

成员读取和提交要求家庭连接就绪；同一家庭短暂失去同步时保留已加载资料和草稿，并禁用表单与提交，恢复同步后可继续编辑。退出账号或家庭访问失效时卸载编辑区并清除草稿。成员 mutation 在业务模块统一处理缓存协调，页面离开后的迟到响应不能触发导航。名称最多 100 字符，物种最多 50 字符，描述最多 2,000 字符，每个绑定家庭最多登记 500 位成员。

## 家庭数据库浏览

侧栏“DB”（`/data`）只读展示 `household_subjects`、`context_records` 和 `context_entities`。使用顶部下划线标签切换数据表，查看记录总数、搜索结果和分页，每页最多 25 条，后台按完整响应的 2 MiB 字节预算保留完整记录，较大的记录会减少当页条数；单条记录超预算时明确报错，不跳过该记录。空表不显示分页，但仍可展开“字段结构”查看列名、类型、允许空值和主键信息。宽表格在表格区域内横向滚动，保持页面与顶部控件的宽度；只有实际横向溢出的表格区域进入 Tab 顺序，聚焦后可使用方向键滚动；窗口尺寸或表格宽度变化时同步更新。点击记录整行展开详情和完整 JSON，关闭详情后焦点回到搜索框。后台刷新失败保留已加载表格和详情，并显示具体错误。成员详情可跳到相关上下文，上下文详情可跳到关联对象，关联详情可返回正文。搜索范围分别为成员名称、上下文描述或主题、关联对象 ID；成员计数为全表准确数量，上下文和关联计数为数据库维护的全表估计，标签与页脚以“约”标识；它们不是搜索匹配数。翻页使用后台返回的游标，页面保存已访问页的位置以支持返回上一页。

上下文记录表格隐藏内部去重字段 `source_key`；完整字段结构和展开后的原始 JSON 仍包含该字段，供排查重复写入使用。

切换数据表、搜索或翻页时保留上一份结果，待新结果到达后一起替换内容；等待新结果时明确标识目标表和当前展示的表，关联筛选说明随已展示结果更新；此时旧记录的详情入口不可操作，请求期间分页不可操作。加载状态与完成结果通过独立状态区域播报。加载与空状态保持相同的最小高度。清除搜索和清除关联筛选分别只移除对应条件，并把焦点送回搜索框。

页面读取真实数据库，不自动创建示例数据。尚未接入业务写入时空表属正常状态。家庭运行就绪后才查询；断连或运行标识变化时卸载旧浏览器并丢弃查询缓存，恢复后重新读取。只读接口及访问边界见 [Backend 数据库说明](../backend/README.md#家庭上下文表)。

## 检查

```sh
bunx turbo run lint check-types --filter=@home-agent/web
bunx turbo run build --filter=@home-agent/web
```

通过上述 Turbo 命令构建时会先检查 TypeScript；直接运行 Web 包的 `build` 只执行 Vite 打包，需另运行 `check-types`。Oxfmt 负责格式化。API 契约来自 `@home-agent/api/contracts` 和 `@home-agent/api/mijia`。`VITE_*` 变量会暴露给浏览器，不得存放凭据。

## 自动化规则

`/automations` 提供规则列表、条件树编辑、自然语言草稿、启停和执行记录。条件树使用 `react-querybuilder` 与拖拽适配器，页面边界转换为共享规则契约。生成请求经 Backend `/api/workflows`，返回草稿默认停用；固定动作支持属性写入、设备动作及执行记录中的通知。AI 判断与动作选择尚未启用，编辑器不提供新增选项，Backend 同时拒绝启用包含这些配置的规则。规则和执行语义、接口与验证限制见[家庭自动化](../../docs/automations.md)。
